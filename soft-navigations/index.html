1. 소개

이 절은 비규범적이다.

현대 웹 애플리케이션은 전체 페이지 내비게이션을 수행하지 않고도 사용자 상호작용에 응답하여 콘텐츠를 동적으로 업데이트하는 경우가 많다. 구조적 DOM 수정, 콘텐츠풀 페인트, 기록 상태 변경과 같은 이러한 상호작용으로 시작된 효과는 역사적으로 올바른 사용자 동작에 측정하고 귀속하기가 어려웠다.

전형적인 단일 페이지 애플리케이션 패턴을 생각해 보자. 사용자가 제품 링크를 클릭하면 click 이벤트 핸들러가 트리거된다. 이 핸들러는 제품 세부 정보를 위한 네트워크 fetch()를 시작한다. 응답이 도착하면 콜백이 실행되어 새 콘텐츠를 DOM에 동적으로 주입하고 History 또는 Navigation API를 사용해 URL을 업데이트한다. 사용자의 눈에는 이것이 내비게이션처럼 보이지만, Largest Contentful Paint (LCP) ([LARGEST-CONTENTFUL-PAINT]) 같은 기존 메트릭은 초기 페이지 로드만 측정하고, Interaction to Next Paint (INP)는 클릭 자체의 즉각적인 시각적 피드백만 측정하므로, 그 뒤의 중요한 렌더링과 "소프트" 내비게이션은 포착되지 않는다.

이 명세는 [EVENT-TIMING] API를 활용하여 상호작용을 정의하고, [ASYNC-CONTEXT] 제안을 활용하여 비동기 작업 경계를 가로지르는 인과성을 추적한다. 이 명세는 브라우저가 이러한 효과를 식별하고 보고하는 방법을 정의하며, 여기에는 [PAINT-TIMING] 및 [LARGEST-CONTENTFUL-PAINT]와 통합하여 렌더링 변경을 성능 타임라인에 귀속하는 방식으로 "소프트 내비게이션"을 포함한다.

또한 이 명세는 [CONTAINER-TIMING] 제안과 통합된다. 사용자 상호작용이 DOM 수정을 일으키면, 수정된 노드가 새로운 "컨테이너 루트"로 지정된다. 해당 서브트리 안에서 뒤이어 발생하는 모든 콘텐츠풀 페인트는 각 루트에 귀속되고, 이 루트는 다시 원래 상호작용으로 추적된다. 이를 통해 초기 이벤트 디스패치 이후 한참 뒤에 발생하는 풍부하고 동적인 페이지 업데이트도 효율적이고 정확하게 측정할 수 있다.

2. 상호작용 인프라

2.1. 내비게이션 ID

내비게이션 id는 전역 객체의 수명 안에서 각 내비게이션(하드 및 소프트 모두)에 할당되는 고유한 식별자이다.

각 전역 객체는 현재 내비게이션 id를 가지며, 이는 unsigned long long이고, 초깃값은 Document의 초기 interactionId 값과 Navigation Timing의 초기 navigationId를 초기화하는 값과 동일하게 설정된다.

2.2. 상호작용 컨텍스트 소개

소프트 내비게이션 감지는 작업의 인과성을 추적하고 특정 작업(예: DOM 노드 추가)이 특정 사용자 상호작용에 의해 트리거되었음을 관찰할 수 있는 능력에 의존한다.

이 명세는 이러한 전파를 처리하기 위해 TC39 [ASYNC-CONTEXT] 제안을 활용한다. Event Timing에서 정의한 모든 새로운 사용자 상호작용 또는 관련 내비게이션 이벤트는 새로운 InteractionContext를 생성한다. 이 컨텍스트는 숨겨진 내부 전용 AsyncContext.Variable ([[ActiveInteractionContext]]로 표시됨)에 저장된다.

웹 플랫폼과 AsyncContext의 통합은 이 변수가 비동기 연속 작업(예: setTimeout, fetch, await)에 자동으로 첨부되도록 보장하여, 브라우저가 나중에 발생하는 효과를 원래 상호작용에 다시 귀속할 수 있게 한다.

스크립트 전파 외에도, 이 명세는 DOM을 수정하는 사용자 상호작용이 어떻게 컨테이너 루트를 설정하는지 정의한다([CONTAINER-TIMING] 사용). 이러한 루트는 콘텐츠풀 페인트와 같은 뒤이은 렌더링 효과를, 현재 활성 비동기 스크립트가 없더라도 시작한 상호작용 컨텍스트까지 추적할 수 있게 한다.

2.3. InteractionContext 구조체

InteractionContext는 단일 상호작용에서 소프트 내비게이션을 감지하는 데 필요한 데이터를 유지하는 데 사용되는 구조체이다. 이는 다음 항목을 가진다:

  • id, 처음에는 미설정 - 이 컨텍스트와 연관된 상호작용 id.

  • 컨텍스트 문서, Document - 이 컨텍스트와 연관된 Document.

  • 시작 시간, 처음에는 미설정 - 상호작용의 시작 시간을 나타낸다.

  • 내비게이션 타입, 처음에는 미설정 - 내비게이션의 타입(예: "push", "replace")을 나타낸다.

  • 첫 URL 값, 처음에는 미설정 - 첫 번째 수정 시점의 URL 값을 나타낸다.

  • 첫 URL 업데이트 타임스탬프, 처음에는 미설정 - 이 상호작용 동안 첫 번째 URL 수정이 발생한 시간을 나타낸다.

  • 첫 스크롤 타임스탬프, 처음에는 미설정 - 이 상호작용 동안 첫 번째 스크롤 이벤트가 발생한 시간을 나타낸다.

  • 첫 입력 타임스탬프, 처음에는 미설정 - 이 상호작용 동안 첫 번째 입력 이벤트가 발생한 시간을 나타낸다.

  • 첫 콘텐츠풀 페인트, 처음에는 null - 이 상호작용에 대한 첫 번째 InteractionContentfulPaint 항목.

  • 가장 큰 콘텐츠풀 페인트, 처음에는 null - 지금까지 이 상호작용에 대한 가장 큰 InteractionContentfulPaint 항목.

  • 마지막 URL 값, 처음에는 미설정 - 이 상호작용 동안 가장 최근 URL 수정의 값을 나타낸다.

  • emitted 플래그, 처음에는 false - 소프트 내비게이션 항목이 이 상호작용에 의해 방출되었음을 나타낸다.

참고: 이 명세의 향후 버전은 내비게이션의 더 완전한 이력을 제공하기 위해 상호작용 컨텍스트 동안 발생하는 모든 URL 업데이트를 추적할 수 있다. 마지막 URL 값은 현재 PerformanceSoftNavigation의 name에는 첫 URL 값만 노출되더라도, 최종 상호작용 상태에 효과를 정확히 다시 귀속할 수 있도록 내부적으로 추적된다.

2.4. 인프라 알고리즘

Document document가 주어졌을 때 현재 상호작용 컨텍스트를 얻으려면:

  1. context를 내부 AsyncContext.Variable [[ActiveInteractionContext]]의 값으로 둔다.

  2. context가 null이 아니고 context의 컨텍스트 문서가 document와 같지 않으면, null을 반환한다.

  3. context를 반환한다.

Document document, interaction id, 그리고 Event event가 주어졌을 때 상호작용에 대한 컨텍스트를 얻으려면:

  1. document의 상호작용 id에서 상호작용 컨텍스트로의 매핑[interaction id]가 존재하면, document의 상호작용 id에서 상호작용 컨텍스트로의 매핑[interaction id]를 반환한다.

  2. interaction context를 새 InteractionContext로 둔다.

  3. interaction context의 id를 interaction id로 설정한다.

  4. interaction context의 컨텍스트 문서를 document로 설정한다.

  5. interaction context의 시작 시간을 event의 startTime으로 설정한다.

  6. document의 상호작용 id에서 상호작용 컨텍스트로의 매핑[interaction id]을 interaction context로 설정한다.

  7. interaction context를 반환한다.

Document document와 Event event가 주어졌을 때 이벤트에 대한 상호작용 컨텍스트들을 업데이트하려면:

  1. timestamp를 document의 관련 전역 객체가 주어졌을 때의 현재 고해상도 시간으로 둔다.

  2. is scroll을 event의 타입이 "scroll"이면 true, 그렇지 않으면 false로 둔다.

  3. is input을 event의 타입이 has dispatched input event를 트리거할 이벤트 타입이면 true(이는 [EVENT-TIMING]에 정의됨), 그렇지 않으면 false로 둔다.

  4. is scroll이 false이고 is input이 false이면 반환한다.

  5. document의 상호작용 id에서 상호작용 컨텍스트로의 매핑의 값들 각각의 interaction context에 대해:

    1. is scroll이 true이고 interaction context의 첫 스크롤 타임스탬프가 미설정이면:

      1. interaction context의 첫 스크롤 타임스탬프를 timestamp로 설정한다.

    2. is input이 true이고 interaction context의 첫 입력 타임스탬프가 미설정이면:

      1. interaction context의 첫 입력 타임스탬프를 timestamp로 설정한다.

null 또는 PerformanceEventTiming 객체 timingEntry가 주어졌을 때 이벤트 디스패치를 위한 현재 상호작용 컨텍스트를 설정하려면:

  1. timingEntry가 null이면, null을 반환한다.

  2. event를 timingEntry의 연관된 이벤트로 둔다.

  3. interaction id를 timingEntry의 interactionId로 둔다.

  4. interaction id가 null 또는 0이면, null을 반환한다.

  5. document를 event의 관련 전역 객체의 연관된 Document로 둔다.

  6. document와 event가 주어졌을 때 이벤트에 대한 상호작용 컨텍스트들을 업데이트한다.

  7. interaction context를 document, interaction id, event가 주어졌을 때 상호작용에 대한 컨텍스트를 얻은 결과로 둔다.

  8. 내부 AsyncContext.Variable [[ActiveInteractionContext]]의 값을 interaction context로 설정한다.

  9. interaction context를 반환한다.

이벤트 디스패치 후 현재 상호작용 컨텍스트를 해제하려면:

  1. 내부 AsyncContext.Variable [[ActiveInteractionContext]]의 값을 null로 설정한다.

3. 상호작용 콘텐츠풀 페인트

3.1. InteractionContentfulPaint 인터페이스

[Exposed=Window]
interface InteractionContentfulPaint : PerformanceEntry {
    readonly attribute LargestContentfulPaint largestContentfulPaint;
    readonly attribute unsigned long long interactionId;

    object toJSON();
};

InteractionContentfulPaint includes PaintTimingMixin;

각 InteractionContentfulPaint는 다음을 가진다:

  • 연관된 컨텍스트, 즉 InteractionContext.

  • 연관된 최대 콘텐츠풀 페인트, 즉 LargestContentfulPaint 엔트리.

  • 연관된 페인트 타이밍 정보.

largestContentfulPaint 속성의 getter는 this의 최대 콘텐츠풀 페인트를 반환해야 한다.

interactionId 속성의 getter는 this의 컨텍스트의 id를 반환해야 한다.

name 속성의 getter는 빈 문자열을 반환해야 한다.

entryType 속성의 getter는 "interaction-contentful-paint"를 반환해야 한다.

startTime 속성의 getter는 this의 컨텍스트의 시작 시간을 반환해야 한다.

duration 속성의 getter는 this의 페인트 타이밍 정보에 대한 기본 페인트 타임스탬프와 this의 컨텍스트의 시작 시간 사이의 차이를 반환해야 한다.

참고: 엔트리가 연관된 InteractionContext에서 정적 상호작용 속성(interactionId 및 startTime 등)을 동적으로 질의하더라도, 생성 시점에 페인트의 페인트 타이밍 정보와 후보 LargestContentfulPaint 엔트리의 정적 스냅샷을 캡처하여 이러한 메트릭이 해당 시각적 업데이트의 정확한 상태를 반영하도록 보장한다.

3.2. 상호작용 콘텐츠풀 페인트 알고리즘

전역 객체 global, InteractionContext interaction context, LargestContentfulPaint lcpEntry, 그리고 페인트 타이밍 정보 paintTimingInfo가 주어졌을 때 상호작용 콘텐츠풀 페인트 엔트리를 생성하려면:

  1. entry를 global의 realm 안의 새 InteractionContentfulPaint 객체로 둔다.

  2. entry의 컨텍스트를 interaction context로 설정한다.

  3. entry의 최대 콘텐츠풀 페인트를 lcpEntry로 설정한다.

  4. entry의 연관된 페인트 타이밍 정보를 paintTimingInfo로 설정한다.

  5. entry를 반환한다.

LargestContentfulPaint lcpEntry, Document document, 그리고 InteractionContext interaction context가 주어졌을 때 새로 귀속된 콘텐츠풀 페인트 후보를 처리하려면:

  1. interaction context의 첫 스크롤 타임스탬프가 설정되어 있고 lcpEntry의 renderTime이 interaction context의 첫 스크롤 타임스탬프보다 크면, 반환한다.

  2. interaction context의 첫 입력 타임스탬프가 설정되어 있고 lcpEntry의 renderTime이 interaction context의 첫 입력 타임스탬프보다 크면, 반환한다.

  3. global을 document의 관련 전역 객체로 둔다.

  4. paint timing info를 lcpEntry의 연관된 페인트 타이밍 정보로 둔다.

  5. icpEntry를 global, interaction context, lcpEntry, 그리고 paint timing info가 주어졌을 때 상호작용 콘텐츠풀 페인트 엔트리를 생성한 결과로 둔다.

  6. icpEntry를 큐에 넣는다.

  7. icpEntry를 global의 성능 엔트리 버퍼에 추가한다.

  8. interaction context의 첫 콘텐츠풀 페인트가 null이면:

    1. interaction context의 첫 콘텐츠풀 페인트를 icpEntry로 설정한다.

  9. interaction context의 최대 콘텐츠풀 페인트를 icpEntry로 설정한다.

참고: InteractionContentfulPaint 엔트리는 상호작용이 최종적으로 소프트 내비게이션으로 이어지는지와 관계없이, 감지되는 즉시 성능 타임라인으로 방출된다. 이를 통해 개발자는 모든 상호작용에 대한 렌더링 업데이트를 모니터링할 수 있다.

4. 소프트 내비게이션

4.1. PerformanceSoftNavigation 인터페이스

[Exposed=Window]
interface PerformanceSoftNavigation : PerformanceEntry {
    readonly attribute DOMString navigationType;
    readonly attribute unsigned long long interactionId;
    InteractionContentfulPaint? getLargestInteractionContentfulPaint();
};

PerformanceSoftNavigation includes PaintTimingMixin;

각 PerformanceSoftNavigation는 다음을 가진다:

  • 연관된 컨텍스트, 즉 InteractionContext.

  • 연관된 페인트 타이밍 정보.

navigationType 속성의 getter는 this의 컨텍스트의 내비게이션 타입을 반환해야 한다.

interactionId 속성의 getter는 this의 컨텍스트의 id를 반환해야 한다.

getLargestInteractionContentfulPaint() 메서드는 this의 컨텍스트의 최대 콘텐츠풀 페인트를 반환해야 한다.

name 속성의 getter는 this의 컨텍스트의 첫 URL 값을 반환해야 한다.

entryType 속성의 getter는 "soft-navigation"을 반환해야 한다.

startTime 속성의 getter는 this의 컨텍스트의 시작 시간을 반환해야 한다.

duration 속성의 getter는 this의 presentationTime과 this의 컨텍스트의 방출 시점 시작 시간 사이의 차이를 반환해야 한다.

참고: 실제로 getLargestInteractionContentfulPaint()는 null이 아닌 엔트리를 반환할 것으로 예상된다. 확인된 소프트 내비게이션은 그 방출을 트리거하려면 최소 하나의 감지된 상호작용 콘텐츠풀 페인트를 필요로 하기 때문이다.

그러나 향후 반복에서는 소프트 내비게이션을 첫 페인트 이전의 URL 수정 즉시 커밋된 것으로 간주할 수 있는지 평가할 수 있다. 그러한 모델에서는 이 메서드가 방출 시점에 null을 반환할 수도 있다.

이 타이밍에 대한 주된 설계 고려사항은 URL 수정과 첫 페인트 사이의 구간에서 발생하는 다른 타임라인 엔트리(예: LayoutShift, PerformanceResourceTiming, LongAnimationFrameTiming 등)의 귀속이다. 많은 사이트는 예를 들어 fetch 요청을 시작하는 즉시 새 URL을 커밋하지만, 그동안 현재 페이지는 이전 내비게이션 상태에 남아 있다. 일관된 타임라인 분할을 보장하기 위해, 이 명세는 첫 페인트가 전환을 확인할 때까지 그러한 모든 엔트리를 이전 내비게이션 식별자에 귀속한다.

4.2. 소프트 내비게이션 알고리즘

소프트 내비게이션은 다음 조건을 만족하는 동일 문서 내비게이션이다:

  • InteractionContext가 활성인 동안 동일 문서 URL 변경이 발생한다.

  • 동일한 InteractionContext에 귀속된 콘텐츠풀 페인트가 발생한다.

Document document와 InteractionContext interaction context가 주어졌을 때 소프트 내비게이션 방출을 평가하려면:

  1. interaction context의 emitted가 true이면, 반환한다.

  2. document의 활성 소프트 내비게이션 후보가 interaction context가 아니면, 반환한다.

  3. interaction context의 첫 URL 값이 미설정이면, 반환한다.

  4. interaction context의 첫 콘텐츠풀 페인트가 null이면, 반환한다.

  5. global을 document의 관련 전역 객체로 둔다.

  6. entry를 global과 interaction context가 주어졌을 때 소프트 내비게이션 엔트리를 생성한 결과로 둔다.

  7. global과 entry가 주어졌을 때 소프트 내비게이션 엔트리를 방출한다.

  8. interaction context의 emitted를 true로 설정한다.

전역 객체 global과 InteractionContext interaction context가 주어졌을 때 소프트 내비게이션 엔트리를 생성하려면:

  1. entry를 global의 realm 안의 새 PerformanceSoftNavigation 객체로 둔다.

  2. entry의 컨텍스트를 interaction context로 설정한다.

  3. first paint를 interaction context의 첫 콘텐츠풀 페인트로 둔다.

  4. first paint가 null이 아니면:

    1. entry의 연관된 페인트 타이밍 정보를 first paint의 연관된 페인트 타이밍 정보로 설정한다.

  5. entry를 반환한다.

참고: navigationId는 아래의 PerformanceEntry를 큐에 넣기에서 설정된다.

전역 객체 global과 PerformanceSoftNavigation entry가 주어졌을 때 소프트 내비게이션 엔트리를 방출하려면:

  1. entry의 내비게이션 id를 entry의 interactionId로 설정한다.

  2. global의 현재 내비게이션 id를 entry의 interactionId로 설정한다.

  3. entry를 큐에 넣는다.

  4. entry를 global의 성능 엔트리 버퍼에 추가한다.

Document document, 문자열 url, 그리고 문자열 navigation type이 주어졌을 때 동일 문서 커밋을 처리하려면:

  1. url이 document의 url과 같으면, 반환한다.

  2. interaction context를 document가 주어졌을 때 현재 상호작용 컨텍스트를 얻은 결과로 둔다.

  3. interaction context가 null이면, 반환한다.

  4. interaction context의 마지막 URL 값을 url로 설정한다.

  5. interaction context의 첫 URL 업데이트 타임스탬프가 미설정이면:

    1. interaction context의 첫 URL 업데이트 타임스탬프를 document의 관련 전역 객체가 주어졌을 때의 현재 고해상도 시간으로 설정한다.

    2. interaction context의 첫 URL 값을 url로 설정한다.

    3. interaction context의 내비게이션 타입을 navigation type으로 설정한다.

  6. document의 활성 소프트 내비게이션 후보를 interaction context로 설정한다.

  7. document와 interaction context가 주어졌을 때 소프트 내비게이션 방출을 평가한다.

5. PerformanceEntry 확장

[Exposed=(Window,Worker)]
partial interface PerformanceEntry {
    readonly attribute unsigned long long navigationId;
};
각 PerformanceEntry는 연관된 내비게이션 id를 가지며, 이는 unsigned long long이고, 처음에는 0이다.

6. 명세 통합

6.1. HTML 통합

6.1.1. Document

각 document는 상호작용 id에서 상호작용 컨텍스트로의 매핑을 가지며, 이는 맵이고, 처음에는 비어 있다.

각 document는 활성 소프트 내비게이션 후보를 가지며, 이는 InteractionContext 또는 null이고, 처음에는 null이다.

6.1.2. History

history step 적용을 위해 document 업데이트에서, 5.5.1 이전에(documentsEntryChanged가 true이고 documentIsNew가 false인 경우), 동일 문서 커밋을 처리한다. 이때 Document, 대상 엔트리의 url, 그리고 "traverse"가 주어진다.
공유 history push/replace 단계 ([HTML]에 정의됨)에서 URL이 업데이트된 후, 동일 문서 커밋을 처리한다. 이때 Document, 새 URL, 그리고 작업 타입("push" 또는 "replace" 중 하나)이 주어진다.

6.1.3. Node

각 node는 연관된 상호작용 컨텍스트를 가지며, 처음에는 null이다.

6.1.4. 하드 내비게이션

새 전역 객체 global이 생성될 때(예: "하드" 내비게이션 중), 그 현재 내비게이션 id는 § 2.1 내비게이션 ID에 지정된 대로 초기화된다.

[NAVIGATION-TIMING]에서, 초기 내비게이션에 대한 PerformanceNavigationTiming 엔트리를 생성할 때, 사용자 에이전트는 그 navigationId를 전역 객체의 현재 내비게이션 id로 설정해야 한다.

6.2. Event Timing 통합

이 명세는 현대 웹 애플리케이션과 단일 페이지 애플리케이션에 관련된 추가 이벤트 타입을 포함하도록 [EVENT-TIMING]의 상호작용 정의를 확장한다.

다음 이벤트 타입은 상호작용의 일부로 간주된다([EVENT-TIMING]에 정의됨):

  • navigate

  • popstate

  • hashchange

이 이벤트들이 사용자 상호작용의 결과로 디스패치될 때, 사용자 에이전트는 문서의 관련 전역 객체에 대해 다음 interactionId를 얻어 획득한 고유한 상호작용 id를 이 이벤트들에 할당해야 한다. 어떤 이벤트가 이미 할당된 상호작용 id를 가진 이전 상호작용에 의해 트리거된 경우, 사용자 에이전트는 동일한 식별자를 재사용해야 한다.

참고:이 이벤트들은 사용자 동작에서 시작되는 이벤트인 경우(예: 브라우저 UI의 뒤로 버튼 클릭)에만 기본 상호작용으로 보고된다. 대부분의 다른 시나리오—예컨대 click 핸들러가 history를 수동으로 조작하는 경우—에서는 그 뒤의 popstate 또는 navigate 이벤트가 독립적인 사용자 상호작용으로 간주되지 않는다.

이러한 프로그래밍 방식으로 트리거된 이벤트에는 isTrusted 플래그가 설정되지 않을 수 있지만, history 및 navigation API가 시작 작업의 비동기 연속 작업으로 취급되므로, [ASYNC-CONTEXT]를 통해 원래 상호작용으로 올바르게 귀속된다.

참고: navigate, popstate, 그리고 hashchange 이벤트는 소프트 내비게이션을 추적하고 interactionId를 할당하기 위한 내부 신호로 사용된다. 이 명세는 이러한 이벤트 타입을 성능 타임라인에 PerformanceEventTiming 엔트리로 노출할 것을 요구하지 않으며, 그 결정은 [EVENT-TIMING] 명세에 맡긴다.

참고: [EVENT-TIMING] 명세는 processingStart 및 processingEnd 훅을 명시적으로 정의하고, 이 통합을 위해 interactionId 할당이 충분히 이른 시점에 일어나도록 업데이트될 것으로 예상된다. 현재 interactionId 할당은 일반적으로 이벤트 처리의 끝까지 지연된다.

이 명세는 안전한 전역 카운터를 보장하기 위해 interactionId에 unsigned long long을 사용하지만, [EVENT-TIMING]은 현재 이를 unsigned long으로 정의한다. 이 불일치는 두 명세의 향후 버전에서 해결될 것으로 예상된다.

Window window에 대해 다음 interactionId를 얻으려면:

  1. window의 상호작용 카운트를 window의 상호작용 카운트에 1을 더한 값으로 설정한다.

  2. window의 초기 interactionId 값에 (window의 상호작용 카운트에 window의 interactionId 증가분을 곱한 값)을 더한 값을 반환한다.

[EVENT-TIMING]에 정의된 DOM 명세의 이벤트 디스패치 알고리즘 수정에서:

  1. timingEntry를 이벤트 타이밍 처리 시작을 초기화하고 기록한 결과로 설정하는 단계 바로 뒤에, 다음 단계를 실행한다:

    1. timingEntry가 주어졌을 때 이벤트 디스패치를 위한 현재 상호작용 컨텍스트를 설정한다.

  2. 이벤트 타이밍 처리 종료를 기록하는 단계를 호출하기 바로 전에, 다음 단계를 실행한다:

    1. 이벤트 디스패치 후 현재 상호작용 컨텍스트를 해제한다.

6.3. Largest Contentful Paint (LCP) 통합

이 명세는 페인트를 상호작용에 귀속하기 위해 [LARGEST-CONTENTFUL-PAINT] 알고리즘에 훅을 건다.

largest contentful paint 보고에서, candidates를 페인트된 이미지 목록과 페인트된 텍스트 목록의 합집합으로 둔다:

  1. contextToNewLargestCandidate를 새 맵으로 둔다.

  2. candidates 안의 각 candidate에 대해:

    1. element를 candidate의 element로 둔다.

    2. element가 null이면, 계속한다.

    3. interaction context를 element의 연관된 상호작용 컨텍스트로 둔다.

    4. interaction context가 null이면, 계속한다.

    5. size를 candidate의 size로 둔다.

    6. interaction context의 최대 콘텐츠풀 페인트가 null이 아니고 size가 interaction context의 최대 콘텐츠풀 페인트의 largestContentfulPaint의 size보다 작거나 같으면, 계속한다.

    7. contextToNewLargestCandidate[interaction context]가 미설정이거나 size가 contextToNewLargestCandidate[interaction context]의 size보다 크면:

      1. contextToNewLargestCandidate[interaction context]를 candidate로 설정한다.

  3. contextToNewLargestCandidate 안의 각 interaction context → newLcpCandidate에 대해:

    1. newLcpEntry를 newLcpCandidate를 나타내는 LargestContentfulPaint 엔트리로 둔다.

    2. newLcpEntry, document, 그리고 interaction context가 주어졌을 때 새로 귀속된 콘텐츠풀 페인트 후보를 처리한다.

    3. document와 interaction context가 주어졌을 때 소프트 내비게이션 방출을 평가한다.

참고: § 6.4 Container Timing 통합 절은 DOM 수정이 영향을 받은 요소에 대한 이전에 보고된 페인트를 어떻게 재설정하는지를 정의하여, 이들이 [LARGEST-CONTENTFUL-PAINT] 알고리즘에 의해 다시 평가되고 현재 상호작용에 올바르게 귀속되도록 보장한다.

참고: [LARGEST-CONTENTFUL-PAINT] 알고리즘은 연관된 상호작용 컨텍스트가 있는 모든 페인트를 무시할 것으로 예상된다. 이러한 페인트는 이 명세의 § 3.1 InteractionContentfulPaint 인터페이스에서 처리되기 때문이다.

6.4. Container Timing 통합

[CONTAINER-TIMING] API는 공통 DOM 조상별로 렌더링 효과를 그룹화하는 메커니즘을 제공한다. 이 명세는 사용자 상호작용으로 렌더링 변경을 다시 귀속하기 위해 해당 메커니즘과 통합된다.

node insert에서, 또는 node가 다음 방식 중 하나로 수정될 때:

  • 요소의 class 또는 style 속성이 수정된다.

  • 리소스 속성(예: img 또는 video 요소의 src)이 수정된다.

다음 단계를 실행한다:

  1. document를 노드의 노드 문서로 둔다.

  2. interaction context를 document가 주어졌을 때 현재 상호작용 컨텍스트를 얻은 결과로 둔다.

  3. interaction context가 null이 아니면:

    1. 노드의 연관된 상호작용 컨텍스트를 interaction context로 설정한다.

    2. 노드를 컨테이너 루트로 지정한다([CONTAINER-TIMING]에 정의됨).

    3. 노드와 그 각 자손을 Document의 이전에 보고된 페인트에서 제거한다 ([PAINT-TIMING]에 정의됨).

참고: 수정된 서브트리를 이전에 보고된 페인트 집합에서 제거함으로써, 사용자 에이전트는 이러한 요소의 다음 콘텐츠풀 페인트가 다시 감지되고 새로운 InteractionContext에 올바르게 귀속되도록 보장한다.

참고: "node insert"에 대한 참조는 문서 구조에 새 요소를 추가하는 모든 작업(예: appendChild, innerHTML 업데이트 등)을 포괄하는 고수준 설명이다. 이를 문서 구조 수정을 추적하는 내부 구현 훅에 매핑하는 것은 사용자 에이전트의 몫이다.

참고: 사용자 에이전트는 컨테이너 루트의 희소 트리를 유지하는 것이 권장된다. 노드가 동일한 상호작용 컨텍스트와 연관된 기존 컨테이너 루트의 자손인 상태에서 수정되는 경우, 사용자 에이전트는 새로운 중복 루트를 생성하지 않도록 선택할 수 있다.

또한 큰 DOM 수정 중에 비용이 큰 메인 스레드 작업을 피하기 위해, 사용자 에이전트는 자손을 이전에 보고된 페인트에서 제거하는 작업을 최적화하는 것이 권장된다. 즉시 전체 순회를 수행하는 대신, 사용자 에이전트는 수정된 루트를 "dirty"로 표시하고 이후의 트리 순회(예: 레이아웃 또는 페인트 중)에 이 상태를 지연 전파할 수 있다. 보이지 않거나 content-visibility 또는 CSS containment 같은 기존 메커니즘에 의해 건너뛰어지는 것으로 알려진 서브트리도 이 재설정 과정에서 건너뛸 수 있다.

7. 보안 및 개인정보 보호 고려사항

Soft Navigations를 성능 타임라인에 노출하는 것 자체에는 보안 및 개인정보 보호 관련 영향이 없다. 그러나 감지된 소프트 내비게이션의 결과로 여러 paint timing 엔트리를 재설정하는 것은 영향을 줄 수 있으며, 특히 방문한 링크가 파티셔닝되기 전에는 더욱 그렇다. 따라서 :visited 캐시를 파티셔닝하지 않은 채 그러한 페인트 작업을 노출하는 것은, 해당 페인트 작업이 출처를 가로질러 사용자의 기록을 노출하지 않는지 확인하기 위해 신중한 분석을 거친 후에만 이루어져야 한다.

8. 부록: 중첩되는 상호작용과 경합 조건

이 절은 비규범적이다.

웹 애플리케이션은 여러 사용자 상호작용을 빠르게 연속해서 처리하는 경우가 많다. 이 명세는 다음 모델을 통해 이러한 중첩되는 상호작용을 처리한다:

  • 컨텍스트 독립성: 각 상호작용은 자체 InteractionContext를 독립적으로 관리한다. 여러 컨텍스트가 동시에 "진행 중"일 수 있으며, 각 컨텍스트는 자체 URL 수정과 콘텐츠풀 페인트를 추적한다.

  • 활성 후보 단일성: 많은 상호작용이 활성일 수 있지만, Document는 어느 시점에든 하나의 활성 소프트 내비게이션 후보만 인식한다.

  • 선점: 상호작용 컨텍스트는 첫 번째 동일 문서 URL 수정을 트리거하는 순간 활성 소프트 내비게이션 후보가 된다. 이후의 상호작용 수정이 발생하면, 그것이 이전 후보를 선점하고 새로운 후보가 된다.

  • 방출 검증: PerformanceSoftNavigation은 방출 기준(URL 변경 + 콘텐츠풀 페인트)이 충족되는 순간 활성 소프트 내비게이션 후보인 상호작용 컨텍스트에 대해서만 방출된다. 이는 소프트 내비게이션 보고가 문서의 현재 시각적 상태 및 내비게이션 상태와 일관되게 유지되도록 보장한다.

  • 지속적 귀속: 어떤 상호작용이 소프트 내비게이션 후보로서 선점되더라도, 그것은 활성 상태로 남아 있는 한 자체 InteractionContentfulPaint 엔트리를 계속 귀속하고 보고한다. 이를 통해 그 자체가 "내비게이션"으로 간주되지 않는 동시 렌더링 업데이트도 정확하게 측정할 수 있다.

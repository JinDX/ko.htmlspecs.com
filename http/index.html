📄 HTTP 문서

HTTP는 이러한 IETF RFC와 IANA 레지스트리에 의해 정의됩니다.

핵심 명세

HTTP 프로토콜의 “핵심” 의미는 다음에 의해 정의됩니다:

  • RFC 9110: HTTP Semantics HTTP 의미론
  • RFC 9111: HTTP Caching HTTP 캐싱

해당 의미들은 “on the wire”에서 세 가지 방식으로 표현됩니다:

  • RFC 9112: HTTP/1.1 HTTP/1.1
  • RFC 9113: HTTP/2 HTTP/2
  • RFC 9114: HTTP/3 HTTP/3

이후 버전의 HTTP는 필드 압축을 제공합니다:

  • RFC 7541: HPACK Header Compression for HTTP/2 HTTP/2용 HPACK 헤더 압축
  • RFC 9204: QPACK Field Compression for HTTP/3 HTTP/3용 QPACK 필드 압축

이들 RFC는 HTTP를 정의한 이전의 모든 RFC를 집단적으로 대체합니다. 여기에는 RFC 1945, RFC 2068, RFC 2616, RFC 2617, RFC 7230-5, 및 RFC 7540가 포함됩니다.

또한 점점 더 많은 헤더와 트레일러에서 사용되는 구조화된 필드 값 명세도 관련이 있습니다:

  • RFC 9651: Structured Field Values for HTTP HTTP 구조화된 필드 값 (test suite)

HTTP 위에 구축된 프로토콜은 여기에 문서화된 대로 최신 권장 관행(Best Current Practice)을 따라야 합니다:

  • RFC 9205: Building Protocols with HTTP HTTP로 프로토콜 구축

확장 레지스트리

메서드, 상태 코드 및 헤더를 포함한 많은 수의 HTTP 확장이 있습니다. 이러한 확장들은 적절한 레지스트리에 등재되어 있는 한 모두 HTTP의 "일부"임을 유의해야 합니다:

  • HTTP 메서드 레지스트리 - 자세한 정보
  • HTTP 상태 코드 레지스트리 - 자세한 정보
  • HTTP 필드 이름 레지스트리 - 자세한 정보
  • HTTP/2 매개변수 - 프레임 유형, 설정, 오류 코드
  • HTTP/3 매개변수 - 프레임 유형, 설정, 오류 코드

개별 헤더는 허용 가능한 값을 규제하는 자체 레지스트리를 가지고 있으며, 다음과 같은 것들이 있습니다:

  • HTTP 인증 스킴 레지스트리 - 자세한 정보
  • HTTP 캐시 지시자 레지스트리 - 자세한 정보
  • HTTP 매개변수 - Content-codings, transfer-codings, Forwarded, Prefer 및 Range 관련 헤더

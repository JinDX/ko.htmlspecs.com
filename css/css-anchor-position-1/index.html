요약

이 명세서는 앵커 위치 지정을 정의합니다. 위치가 지정된 요소가 페이지의 하나 이상의 “앵커 요소”를 기준으로 자신의 크기와 위치를 정할 수 있도록 합니다.

CSS는 구조화된 문서(HTML, XML 등)의 렌더링을 화면, 인쇄물 등에서 기술하기 위한 언어입니다.

1. 소개

CSS 절대 위치 지정은 작성자가 박스를 페이지 어디든지 배치할 수 있게 해주며, 다른 박스의 레이아웃과 상관없이 오직 자신의 포함 블록만을 고려합니다. 이러한 유연성은 매우 유용할 수 있지만, 동시에 제약이 따르기도 합니다—​종종 다른 박스를 기준으로 위치를 지정하고 싶을 때가 있습니다. 앵커 위치 지정 (position-anchor 및 position-area 속성, 또는 앵커 함수 anchor(), anchor-size() 활용) 를 통해 작성자는 절대 위치 박스를 페이지의 하나 이상의 다른 박스(그 앵커 참조)에 “앵커링”할 수 있습니다. 동시에 여러 가지 위치를 시도하여 겹침이나 오버플로우를 피하는 “최적”의 위치를 찾을 수도 있습니다.

예를 들어, 작성자는 툴팁을 타겟 요소의 중앙 위에 위치시키고 싶어 할 수 있습니다. 만약 그렇게 하면 툴팁이 화면 밖으로 벗어나게 되는 경우, 툴팁은 타겟 요소의 아래에 위치해야 합니다. 이는 다음과 같은 CSS로 구현할 수 있습니다: 
.anchor {
  anchor-name: --tooltip;
}
.tooltip {
  /* Fixpos는 포함 블록 관계를 걱정할 필요가 없다는 의미입니다.
     툴팁은 DOM 어디서든 존재할 수 있습니다. */
  position: fixed;

  /* 모든 앵커링 동작은 기본적으로
     --tooltip 앵커를 참조하게 됩니다. */
  position-anchor: --tooltip;

  /* 툴팁의 하단이 앵커 상단에 정렬되도록 합니다.
     이는 또한 가로 쓰기 모드에서 툴팁과 앵커가 수평 중앙 정렬되는 것도 기본 설정입니다. */
  position-area: block-start;

  /* 만약 툴팁이 윈도우를 넘치면 자동으로 전환해서
     툴팁의 상단이 앵커의 하단에 정렬되도록 합니다. */
  position-try: flip-block;

  /* 너무 넓어지는 것을 방지 */
  max-inline-size: 20em;
}

Popover API 를 사용하면 position이 자동으로 설정되고 앵커링 관계가 생성됩니다. (anchor-name이나 position-anchor 값을 따로 지정하지 않아도 됨. 암시적 앵커 요소가 정의됩니다.) 따라서 이러한 속성들은 명시적으로 다시 지정할 필요가 없습니다. 올바른 마크업을 사용하면, 이 예제는 다음과 같이 간단해집니다: 

.tooltip {
  /* popover + popovertarget 속성을 사용하면 'position: fixed'가 설정되고
     필요한 position-anchor 관계가 이미 만들어집니다. */
  position-area: block-start;
  position-try: flip-block;
  max-inline-size: 20em;
}

1.1. 값 정의

이 명세는 CSS 속성 정의 관례를 [CSS2]에서 따르며, 값 정의 문법을 [CSS-VALUES-3]에서 사용합니다. 이 명세서에서 정의되지 않은 값 타입은 CSS Values & Units [CSS-VALUES-3]에 정의되어 있습니다. 다른 CSS 모듈과의 결합으로 이러한 값 타입의 정의가 확장될 수 있습니다.

각 속성 정의에 나열된 속성별 값 외에도, 이 명세서에서 정의된 모든 속성은 CSS 전역 키워드를 속성 값으로 허용합니다. 가독성을 위해 별도로 반복적으로 적지 않았습니다.

선택자 매칭을 제외한 대부분의 CSS 동작과 마찬가지로, 이 명세서에 나오는 기능은 플랫(flat) 요소 트리에 적용됩니다.

2. 앵커 결정

이 명세서의 여러 기능은 앵커 박스의 위치와 크기를 참조합니다. 별도의 명시가 없는 경우, 이는 해당 border box 가장자리와, 관련 주요 박스 및 관련 앵커 요소를 의미합니다. 대부분의 경우 관련 앵커 요소는 기본 앵커 요소로 지정되며, position-anchor 속성을 통해 지정할 수 있습니다. 이는 호스트 언어에서 정의한 암시적 앵커 요소이거나, CSS anchor-name 및 anchor-scope 속성으로 이름이 지정된 앵커일 수 있습니다. (anchor() 함수로도 이름이 지정된 앵커를 직접 참조할 수 있습니다.)

앵커 박스의 위치와 크기는 레이아웃 이후에 결정됩니다. 이 위치와 크기에는 zoom 및 position 기반의 조정 (position: relative 또는 position: sticky 등)과 변형(transform, offset-path 등)이 포함됩니다. 이 경우, 관련 절대 위치 요소의 포함 블록 좌표계에서 앵커 박스의 축정렬 경계 사각형(axis-aligned bounding rectangle)이 사용됩니다. 변형은 종종 별도의 스레드에서 최적화되므로, 앵커 박스의 위치에 대한 변형 기반 갱신은 몇 프레임 지연될 수 있습니다. 실질적으로 가능하다면, 작성자는 대신 절대 또는 상대 위치를 사용하여 이 지연을 피할 수 있습니다.

앵커 박스가 분할(fragmented)된 경우, 해당 포함 블록이 절대 위치 박스의 관련 앵커 박스 외부인 경우, 박스 분할(box fragments)의 축정렬 경계 사각형이 대신 사용됩니다. (절대 위치 박스가 분할 컨텍스트(fragmentation context) 내부에 있으면 앵커 박스를 비분할로 간주하며, 해당 분할 컨텍스트에 의해 스스로도 분할될 수 있습니다.)

성능상의 이유로, 스크롤은 특별하게 처리되며, § 3.3 스크롤 반영을 참고하세요. 기타 레이아웃 후 효과(예: 필터)는 앵커 박스 위치에 영향을 주지 않습니다.

2.1. 앵커 생성: anchor-name 속성

이름: anchor-name
값: none | <anchor-name>#
초깃값: none
적용 대상: 모든 주 박스(principal box)를 생성하는 요소
상속 여부: no
백분율: 해당 없음
계산값: 지정된 대로(as specified)
정규 순서: 문법에 따름(per grammar)
애니메이션 유형: 불연속(discrete) 
<anchor-name> = <dashed-ident>

anchor-name 속성은 해당 요소가 앵커 요소임을 선언하며, 해당 요소의 주 박스(principal box)가 앵커 박스(anchor box)가 되도록 합니다. 또한 이 요소가 타겟팅될 앵커 이름(anchor names) 목록을 부여합니다. 값은 다음과 같이 정의됩니다:

none

이 속성은 아무런 효과도 없습니다.

<anchor-name>#

해당 요소가 주 박스(principal box)를 생성하는 경우, 이 요소는 앵커 요소(anchor element)가 되며 지정된 앵커 이름 목록을 가집니다. 각 앵커 이름(anchor name)은 느슨하게 일치하는 트리 범위 이름(tree-scoped name)입니다.

그렇지 않은 경우 이 속성은 아무런 효과도 없습니다.

앵커 이름(anchor names)은 유일할 필요가 없습니다. 모든 요소가 해당 박스의 타겟 앵커 요소(target anchor element)가 될 수 있는 것은 아닙니다. 따라서 사용 범위가 적절히 지정되는 한, 하나의 이름이 여러 곳에서 재사용될 수 있습니다.

참고: 여러 요소가 동일한 앵커 이름을 공유하며 모두 특정 위치 지정 박스에 대해 가시적인 경우, 타겟 앵커 요소(target anchor element)는 가장 가까운 조상(존재할 경우) 또는 DOM 순서상 마지막 요소가 됩니다. anchor-scope 속성을 사용하면 특정 참조 박스에서 어떤 이름이 보일지 더 제한할 수 있습니다.

앵커 이름(anchor names)은 기본적으로 컨테인먼트(containment)로 범위가 제한되지 않습니다. 요소에 스타일 또는 레이아웃 컨테인먼트(layout containment) (혹은 유사한 형태의 컨테인먼트)가 있더라도, 그 하위 요소의 앵커 이름(anchor names)은 페이지 내 다른 요소에서도 볼 수 있습니다.

참고: 요소가 다른 요소의 생략된 내용(skipped contents) 내에 있을 때 (예: content-visibility: hidden 등으로 인해) 그 요소는 허용 가능한 앵커 요소(acceptable anchor element)가 아니며, 실질적으로 이름이 없는 것처럼 동작합니다.

참고: 섀도우 트리(shadow trees) 내의 위치가 지정된 요소는 “상위(higher)” 트리에 정의된 앵커 이름(anchor names)을 참조할 수 있습니다. 현재로서는 “하위(lower)” 섀도우 트리에 정의된 앵커 이름(anchor names)은 참조할 수 없습니다.

2.2. 앵커 이름 범위 지정: anchor-scope 속성

이름: anchor-scope
값: none | all | <anchor-name>#
초깃값: none
적용 대상: 모든 요소
상속 여부: no
백분율: 해당 없음
계산값: 지정된 대로(as specified)
정규 순서: 문법에 따름(per grammar)
애니메이션 유형: 불연속(discrete)

이 속성은 지정된 앵커 이름과 해당 앵커 이름에 대한 조회 범위를 이 요소의 하위 트리로 한정합니다. § 2 앵커 결정을 참조하세요.

값은 다음 의미를 가집니다:

none
앵커 이름 범위에 변화가 없습니다.
all
이 값은 이 요소나 그 후손이 정의한 모든 앵커 이름이 (후손이 anchor-scope로 이미 범위가 제한되어 있지 않다면) 이 요소의 후손에게만 범위 내에 있도록 지정합니다. 그리고 후손이 이 앵커 이름만 이 하위트리 내의 앵커 요소에 일치하도록 제한합니다.

이 값은 동일 트리스코프 내 앵커 이름에만 영향을 미치며, 엄격히 일치(strictly matched) 트리 스코프 이름처럼 동작합니다. (즉, anchor-scope: all은 anchor-scope: --foo, --bar, ...와 동일하게, 모든 관련 앵커 이름을 명시적으로 나열한 것과 같습니다.)

<anchor-name>
이 값은 이 요소 또는 그 후손이 정의한(후손이 anchor-scope로 이미 범위가 제한되지 않은) 해당하는 앵커 이름만 이 요소의 후손에게만 범위 내에 있도록 지정합니다. 그리고 후손이 이 앵커 이름만 이 하위트리 내의 앵커 요소에 일치하도록 제한합니다.

<anchor-name>은 엄격히 일치하는 트리 스코프 이름을 의미합니다. 즉, 동일한 섀도우 트리 내의 앵커 이름과만 매칭될 수 있습니다.[CSS-SCOPING-1]

이 속성은 암시적(implicit) 앵커 요소에는 효과가 없습니다.

참고: 위치 지정된 요소의 조상이 우선적으로 체크되므로, 원하는 앵커가 조상인 경우 대개 anchor-scope를 사용할 필요가 없습니다. 원하는 앵커가 조상이 아니거나, 해당 앵커를 페이지 다른 곳에서 참조되지 않게 "숨기고" 싶을 때만 필요합니다.

디자인 패턴이 재사용될 때, anchor-scope로 동일 컴포넌트 간 이름 충돌을 방지할 수 있습니다. 예를 들어, 리스트가 각 항목 안에 위치 지정된 요소를 포함하고 있고, 이 요소들이 자신이 속한 리스트 항목을 기준(anchor)으로 삼고 싶은 경우, 
li {
  anchor-name: --list-item;
  anchor-scope: --list-item;
}
li .positioned {
  position: absolute;
  position-anchor: --list-item;
  position-area: inline-start;
}

anchor-scope가 없으면, 모든 li 요소가 모든 위치 지정 요소에 대해 보이게 되어, 이 요소들이 모두 마지막 li 를 기준(anchor)으로 삼아, 서로 겹쳐 정렬됩니다.

위의 예시는 이제 해당 사용 사례가 자동화되므로 수정되어야 합니다.

2.3. 앵커 찾기

이 명세의 여러 항목은 타겟 앵커 요소를 찾습니다. 여기서 앵커 지정자가 주어집니다. 이는 <dashed-ident> (그리고 트리 범위 참조(tree-scoped reference)) 이고, 이는 페이지 내 다른 위치의 anchor-name 값과 일치해야 합니다. 또는 키워드 auto이거나, 또는 아무것도 없을 수 있습니다(지정자가 누락됨).

참고: 이 조건들이 담고 있는 일반 규칙은, 요소가 위치 지정 박스(positioned box)의 타겟 앵커 요소가 되려면, 그 자체의 박스가 참조 대상 위치 지정 박스가 레이아웃 되기 전에 완전히 레이아웃 되어 있어야 한다는 점입니다. CSS의 레이아웃 규칙은 앵커와 위치 지정 박스 간의 관계 및 그들의 포함 블록에 따라 이런 보장을 제공합니다. 아래 조건 목록은 스태킹 컨텍스트 규칙을 바로 이 목적에 맞게 재정의한 것으로, 앵커 포지셔닝에서 순환(circularity)이 불가능하도록 보장합니다.

쿼리 요소 query el과 선택적 앵커 지정자 anchor spec이 주어졌을 때, 타겟 앵커 요소를 결정하는 알고리즘:

  1. anchor spec이 전달되지 않은 경우, 기본 앵커 요소가 있으면 반환하고, 없으면 아무것도 반환하지 않습니다.

  2. anchor spec이 auto인 경우:

    1. query el에 암시적 앵커 요소가 있으며 그 요소가 허용 가능한 앵커 요소라면, 그 요소를 반환합니다.

    2. 그렇지 않으면 아무것도 반환하지 않습니다.

    참고: 향후 API가 암시적 앵커 요소를 정의할 수도 있습니다. 이 경우 본 알고리즘에서 명시적으로 다루어, 연동을 보장할 것입니다.

  3. 그 외의 경우, anchor spec은 <dashed-ident>입니다.

    query el의 조상 중 아래 조건을 만족하는 요소가 있다면, query el에 가장 가까운 요소를 반환합니다. 그렇지 않으면, 조건을 만족하는 트리 순서상 마지막 el을 반환합니다.

    • el은 앵커 요소이고 anchor name으로 anchor spec을 가진다.

    • el의 anchor name이 느슨하게 일치(loosely matches)해야 하며, anchor spec과 비교함.

      참고: anchor name은 트리 스코프 이름(tree-scoped name)이고, anchor spec은 트리 스코프 참조(tree-scoped reference)입니다.

    • el은 query el에 대해 허용 가능한 앵커 요소이다.

    위 조건을 만족하는 요소가 없으면 아무것도 반환하지 않습니다.

    참고: anchor-scope는 특정 앵커 이름의 가시성에 영향을 줄 수 있어, 어떤 요소가 주어진 조회에 앵커 요소가 될 수 있는지에 영향을 미칩니다.

참고: 한 anchor-name이 한 섀도우 트리의 스타일로 정의될 경우, 다른 섀도우 트리의 스타일에 있는 앵커 함수에서 보이지 않습니다. (캡슐화를 보장함) 그러나 요소는 서로 다른 섀도우 트리에 있어도 서로를 기준(anchor)으로 할 수 있습니다. 단, anchor-name과 anchor function 모두 동일 트리의 스타일에서 나와야 하며, 예컨대 섀도우 내부의 요소를 ::part()로 스타일링한다면 가능합니다. (암시적 앵커 요소도 본질적으로 단일 트리에 한정되지 않으나, 이 경우 세부 조작은 할당 API에 따라 다릅니다.)

요소 possible anchor가 절대 위치(absolute) 요소 positioned el에 대해 허용 가능한 앵커 요소(acceptable anchor element)가 되려면 아래 모든 조건을 만족해야 합니다:

  • possible anchor는 요소(element)이거나 완전한 스타일링이 가능한 트리-기준 의사요소(tree-abiding pseudo-element)여야 한다.

  • possible anchor는 anchor-scope의 영향에 따라 possible anchor 또는 그 조상 기준으로 positioned el에 대해 “scope” 내에 있어야 한다.

  • possible anchor가 positioned el보다 엄격하게 먼저 레이아웃되어야(laied out strictly before) 하며, 즉 아래 중 하나가 참입니다:

    • possible anchor와 positioned el이 동일한 원래 포함 블록(original containing block)을 갖고, 다음 중 하나:

      • possible anchor가 더 낮은 top layer에 위치하거나,

      • 둘 다 동일한 top layer에 있고, 단 possible anchor가 절대 위치가 아니거나, flat tree 순서상 positioned el보다 앞에 있어야 한다.

    • possible anchor의 포함 블록(containing block)을 생성하는 요소가 있다면, 이 요소가 positioned el에 대해 허용 가능한 앵커 요소여야 한다.

  • possible anchor가 생략된 컨텐츠(skipped contents) 내에 있다면, positioned el도 동일 요소의 생략된 컨텐츠 내에 있어야 합니다.

    참고: 즉, positioned el과 possible anchor가 동일한 생략 "leaf" 안에 있다면 앵커링할 수 있지만, "leaf"를 넘어서는 참조는 불가합니다. 이는 둘 다 묶은 요소를 생략(skipped)해도 positioned el이 갑자기 다른 앵커로 이동하는 일이 없도록 보장하며, 동시에 페이지 내 다른 곳에 있는 위치 지정 요소들이 생략된 요소를 앵커로 삼는 것을 방지합니다.

2.4. 기본 앵커: position-anchor 속성

이름: position-anchor
값: normal | none | auto | <anchor-name> | match-parent
초깃값: normal
적용 대상: 절대 위치 박스(absolutely positioned boxes)
상속 여부: no
백분율: 해당 없음
계산값: 지정된 대로(as specified)
정규 순서: 문법에 따름(per grammar)
애니메이션 유형: 불연속(discrete)

position-anchor 속성은 기본 앵커 요소(default anchor element)를 지정하며, 이는 position-area, position-try, 및 (기본적으로) 이 요소에 적용된 모든 앵커 함수(anchor functions)에 의해 사용됩니다. position-anchor는 reset-only 하위 속성이며 position 속성의 일부입니다.

normal

position-area가 none이면, none처럼 동작합니다. 그렇지 않으면, auto처럼 동작합니다.

none

이 박스는 기본 앵커 요소(default anchor element)를 가지지 않습니다.

auto

암시적 앵커 요소(implicit anchor element)가 있으면 사용하고, 없으면 이 박스는 기본 앵커 요소(default anchor element)를 가지지 않습니다.

<anchor-name>

지정된 <anchor-name>으로 선택된 타겟 앵커 요소(target anchor element)가 이 박스의 기본 앵커 요소가 됩니다.

match-parent

부모와 동일한 기본 앵커 요소를 사용합니다. 만약 이 요소가 기원 요소인 가상 요소라면, 기원 요소의 기본 앵커 요소를 사용합니다(있는 경우). 그리고 그 요소가 허용 가능한 앵커 요소여야 합니다. 그렇지 않으면, 해당 박스는 기본 앵커 요소를 가지지 않습니다.

기본 앵커 요소(default anchor element)의 주 박스(principal box)가 이 박스의 기본 앵커 박스(default anchor box)가 됩니다.

예를 들어, 아래 코드에서 .foo와 .bar 요소 모두 같은 포지셔닝 속성을 사용할 수 있고, 각각 자신이 참조하는 앵커 요소만 다르게 지정할 수 있습니다: 
.anchored {
  position: absolute;
  top: calc(.5em + anchor(outside));
  /* 이름이 지정되지 않은 경우,
     자동으로 기본 앵커 박스를 참조합니다. */
}

.foo.anchored {
  position-anchor: --foo;
}
.bar.anchored {
  position-anchor: --bar;
}

2.5. 앵커 관련성

요소 el이 사용자에게 관련이 있는지 판단할 때, el의 자손이 위치 지정 박스의 대상 앵커 요소인 경우 (해당 박스 자체는 생략(skipped)되지 않았고, 그 포함 블록이 el 또는 el의 자손이 아닌 경우), el은 사용자에게 관련이 있다고 간주해야 합니다.

참고: 예를 들어, content-visibility: auto 하위 트리에서의 앵커는 그 트리를 사용하는 위치 지정 박스가 skipped되지 않은 한, 콘텐츠 생략이 일어나지 않도록 하게 됩니다. (단, 앵커와 위치 지정 박스 모두 동일한 content-visibility: auto 요소 하위에 있으면 서로 순환적으로 서로를 계속 보이게 하지 않습니다.)

3. 앵커 기반 위치 지정

절대 위치 박스는 페이지 내 여러 앵커 박스를 기준으로 위치를 잡을 수 있습니다.

position-area 속성은 기본 앵커 박스를 기준으로 한 격자(grid) 기반 위치 지정 개념을 쉽게 제공하며, 더 복잡하거나 여러 박스를 기준으로 한 위치 지정에는 anchor() 함수를 inset 속성에서 활용해 특정 앵커 박스의 변(edge)을 명시적으로 참조할 수 있습니다.

3.1. position-area 속성

이름: position-area
값: none | <position-area>
초깃값: none
적용 대상: 기본 앵커 박스(default anchor box)가 있는 위치 지정 박스
상속 여부: no
백분율: 해당 없음
계산값: 키워드 none 또는 키워드 쌍, § 3.1.3 <position-area>의 계산값과 직렬화 참고
정규 순서: 문법에 따름(per grammar)
애니메이션 유형: 이산

앵커 위치 지정의 대부분의 일반적인 사용 사례는, 위치 지정된 박스의 포함 블록의 변과 기본 앵커 박스의 변만을 고려합니다. 이러한 선들은 3×3 그리드를 정의하는 것으로 볼 수 있으며, position-area로 이 position-area 그리드의 어떤 영역에 위치시킬지 쉽게 지정할 수 있습니다.

none

이 속성은 아무런 효과가 없습니다.

<position-area>

박스에 기본 앵커 박스가 없거나, 절대 위치 박스가 아닌 경우, 이 값은 효과가 없습니다.

그 외에는, position-area 그리드의 영역을 선택하며, 해당 영역이 이 박스의 포함 블록이 됩니다.

참고: 즉, inset 속성 들은 position-area로부터의 오프셋을 지정하게 되며, max-height: 100%같은 일부 속성 값도 position-area 기준이 됩니다.

none이 아닌 값은 다음 추가 효과를 가집니다:

  • 스크롤 가능 포함 블록이 로컬 포함 블록 대신 사용됩니다. absolute-position 포함 블록이 스크롤 컨테이너에 의해 생성될 때 전체 스크롤 가능 오버플로 영역이 (대부분) 위치 지정에 제공되게 됩니다.

  • 모든 auto inset 속성 및 auto margin 속성의 사용 값은 0이 됩니다.

  • normal 값이 자기 정렬(self-alignment) 속성에서 대응되는 값으로 변환됩니다. § 4.1 영역별 기본 정렬 참고.

3.1.1. Position Area Grid 해석

position-area 그리드는 3×3 그리드이며, 각 축에 4개의 그리드 선이 있습니다. 순서는 (쓰기 모드를 기준으로 포함 블록의):

  • 박스의 수정 전 포함 블록의 start 엣지, 또는 기본 앵커 박스의 start 엣지(더 바깥쪽이면)

  • 기본 앵커 박스의 start 엣지

  • 기본 앵커 박스의 end 엣지

  • 박스의 수정 전 포함 블록의 end 엣지, 또는 기본 앵커 박스의 end 엣지(더 바깥쪽이면)

참고: 기본 앵커 박스가 수정 전 포함 블록의 일부 또는 전체 바깥에 있으면, position-area 그리드의 일부 행/열 크기가 0이 될 수 있습니다.

3.1.2. <position-area> 값의 문법

위치는 값 쌍으로 지정하며, 플로우 기준 또는 물리적 용어로 표현할 수 있습니다. <position-area> 값의 허용 문법은 다음과 같습니다: 

<position-area> = [
  [ left | center | right | span-left | span-right
  | x-start | x-end | span-x-start | span-x-end
  | self-x-start | self-x-end | span-self-x-start | span-self-x-end
  | span-all ]
  ||
  [ top | center | bottom | span-top | span-bottom
  | y-start | y-end | span-y-start | span-y-end
  | self-y-start | self-y-end | span-self-y-start | span-self-y-end
  | span-all ]
|
  [ block-start | center | block-end | span-block-start | span-block-end | span-all ]
  ||
  [ inline-start | center | inline-end | span-inline-start | span-inline-end
  | span-all ]
|
  [ self-block-start | center | self-block-end | span-self-block-start
  | span-self-block-end | span-all ]
  ||
  [ self-inline-start | center | self-inline-end | span-self-inline-start
  | span-self-inline-end | span-all ]
|
  [ start | center | end | span-start | span-end | span-all ]{1,2}
|
  [ self-start | center | self-end | span-self-start | span-self-end | span-all ]{1,2}
]

<position-area> 값은 position-area 그리드의 영역을 선택하며, 해당 영역이 차지하는 행과 열을 다음과 같이 지정합니다:

start, end, self-start, self-end
top, bottom, left, right
y-start, y-end, self-y-start, self-y-end
x-start, x-end, self-x-start, self-x-end
block-start, block-end, self-block-start, self-block-end
inline-start, inline-end, self-inline-start, self-inline-end
center

해당 축의 단일 행 또는 열.

anchor()와 마찬가지로 일반 논리 키워드(start, end 등)는 박스의 쓰기 모드 기준입니다. x-start 등은 지정된 물리 축 기준으로 방향을 결정합니다.

self-* 논리 키워드는 (self-start, self-x-end 등) 동일하지만 박스의 쓰기 모드 기준입니다.

span-start, span-end, span-self-start, span-self-end
span-top, span-bottom, span-left, span-right
span-y-start, span-y-end, span-self-y-start, span-self-y-end
span-x-start, span-x-end, span-self-x-start, span-self-x-end
span-block-start, span-block-end, span-self-block-start, span-self-block-end
span-inline-start, span-inline-end, span-self-inline-start, span-self-inline-end

해당 축의 인접한 두 행 또는 열. 중심 행/열과 단일 키워드에 해당하는 행/열. (예: span-top은 첫 두 행(중심+top)을 포함.)

span-all

해당 축의 모든 3개 행 또는 열.

일부 키워드는 축이 명확하지 않습니다: center, span-all, start 등 block/inline 축을 명확히 지정하지 않은 키워드. 다른 키워드가 축을 명확히 한다면, 모호한 키워드는 반대 축을 가리킵니다. (예: block-start center에서 center는 inline 축.) 둘 다 모호하면, 첫 번째는 박스의 block 축, 두 번째는 inline 축입니다. (예: span-all start는 span-all inline-start와 동일.)

키워드가 하나면, 해당 축이 명확하면 두 번째 키워드는 span-all로 처리; 그렇지 않으면 키워드를 반복해서 사용한 것과 동일하게 동작합니다. (예: top은 top span-all과 같고, center는 center center와 동일.)

3.1.3. <position-area>의 계산값 및 직렬화

계산값은 <position-area> 값에서 각 축에 대해 선택된 트랙을 나타내는 두 키워드이며, 긴 논리(block-start)와 짧은 논리(start) 키워드는 동등하게 처리합니다. 직렬화는 위 문법 순서대로, 논리 키워드는 짧은 형태로 직렬화됩니다 (예: start start 대신 block-start inline-start 대신).

3.2. 앵커 기준 인셋: anchor() 함수

절대 위치 박스는 anchor() 함수를 인셋 속성 값으로 사용해 하나 이상의 앵커 박스의 위치를 참조할 수 있습니다. anchor() 함수는 <length>로 해석됩니다. 이 함수는 inset 속성에서만 허용되며, 그 외의 경우에는 유효하지 않습니다.

이름: top, left, right, bottom
새로운 값: <anchor()> 
<anchor()> = anchor( <anchor-name>? && <anchor-side>, <length-percentage>? )
<anchor-side> = inside | outside
       | top | left | right | bottom
       | start | end | self-start | self-end
       | <percentage> | center

anchor() 함수는 세 가지 인수를 가집니다:

  • <anchor-name> 값은 어떤 방법으로 앵커 요소를 찾아 그 요소로부터 포지셔닝 정보를 받을지 지정합니다. 가능한 값은 다음과 같습니다:

    <dashed-ident>

    찾으려는 앵커 이름(anchor name)을 지정합니다. 이 이름은 트리 범위 참조(tree-scoped reference)입니다.

    생략됨

    박스에 대해 정의된 기본 앵커 요소(default anchor element)를 선택합니다 (가능한 경우).

    자세한 내용은 타겟 앵커 요소(target anchor element)를 참조하세요.

  • <anchor-side> 값은 대상 앵커 요소의 해당 변 위치를 참조합니다. 가능한 값은 다음과 같습니다:

    inside
    outside

    앵커 박스의 변 중 하나로 해석되며, 어느 inset 속성에 사용되었는지에 따라 달라집니다. inside는 inset 속성과 같은 방향(변)을 의미하며 (즉, 위치 지정 박스를 앵커 박스의 "안쪽"에 맞춤), outside는 반대쪽을 의미합니다.

    top
    right
    bottom
    left

    앵커 박스의 해당 변을 참조합니다.

    참고: 이 값들은 inset 속성의 동일 축에서만 사용할 수 있습니다. 예를 들어, left는 left, right, 또는 수평 축의 논리 inset 속성에서 사용할 수 있습니다.

    start
    end
    self-start
    self-end

    해당 축에서 앵커 박스의 한 변을 참조하며, 키워드는 쓰기 모드를 기준으로 해석됩니다. (self-start와 self-end는 위치 지정 박스, start, end는 포함 블록의 쓰기 모드 기준)

    <percentage>
    center

    해당 변의 start에서 end까지의 일정 퍼센트 위치를 참조합니다. 0%는 start와 같으며, 100%는 end와 같습니다.

    center는 50%와 같습니다.

  • 마지막 선택적 <length-percentage> 인수는 폴백 값으로, 해결 불가 anchor 함수일 때 적용될 값을 지정합니다.

anchor() 함수가 해결 가능한 anchor 함수일 때는 계산값 시점에 (스타일 & 레이아웃 인터리빙 사용) 위치 지정 박스의 <length>로 해석되며, 해당 속성에 맞는 inset-modified 포함 블록의 변과 대상 앵커 요소의 앵커 박스의 지정된 변을 맞추기에 필요한 값을 나타냅니다.

참고: 이것은 트랜지션 또는 애니메이션이 앵커 함수를 사용하는 속성에 적용되는 경우, 다양한 변화에 대해 "기대한 대로" 동작함을 의미합니다: 앵커 박스(anchor box)가 이동하거나, 앵커 요소(anchor elements)가 문서에 추가되거나 삭제되거나, 앵커의 anchor-name 속성이 변경되는 등의 상황에서도 제대로 작동한다는 뜻입니다.

예를 들어, .bar { inset-block-start: anchor(--foo block-start); }에서는 anchor() 함수가 .bar 요소의 block-start 변을 --foo 앵커의 block-start 변에 맞추도록 길이를 해석합니다.

반면에, .bar { inset-block-end: anchor(--foo block-start); }에서는 .bar 요소의 block-end 변을 --foo 앵커의 block-start 변에 맞추도록 해석됩니다.

inset-block-start와 inset-block-end 값은 각기 다른 변(요소의 포함 블록의 block-start, block-end) 기준 오프셋이므로, 동일한 anchor()도 각각 다른 길이로 해석될 수 있습니다.

anchor() 함수가 <length>로 해석되기 때문에, 다른 길이 값처럼 수학 함수들에서 사용할 수 있습니다.

예를 들어, 아래 차트에서는 세 개의 막대가 앵커 후보로 설정되어 있고, 최소/최대 선 및 툴팁은 min()과 max() 함수를 이용해서 세 개 모두를 참조하는 anchor() 함수들을 조합하여 자신이 어디에 배치되어야 하는지 계산합니다. 각 열 아래의 range 인풋으로 높이를 조절할 수 있고, 최저/최고 막대에 맞춰 앵커된 선과 툴팁이 동적으로 조정되는 것을 볼 수 있습니다.

이 동작을 위한 핵심 코드 조각은 다음과 같습니다:

#bar-1 { anchor-name: --anchor-1; }
#bar-2 { anchor-name: --anchor-2; }
#bar-3 { anchor-name: --anchor-3; }
.line {
  position: absolute;
  left: anchor(--chart left);
  right: anchor(--chart right);
  &.max {
    bottom: max(
      anchor(--anchor-1 top),
      anchor(--anchor-2 top),
      anchor(--anchor-3 top)
    );
  }
  &.min {
    bottom: min(
      anchor(--anchor-1 top),
      anchor(--anchor-2 top),
      anchor(--anchor-3 top)
    );
  }
}

3.2.1. anchor()의 해상도

anchor() 함수는 해결 가능한 anchor 함수 가 되려면 다음 모든 조건을 만족해야 합니다:

  • 이 속성은 절대 위치 박스에 적용됩니다.

  • 여기서 <anchor-side>가 물리적 키워드를 지정했다면, 해당 축에 적용되는 inset 속성에 지정되어야 합니다. (예를 들어, left는 left나 right 또는 수평축의 논리 inset 속성에만 사용할 수 있습니다.)

  • 이 함수가 사용된 박스에 대해 타겟 앵커 요소가 존재해야 하며, 함수에 지정된 <anchor-name> 값이 사용됩니다.

이 중 어느 하나라도 거짓이면, anchor() 함수는 지정된 폴백 값으로 계산됩니다. 폴백 값이 없다면, 이를 참조한 선언은 계산값 시점에서 무효가 됩니다.

3.3. 스크롤 반영

성능 때문에, 구현은 보통 스크롤을 별도의 스크롤/컴포지팅 스레드에서 처리하며, 여기서는 레이아웃 등 무거운 작업이 아니라 단순 이동/변환 등만 처리되어 스크롤 반응이 인간 감각상 '즉각적'으로 느껴질 수 있습니다.

스크롤로 인해 단순히 anchor-positioned 요소가 이동하기만 할 때는 문제 없습니다; 움직임은 스크롤 스레드에서 수행되어 스크롤 콘텐츠와 같이 매끄럽게 움직일 수 있습니다. 하지만 앵커 위치 지정(anchor positioning)은 요소가 자신의 반대쪽 변의 위치를 서로 다른 스크롤 컨텍스트의 요소에 의존하게 할 수 있으므로, 스크롤이 변의 하나만 이동시키고 크기 변화를 유발해 결국 레이아웃이 필요할 수도 있습니다. 이런 경우 스크롤 스레드에서 처리할 수 없습니다!

이를 보완하고 다양한 앵커 지정의 자유도는 최대한 유지하기 위해, 앵커 위치 지정(anchor positioning)은 기억된 스크롤 오프셋과 스크롤 보상 개념을 함께 사용합니다.

여기의 내용은 기술적이지만 요지는 다음과 같습니다:

  • 위치 지정 요소가 처음 화면에 보이거나 폴백이 바뀔 때, 위치는 모든 앵커 참조(anchor reference)의 최신 위치에 따라 올바르게 계산됩니다.

    이 앵커 참조(anchor reference)가 서로 다른 스크롤 컨텍스트에 속한다면, 그 총 스크롤 오프셋이 기억되며, 이후 해당 요소가 스크롤되어도 레이아웃은 기억된 오프셋을 계속 사용합니다. (기억되는 것은 스크롤 오프셋 자체뿐이며, 실질적인 레이아웃 위치는 매번 새로 계산되어 정확성을 유지함.) 위치 지정 요소가 더 이상 표시되지 않거나 폴백이 바뀌면 새로 계산합니다.

  • 유일한 예외는 기본 앵커 요소입니다; 그 요소가 기억된 스크롤 오프셋에서 벗어나면 위치 지정 요소가 함께 움직입니다. 이것은 *오직* 위치 이동만 반영하므로, 위치 지정 요소의 크기가 변하거나 재레이아웃이 필요한 변화는 일으킬 수 없습니다.

결론적으로 앵커 위치 지정은 어떤 요소에 앵커링하든 대체로 "그냥 동작"하지만, 스크롤에 어떻게 반응할 수 있는지는 일부 제한이 있을 수 있습니다.

앵커 재계산 지점 은(는) 절대 위치 지정 요소가 박스 생성(즉, display:none 또는 display:contents 에서 다른 display 값으로 전환) 를 시작할 때마다 발생합니다. 이는 CSS 애니메이션이 시작될 때와 동일합니다.

앵커 재계산 지점은 요소의 포지션 폴백 스타일 결정 시점에도 발생합니다. 만약 그 결과 폴백 스타일이 변경된다면, 선택된 폴백 스타일 집합에 연결된 앵커 재계산 지점의 결과를 사용합니다.

요소 abspos에 대해 앵커 재계산 지점이 발생하면, abspos의 각 앵커 참조(anchor reference)가 가리키는 anchor 에 대해, 기억된 스크롤 오프셋(remembered scroll offset)을 연관시킵니다. 이는 anchor의 모든 스크롤 컨테이너 조상들(단, abspos의 containing block 전까지만) 의 스크롤 오프셋 을 현재 합산한 값입니다. 기억된 스크롤 오프셋은 position: sticky 등 스크롤에 의존한 다른 포지셔닝 변화도 포함합니다. abspos에 기본 앵커 요소가 있다면, abspos가 해당 요소에 대한 앵커 참조를 실제로 가지고 있지 않아도 항상 기억된 스크롤 오프셋을 계산합니다.

모든 앵커 참조는 모든 스크롤 컨테이너들이 초기 스크롤 위치에 있다고 가정하고 계산되며, 이후 각 앵커에 연관된 기억된 스크롤 오프셋이 더해집니다.

변환(transform)에 대해서도 스크롤과 동일한 이슈가 있어, 앵커 포지셔닝(Anchor Positioning) 역시 기본적으로 무시합니다. 여기서 transform 효과도 함께 적용할 수 있을까요?

위 내용은 위치 지정 요소가 그 앵커 참조(anchor reference) 의 스크롤 위치 변화에 한 번 반응하도록 합니다. 하지만 그들 중 하나가 스크롤되면, 위치 지정 요소는 더 이상 해당 앵커에 고정되어 보이지 않게 됩니다 (비록 스크롤 이외의 위치 이동에는 계속 반응함). 이 문제는 일반적으로 완벽히 해결할 수 없지만, 하나의 앵커 참조에 대한 스크롤에는 대응할 수 있습니다; 즉, 기본 앵커 요소에 한정하여 지원합니다:

절대 위치 박스 abspos는 수평 혹은 수직 축에서 아래 두 조건을 모두 만족하면 스크롤 보상(compensate for scroll)을 수행합니다:

  • abspos에 기본 앵커 박스(default anchor box)가 존재한다.

  • abspos가 그 기본 앵커 박스 또는 적어도 동일 스크롤 컨텍스트 내의 무언가에 대한 앵커 참조(anchor reference)를 가진다. 즉, 적어도 아래 중 하나가 참이어야 함:

    • abspos의 해당 축 self-alignment property 값이 anchor-center이다.

    • abspos의 position-area 값이 none 이 아니다.

    • 해당 축에 대해 abspos의 used inset 속성 중 최소 하나에 anchor() 함수가 사용되며, 이 함수가 가리키는 타겟 앵커 요소와 abspos의 기본 앵커 박스가 동일한 최근접 스크롤 컨테이너 조상을 가진다.

참고: abspos에 포지션 옵션 목록(position options list)이 있다면, 어느 축에서 스크롤 보상을 적용할지는 적용된 폴백 스타일에도 영향을 받습니다.

abspos의 기본 스크롤 이동(default scroll shift)은 수평/수직 축 각각에 대한 길이 쌍(length pair)입니다. 각 길이는 다음과 같이 계산됩니다:

  • abspos가 해당 축에서 스크롤 보상을 하고 있으면, 그 길이는 기본 앵커 요소(default anchor element)의 기억된 스크롤 오프셋과 만약 지금 다시 계산한다면 얻어질 기억된 스크롤 오프셋 간의 차이입니다.

  • 그렇지 않으면, 해당 길이는 0입니다.

abspos의 레이아웃이 끝난 뒤, 기본 스크롤 이동(default scroll shift)만큼 추가로 이동하며, 이는 별도의 변환(transform)이 적용된 것과 같고, (다른 변환들보다 먼저 적용됨)

이 스냅샷 시점의 정확한 타이밍 정의 필요: 각 프레임마다 갱신, 스타일 재계산 전.

기억된 스크롤 오프셋과 유사하게, 기본 앵커 요소에 transform 효과도 반영해야 할까요?

참고: 기억된 스크롤 오프셋 은 anchor() 함수의 값에 영향을 주지만, 기본 스크롤 이동(default scroll shift) 은 inset 속성의 값과 정렬 등을 결정한 후에 요소를 직접 이동시킵니다. 이는 보통 구별되지 않지만, round(anchor(outside), 50px)처럼 기본 앵커 요소의 위치를 비선형적으로 변환하는 경우에는 동작 차이가 드러날 수 있습니다.

4. 앵커 기반 정렬

4.1. 영역별 기본 정렬

position-area가 none이 아닌 경우, 사용 값이 normal인 self-alignment는 <position-area> 값에 따라 달라지며, 박스가 앵커 쪽으로 정렬되도록 변경됩니다:

  • 한 축에서 center 트랙만 선택된 경우, 해당 축의 기본 정렬은 center입니다.

  • 세 트랙 모두 선택된 경우, 해당 축의 기본 정렬은 anchor-center입니다.

  • 그 외의 경우, 해당 축의 기본 정렬은 명시되지 않은 쪽 트랙 방향으로 됩니다: 만약 축의 “start” 트랙만 명시된 경우, 기본 정렬은 end 등입니다.

하지만 관련 축의 inset 속성 중 하나만 auto이면, 기본 정렬은 auto가 아닌 인셋 쪽 변으로 향하고, 이 정렬은 unsafe 정렬입니다.

Note: 이 단일 auto 동작은 한 인셋값으로 절대 위치 박스의 위치를 제어하던 기존 방식과 호환됩니다.

예를 들어, 영문 환경에 해당하는 쓰기 모드(horizontal-tb, ltr)라고 할 때, span-x-start top 값은 수직축의 start 영역과, 수평축의 start 및 center 영역을 선택하게 되므로 기본 정렬 값은 align-self: end (박스의 하단 margin edge가 top 영역 하단과 맞닿음), 수평축에서는 justify-self: end (박스의 end 변 margin edge가 span-start 영역의 end와 맞닿음)입니다.
박스가 자신의 inset-수정 포함 블록을 넘치지만, 여전히 자신의 원래 포함 블록 내에서는 들어갈 수 있다면, 기본적으로 그것은 원래 포함 블록 내에 있도록 "이동"하게 되며, 이로 인해 일반적인 정렬을 위배할 수도 있습니다. 자세한 내용은 CSS Box Alignment 3 § 4.4 Overflow Alignment: the safe and unsafe keywords and scroll safety limits를 참고하세요.

이러한 동작으로 인해 위치 지정된 박스가 의도한 영역 내에, 그리고 화면에 보이도록 더 쉽게 유지됩니다. 이는 포함 블록이 예상보다 더 작아지더라도 마찬가지입니다.

예를 들어, position-area: bottom span-right 값은 위치 지정 박스가 앵커의 왼쪽 끝에서 포함 블록의 오른쪽 끝까지 늘어나게 하고, 기본적으로 그 공간에서 왼쪽 정렬됩니다. 하지만 만약 박스가 그 공간보다 크면 (예: 앵커가 화면의 오른쪽 끝에 매우 가까울 때), 박스는 보이도록 왼쪽으로 이동합니다.

4.2. 앵커에 중앙 정렬: anchor-center 정렬 값

이름: justify-self, align-self
새 값: anchor-center

self-alignment 속성은 절대 위치 박스가 inset-수정 포함 블록 내에서 스스로를 정렬할 수 있게 해줍니다. 기존 값들과 신중하게 선택된 inset 속성만으로도 대부분 쓸모있는 정렬이 가능하지만, 앵커 위치 지정에서 자주 필요한—​앵커 박스 위 중앙 정렬—​은 달성하려면 상당히 신경써서 복잡하게 설정해야 하는 경우가 많습니다.

새로운 anchor-center 값은 이러한 경우를 매우 간단하게 만들어 줍니다: 위치 지정 박스에 기본 앵커 박스가 있다면, 해당 축에서 (가능한 한) 기본 앵커 박스 위에 중앙 정렬됩니다. 추가로:

  • 스크롤 가능한 포함 블록은 해당되는 경우 로컬 포함 블록 대신 사용되며, 따라서 전체 스크롤 가능한 오버플로우 영역이 (대개) 배치에 활용됩니다.

  • 사용된 값이 모든 auto inset 속성과 auto 마진 속성에 대해 0으로 처리됩니다.

박스가 절대 위치 지정이 아니거나, 기본 앵커 박스가 없다면, 이 값은 center와 동일하게 동작하며 inset 속성에 별 영향을 주지 않습니다.

참고: anchor-center 사용 시 기본적으로 앵커가 박스의 원래 포함 블록의 경계에 너무 가깝다면, 순수하게 중앙 정렬되지는 않고 원래 포함 블록 안에 남도록 "이동"하게 됩니다. 자세한 내용은 CSS Box Alignment 3 § 4.4 Overflow Alignment: the safe and unsafe keywords and scroll safety limits를 참고하세요.

5. 앵커 기반 크기 조정

절대 위치 박스는 anchor-size() 함수를 크기 속성(sizing properties)에 사용해, 하나 이상의 앵커 박스의 크기를 참조할 수 있습니다. anchor-size() 함수는 <length>로 해석됩니다. 이 함수는 허용된 @position-try 속성에서만 허용되며, 그 외에는 유효하지 않습니다.

5.1. anchor-size() 함수

이름: width, height, min-width, min-height, max-width, max-height, top, left, right, bottom, margin-top, margin-left, margin-right, margin-bottom
새로운 값: <anchor-size()> 
anchor-size() = anchor-size( [ <anchor-name> || <anchor-size> ]? , <length-percentage>? )
<anchor-size> = width | height | block | inline | self-block | self-inline

anchor-size() 함수는 anchor()와 유사하며, 동일한 인자를 받지만, <anchor-side> 키워드 대신 <anchor-size>로 교체됩니다. 이것은 서로 반대되는 두 변 사이의 거리를 가리킵니다.

물리적 <anchor-size> 키워드 (width 및 height)는 각각 타깃 앵커 요소의 너비와 높이를 의미합니다. anchor()와 달리 축이 일치해야 할 필요는 없습니다; 예를 들면, width: anchor-size(--foo height); 와 같은 선언도 유효합니다.

논리적 <anchor-size> 키워드 (block, inline, self-block, self-inline) 은 해당 박스의 쓰기 모드 ( self-block 및 self-inline의 경우 ) 또는 박스의 쓰기 모드에 따라 포함 블록 ( block 및 inline의 경우 ) 중 하나의 물리적 키워드에 매핑됩니다.

<anchor-size> 키워드를 생략하면, anchor-size()가 사용된 속성의 축과 맞는 키워드로 동작하는 것이 기본입니다. (예: width: anchor-size() 는 width: anchor-size(width)와 동일합니다.)

anchor-size() 함수가 해결 가능한 anchor-size 함수를 나타내면, computed value 시점에 (스타일 & 레이아웃 인터리빙을 통해) 해당 축에서 <length> 값을 반환합니다. 이는 타깃 앵커 요소의 앵커 박스에서 (방향에 따라) 해당되는 두 변(left/right or top/bottom) 사이의 길이입니다.

5.1.1. anchor-size()의 해상도

anchor-size() 함수는 해결 가능한 anchor-size 함수가 되려면 다음 조건을 모두 만족해야 합니다:

  • 절대 위치 박스에 적용되어야 합니다.

  • 함수가 사용된 박스와 함수에 명시된 <anchor-name>에 대해 대상 앵커 요소가 존재해야 합니다.

이 조건 중 하나라도 거짓이면, anchor-size() 함수는 지정된 폴백 값으로 해석됩니다. 폴백 값이 없는 경우, 이를 참조한 선언은 계산값 단계에서 무효가 됩니다.

6. 오버플로우 관리

앵커 위치 지정은 강력하지만, 예측하기 힘든 점도 있습니다. 앵커 박스는 페이지 어디에나 있을 수 있으므로, 박스를 특정 방식(예: 앵커 위나, 오른쪽 등)으로 배치하려 해도, 그 박스가 포함 블록을 넘치거나, 일부가 화면 밖에 위치할 수 있습니다.

이를 보완하기 위해 절대 위치 지정 박스는 position-try-fallbacks 속성을 사용해 추가적인 위치 옵션을 지정할 수 있습니다 (박스의 기존 스타일에서 파생되거나, @position-try 규칙 내에 지정된 위치/정렬 속성의 변형 세트). UA는 박스가 최초 위치에서 넘치면 이 옵션들을 차례대로 시도할 수 있습니다. 각 옵션은 position-try-order에서 지정한 순서대로 박스에 차례로 적용되며, 박스를 포함 블록에 넘치지 않게 만드는 첫 번째 옵션이 채택되어 사용됩니다.

한 번 선택된 옵션은 그 박스가 다시 넘치기 전까지 계속 적용되며, (이전, 좀 더 바람직할) 다른 옵션이 넘침 없이 쓸 수 있게 되어도 다시 돌아가지 않습니다. (참고: 마지막 성공한 위치 옵션 기록.)

예를 들어, 아래 CSS는 "popover"를 우선 해당 요소 아래에 배치하려 시도하고, 만약 화면에 다 들어가지 않으면 위로 전환합니다. 기본적으로 앵커에 시작점 정렬을 시도하며, 이것도 맞지 않으면 끝점 정렬로 바뀝니다. 어느 쪽도 화면에 다 들어가지 않으면, popover가 수평 공간 전체를 차지하며, 가능하면 앵커를 기준으로 중앙 정렬됩니다 (§ 4.1 영역별 기본 정렬 덕분). 
#myPopover {
  position: fixed;
  position-anchor: --button;
  position-area: bottom span-x-end;
  position-try-fallbacks: flip-x, flip-y, flip-x flip-y, bottom, top;

  /* popover은 최소 버튼만큼 넓도록 */
  min-width: anchor-size(width);

  /* popover은 최소 2개 메뉴 항목 높이 */
  min-height: 6em;
}

6.1. 대체 옵션 제공: position-try-fallbacks 속성

이름: position-try-fallbacks
값: none | [ [<dashed-ident> || <try-tactic>] | <position-area> ]#
초기값: none
적용 대상: 절대 위치 박스(absolutely positioned boxes)
상속: no
백분율: n/a
계산값: 지정된 대로(as specified)
정식 순서: 문법에 따름(per grammar)
애니메이션 타입: 이산

이 속성은 절대 위치 박스가 자신의 inset-수정 포함 블록을 넘칠 때 적용할 대체 위치 스타일 목록을 제공합니다. 이 position options list 는 처음에 요소의 fallback 기본 스타일 (즉, computed styles에서 position-try-fallbacks을 적용하지 않은 것)을 기반으로 생성된 하나의 position option만을 포함합니다.

목록의 각 쉼표로 구분된 항목은 별개의 옵션입니다: @position-try 블록의 이름이거나, 박스의 기존 계산 스타일에서 자동 변환을 나타내는 <try-tactic>입니다.

값은 다음 의미를 가집니다:

none

이 속성은 아무 영향이 없습니다; 박스의 position options list는 비어 있습니다.

<dashed-ident>

주어진 이름의 @position-try 규칙이 있으면, 그에 연결된 position option이 position options list에 추가됩니다.

없으면, 이 값은 아무 영향이 없습니다.

<try-tactic>

지정된 try tactic을 기본 스타일에 실행 하여 position option을 자동으로 생성한 다음, 그 position option을 박스의 position options list에 추가합니다. 

<try-tactic> = flip-block || flip-inline || flip-start || flip-x || flip-y
flip-block

block axis 방향의 값들 (예: margin-block-start 및 margin-block-end) 을 서로 바꿉니다, 사실상 inline-axis 축 대칭입니다.

flip-inline

inline axis 값들을 서로 바꾸며, 사실상 block-axis 축 대칭입니다.

flip-x

수평 축 값들 (예: margin-left 및 margin-right) 을 서로 바꿔, 사실상 수직 축 대칭입니다.

flip-y

수직 축 값들을 바꿔, 사실상 수평 축 대칭입니다.

flip-start

start 속성끼리, 그리고 end 속성끼리 (예: margin-block-start 와 margin-inline-start) 값을 서로 교체하며, 이는 start-start 코너에서 end-end 코너로 가로지르는 대각선 기준 대칭입니다.

키워드를 여러 개 주면, 해당 변환을 순차적으로 합성해서 하나의 position option을 생성합니다. 논리 방향은 쓰기 모드에 따라 포함 블록 기준으로 해석됩니다.

<dashed-ident> || <try-tactic>

이전 두 옵션의 효과를 결합합니다: 주어진 이름의 @position-try 규칙이 있으면, 그 position option을 기본 스타일에 적용한 다음, 지정한 <try-tactic> 변환 결과를 박스의 position options list에 추가합니다.

없으면 아무것도 하지 않습니다.

<position-area>

지정한 값의 position-area 속성만을 포함하는 position option을 자동으로 생성합니다.

6.2. 폴백 순서 결정: position-try-order 속성

이름: position-try-order
값: normal | <try-size>
초기값: normal
적용 대상: 절대 위치 박스
상속: no
백분율: n/a
계산값: 지정된 대로(as specified)
정식 순서: 문법에 따름(per grammar)
애니메이션 타입: 이산

이 속성은 요소가 position options를 선언된 position-try-fallbacks 순서를 엄격히 따르기보다는, 박스가 가능한 한 넓은 공간을 확보하는 것이 더 중요할 때, 각 옵션이 제공하는 공간의 크기로 정렬할 수 있게 해줍니다.

<try-size> = most-width | most-height | most-block-size | most-inline-size
normal

position options들을 position-try-fallbacks에 지정된 순서대로 시도합니다.

most-width
most-height
most-block-size
most-inline-size

position options list의 각 항목에 대해, 해당 position option을 적용하여 박스의 크기, 즉 해당 스타일에 따른 inset-수정 포함 블록 크기를 구합니다 (auto inset 값은 0으로 간주). 이 크기를 기준으로 position options list를 안정 정렬(stable sort)합니다, 가장 큰 크기가 맨 앞에 오게 합니다.

논리 방향은 쓰기 모드 기준 포함 블록에 대해 해석됩니다.

예를 들어, 아래 스타일은 팝업 리스트를 우선 앵커 버튼 위쪽 또는 아래쪽 중 더 큰 공간을 가진 쪽에 배치합니다. 
.anchor { anchor-name: --foo; }
.list {
  position: fixed;
  position-anchor: --foo;
  position-area: block-end span-inline-end;
  position-try-fallbacks: --bottom-scrollable, flip-block, --top-scrollable;
  position-try-order: most-height;
}
@position-try --bottom-scrollable {
  align-self: stretch;
}
@position-try --top-scrollable {
  position-area: block-start span-inline-end;
  align-self: stretch;
}

기본 스타일과 --bottom-scrollable 옵션은 모두 동일한 사용 가능 높이를 갖습니다, 두 경우 모두 inset-수정 포함 블록이 앵커~포함 블록의 경계까지 늘어나기 때문입니다. 마찬가지로 flip-block 옵션과 --top-scrollable 옵션도 같은 높이를 가집니다. position-try-order가 안정 정렬을 사용하기 때문에, 이러한 쌍은 각자 목록에서의 상대적 위치를 유지하면서, *-scrollable 옵션이 항상 뒤로 옵니다; 그리고 더 많은 공간이 있는 쪽 쌍이 맨 앞에 위치합니다.

이로 인해 박스는 먼저 자연 높이에서 앵커와 맞닿는 쪽 중 더 큰 쪽에 정렬을 시도하고 (기본 스타일이나 flip-block 스타일 사용), 만약 넘치는 경우, 해당 공간을 채우며 스크롤 가능한 모드로 대체됩니다 (해당 *-scrollable 스타일 사용), 따라서 절대 공간 부족한 더 좁은 쪽으로 넘어가지 않습니다.

6.4. @position-try 규칙

@position-try 규칙은 특정 이름의 위치 옵션을 정의하며, 여러 개의 위치 지정 속성 집합을 지정하여 position-try-fallbacks를 통해 박스에 적용할 수 있습니다.

@position-try 규칙의 문법은 다음과 같습니다:

@position-try <dashed-ident> {
  <declaration-list>
}

전주에 명시된 <dashed-ident>가 규칙의 이름입니다. 같은 이름으로 @position-try 규칙이 여러 개 선언된 경우, @keyframe 규칙과 동일하게 카스케이드(cascade)됩니다.

@position-try 규칙에서는 다음 속성만 허용됩니다:

  • inset 속성

  • margin 속성

  • 크기 속성(sizing properties)

  • self-alignment 속성

  • position-anchor

  • position-area

<declaration-list> 내 속성에 !important를 사용하면 해당 속성은 무효가 되지만, @property-try 규칙 전체가 무효가 되진 않습니다.

@position-try 내 모든 속성은 위치 폴백 오리진(Position Fallback Origin)의 일부로 박스에 적용되며, 이 오리진은 Author Origin 과 Animation Origin 사이에 위치하는 새로운 카스케이드 오리진(cascade origin)입니다.

Animation Origin과 마찬가지로 revert 값을 사용하면, 해당 속성이 Author Origin의 일부였던 것처럼 동작하여, 대신 User Origin으로 되돌아갑니다. (단, Animation Origin처럼, revert-layer는 특별한 동작 없이 명시된 대로 동작합니다.)

참고: 허용되는 @position-try 속성들은 박스 자기 자신의 크기와 위치에만 영향을 미치며, 내용물이나 스타일에는 영향을 주지 않는 최소 범위의 속성입니다. 이로써 위치 폴백 구현을 단순화하면서도 공간에 따른 앵커 위치 지정 박스 이동이라는 본질적 과제를 해결할 수 있게 됩니다. 이런 규칙들은 Author Origin의 선언을 덮어쓰기 때문에 @position-try 선언과 다른 속성의 일반적인 상속·카스케이드 충돌을 방지합니다. 향후 컨테이너 쿼리(container query) 등 확장에서 요소의 위치 폴백별 조건부 스타일링 지원이 기대됩니다. (현 제한적 속성 리스트로는 불가)

참고: 여러 요소가 같은 @position-try 규칙을 쓰고자 할 때, 각자 자신의 앵커 요소를 기준으로 쓰려면 <anchor-name>을 anchor()에 명시하지 말고, 각 박스의 position-anchor에서 각자 지정하세요.

참고: 가장 일반적인 폴백 위치 지정(기본적으로 한쪽, 넘치면 반대로 "플립")은 position-try-fallbacks의 키워드만으로도 쓸 수 있고, @position-try는 필요 없습니다.

6.5. 위치 폴백 적용

위치 지정 박스가 (기본 스크롤 시프트를 적용한 후) inset-modified 포함 블록을 넘치고, 위치 옵션 리스트에 두 개 이상 위치 옵션이 있을 경우, 위치 폴백 스타일 결정을 실행해 넘침 없는 옵션을 찾으려고 시도합니다. 적용 결과 스타일은 스타일·레이아웃 인터리빙으로 요소에 적용돼 계산값에도 반영되므로(트랜지션 등 발생 가능) 레이아웃·사용값에 의존해도 처리됩니다.

구현체는 과도한 레이아웃 비용 제한을 위해 위치 옵션 리스트 길이에 임의로 제한을 둘 수 있습니다. 단, 이 제한은 최소 다섯 이상이어야 합니다.

요소 abspos에 대한 위치 폴백 스타일 결정 방법:

  1. current styles를 abspos의 현재 사용된 스타일로 둔다. 이는 계산된 기본 스타일(이전 폴백 결과일 수도 있음)에서 유도된다.

  2. 각 option에 대해 포지션 옵션 목록에서:

    1. 만약 option이 현재 abspos의 마지막으로 성공한 위치 옵션이라면, 계속.

    2. adjusted styles를 위치 옵션 적용 을 option과 abspos에 수행한 결과로 둔다.

    3. el rect는 abspos의 margin box의 크기와 위치, cb rect는 abspos의 inset-수정 포함 블록의 크기와 위치로 둔다. 두 값 모두 adjusted styles로 레이아웃했을 때 기준이다.

    4. 만약 cb rect가 어느 축에서든 음수 크기를 가지다 0 크기로 보정된 경우, 계속.

      참고: 이렇게 하면 크기가 0인 el rect가 크기가 음수였던 cb rect 내에 있다고 간주되어 성공적인 옵션으로 잘못 선택되는 것을 막아준다.

    5. 만약 el rect가 cb rect에 완전히 포함되지 않는다면, 계속.

    6. adjusted styles와, 그에 대해 가상으로 계산된 기억된 스크롤 오프셋 집합을 반환한다.

  3. 단언: 이전 단계가 오버플로우를 피하는 포지션 옵션을 찾지 못하고 종료되었음.

  4. current styles를 반환한다.

참고: 자식 요소가 abspos를 넘치는 것은 이 계산에 영향을 주지 않습니다. 오직 abspos의 margin box만 기준입니다.

참고: 일부러 현재 적용된 위치 옵션을 건너뛰므로, 그 기억된 스크롤 오프셋은 갱신되지 않습니다. 다른 폴백이 실패해서 기존 스타일을 계속 쓴 경우 기억된 스크롤 오프셋도 그대로 유지됩니다.

전체 레이아웃 단계 중 한 박스가 폴백 스타일을 결정하고(혹은 폴백 없음으로 결정하고) 나면, 이후 레이아웃되는 요소가 이 결정을 바꿀 수 없습니다.

예를 들어 A, B 두 위치 지정 박스가 있고, A가 B보다 먼저 레이아웃됩니다. B가 넘쳐서 A의 포함 블록에 스크롤바가 생기는 경우, 이것만으로는 A가 다시 폴백 스타일 결정을 바꾸는 "뒤로가기"가 불가합니다. (최악엔 순환할 수 있어, 레이아웃이 끝없이 반복될 수 있음)

즉, 레이아웃은 "뒤로 가지 않습니다".

6.5.1. 폴백 선택 유지 및 해제

박스에 대한 특정 변경은 위치 폴백 스타일 재결정에 직결적 영향을 주며, 특수 동작을 유발합니다. 이런 폴백 민감 변경(fallback-sensitive changes)은 아래와 같습니다:

  • 계산된 position 값이 변경되었거나, 포함 블록 연관이 바뀌었거나, 더 이상 박스를 생성하지 않게 된 경우.

  • 어떤 롱핸드 position-try의 계산값이 변경된 경우.

  • 어떤 허용된 @position-try 속성의 계산값이 변경된 경우.

  • 참조된 @position-try 규칙 중 어느 하나라도 추가·삭제·변경된 경우.

이 목적을 위해서는 계산된 기본 스타일의 변화만 고려한다. 즉, 트렌지션 또는 애니메이션 cascade origin에서 유래한 선언은 무시한 계산된 스타일 기준이다.

6.5.1.1. 마지막으로 성공한 위치 옵션 기록

레이아웃의 안정성을 최대한 유지하기 위해, 위치 폴백 스타일 결정은 마지막으로 성공한 위치 옵션을 우선시한다. 이 값은 다음과 같이 결정된다:

ResizeObserver 이벤트가 결정되어 전달되는 시점에, 박스는 아래와 같이 마지막으로 성공한 위치 옵션을 기록해야 한다:

  • 만약 el에 마지막으로 성공한 위치 옵션이 있다면, 폴백 민감 변경(fallback-sensitive changes)이 발생한 경우 마지막으로 성공한 위치 옵션을 제거한다. 그 후 위치 폴백 스타일 결정을 el에 대해 실행하고, 마지막으로 성공한 위치 옵션을 현재 사용 중인 허용된 @position-try 속성(및 값) 세트로 설정한다.

  • 그 밖의 경우, 박스 el이 절대 위치 박스라면, 그 마지막으로 성공한 위치 옵션을 현재 사용 중인 허용된 @position-try 속성(및 값) 세트로 설정한다.

참고: 이 기록/제거의 타이밍은 마지막 기억된 크기(last remembered sizes)의 처리와 의도적으로 동일하다.

6.5.2. 위치 옵션 적용

박스의 요소 el에 위치 옵션 적용을 하려면, 위치 옵션 new styles이 제공된다면:

  1. new styles를 위치 폴백 오리진에서 카스케이드에 삽입한 뒤, 카스케이드를 해석하고, el의 사용된 스타일을 산출할 만큼의 레이아웃을 수행한다.

    이 스타일들을 계산하기 위해, 가상 앵커 재계산 지점을 계산하고, 그로부터 얻은 가상의 기억된 스크롤 오프셋을 이용해 el의 스타일을 결정한다.

  2. el의 사용된 스타일을 반환한다.

박스 요소 el의 styles에 대해, 두 방향 directions을 기준으로 try-tactic을 적용하려면:

  1. directions이 같은 축에서 반대라면 “opposing”, 다른 축이라면 “perpendicular”입니다.

  2. el에 허용된 @position-try 속성의 지정 값을 구해, styles로 둡니다.

  3. var 치환, env() 함수, 및 그 외 임의 치환 함수를 styles에 적용합니다.

    env() 함수에 대해 참조된 환경 변수가 축 혹은 방향 관련이면 (예: safe-area-inset-top 등) directions에 맞는 것으로 참조 환경 변수를 바꿔줍니다.

    예: top: env(safe-area-inset-top);로 지정돼 있고 directions가 up, left라면, env()는 env(safe-area-inset-left)로 동작. (그리고 다음 단계에서 left 속성으로 치환됨)

  4. directions에 해당하는 관련 속성들끼리 styles 값을 교체합니다.

    예: "top"과 "left"를 교체한다면, margin-top과 margin-left 값, width와 height 값 등도 교체합니다.

    참고: 같은 축 반대 방향이면, width나 align-self 등 일부 속성은 자체 축 대응이라 바뀌지 않으며, 다음 단계에서 값만 조정될 수 있습니다.

  5. 다음과 같이, 교체 후 속성의 값도 새로운 방향에 맞춰 보정합니다:

    • inset 속성의 경우, anchor() 함수에서 지정한 방향을 기존 방향과 새로운 방향 사이의 상대적 관계가 동일하게 유지되도록 변경합니다.

      <percentage>가 사용되고 방향(directions)이 서로 반대라면, 그 값을 기존 퍼센트에서 100%을 뺀 값으로 바꿉니다.

      예를 들어, "top"과 "left"가 교체되는 경우, margin-top: anchor(bottom) 은 margin-left: anchor(right) 로 바뀝니다.

      "top"과 "bottom"이 교체되는 경우, margin-top: anchor(20%) 은 margin-bottom: anchor(80%)로 바뀝니다.

    • 크기 속성(sizing properties)의 경우, anchor-size() 함수에서 지정한 축을 기존 방향과 새로운 방향 사이의 상대적 관계가 동일하게 유지되도록 변경합니다.

      예를 들어, "top"과 "left"가 교체되는 경우, width: anchor-size(width) 는 height: anchor-size(height) 로 바뀝니다.

    • self-alignment 속성의 경우, 방향이 서로 반대라면, 지정된 <self-position> (또는 left/right 키워드)을, 기존 방향과 새로운 방향 사이의 상대적 관계가 동일하게 유지되도록 변경합니다.

      예를 들어, "top"과 "bottom"이 교체되는 경우, align-self: start 는 align-self: end 로 바뀝니다.

      그러나 align-self: center는 양쪽 모두에서 동일한 관계이므로 바뀌지 않습니다.

      마찬가지로 align-self: first baseline도 <baseline-position> 이기 때문에 <self-position>에 해당하지 않아 변경되지 않습니다.

    • position-area의 경우, 값을 변경해 position-area grid의 선택된 행/열이 기존 방향과 새로운 방향 사이의 상대적 관계가 동일하게 유지되도록 만듭니다.

      예를 들어, "top"과 "left"가 교체되는 경우, position-area: left span-bottom 은 position-area: top span-right로 바뀝니다.

  6. styles를 반환합니다.

6.6. 조건부 숨김: position-visibility 속성

이름: position-visibility
값: always | [ anchors-valid || anchors-visible || no-overflow ]
초깃값: anchors-visible
적용 대상: 절대 위치 박스
상속 여부: 아니오
백분율: 해당 없음
계산값: 지정 값 그대로
정식 순서: 문법에 따름
애니메이션 유형: 불연속

일부 상황에서는 절대 위치 박스를 표시하는 것이 적절하지 않을 수도 있습니다. 이 속성을 사용하면, 흔히 필요한 레이아웃 조건에 따라 이러한 박스가 조건부로 보이도록 할 수 있습니다.

always

이 속성은 아무 효과가 없습니다. (박스는 앵커나 오버플로우 상태와 관계없이 표시됩니다.)

anchors-valid

박스의 필요한 앵커 참조 중 하나라도 타깃 앵커 요소로 해결되지 않으면, 박스의 visibility 속성은 force-hidden으로 계산됩니다.

필요한 앵커 참조(required anchor reference)란 무엇인가? anchor() 함수 중 폴백 값이 없는 것들; 기본 앵커는 *가끔* 포함되나? 여기 더 구체적인 설명 필요.

어느 하나라도 앵커가 빠지면인지, 아니면 모두 앵커가 빠져야 하는지? 두 경우 모두 사용사례가 있음. 여기서 결정할지, 제어 가능하게 할지 논의 필요.

anchors-visible

박스에 기본 앵커 박스가 있지만, 해당 앵커 박스가 보이지 않거나 또는 중간 박스에 의해 잘려있는 경우, 박스의 visibility 속성은 force-hidden으로 계산됩니다.

no-overflow

박스가 inset-수정 포함 블록을 position-try를 적용한 이후에도 여전히 넘치면, 박스의 visibility 속성은 force-hidden으로 계산됩니다.

앵커 박스 anchor는 위치 박스 abspos에 대해 상대적으로 중간 박스에 의해 잘림(clipped by intervening boxes) 상태가 됩니다. 이는 anchor의 잉크 오버플로우 사각형(ink overflow rectangle)이 박스에 완전히 잘릴 때이며, 여기서 그 박스는 anchor의 상위 요소이자 abspos의 포함 블록의 하위 요소입니다. 잘린다는 것은 기본적으로 IntersectionObserver에서 확인하는 클리핑 효과에 해당합니다. 즉, clip-path, overflow, 또는 paint containment와 같은 오버플로우 클립 경계(overflow clip edge)에 의한 효과입니다. anchor에 면적이 있다면, 영역이 완전히 잘려있지 않은 경우만 잘리지 않은 것으로 간주합니다.

anchor가 중간 박스에 잘려 있는지 여부는 문서용 콘텐츠 유효성 업데이트 이후 ( content-visibility 참고, [css-contain-2]) 그리고 ResizeObserver 동작 이후, IntersectionObserver 동작 이전에 확인해야 합니다. 반응성 향상을 위해 그 외에도 검증할 수 있습니다.

참고: 예를 들어 abspos가 앵커 옆에 DOM상에 있다면, 앵커가 스크롤되어 안 보이게 되더라도, 어차피 같은 스크롤러에 의해 잘리므로 여전히 visible 상태가 됩니다.

이 clipped 정의가 View Transitions(동일 개념 필요)에 일관되는지 확인할 것.

참고: "연쇄 앵커(chained anchor)" 상황에서 이 속성으로 첫 번째 abspos가 숨겨지면 (앵커가 스크롤되어 보이지 않음 등), 해당 박스를 앵커로 쓰는 또 다른 abspos도 같이 숨겨져야 하며, 그렇지 않으면 어이없는 위치에 떠다니는 일이 발생할 수 있습니다.

7. 접근성 영향

CSS 앵커 위치 지정은 어떤 접근성 바인딩도 생성, 삭제, 변경하지 않습니다. 저자는 해당 바인딩을 제어하고 싶다면 적절한 마크업 특성을 사용해야 합니다.

이 기능은 다양한 용도와 다양한 방식으로 쓸 수 있기 때문에, CSS 앵커 위치 지정이 위치 박스와 각각의 앵커 사이에 어떤 시맨틱 관계도 자동으로 만들어 주지는 않습니다. 예를 들어, 디자인 상 시각적 앵커 관계는 특정 요소와 시맨틱 앵커 사이가 될 수도 있고, 원하는 연출에 따라 그 시맨틱 앵커의 상위·형제·하위 요소와 연결될 수도 있습니다. 반대로 시맨틱 관계만 있고 시각적 앵커 관계는 없는 디자인도 있을 수 있습니다.

저자는 CSS 위치 지정이 만들어내는 시각적 연결만으로 요소들을 의미론적으로 연결한다고 생각해서는 안 됩니다. 적절한 마크업 없이 시각적으로 이어진 요소는 아무 DOM상 의미 관계도 가지지 않으며, 만약 실제로 의미 있는 관계가 존재한다면, 비시각적 사용자 에이전트(예: 스크린리더)나 비그래픽 탐색 모드(예: Tab 이동 등)에서 사용하기 어렵거나 불가능해질 수 있습니다.

웹 플랫폼의 여러 기능(기존 기능과 새로 추가되는 것들 모두)은 시맨틱 연결을 명시적으로 만들 수 있도록 하여 비시각적 사용자 에이전트에도 이점이 있게 해줍니다. 예를 들어, HTML의 Popover API는 호출 버튼과 팝오버 요소를 자동으로 연결합니다. 이 과정에서 Tab 이동 순서도 자동 조정되며, 추가로 그 버튼을 팝오버의 암시적 앵커 요소로 지정해, 앵커 위치 지정도 쉽게 활용 가능하게 만듭니다.

Popover 예제를 추가할 것.

더 일반적인 경우에는, ARIA 기능 중 aria-details나 aria-describedby 속성을 앵커 요소에 부여하면 좀 더 수동적으로 연결을 만들 수 있습니다. 위치 지정된 요소에 role 속성을 함께 지정하면, 비시각적 사용자 에이전트가 두 요소 간의 관계를 사용자에게 안내하고, 이들끼리 자동으로 이동 가능하게 해줍니다.

하지만 이런 기능도 남용해서는 안 됩니다. 불필요하게 많은 시맨틱 연결로 페이지가 복잡해질 수 있습니다.

이 섹션 개선 아이디어나, 특히 공통 용도에 대한 모범 사례 및 저자 안내 예시 제안 환영. [Issue #10311]

9. 부록: 스타일 & 레이아웃 인터리빙

스타일 & 레이아웃 인터리빙은 스타일 업데이트가 레이아웃 과정 중 서브트리에 발생하여, 요소의 계산된 스타일을 소급해 갱신하는 기법입니다.

이 개념은 여기에 맞는 명세가 아니며, 아마 Cascade에 들어가야 하지만, 참고용 개요가 필요해 여기에 둡니다.

참고: 스타일 & 레이아웃 인터리빙은 이미 컨테이너 쿼리와 컨테이너 쿼리 길이에도 사용됩니다. 10cqw와 같은 길이는 쿼리 컨테이너의 크기 레이아웃 정보를 이용해 계산된 길이로 해석되며, 컨테이너 크기가 레이아웃마다 바뀌면 트랜지션도 트리거될 수 있습니다.

허용된 @position-try 속성도 대체 해석 시 인터리빙됩니다 (position-try 참고).

당연히 훨씬 더 많은 세부 내용이 필요하지만, "컨테이너 쿼리에서 하는 대로 동작" 정도면 충분합니다. 그 동작도 정의되어 있진 않지만, 적어도 어느 정도 상호운용성이 있습니다.

렌더러가 본 명세서에 적합하려면, 스타일 시트를 해당 명세서에 정의된 대로 해석하는 것 외에도, 본 명세서에서 정의된 모든 기능을 정확하게 파싱하고 문서를 이에 맞게 렌더링해야 합니다. 단, UA가 디바이스의 한계로 인해 문서를 올바르게 렌더링하지 못하더라도 UA가 비적합한 것은 아닙니다. (예: UA가 단색 모니터에서 색상을 렌더링할 필요는 없습니다.)

저작 도구가 본 명세서에 적합하려면, 일반 CSS 문법 및 이 모듈의 각 기능별 개별 문법에 따라 문법적으로 올바른 스타일 시트를 작성해야 하며, 이 모듈에 설명된 스타일 시트의 모든 기타 적합성 요구사항을 충족해야 합니다.

부분 구현

저작자가 미래 호환 파싱 규칙을 활용하여 대체 값을 지정할 수 있도록, CSS 렌더러는 반드시 사용 가능한 수준의 지원이 없는 at-rule, 속성, 속성 값, 키워드, 기타 문법 구조를 무효(그리고 적절하게 무시) 처리해야 합니다. 특히 사용자 에이전트는 지원하지 않는 구성 값만 선택적으로 무시하고 지원되는 값만 처리해서는 안 됩니다. 즉, 다중 값 속성 선언에서 하나라도 값이 무효(지원되지 않는 값은 반드시 무효로 간주) 인 경우 전체 선언을 무시해야 한다고 CSS는 요구합니다.

불안정 및 독점 기능 구현

향후 안정적인 CSS 기능과의 충돌을 피하기 위해, CSSWG는 최선의 구현 관행을 따를 것을 불안정 기능 및 독점 확장 구현 시 권장합니다.

비실험적 구현

명세서가 후보 권고(Candidate Recommendation) 단계에 도달하면, 비실험적 구현이 가능하며, 구현자는 명세에 따라 올바르게 구현된 CR 수준 기능에 대해 접두사가 없는(unprefixed) 구현을 공개해야 합니다.

CSS의 상호운용성을 구현 간에 확립하고 유지하기 위해, CSS 워킹 그룹은 비실험적 CSS 렌더러가 W3C에 구현 보고서(필요한 경우 테스트 케이스 포함)를 해당 CSS 기능의 접두사 없는 구현을 출시하기 전에 제출할 것을 요청합니다. W3C에 제출된 테스트 케이스는 CSS 워킹 그룹의 검토 및 수정 대상이 됩니다.

테스트 케이스 및 구현 보고서 제출에 관한 추가 정보는 CSS 워킹 그룹 웹사이트 https://www.w3.org/Style/CSS/Test/에서 확인할 수 있습니다. 문의는 public-css-testsuite@w3.org 메일링 리스트로 하시기 바랍니다.

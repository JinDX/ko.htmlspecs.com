초록

이 모듈은 콘텐츠 기반의 "내재적" 크기와 컨텍스트 기반의 "외재적" 크기를 나타내는 키워드로 CSS 크기 조정 속성을 확장하여 CSS가 콘텐츠에 맞는 박스나 특정 레이아웃 컨텍스트에 맞는 박스를 더 쉽게 설명할 수 있도록 합니다. 이 명세는 CSS 크기 조정 레벨 3에 대한 차이 명세입니다.

CSS는 구조화된 문서 (예: HTML 및 XML)가 화면, 종이 등에 렌더링되는 방식을 설명하는 언어입니다.

1.1. 모듈 상호작용

이 모듈은 width, height, min-width, min-height, max-width, max-height 및 column-width 기능을 확장하며, 이 기능들은 [CSS2] 제10장 및 [CSS3COL]에 정의되어 있습니다.

1.2. 값 정의

이 명세는 CSS 속성 정의 규칙을 [CSS2]에서 따르며, 값 정의 구문은 [CSS-VALUES-3]을 사용합니다. 이 명세에서 정의되지 않은 값 유형은 CSS Values & Units [CSS-VALUES-3]에 정의되어 있습니다. 다른 CSS 모듈과 결합하면 이러한 값 유형의 정의가 확장될 수 있습니다.

각 정의에 나열된 속성별 값 외에도, 이 명세에서 정의된 모든 속성은 CSS 전역 키워드도 속성 값으로 허용합니다. 가독성을 위해 이를 명시적으로 반복하지 않았습니다.

3.2. 새로운 크기 조정 값: contain, fit-content() 및 calc-size() 값

CSS Sizing 3 § 3.2 크기 조정 값: <length-percentage>, auto | none, min-content, max-content 및 fit-content() 값

레벨 4에서는 contain, fit-content() 및 calc-size() 값을 크기 조정 속성에서 사용할 수 있는 기능이 추가되며, 이에 따라 <box-size> 생성식이 다음과 같이 확장됩니다: 

<box-size> = <length-percentage> | stretch | contain | min-content | max-content | fit-content | fit-content() | calc-size()
이름: width, height, min-width, min-height, max-width, max-height
새로운 값: contain | fit-content(<length-percentage [0,∞]>)
fit-content(<length-percentage [0,∞]>)
지정된 인수로 사용 가능한 공간을 대체하여 fit-content 공식을 사용합니다. 즉, min(max-content, max(min-content, <length-percentage>))이며, 여기서 <length-percentage> 인수는 단독으로 사용되는 <length-percentage> 값과 정확히 같은 방식으로 해석됩니다.

음수 <length-percentage> 값은 유효하지 않습니다.

4. 종횡비

이미지는 흔히 고유 종횡비를 가지며, CSS 레이아웃 알고리즘은 요소의 크기를 조정할 때 이 비율을 유지하려고 합니다.

aspect-ratio 속성을 사용하면 비대체 요소에 대해 이 동작을 지정하고, 대체 요소의 유효 종횡비를 변경할 수 있습니다.

이 절의 세부 사항은 아직 작업 중입니다. 여기에서 지정된 동작 중 대체 요소가 선호 종횡비를 가질 때 CSS2, Flex Layout 및 Grid Layout 명세의 요구 사항을 결합했을 때(이 명세가 적용되지 않는 경우)와 다르게 동작하게 하는 내용이 있다면, 이는 오류이며 CSSWG에 보고해야 합니다. 열려 있는 aspect-ratio 이슈 목록이 있습니다.

4.2. 선호 종횡비가 자동 크기에 미치는 영향

박스에 선호 종횡비가 있으면, 해당 박스의 자동 크기는 대체 요소가 고유 종횡비를 갖고 해당 축에 고유 크기가 없는 경우와 같은 방식으로 계산됩니다. 예를 들어 CSS2 § 10 및 CSS Flexible Box Model Level 1 § 9.2를 참조하세요. 선호 크기 계산이 이 종횡비에 의존하는 축을 비율 의존 축이라고 하며, 입력 크기도 확정되어 있다면 결과 크기는 확정됩니다. 반대쪽 축(비율 의존 축의 크기가 의존하는 축)은 비율 결정 축입니다.

참고: 선호 종횡비는 박스 크기 중 적어도 하나가 자동인 경우에만 영향을 줍니다. width와 height 중 어느 것도 자동 크기가 아니면, 선호 종횡비는 해당 요소의 선호 크기에 영향을 줄 수 없습니다.

모든 크기 조정 정보를 여기로 옮겨 2.1에 억지로 끼워 넣지 않게 되면, 여기서의 핵심 원칙은 단순합니다: 비율 결정 축에서 해석된 선호 크기가 (최소/최대값을 적용하기 전에) 비율을 통해 전달됩니다. 최소/최대 제약 조건은 그 이후에 전달되며, 종횡비와 관계없이 각 축에 독립적으로 적용됩니다.

4.4. 최소/최대 크기 전달

어느 축이든 그 축의 크기 조정 제약 조건 (origin 축)은 선호 종횡비를 통해 전달되고, 다른 축(destination 축)의 미확정 최소, 최대 또는 선호 크기에 다음과 같이 적용됩니다:

  • 먼저, 모든 확정 최소 크기는 origin 축에서 destination 축으로 변환되어 전달됩니다. 이렇게 전달된 최소값은 destination 축의 모든 확정 선호 또는 최대 크기를 상한으로 합니다.

  • 그다음, 모든 확정 최대 크기는 origin에서 destination으로 변환되어 전달됩니다. 이렇게 전달된 최대값은 destination 축의 모든 확정 선호 또는 최소 크기, 그리고 존재하는 경우 전달된 최소값을 하한으로 합니다.

참고: 따라서 확정 크기는 전달된 제약 조건의 영향을 전혀 받지 않습니다. 또한 전달된 최소값으로 인해 요소가 확정 선호/최대 크기를 초과하는 일은 없으며, 전달된 최대값으로 인해 요소가 선호/최소 크기를 위반하는 일도 없습니다.

참고: 기본 원칙은 크기 조정 제약 조건이 종횡비를 통해 반대쪽으로 전달되어, 영향을 받는 축에 명시적으로 지정된 크기를 위반하지 않는 범위에서 가능한 한 종횡비를 유지하는 것입니다. (이 원칙은 CSS2 제10.4절의 제약 조건 표 내용을 결정한 원칙입니다.)

다음 예제에서: 
<div id=container style="height: 100px; float: left;">
  <div id=item style="height: 100%; aspect-ratio: 1/1;">content</div>
</div>

#item의 높이는 확정 컨테이너를 기준으로 해석되는 백분율이므로, 항목의 너비는 내재적 크기 기여 및 최종 레이아웃 모두에서 100px로 해석되며, 따라서 컨테이너의 너비도 100px로 결정됩니다.

<div id=container style="height: auto; float: left;">
  <div id=item style="height: 100%; aspect-ratio: 1/1;">content</div>
</div>

다음 예제에서는 항목의 백분율 높이를 해석할 수 없으므로 auto처럼 동작합니다 (CSS 2 § 10.5 콘텐츠 높이: 'height' 속성 참조). 이제 두 축 모두 자동 크기를 가지므로, 높이가 비율 의존 축이 됩니다. 박스의 내재적 크기 기여를 계산하면 콘텐츠에서 파생된 너비와, 해당 너비 및 종횡비로 계산된 높이가 생성되어, “content”라는 단어의 너비에 맞춰 크기가 정해진 정사각형 박스(및 컨테이너)가 만들어집니다.

5.2.1. 마지막으로 기억된 크기

크기 격리는 페이지를 효율적으로 렌더링할 수 있게 보장하는 데 매우 유용하며, 요소의 렌더링 변경으로 인해 발생할 수 있는 레이아웃 작업의 범위를 제한합니다. 그러나 작성자에게는 매우 제한적이기도 하여, 요소의 크기가 어떻게 될지 정확히 예측해야 합니다. 이 추정이 조금이라도 틀리면, 보기 흉한 스크롤바가 생기거나 콘텐츠가 의도치 않게 숨겨질 수 있습니다.

contain-intrinsic-size의 auto 키워드는 중간적인 선택지를 제공합니다: 요소가 어느 시점에든 크기 격리되지 않은 상태라면, 이 값은 요소가 자신의 크기를 기억하게 합니다 (레이아웃에서 평소와 같이 계산됨). 이후 요소에 크기 격리가 적용되면, 기억된 크기를 사용하여 크기 격리의 성능상 이점을 제공하면서 대체로 콘텐츠에 정확히 맞는 크기를 사용할 수 있습니다.

ResizeObserver 대상이 될 수 있는 요소만 마지막으로 기억된 크기를 가질 수 있습니다.

요소의 마지막으로 기억된 크기는 다음과 같이 결정됩니다:

  • ResizeObserver 이벤트가 결정되고 전달되는 시점에, 요소가 contain-intrinsic-size 속성에 auto 키워드를 가지고 있고, ResizeObserver 대상이 될 수 있지만 크기 격리가 없는 경우, 해당 요소의 주 박스의 현재 내부 치수를 마지막으로 기억된 크기로 기록합니다.

  • ResizeObserver 이벤트가 결정되고 전달되는 시점에, 요소에 마지막으로 기억된 크기가 있지만 contain-intrinsic-size 속성에 auto 키워드가 없는 경우, 해당 요소의 마지막으로 기억된 크기를 제거합니다.

참고: 마지막으로 기억된 크기는 요소가 생성한 특정 박스가 아니라 요소 자체에 연결된 상태입니다. 요소가 contain-intrinsic-size 속성에 auto 키워드를 유지하는 한, display: none으로 전환하거나 그 상태에서 벗어나는 등의 변경이 있더라도 마지막으로 기억된 크기를 계속 기억합니다.

5.2.2. overflow: auto와의 상호작용

contain-intrinsic-size 속성은 작성자가 요소의 콘텐츠가 어느 정도 크기일 것으로 예상하는지에 대한 추정치를 제공하지만, 이 추정치는 실제 콘텐츠가 아니며 사용자에게 표시해야 할 어떤 것도 나타내지 않습니다. 따라서 overflow: auto인 요소는 contain-intrinsic-size로 인해 스크롤바를 생성해서는 안 됩니다.

그러나 contain-intrinsic-size가 그 크기의 실제 콘텐츠를 포함했다면 요소가 스크롤바를 생성할 만큼 충분히 큰 크기를 나타내는 경우, 요소는 그러한 가상의 콘텐츠에 따라 스크롤바를 생성한 것처럼 크기가 정해져야 합니다.

다음 예제 코드에서: 
div {
  width: max-content;
  contain-intrinsic-size: 100px 100px;
  overflow: auto;
}

요소는 최종적으로 너비 100px, 높이 100px가 됩니다: contain-intrinsic-size가 max-content 너비와 높이를 모두 제공합니다.

이후 요소에 높이가 150px인 콘텐츠가 생기면 세로 스크롤바가 표시됩니다. 스크롤바가 오버레이가 아니라면 그 100px 너비의 일부를 차지하여 콘텐츠가 배치될 수 있는 공간이 더 작아집니다 (일반적으로 약 84px). (CSS Overflow 3 § 4 스크롤바와 레이아웃을 참조하세요.)

이제 콘텐츠에 사용할 수 있는 가로 공간이 100px보다 작더라도, contain-intrinsic-size가 100px 너비를 나타낸다는 이유만으로 가로 스크롤바가 생성되지는 않습니다. 실제 콘텐츠에 줄바꿈할 수 없는 항목이 있고 그 항목이 남은 공간보다 넓은 경우에만 가로 스크롤바가 생성됩니다.

반면 다음 예제 코드에서는: 
div {
  width: max-content;
  contain-intrinsic-size: 100px 100px;
  height: 50px;
  overflow: auto;
}

요소의 높이는 고정된 50px이지만, contain-intrinsic-size는 100px의 “예상 콘텐츠 높이”를 나타냅니다. 따라서 요소는 실제 콘텐츠로 채워질 때 세로 스크롤바가 필요할 것으로 가정하여, max-content 너비가 100px보다 약간 더 커집니다 (일반적으로 약 116px). 이는 contain-intrinsic-size에서 제공되는 예상 100px의 max-content 너비와 세로 스크롤바의 너비(일반적으로 약 16px)를 모두 수용하기 위한 것입니다.

그러나 요소가 스크롤바가 필요하다고 가정해 공간을 예약하더라도, 실제 콘텐츠가 오버플로하지 않는 한 실제 스크롤바는 생성되지 않습니다. 최종적으로 높이가 50px보다 작은 콘텐츠를 포함하게 되면 세로 스크롤바는 전혀 생성되지 않지만, 요소의 너비는 여전히 116px입니다.

auto

content-width
content-height
content-block-size
content-inline-size

요소에 내부 레이아웃 내재적 크기가 있으면, 해당 요소의 내재적 크기는 대응하는 치수 (너비 또는 높이)를 내부 레이아웃 내재적 크기에서 가져옵니다. (다른 치수는 일반적인 방식으로 결정됩니다.)

논리적 방향은 요소의 쓰기 모드를 기준으로 해석됩니다. (임베드된 문서가 아닙니다.)

어떤 요소가 내부 레이아웃 내재적 크기를 가질 수 있는지와 그것을 어떻게 결정하는지는 문서 언어가 결정합니다. HTML에서는 iframe 요소만 내부 레이아웃 내재적 크기를 가질 수 있으며, 또한 포함된 문서도 <meta name=responsive-embedded-sizing> 요소를 통해 이 기능을 사용하도록 선택한 경우에만 가능합니다. (§ 5.3.1 HTML iframe 세부사항을 참조하세요.)

임베드된 문서에 다음 HTML이 있는 경우: 
<meta name="responsive-embedded-sizing">
<div style="height: 500px"></div>

그리고 임베드하는 문서에 다음 CSS가 있는 경우:

iframe {
  frame-sizing: content-height;
}

iframe의 높이는 처음에는 기본 iframe 높이(일반적으로 150px)가 되지만, iframe의 문서가 로드되면 500px로 업데이트됩니다.

또한 내부 문서는 window.requestResize()를 호출하여 나중에 자신의 내부 레이아웃 내재적 크기를 업데이트할 수 있습니다.

5.3.1. HTML iframe 세부사항

HTML에서는 iframe 요소만 내부 레이아웃 내재적 크기를 가질 수 있으며, iframe의 임베드된 문서가 적절하게 이 기능을 사용하도록 선택한 경우에만 가능합니다.

HTML Document 객체에는 반응형 임베디드 크기 조정 플래그가 연결되어 있으며, 처음에는 설정되지 않은 상태입니다. 이 플래그는 초기 문서 파싱 중 다음 항목 중 먼저 발생하는 것에 따라 true 또는 false로 설정됩니다:

  • <meta name=responsive-embedded-sizing> 요소를 만나면 true로 설정합니다.

  • body 요소가 열리거나(명시적 또는 암시적으로), 파서에 의해 문서에 삽입되면 false로 설정합니다.

한 번 true 또는 false로 설정되면, 이 플래그는 해당 Document의 수명 동안 다시 값을 변경하지 않습니다.

참고: 현재 HTML에서는 HTML 문서의 head에 나타나는 meta 요소가 임베드된 문서에서 이 기능을 사용하도록 선택할 수 있는 유일한 방법입니다. 이는 iframe 안의 SVG 문서는 이 기능을 사용할 수 없음을 의미합니다.

참고: HTML 파서의 특성 때문에 meta 요소는 기술적으로 head 요소와 body 요소 사이에 나타날 수 있으며, 이후 head로 부모가 변경됩니다. 이 위치는 body가 아직 열리지 않았으므로 <meta name=responsive-embedded-sizing> 요소에 여전히 유효한 위치입니다. 대부분의 HTML 요소는 body 시작 태그가 없더라도 암시적으로 body 요소를 연다는 점에 유의하세요. 또한 문서에 해당 요소가 전혀 없으면, 빈 요소가 자동으로 생성되어 삽입됩니다.

내부 레이아웃 내재적 크기는 임베드된 문서가 DOMContentLoaded 이벤트를 발생시킨 후 수행되는 첫 번째 레이아웃의 결과로 처음 설정되고, load 이벤트가 Window에서 발생할 때 다시 설정됩니다. 이후 임베드된 문서의 콘텐츠, 스타일 또는 레이아웃 변경은 내부 레이아웃 내재적 크기에 자동으로 영향을 주지 않지만, requestResize()를 참조하세요.

임베드된 문서는 추가로 고정된 임베디드 ICB 크기를 가질 수 있으며, 처음에는 null입니다. 문서가 레이아웃을 수행할 때 문서의 반응형 임베디드 크기 조정 플래그가 true이고 해당 문서의 고정된 임베디드 ICB 크기가 null이면, 현재 초기 컨테이닝 블록 크기를 고정된 임베디드 ICB 크기로 기록합니다. 이후 레이아웃에서는 초기 컨테이닝 블록 크기를 일반적으로 계산하는 대신 고정된 임베디드 ICB 크기를 사용합니다.

참고: ICB를 이렇게 고정하면 레이아웃 루프가 발생할 가능성을 줄일 수 있습니다. (iframe 문서의 크기가 ICB보다 약간 더 커지고, 그에 맞춰 상위 iframe의 크기가 변경된 다음, 다음 레이아웃에서 다시 ICB보다 약간 더 커지고, 이런 과정이 무한히 반복되는 경우 등입니다.)

iframe이 자신의 고정된 임베디드 ICB 크기를 강제로 잊게 하는 방법이 필요할까요? 아마 frame-sizing을 껐다가 다시 켜는 방식일까요?

iframe의 문서를 탐색하면 해당 문서는 자신의 고정된 임베디드 ICB 크기를 잊습니다. 새 문서의 반응형 임베디드 크기 조정 플래그가 설정되지 않은 동안에는 내부 레이아웃 내재적 크기를 잊지 않습니다. 플래그가 설정되면(true 또는 false), 내부 레이아웃 내재적 크기를 잊으며, 플래그가 true로 설정된 경우 두 값 모두 일반적인 방식으로 새로 계산됩니다.

  3. document를 this의 활성 문서로 둡니다. document의 반응형 임베디드 크기 조정 플래그가 설정되지 않았거나 false이면, NotAllowedError DOMException을 던집니다.

  4. document에 보류 중인 스타일 또는 레이아웃 변경이 있으면, 이를 수행합니다.

  5. host element의 내부 레이아웃 내재적 크기를 this의 스크롤 영역의 너비와 높이로 설정합니다.

5.4. 내재적 크기 기여

CSS 크기 조정 3 § 5.2 내재적 기여

5.5. 최소 콘텐츠 크기 기여를 0으로 만들기: min-intrinsic-sizing 속성

이름: min-intrinsic-sizing
값: legacy | zero-if-scroll || zero-if-extrinsic
초깃값: legacy
적용 대상: 인라인 박스를 제외한 모든 요소
상속: 아니요
백분율: 해당 없음
계산값: 지정한 대로
정규 순서: 문법에 따름
애니메이션 유형: 불연속

이 속성은 이름을 진지하게 다시 논의할 필요가 있습니다.

이 속성은 비대체 박스의 최소 콘텐츠 기여가 특정 상황에서 “압축”되는지 여부를 정의합니다. 값의 의미는 다음과 같습니다:

legacy
박스의 최소 콘텐츠 기여를 일반적인 방식으로 처리합니다.
zero-if-scroll
박스가 해당 축에서 스크롤 컨테이너인 경우, 박스의 최소 콘텐츠 기여가 “압축”됩니다.
zero-if-extrinsic
박스에 외재적 선호 크기 또는 최대 크기가 있으면, 박스의 최소 콘텐츠 기여가 “압축”됩니다.

참고: 이는 대부분의 대체 요소의 기본 동작입니다.

다음 규칙은 모든 스크롤 컨테이너가 자신의 크기 기여를 상위로 전달할 때 사실상 자신의 콘텐츠를 무시하도록 합니다 (콘텐츠 기반 크기를 명시적으로 요청한 경우는 제외합니다): 
*, ::before, ::after { min-intrinsic-sizing: zero-if-scroll; }

이렇게 하면 스크롤 컨테이너에 표나 줄바꿈할 수 없는 긴 텍스트 줄 같은 큰 항목이 포함되어 있어도 조상 요소의 크기를 지나치게 키우지 않게 됩니다. 한편 스크롤 컨테이너가 아닌 박스는 계속해서 조상 요소의 최소 콘텐츠 크기에 영향을 줄 수 있습니다.

참고: zero-if-scroll의 동작이 더 나은 기본값이었겠지만, Web 호환성 때문에 초깃값으로 사용할 수 없습니다. :(

“압축된” 최소 콘텐츠 기여는 박스가 비어 있다고 가정하여 계산합니다. 단, 크기 조정 속성의 명시적 min-content, max-content 및 fit-content 값이 부과하는 크기 조정 제약을 고려할 때는 예외입니다.

5.6. 새로운 열 크기 조정 값: stretch, min-content, max-content, fit-content 및 fit-content() 값

이름: column-width
새로운 값: <box-size>
계산값: 지정한 대로이며, <length-percentage> 값은 계산됨
애니메이션 유형: 계산값 유형에 따름

column-width의 값으로 사용되는 경우, 새로운 키워드는 최적의 열 너비를 지정합니다:

stretch
다단 컨테이너의 stretch-fit 인라인 크기를 최적의 열 너비로 지정합니다.
min-content
다단 컨테이너 콘텐츠의 최소 콘텐츠 인라인 크기를 최적의 열 너비로 지정합니다.
max-content
다단 컨테이너 콘텐츠의 최대 콘텐츠 인라인 크기를 최적의 열 너비로 지정합니다.
fit-content
최적의 열 너비를 min(최대 콘텐츠 인라인 크기, max(최소 콘텐츠 인라인 크기, stretch-fit 인라인 크기))로 지정합니다.
fit-content(<length-percentage>)
최적의 열 너비를 min(최대 콘텐츠 크기, max(최소 콘텐츠 크기, <length-percentage>))로 지정합니다.

참고: 열 너비는 열마다 달라지지 않습니다. 열 너비가 다단 컨테이너의 콘텐츠에 의해 결정되는 경우 (위의 키워드와 같은 경우), 모든 콘텐츠가 고려되며 계산된 너비가 모든 열에 공통으로 적용됩니다.

CSS 크기 조정 3 § 4 외재적 크기 결정

6.1. Contain-fit 크기 조정: 종횡비를 유지하면서 늘이기

Contain-fit 크기 조정은 본질적으로 stretch-fit 크기 조정을 적용하지만, 박스의 한 축 크기를 줄여 박스의 선호 종횡비를 유지합니다. 이는 object-fit 및 background-size 속성의 contain 키워드와 유사합니다.

먼저 대상 사각형을 결정합니다:

  1. 초기 대상 사각형은 박스의 컨테이닝 블록 크기이며, 정해지지 않은 크기는 무한대로 가정합니다. 두 치수 모두 정해지지 않은 경우, 초기 대상 사각형은 박스가 stretch-fit 크기 조정되었을 때의 박스 바깥쪽 가장자리와 일치하도록 설정합니다.
  2. 다음으로, 박스에 none이 아닌 max-width 또는 max-height가 있으면, 대상 사각형의 해당 치수를 박스 마진 박스의 “최대 크기” 이하로 제한합니다. 즉, 박스가 max-width/height 크기로 조정되었을 때 마진 박스가 갖게 되는 크기입니다. (일반적인 박스 크기 조정 규칙과 일관되게, 이 “최대 크기”에는 박스의 min-width/min-height 효과에 따른 하한이 적용된다는 점에 유의하세요.)
  3. 마지막으로 대상 사각형의 한 치수를 박스의 선호 종횡비와 일치시키는 데 필요한 최소한의 양만큼 줄입니다.

각 치수의 contain-fit 크기는 대상 사각형에 stretch-fit을 적용했을 때 얻어지는 크기입니다.

마진 상쇄와 관련하여 stretch-fit이 최종적으로 수행하는 동작을 그대로 복사하세요.

한 치수에 최소 크기가 있고, 종횡비를 유지할 경우 대상 사각형을 오버플로하게 된다면, 종횡비를 유지해야 할까요, 아니면 이미지를 왜곡해야 할까요? 전자라면 관련 최소값을 적용하는 #2와 유사한 단계가 필요합니다.

    • 그다음 모든 확정된 최대 크기는 origin에서 destination으로 변환되어 전달됩니다. 전달된 최대값의 하한은 destination 축의 모든 확정된 선호 크기 또는 최소 크기와, 전달된 최소값이 있는 경우 그 최소값입니다.

    참고: 기본 원칙은 크기 조정 제약이 종횡비를 통해 반대쪽으로 전달되어, 영향을 받는 축에 명시적으로 지정된 크기를 위반하지 않는 범위에서 가능한 한 종횡비를 유지한다는 것입니다.

  • 자연 크기를 하나만 가진 대체 요소의 aspect-ratio가 다른 치수를 결정한다는 점을 명확히 했습니다. (이슈 5306)

    대체 요소의 유일한 자연 치수가 자연 너비 또는 자연 높이인 경우, 해당 요소에 선호 종횡비를 지정하면 누락된 쪽에 따라 자연 높이 또는 너비도 부여되며, 기존 크기를 선호 종횡비를 통해 전달하여 계산합니다.

  • aspect-ratio가 마진 자체 상쇄를 억제한다고 정의했습니다. (이슈 5328)

    마진 상쇄를 위해(CSS 2 § 8.3.1 마진 상쇄), 블록 축이 비율 종속 축이면, 해당 축은 auto의 계산된 block-size를 갖는 것으로 간주하지 않습니다.

  • 크기 조정 속성을 위한 fit-content() 함수와 contain 키워드를 추가했습니다.

테스트

이 명세의 내용과 관련된 테스트는 이와 같은 “테스트” 블록에 문서화될 수 있습니다. 이러한 블록은 모두 비규범적입니다.

    적합성 클래스

    이 명세에 대한 적합성은 세 가지 적합성 클래스에 대해 정의됩니다:

    스타일 시트
    CSS 스타일 시트입니다.
    렌더러
    스타일 시트의 의미를 해석하고 이를 사용하는 문서를 렌더링하는 UA입니다.
    저작 도구
    스타일 시트를 작성하는 UA입니다.

    스타일 시트가 이 명세에 적합하려면 이 모듈에서 정의된 구문을 사용하는 모든 선언이 일반 CSS 문법과 이 모듈에서 정의된 각 기능의 개별 문법에 따라 유효해야 합니다.

    렌더러가 이 명세에 적합하려면 해당 명세에 정의된 대로 스타일 시트를 해석하는 것뿐만 아니라, 이 명세에서 정의된 모든 기능을 올바르게 파싱하고 그에 따라 문서를 렌더링하여 지원해야 합니다. 다만 장치의 한계로 인해 UA가 문서를 올바르게 렌더링하지 못한다고 해서 해당 UA가 부적합한 것은 아닙니다. (예를 들어 UA는 흑백 모니터에서 색상을 렌더링할 필요가 없습니다.)

    저작 도구가 이 명세에 적합하려면 일반 CSS 문법과 이 모듈의 각 기능에 대한 개별 문법에 따라 구문적으로 올바른 스타일 시트를 작성하고, 이 모듈에 설명된 스타일 시트의 기타 모든 적합성 요구사항을 충족해야 합니다.

    부분 구현

    작성자가 순방향 호환 파싱 규칙을 활용하여 대체 값을 지정할 수 있도록 CSS 렌더러는 사용 가능한 수준으로 지원하지 않는 모든 at-rule, 속성, 속성 값, 키워드 및 기타 구문 구조를 무효로 처리하고(그리고 적절히 무시해야) 합니다. 특히 사용자 에이전트는 하나의 다중 값 속성 선언에서 지원되지 않는 구성요소 값만 선택적으로 무시하고 지원되는 값만 적용해서는 안 됩니다. 어떤 값이라도 무효로 간주되면 (지원되지 않는 값은 반드시 그렇게 간주해야 하므로), CSS는 전체 선언을 무시하도록 요구합니다.

    불안정 기능 및 독점 기능의 구현

    향후 안정적인 CSS 기능과의 충돌을 피하기 위해, CSSWG는 CSS의 불안정 기능 및 독점 확장을 구현할 때 모범 사례를 따를 것을 권장합니다.

    비실험적 구현

    명세가 후보 권고안 단계에 도달하면 비실험적 구현이 가능하며, 구현자는 명세에 따라 올바르게 구현되었음을 입증할 수 있는 모든 CR 수준 기능을 접두사 없는 구현으로 출시해야 합니다.

    구현 간 CSS의 상호운용성을 확립하고 유지하기 위해, CSS 작업 그룹은 비실험적 CSS 렌더러가 CSS 기능의 접두사 없는 구현을 출시하기 전에 구현 보고서(필요한 경우 해당 구현 보고서에 사용된 테스트 사례도 함께)를 W3C에 제출하도록 요청합니다. W3C에 제출된 테스트 사례는 CSS 작업 그룹의 검토와 수정을 받을 수 있습니다.

    테스트 사례와 구현 보고서 제출에 대한 자세한 정보는 CSS 작업 그룹의 웹사이트 https://www.w3.org/Style/CSS/Test/에서 확인할 수 있습니다. 질문은 public-css-testsuite@w3.org 메일링 리스트로 보내주시기 바랍니다.

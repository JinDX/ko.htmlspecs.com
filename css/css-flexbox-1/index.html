요약

이 명세서는 사용자 인터페이스 디자인에 최적화된 CSS 박스 모델을 설명합니다. 플렉스 레이아웃 모델에서는 플렉스 컨테이너의 자식들이 어느 방향으로든 배치될 수 있으며, 크기를 “플렉스”하여 남는 공간을 채우거나 부모를 넘치지 않도록 크기를 줄일 수도 있습니다. 자식 요소의 수평 및 수직 정렬을 쉽게 조작할 수 있습니다. 이러한 박스의 중첩(수평 안에 수직, 또는 수직 안에 수평)을 이용하여 2차원 레이아웃을 만들 수 있습니다.

CSS는 구조화된 문서(예: HTML 및 XML)의 렌더링을 화면, 인쇄물 등에서 기술하는 언어입니다.

1. 소개

이 섹션은 규범적이지 않습니다.

CSS 2.1은 네 가지 레이아웃 모드 — 박스의 형제 및 조상 박스와의 관계를 기반으로 크기와 위치를 결정하는 알고리즘 — 를 정의했습니다:

  • 블록 레이아웃: 문서 레이아웃에 최적화됨

  • 인라인 레이아웃: 텍스트 레이아웃에 최적화됨

  • 테이블 레이아웃: 2차원 데이터를 표 형식으로 레이아웃

  • 포지션 레이아웃: 문서 내 다른 요소와는 관계없이 명확한 위치 지정에 최적화됨

이 모듈은 더 복잡한 애플리케이션과 웹페이지의 레이아웃을 위해 설계된 새로운 레이아웃 모드인 플렉스 레이아웃을 도입합니다.

1.1. 개요

이 섹션은 규범적이지 않습니다.

플렉스 레이아웃은 표면적으로 블록 레이아웃과 비슷합니다. 블록 레이아웃에서 사용되는 float이나 column과 같은 복잡한 텍스트 또는 문서 중심 속성이 많이 없습니다. 대신, 웹 앱과 복잡한 웹페이지에서 자주 필요한 공간 분배와 콘텐츠 정렬을 위한 간단하고 강력한 도구를 제공합니다. 플렉스 컨테이너의 내용은 다음과 같습니다:

  • 어떤 흐름 방향(왼쪽, 오른쪽, 아래, 심지어 위쪽)으로든 배치될 수 있습니다.

  • 스타일 레이어에서 표시 순서를 역순 또는 재정렬할 수 있습니다. (즉, 시각적 순서가 소스 및 음성 순서와 독립적으로 설정될 수 있습니다.)

  • 단일 (주) 축을 따라 선형적으로 배치하거나 여러 줄로 래핑할 수 있습니다. 래핑은 보조 (교차) 축을 따라 이루어집니다.

  • “플렉스” 크기로 사용 가능한 공간에 따라 반응할 수 있습니다.

  • 보조 (교차) 축 기준으로 컨테이너나 서로 간에 정렬될 수 있습니다.

  • 숨김/보임 상태를 주축 기준으로 동적으로 변경하면서, 컨테이너의 교차 크기를 유지할 수 있습니다.

여기 각 항목에 제목, 사진, 설명, 구매 버튼이 있는 카탈로그 예제가 있습니다. 디자이너의 의도는 각 항목이 동일한 전체 크기를 가지며, 사진이 텍스트 위에 위치하고, 구매 버튼이 항목 설명 길이에 관계없이 항상 하단에 정렬되는 것입니다. 플렉스 레이아웃은 이러한 디자인의 많은 부분을 쉽게 만듭니다:

  • 카탈로그는 행의 항목을 수평으로 배치하기 위해 플렉스 레이아웃을 사용하며, 행 내 모든 항목이 같은 높이를 갖도록 합니다. 각 항목은 자체적으로 세로로 콘텐츠를 배치하는 열 플렉스 컨테이너가 됩니다.

  • 각 항목 내에서 소스 문서의 콘텐츠는 제목→설명→사진 순서로 논리적으로 배치됩니다. 이는 음성 렌더링 및 비 CSS 브라우저에서도 합리적인 순서를 제공합니다. 더 매력적인 시각적 표현을 위해 order를 사용하여 이미지를 상단으로 이동시키고, align-self로 이미지를 가로로 가운데 정렬합니다.

  • 구매 버튼 위에 auto 마진을 추가하면 해당 항목 설명의 높이에 관계없이 버튼이 항상 항목 박스의 하단에 위치하게 됩니다.

#deals {
  display: flex;        /* 플렉스 레이아웃: 항목 높이 동일  */
  flex-flow: row wrap;  /* 여러 줄로 래핑 허용 */
}
.sale-item {
  display: flex;        /* 각 항목을 플렉스 레이아웃으로 배치 */
  flex-flow: column;    /* 항목 내용 세로 배치  */
}
.sale-item > img {
  order: -1;            /* 이미지를 상단으로 이동 (시각적 순서) */
  align-self: center;   /* 이미지를 가로로 가운데 정렬         */
}
.sale-item > button {
  margin-top: auto;     /* auto top margin으로 버튼을 하단에 배치 */
}

<section id="deals">
  <section class="sale-item">
    <h1>컴퓨터 스타터 키트</h1>
    <p>돈이 많지 않다면, 이게 최고의 컴퓨터입니다.
    <ul>
      <li>컴퓨터
      <li>모니터

1.2. 모듈 상호작용

이 모듈은 display 속성 [CSS21]의 정의를 확장하여, 새로운 블록 레벨과 인라인 레벨 display 타입을 추가하고, 레이아웃을 제어하는 속성과 함께 새로운 형식 컨텍스트 유형을 정의합니다. 이 모듈에서 정의된 속성은 ::first-line 또는 ::first-letter 의사 요소에는 적용되지 않습니다.

CSS 박스 정렬 모듈은 여기서 소개된 정렬 속성(justify-content, align-items, align-self, align-content)의 정의를 확장하고 대체합니다.

2. 플렉스 레이아웃 박스 모델 및 용어

플렉스 컨테이너는 요소가 계산된 display 속성으로 flex 또는 inline-flex가 지정될 때 생성되는 박스입니다. 플렉스 컨테이너의 흐름 내 자식들은 플렉스 아이템이라 하며, 플렉스 레이아웃 모델을 사용하여 배치됩니다.

블록 및 인라인 레이아웃과 달리, 그 레이아웃 계산은 블록 및 인라인 흐름 방향에 치우쳐 있지만, 플렉스 레이아웃은 플렉스 방향에 치우쳐 있습니다. 플렉스 레이아웃에 대해 더 쉽게 설명할 수 있도록, 이 섹션에서는 플렉스 흐름 상대 용어 집합을 정의합니다. flex-flow 값과 writing mode에 따라 이 용어들이 실제 방향(위/오른쪽/아래/왼쪽), 축(수직/수평), 크기(너비/높이)로 어떻게 매핑되는지가 결정됩니다.

main axis
main dimension
플렉스 컨테이너의 주 축(main axis)은 플렉스 아이템이 배치되는 주요 축입니다. 주 차원(main dimension)으로 뻗어 있습니다.
main-start
main-end
플렉스 아이템은 컨테이너 내에서 main-start 측에서 시작해 main-end 측으로 배치됩니다.
main size
main size property
플렉스 컨테이너 또는 플렉스 아이템의 너비 또는 높이 중 주 차원에 해당하는 것이 그 박스의 주 크기(main size)입니다. 주 크기 속성(main size property)은 width 또는 height 속성 중 주 차원에 해당하는 것입니다. 마찬가지로, min, max main size property는 min-width/max-width 또는 min-height/max-height 속성 중 주 차원에 해당하는 것이며, min/max main size를 결정합니다.
cross axis
cross dimension
주 축에 수직인 축을 교차 축(cross axis)이라 하며, 교차 차원(cross dimension) 방향으로 뻗어 있습니다.
cross-start
cross-end
플렉스 라인은 아이템으로 채워져 컨테이너에 배치되며, 플렉스 컨테이너의 cross-start 측에서 시작해 cross-end 측으로 배치됩니다.

cross size property
플렉스 컨테이너 또는 플렉스 아이템의 너비 또는 높이 중 교차 차원에 해당하는 것이 그 박스의 교차 크기(cross size)입니다. 교차 크기 속성(cross size property)은 width 또는 height 속성 중 교차 차원에 해당하는 것입니다. 마찬가지로, min, max cross size property는 min-width/max-width 또는 min-height/max-height 속성 중 교차 차원에 해당하는 것이며, min/max cross size를 결정합니다.

이 명세에서 사용하는 추가적인 사이즈 용어는 CSS 내부 및 외부 사이즈에서 정의되어 있습니다. [CSS-SIZING-3]

3. 플렉스 컨테이너: flex 및 inline-flex display 값

이름: display
새 값: flex | inline-flex
flex
이 값은 요소가 플렉스 컨테이너 박스를 생성하게 하며, 블록 레벨로 플로우 레이아웃에 배치됩니다.
inline-flex
이 값은 요소가 플렉스 컨테이너 박스를 생성하게 하며, 인라인 레벨로 플로우 레이아웃에 배치됩니다.

플렉스 컨테이너는 그 내용에 대해 새로운 플렉스 포맷팅 컨텍스트를 생성합니다. 이는 블록 포맷팅 컨텍스트를 생성하는 것과 동일하나, 블록 레이아웃 대신 플렉스 레이아웃이 사용됩니다. 예를 들어, float 요소는 플렉스 컨테이너에 침범하지 않으며, 플렉스 컨테이너의 마진은 그 내용의 마진과 병합되지 않습니다. 플렉스 컨테이너는 그 내용에 대해 블록 컨테이너와 동일하게 포함 블록을 구성합니다. [CSS21] overflow 속성은 플렉스 컨테이너에 적용됩니다.

플렉스 컨테이너는 블록 컨테이너가 아니므로, 블록 레이아웃을 전제로 설계된 일부 속성은 플렉스 레이아웃에서는 적용되지 않습니다. 특히:

  • float와 clear 속성은 플렉스 아이템을 떠있게 하거나 클리어런스를 생성하지 않으며, 흐름에서 제외하지도 않습니다.

  • vertical-align은 플렉스 아이템에 아무런 영향을 주지 않습니다.

  • ::first-line 및 ::first-letter 의사 요소는 플렉스 컨테이너에 적용되지 않으며, 플렉스 컨테이너는 조상에게 첫 번째 포맷팅 라인이나 첫 문자를 제공하지 않습니다.

요소의 지정된 display가 inline-flex이면, 특정 상황에서는 display 속성 값이 flex로 계산됩니다: CSS 2.1 섹션 9.7의 표에 "지정 값" 열에 inline-flex가, "계산 값" 열에는 flex가 추가된 행이 포함됩니다.

4. 플렉스 아이템

대략적으로, 플렉스 아이템은 플렉스 컨테이너의 흐름 내 콘텐츠를 나타내는 박스입니다.

플렉스 컨테이너의 각 흐름 내 자식은 플렉스 아이템이 되며, 연속되는 자식 텍스트 런 시퀀스는 익명 블록 컨테이너 플렉스 아이템으로 감싸집니다. 하지만, 자식 텍스트 런 전체가 공백 문자만 포함하는 경우(즉, white-space 속성의 영향을 받을 수 있는 문자), 렌더링되지 않습니다(마치 텍스트 노드가 display:none인 것처럼).

플렉스 아이템 예시: 

<div style="display:flex">

    <!-- 플렉스 아이템: 블록 자식 -->
    <div id="item1">블록</div>

    <!-- 플렉스 아이템: float 요소; float은 무시됨 -->
    <div id="item2" style="float: left;">float</div>

    <!-- 플렉스 아이템: 인라인 콘텐츠를 감싸는 익명 블록 박스 -->
    익명 아이템 3

    <!-- 플렉스 아이템: 인라인 자식 -->
    <span>
        아이템 4
        <!-- 플렉스 아이템은 블록 기준 분할되지 않음 -->
        <q style="display: block" id=not-an-item>아이템 4</q>
        아이템 4
    </span>
</div>

요소 사이의 공백은 사라집니다: 자체 플렉스 아이템이 되지 않으며, 요소 사이의 텍스트가 실제로 익명 플렉스 아이템으로 감싸지더라도 그렇습니다.

익명 아이템의 박스는 스타일을 지정할 수 없다는 점도 주의하세요. 스타일 규칙을 적용할 요소가 없기 때문입니다. 하지만 그 내용은 플렉스 컨테이너로부터 폰트 설정 등 스타일을 상속받습니다.

플렉스 아이템은 그 내용에 대해 독립적인 포맷팅 컨텍스트를 생성합니다. 하지만 플렉스 아이템 자체는 플렉스 레벨 박스이며, 블록 레벨 박스가 아닙니다: 컨테이너의 플렉스 포맷팅 컨텍스트에 참여하지, 블록 포맷팅 컨텍스트에는 참여하지 않습니다.

참고: 이 명세를 읽는 저자는 다음의 박스 생성 및 정적 위치 설명을 건너뛸 수 있습니다.

display 값은 플렉스 아이템에 대해 blockify됩니다: 플렉스 컨테이너를 생성하는 요소의 흐름 내 자식이 인라인 레벨 값으로 지정된 경우, 그 값은 블록 레벨 값으로 계산됩니다. (CSS2.1§9.7 [CSS21] 및 CSS Display [CSS3-DISPLAY]에서 이 변환 유형에 대한 자세한 내용을 확인하세요.)

참고: 일부 display 값은 원래 박스 주변에 익명 박스를 생성합니다. 만약 해당 박스가 플렉스 아이템이라면, 먼저 blockify되고, 익명 박스가 생성되지 않습니다. 예를 들어, 플렉스 아이템 두 개가 display: table-cell이면, 익명 테이블로 감싸지지 않고, 각각 별도의 display: block 플렉스 아이템이 됩니다.

display: table 플렉스 아이템의 경우, 테이블 래퍼 박스가 플렉스 아이템이 되고, order 및 align-self 속성이 적용됩니다. 캡션 박스의 내용은 테이블 래퍼 박스의 min-content 및 max-content 크기 계산에 기여합니다. 단, width 및 height처럼 flex longhand 속성도 테이블 박스에 다음과 같이 적용됩니다: 플렉스 아이템의 최종 크기는 테이블 래퍼 박스의 테두리+패딩 영역 전체와 테이블 박스의 콘텐츠 경계 간 거리가 테이블 박스의 테두리+패딩 영역 일부인 것처럼 레이아웃을 수행해 테이블 박스가 플렉스 아이템인 것처럼 계산합니다.

4.1. 절대 위치 플렉스 자식

흐름에서 벗어나 있기 때문에, 플렉스 컨테이너의 절대 위치 지정 자식은 플렉스 레이아웃에 참여하지 않습니다.

정적 위치는 플렉스 컨테이너의 절대 위치 지정 자식이 플렉스 아이템 하나뿐인 것처럼 결정됩니다. 즉, 자식과 플렉스 컨테이너가 사용된 크기의 고정 박스라고 가정합니다. 이 목적을 위해 auto 마진은 0으로 처리됩니다.

다시 말해, static-position rectangle은 플렉스 컨테이너의 콘텐츠 박스입니다. static-position rectangle은 절대 위치 박스의 정적 위치 오프셋을 결정할 때 사용하는 alignment container입니다.

(블록 레이아웃에서는 static position rectangle이 CSS2.1§10.3.7의 “가상 박스” 위치에 해당합니다. 정렬 속성이 없기 때문에, CSS2.1은 항상 block-start inline-start 정렬로 절대 위치 박스를 static-position rectangle 안에 배치합니다. 이 정의는 언젠가 CSS Positioning 모듈로 이동할 예정입니다.)

예를 들어 align-self: center;를 플렉스 컨테이너의 절대 위치 자식에 지정하면, auto 오프셋이 해당 자식을 플렉스 컨테이너의 교차 축에서 가운데로 위치시킵니다.

그러나 절대 위치 박스가 "고정 크기"로 간주되므로, stretch 값은 flex-start와 동일하게 처리됩니다.

4.2. 플렉스 아이템 마진 및 패딩

인접한 플렉스 아이템의 마진은 병합되지 않습니다.

플렉스 아이템의 백분율 마진 및 패딩은, 블록 박스와 마찬가지로, 포함 블록의 인라인 크기를 기준으로 계산됩니다. 예를 들어, 좌/우/위/아래 백분율 모두 수평 쓰기 모드에서는 포함 블록의 너비를 기준으로 계산됩니다.

auto 마진은 해당 차원의 남는 공간을 흡수하도록 확장됩니다. 정렬에 사용하거나, 인접한 플렉스 아이템을 서로 밀어낼 때 사용할 수 있습니다. auto 마진으로 정렬을 참고하세요.

4.3. 플렉스 아이템 Z-정렬

플렉스 아이템은 인라인 블록과 정확히 동일하게 페인팅됩니다 [CSS21], 단, order로 변경된 문서 순서가 원본 문서 순서 대신 사용되고, z-index 값이 auto가 아닌 경우 position이 static이어도 스택 컨텍스트를 생성합니다 (마치 position이 relative인 것처럼 동작합니다).

참고: 플렉스 아이템 밖에 위치한 자손들도 플렉스 아이템이 생성한 스택 컨텍스트에 계속 참여합니다.

4.4. 접힌 아이템

visibility:collapse를 플렉스 아이템에 지정하면, 해당 아이템은 접힌 플렉스 아이템이 되어, visibility:collapse가 테이블 행이나 테이블 열에 적용될 때와 유사한 효과를 냅니다: 접힌 플렉스 아이템은 렌더링에서 완전히 제거되지만, 플렉스 라인의 교차 크기를 안정적으로 유지하는 "스트럿"을 남깁니다. 따라서 플렉스 컨테이너에 플렉스 라인이 하나만 있으면, 아이템을 동적으로 접거나 펴는 것이 플렉스 컨테이너의 주 크기는 변경될 수 있지만, 교차 크기에는 영향을 주지 않으며 페이지의 다른 레이아웃이 흔들리지 않습니다. 단, 플렉스 라인 래핑은 접힌 후에 다시 수행되므로, 복수 라인을 가진 플렉스 컨테이너의 교차 크기는 변할 수도 있고 변하지 않을 수도 있습니다.

접힌 플렉스 아이템은 렌더링되지 않지만, 포맷 구조에는 등장합니다. 따라서 display:none 아이템과 달리 [CSS21], 박스가 포맷 구조에 등장하는 것에 의존하는 효과(카운터 증가, 애니메이션 및 트랜지션 실행 등)는 접힌 아이템에도 계속 적용됩니다.

아래 예시에서 사이드바는 콘텐츠 크기에 맞게 조정됩니다. visibility: collapse가 네비게이션 사이드바의 일부를 동적으로 숨기는 데 사용되며, 가장 넓은 항목("Architecture")이 접힌 섹션에 있더라도 너비에는 영향을 주지 않습니다. 
@media (min-width: 60em) {
  /* 충분히 넓을 때 2열 레이아웃 (기본 텍스트 크기 기준) */
  div { display: flex; }
  #main {
    flex: 1;         /* 메인이 남은 공간을 모두 차지 */
    order: 1;        /* 네비게이션 뒤(오른쪽)에 배치 */
    min-width: 12em; /* 메인 콘텐츠 영역 크기 최적화 */
  }
}
/* 메뉴 항목은 visibility:collapse가 동작하도록 플렉스 레이아웃 사용 */
nav > ul > li {
  display: flex;
  flex-flow: column;
}
/* 타깃되지 않거나 호버되지 않은 서브메뉴는 동적으로 접음 */
nav > ul > li:not(:target):not(:hover) > ul {
  visibility: collapse;
}

스트럿의 크기를 계산하기 위해, 모든 아이템이 펴진 상태에서 먼저 플렉스 레이아웃을 수행한 뒤, 각 접힌 아이템을 원래 라인의 교차 크기를 유지하는 스트럿으로 대체하여 다시 수행합니다. visibility:collapse가 플렉스 레이아웃과 상호작용하는 방식의 규범적 정의는 플렉스 레이아웃 알고리즘을 참고하세요.

참고: 플렉스 아이템에 visibility:collapse를 사용하면 플렉스 레이아웃 알고리즘이 중간에 반복되어 가장 비용이 많이 드는 단계가 다시 실행됩니다. 아이템이 동적으로 접히거나 펴지지 않는 경우에는 display:none을 사용해 숨기는 것이 더 효율적이므로, 저자에게 권장됩니다. (visibility가 변경될 때 일부 단계만 반복되므로 동적 상황에서는 'visibility: collapse' 사용이 여전히 권장됩니다.)

4.5. 플렉스 아이템의 자동 최소 크기

참고: auto 키워드, 즉 자동 최소 크기는 min-width 및 min-height 속성의 새로운 초기값입니다. 이 키워드는 이전에는 본 명세에서 정의되었으나, 지금은 CSS Sizing 모듈에서 정의됩니다.

플렉스 아이템에 더 합리적인 기본 최소 크기를 제공하기 위해, 주 축 자동 최소 크기의 사용값이 플렉스 아이템이 스크롤 컨테이너가 아닌 경우 콘텐츠 기반 최소 크기가 됩니다; 스크롤 컨테이너의 자동 최소 크기는 기존처럼 0입니다.

일반적으로 콘텐츠 기반 최소 크기는 플렉스 아이템의 콘텐츠 크기 제안과 명시 크기 제안 중 더 작은 값입니다. 단, 박스에 종횡비가 있고 명시 크기가 없으면, 콘텐츠 기반 최소 크기는 콘텐츠 크기 제안과 전달 크기 제안 중 더 작은 값입니다. 명시 크기 제안과 종횡비가 모두 없으면, 콘텐츠 기반 최소 크기는 콘텐츠 크기 제안이 됩니다.

콘텐츠 크기 제안, 명시 크기 제안, 전달 크기 제안은 관련 min/max/선호 크기 속성을 고려하여 콘텐츠 기반 최소 크기가 저자가 지정한 제약을 방해하지 않도록 합니다. 아래에서 정의합니다:

명시 크기 제안
아이템의 주 크기 속성이 확정적이면, 명시 크기 제안은 그 크기(만약 최대 주 크기 속성이 확정적이면 제한됨)입니다. 그렇지 않으면 정의되지 않습니다.
전달 크기 제안
아이템에 고유 종횡비가 있고, 교차 크기 속성이 확정적이면, 전달 크기 제안은 그 크기(만약 최소 및 최대 교차 크기 속성이 확정적이면 제한됨)이고, 종횡비를 통해 변환됩니다. 그렇지 않으면 정의되지 않습니다.
콘텐츠 크기 제안
콘텐츠 크기 제안은 min-content 크기입니다. 주 축에서, 종횡비가 있을 경우 확정적 최소 및 최대 교차 크기 속성을 종횡비로 변환해 제한하고, 그 후 최대 주 크기 속성이 확정적이면 추가로 제한합니다.

박스의 고유 크기를 계산할 때 (예: 박스의 min-content 크기), 콘텐츠 기반 최소 크기는 해당 축의 크기가 비확정적으로 만듭니다 (예를 들어 width가 확정적이어도 마찬가지). 이 값으로 계산되는 백분율은 auto로 동작함에 유의하세요.

이로 인해 일부 경우에는 백분율을 다시 해석하기 위한 추가 레이아웃 패스가 필요할 수 있지만, (min-content, max-content, fit-content 등 [CSS-SIZING-3]에서 정의된 값과 같이) 이 값은 아이템 내의 백분율 크기 해석을 방해하지 않습니다.

콘텐츠 기반 최소 크기는 대부분 적절하며, 콘텐츠가 겹치거나 컨테이너를 넘치는 것을 방지하지만, 경우에 따라 적절하지 않을 수도 있습니다:

특히, 플렉스 크기가 문서의 주요 콘텐츠 영역에 사용된다면, min-width: 12em처럼 폰트 기준 최소 너비를 명시적으로 지정하는 것이 더 낫습니다. 콘텐츠 기반 최소 너비는 큰 테이블이나 이미지가 전체 콘텐츠 영역을 넘치게 늘려 텍스트 줄이 너무 길어져 가독성이 떨어질 수 있습니다.

또한, 콘텐츠가 많은 아이템에 콘텐츠 기반 크기를 사용하면 레이아웃 엔진이 최소 크기를 찾기 위해 모든 콘텐츠를 순회해야 하며, 저자가 명시적으로 최소 크기를 지정하면 이 과정이 필요 없습니다. (콘텐츠가 적은 아이템의 경우 이 순회는 사소하므로 성능상 문제는 없습니다.)

5. 순서와 방향

플렉스 컨테이너의 내용은 어떤 방향과 어떤 순서로든 배치될 수 있습니다. 이를 통해 저자는 이전에는 복잡하거나 불안정한 방식(예: float와 clear 속성 활용해 억지로 구현했던 효과)을 쉽게 달성할 수 있습니다. 이 기능은 flex-direction, flex-wrap, order 속성으로 제공합니다.

참고: 플렉스 레이아웃의 순서 변경 기능은 오직 시각적 렌더링에만 의도적으로 영향을 주며, 음성 순서와 소스 순서 기반 네비게이션은 그대로 유지됩니다. 저자는 시각적 프레젠테이션을 조작하면서도, 소스 순서를 비 CSS UA나 음성/순차적 네비게이션 모델에 그대로 남겨 접근성을 높일 수 있습니다. 접근성 향상을 위해 이 이분법을 활용한 예시는 순서 변경과 접근성 및 플렉스 레이아웃 개요에서 볼 수 있습니다.

저자는 절대 order 또는 *-reverse 값을 flex-flow/flex-direction에서 올바른 소스 순서의 대체로 사용해서는 안 됩니다. 이는 문서의 접근성을 해칠 수 있습니다.

5.1. 플렉스 흐름 방향: flex-direction 속성

이름: flex-direction
값: row | row-reverse | column | column-reverse
초기값: row
적용 대상: 플렉스 컨테이너
상속: 아니오
백분율: 해당 없음
계산값: 지정된 키워드
정식 순서: 문법 순서
애니메이션 유형: 불연속

flex-direction 속성은 플렉스 컨테이너의 주 축 방향을 설정하여, 플렉스 아이템이 컨테이너에 어떻게 배치될지 지정합니다. 이 속성이 플렉스 아이템의 배치 방향을 결정합니다.

row
플렉스 컨테이너의 주 축이 현재 쓰기 모드의 인라인 축과 동일한 방향입니다. main-start와 main-end 방향은 각각 현재 쓰기 모드의 inline-start와 inline-end와 같습니다.
row-reverse
row와 동일하지만, main-start와 main-end 방향이 서로 뒤바뀝니다.
column
플렉스 컨테이너의 주 축이 현재 쓰기 모드의 블록 축과 동일한 방향입니다. main-start와 main-end 방향은 각각 현재 쓰기 모드의 block-start와 block-end와 같습니다.
column-reverse
column과 동일하지만, main-start와 main-end 방향이 서로 뒤바뀝니다.

참고: reverse 값은 박스의 순서를 뒤집지 않습니다. writing-mode와 direction [CSS3-WRITING-MODES]처럼, 흐름의 방향만 바꿉니다. 페인팅 순서, 음성 순서, 순차적 네비게이션 순서는 영향을 받지 않습니다.

5.2. 플렉스 라인 래핑: flex-wrap 속성

이름: flex-wrap
값: nowrap | wrap | wrap-reverse
초기값: nowrap
적용 대상: 플렉스 컨테이너
상속: 아니오
백분율: 해당 없음
계산값: 지정된 키워드
정식 순서: 문법 순서
애니메이션 유형: 불연속

flex-wrap 속성은 플렉스 컨테이너가 단일 라인인지 다중 라인인지, 그리고 교차축의 방향을 제어합니다. 이 축이 새로운 라인이 쌓이는 방향을 결정합니다.

nowrap
플렉스 컨테이너는 단일 라인입니다.
wrap
플렉스 컨테이너는 다중 라인입니다.
wrap-reverse
wrap과 동일합니다.

wrap-reverse가 아닌 값에 대해, cross-start 방향은 현재 쓰기 모드의 inline-start 또는 block-start 방향과 같으며 (어느 것이 교차축에 해당하는지에 따라 결정됨) cross-end 방향은 cross-start의 반대 방향입니다. flex-wrap이 wrap-reverse일 때는, cross-start와 cross-end 방향이 뒤바뀝니다.

5.3. 플렉스 방향 및 래핑: flex-flow 단축 속성

이름: flex-flow
값: <‘flex-direction’> || <‘flex-wrap’>
초기값: 각 개별 속성 참조
적용 대상: 각 개별 속성 참조
상속: 각 개별 속성 참조
백분율: 각 개별 속성 참조
계산값: 각 개별 속성 참조
애니메이션 유형: 각 개별 속성 참조
정식 순서: 문법 순서

flex-flow 속성은 flex-direction과 flex-wrap 속성을 한 번에 설정할 수 있는 단축 속성입니다. 두 속성은 플렉스 컨테이너의 주 축과 교차 축을 함께 정의합니다.

영어(좌→우, 수평쓰기 모드) 문서에서 올바른 flow 예시: 
div { flex-flow: row; }
/* 초기값. 주축은 인라인, 래핑 없음.
   (아이템은 줄어들거나 넘침) */

div { flex-flow: column wrap; }
/* 주축은 블록 방향(위→아래)
   줄은 인라인 방향(오른쪽)으로 래핑됨. */

div { flex-flow: row-reverse wrap-reverse; }
/* 주축은 인라인 방향의 반대(오른→왼).
   새 줄은 위쪽으로 래핑됨. */
flex-flow 방향은 쓰기 모드에 민감함에 유의하세요. 예를 들어, 일본어 세로쓰기에서는 row 플렉스 컨테이너가 위에서 아래로 콘텐츠를 배치합니다. 다음 예시 참고:
영어 일본어 
flex-flow: row wrap;        
writing-mode: horizontal-tb;
 
flex-flow: row wrap;        
writing-mode: vertical-rl;

5.4. 표시 순서: order 속성

플렉스 아이템은 기본적으로 소스 문서에 나타나는 순서대로 표시·배치됩니다. order 속성을 사용하여 이 순서를 변경할 수 있습니다.

이름: order
값: <integer>
초기값: 0
적용 대상: 플렉스 아이템
상속: 아니오
백분율: 해당 없음
계산값: 지정된 정수
정식 순서: 문법 순서
애니메이션 유형: 계산값 유형 기반

order 속성은 플렉스 아이템에 순서 그룹을 지정함으로써 플렉스 컨테이너 내에서 나타나는 순서를 제어합니다. 하나의 <integer> 값만 사용하며, 해당 플렉스 아이템이 속한 순서 그룹을 지정합니다.

플렉스 컨테이너는 order로 변경된 문서 순서로 콘텐츠를 배치하며, 가장 낮은 순서 그룹부터 시작해서 올라갑니다. 같은 그룹의 아이템은 소스 문서에 등장하는 순서대로 배치됩니다. 이는 페인팅 순서에도 영향을 주며 [CSS21], 마치 소스 문서에서 아이템 순서를 변경한 것과 동일하게 동작합니다. 플렉스 컨테이너의 절대 위치 자식은 order: 0으로 간주되어 플렉스 아이템과의 페인팅 순서가 결정됩니다.

아래 그림은 탭 인터페이스의 예시로, 활성 탭이 항상 첫 번째에 위치합니다:

CSS 예시(관련 코드만 표시):

.tabs {
  display: flex;
}
.tabs > .current {
  order: -1; /* 기본값 0보다 낮음 */
}

향후 명세에서 달리 지정하지 않는 한, 이 속성은 플렉스 아이템이 아닌 박스에는 아무런 효과가 없습니다.

5.4.1. 순서 변경과 접근성

order 속성은 비시각적 미디어(예: 음성)의 순서에는 영향을 주지 않습니다. 마찬가지로 order는 순차적 네비게이션 모드(예: 링크 순서 순환, tabindex [HTML] 참조)의 기본 탐색 순서에도 영향을 주지 않습니다.

저자는 반드시 order를 논리적 순서 변경이 아닌, 시각적 순서 변경에만 사용해야 합니다. order로 논리적 순서를 변경하는 스타일시트는 비준수입니다.

참고: 비시각적 미디어와 비CSS UA는 일반적으로 콘텐츠를 선형으로 표시하므로, 논리적 소스 순서에 의존할 수 있습니다. order는 시각적 순서 조정에만 사용합니다. (시각적 인식은 2차원·비선형이므로, 원하는 시각적 순서가 항상 논리적 순서와 같지는 않습니다.)

많은 웹페이지의 마크업은 비슷한 형태를 가지고 있습니다. 상단에 헤더, 하단에 푸터, 그리고 가운데에는 콘텐츠 영역과 한두 개의 추가 컬럼이 있습니다. 일반적으로, 콘텐츠가 추가 컬럼보다 먼저 소스 코드에 오는 것이 바람직합니다. 그러나 이렇게 하면, 추가 컬럼을 왼쪽에, 콘텐츠를 오른쪽에 두고 싶은 일반적인 디자인이 구현하기 어려워집니다. 이 문제는 다양한 방법으로 해결되어 왔으며, 추가 컬럼이 두 개일 때 "Holy Grail Layout"이라는 이름으로 불리기도 했습니다. order 속성으로 이 문제는 아주 쉽게 해결됩니다. 예를 들어, 페이지 코드와 원하는 레이아웃의 스케치: 
<!DOCTYPE html>
<header>...</header>
<main>
   <article>...</article>
   <nav>...</nav>
   <aside>...</aside>
</main>
<footer>...</footer>

이 레이아웃은 플렉스 레이아웃으로 쉽게 구현할 수 있습니다:

main { display: flex; }
main > article { order: 2; min-width: 12em; flex:1; }
main > nav     { order: 1; width: 200px; }
main > aside   { order: 3; width: 200px; }

추가로, 컬럼은 기본적으로 동일 높이가 되고, 메인 콘텐츠는 화면을 채우기 위해 필요한 만큼 넓어집니다. 또한, 미디어 쿼리를 활용하면 좁은 화면에서 수직 레이아웃으로 쉽게 전환할 수 있습니다:

@media all and (max-width: 600px) {
  /* 3열을 지원하기엔 너무 좁음 */
  main { flex-flow: column; }
  main > article, main > nav, main > aside {
    /* 문서 순서로 복귀 */
    order: 0; width: auto;
  }
}

(다중 라인 플렉스 컨테이너를 더 활용해 더 지능적으로 래핑하는 방법은 독자의 연습으로 남깁니다.)

모든 프레젠테이션 모드에서 저자의 의도한 순서를 유지하려면, 저작 도구(예: WYSIWYG 에디터, 웹 기반 저작 보조 도구)들은 기본 문서 소스를 재정렬해야 하며 order 속성으로 재정렬을 수행해서는 안 됩니다. 단, 저자가 명시적으로 기본 문서 순서(음성·네비게이션 순서 결정)를 시각적 순서와 불일치하도록 지정한 경우는 예외입니다.

예를 들어, 툴이 플렉스 아이템을 드래그 앤 드롭으로 재배치하거나, 각 화면 크기별 대체 레이아웃에 미디어 쿼리를 활용할 수 있습니다.

대부분의 경우, 재배치는 모든 화면 크기뿐 아니라 네비게이션 및 음성 순서에도 영향을 주어야 하므로, 드래그 앤 드롭 재배치는 DOM 레이어에서 수행해야 합니다. 그러나 저자가 화면 크기별로 서로 다른 시각적 순서를 원할 수도 있습니다. 이 경우 툴은 order와 미디어 쿼리를 함께 사용해 화면 크기별 시각적 순서를 제공할 수 있지만, 가장 작은 화면 크기에서는 DOM 순서(논리적·선형 프레젠테이션 순서일 가능성이 높음)에 맞추고, 다른 크기에서는 order로 시각적 순서를 결정할 수 있습니다.

이런 툴은 준수하지만, order만으로 드래그 앤 드롭 재배치를 처리하는 툴은(편하더라도) 비준수입니다.

참고: 사용자 에이전트(브라우저, 접근성 기술, 확장 기능 등)는 공간 네비게이션 기능을 제공할 수 있습니다. 이 섹션은 order 속성을 그런 공간 네비게이션 모드에서 요소 순서를 결정할 때 고려하지 않아야 한다는 뜻이 아닙니다; 오히려 그런 기능이 제대로 동작하려면 반드시 고려되어야 합니다. 그러나 order는 그런 공간 네비게이션을 위한 유일(혹은 주요) CSS 속성은 아니며, 공간 관계를 변경하는 CSS의 모든 레이아웃 기능을 고려해야 합니다.

6. 플렉스 라인

플렉스 아이템은 플렉스 컨테이너 내에서 레이아웃되고 정렬됩니다. 플렉스 라인은 레이아웃 알고리즘이 그룹화 및 정렬을 위해 사용하는 가상의 컨테이너입니다. 플렉스 컨테이너는 단일 라인 또는 다중 라인이 될 수 있으며, 이는 flex-wrap 속성에 따라 결정됩니다:

  • 단일 라인 플렉스 컨테이너(즉, flex-wrap: nowrap인 경우)은 모든 자식을 한 줄에 배치하며, 내용이 넘치더라도 한 줄로 유지됩니다.

  • 다중 라인 플렉스 컨테이너(즉, flex-wrap: wrap 또는 flex-wrap: wrap-reverse인 경우)은 플렉스 아이템을 여러 줄에 걸쳐 배치합니다. 이는 텍스트가 너무 넓어 기존 줄에 맞지 않으면 새 줄로 넘어가는 방식과 유사합니다. 추가 줄이 생성되면, 교차 축을 따라 flex-wrap 속성에 따라 플렉스 컨테이너 내에서 쌓입니다. 각 라인에는 최소 하나의 플렉스 아이템이 포함되며, 플렉스 컨테이너 자체가 완전히 비어 있지 않은 한 항상 그렇습니다.

이 예시는 네 개의 버튼이 가로로 한 줄에 다 들어가지 못해, 여러 줄로 래핑되는 모습을 보여줍니다. 
#flex {
  display: flex;
  flex-flow: row wrap;
  width: 300px;
}
.item {
  width: 80px;
}

<div id="flex">
  <div class="item">1</div>
  <div class="item">2</div>
  <div class="item">3</div>
  <div class="item">4</div>
</div>

컨테이너가 300px 너비이므로, 한 줄에는 세 개만 들어갈 수 있습니다. 세 아이템이 240px을 차지하고, 60px의 공간이 남습니다. flex-flow 속성에 다중 라인 플렉스 컨테이너 (wrap 키워드가 값에 포함됨)이 지정되어 있으므로, 마지막 아이템을 담기 위해 추가 줄이 만들어집니다.

내용이 줄로 나뉜 후, 각 줄은 독립적으로 레이아웃됩니다; flexible 길이와 justify-content, align-self 속성은 한 번에 한 줄의 아이템만 고려합니다.

다중 라인 플렉스 컨테이너(줄이 하나뿐이어도)의 경우, 각 줄의 교차 크기는 해당 줄의 플렉스 아이템을 모두 담기 위한 최소 크기입니다 (align-self로 정렬한 후). 줄들은 align-content 속성으로 컨테이너 내에서 정렬됩니다. 단일 라인 플렉스 컨테이너에서는, 줄의 교차 크기가 플렉스 컨테이너의 교차 크기와 같으며, align-content는 효과가 없습니다. 줄의 주 크기는 항상 플렉스 컨테이너의 콘텐츠 박스 주 크기와 같습니다.

이전 예와 동일한 예시입니다. 단, 플렉스 아이템 모두에 flex: auto가 지정되어 있습니다. 첫 번째 줄에 60px의 남는 공간이 있고, 모든 아이템의 유연성이 같으므로, 해당 줄의 세 아이템 각각에 20px씩 추가 너비가 할당되어, 각 아이템은 100px 너비가 됩니다. 나머지 아이템은 자기 줄에 있으므로 줄 전체 너비인 300px로 확장됩니다.

7. 유연성

플렉스 레이아웃의 핵심 특징은 플렉스 아이템을 “flex”하게 만들어, 주 차원에서 사용 가능한 공간을 채우도록 너비/높이를 변경할 수 있다는 점입니다. 이는 flex 속성으로 구현됩니다. 플렉스 컨테이너는 아이템의 flex grow factor에 비례하여 남는 공간을 아이템에 분배하고, flex shrink factor에 비례하여 넘침을 방지하기 위해 아이템을 축소합니다.

플렉스 아이템의 flex-grow와 flex-shrink 값이 모두 0이면 완전히 유연하지 않음이고, 그렇지 않으면 유연함입니다.

7.1. flex 단축 속성

이름: flex
값: none | [ <‘flex-grow’> <‘flex-shrink’>? || <‘flex-basis’> ]
초기값: 0 1 auto
적용 대상: 플렉스 아이템
상속: 아니오
백분율: 각 개별 속성 참조
계산값: 각 개별 속성 참조
애니메이션 유형: 계산값 유형 기반
정식 순서: 문법 순서

flex 속성은 유연 길이의 구성 요소를 지정합니다: flex 팩터 (grow와 shrink) 그리고 flex 기준값입니다. 박스가 플렉스 아이템일 때는 flex가 주 크기 속성 대신 박스의 주 크기를 결정하는 데 사용됩니다. 박스가 플렉스 아이템이 아니면 flex는 효과가 없습니다.

<‘flex-grow’>
이 <number> 구성 요소는 flex-grow longhand를 설정하며, flex grow 팩터를 지정합니다. 이는 컨테이너에서 양의 남는 공간이 분배될 때 플렉스 아이템이 컨테이너 내 다른 플렉스 아이템에 비해 얼마나 성장할지 결정합니다. 생략 시 1로 설정됩니다.
Flex 값이 0과 1 사이일 때는 특이한 동작이 있습니다: 라인 내 flex 값의 합이 1보다 작으면, 100% 미만의 남는 공간만 차지합니다.

아이템의 flex-grow 값은 남는 공간의 비율을 요청하는 효과가 있으며, 1은 "남는 공간의 100%"를 의미합니다; 라인 내 아이템들이 총 100% 이상을 요청하면 요청 비율을 유지하면서 남는 공간을 정확히 100%만큼 사용하도록 재조정됩니다. 반대로 아이템들이 전체 공간보다 적게 요청하면 (예: 각각 flex-grow: .25인 3개 아이템) 요청한 만큼만 받고 (각각 남는 공간의 25%씩, 남은 25%는 채워지지 않음), §9.7 Flexible Lengths 해석에서 남는 공간 분배의 정확한 규칙을 참고하세요.

이 패턴은 flex-grow가 0에 가까워질 때 (즉, 아이템이 남는 공간을 원하지 않을 때) 연속적인 동작을 위해 필요합니다. 그렇지 않으면 flex-grow: 1 아이템이 모든 남는 공간을 차지하고, flex-grow: 0.1 아이템도, flex-grow: 0.01 아이템도 동일하게 동작하다가, 값이 충분히 작아져 0이 되면 그때서야 남는 공간을 전혀 차지하지 않게 됩니다. 이 동작에서는 대신 flex-grow가 1 이하로 줄어들수록 점점 남는 공간을 덜 차지하게 되어, 0에서는 완전히 남는 공간을 차지하지 않는 쪽으로 부드럽게 변화합니다.

이 “부분 채우기” 동작이 특별히 필요한 게 아니라면, 저자는 1 이상 값을 사용할 것을 권장합니다; 예를 들어 1과 2를 쓰는 것이 .33과 .67보다 더 바람직하며, 아이템을 추가, 제거, 라인 래핑해도 의도대로 동작할 가능성이 높습니다.

<‘flex-shrink’>
이 <number> 구성 요소는 flex-shrink longhand를 지정하며, flex shrink 팩터를 지정합니다. 이는 음의 남는 공간이 분배될 때 플렉스 아이템이 컨테이너 내 다른 플렉스 아이템에 비해 얼마나 축소될지 결정합니다. 생략 시 1로 설정됩니다.

참고: flex shrink 팩터는 음의 공간 분배 시 flex 기준 크기에 곱해집니다. 이는 아이템이 얼마나 축소될 수 있는지 비례하여 음의 공간을 분배하므로, 예를 들어 작은 아이템이 큰 아이템보다 먼저 0이 되지 않도록 합니다.

<‘flex-basis’>
이 구성 요소는 flex-basis longhand를 지정하며, flex 기준값을 지정합니다: 플렉스 아이템의 주 크기의 초기값이며, flex 팩터에 따라 남는 공간이 분배되기 전의 값입니다.

<‘flex-basis’>는 width 및 height 속성과 동일한 값을 허용합니다 (단, auto는 다르게 처리됨) 그리고 content 키워드를 추가로 허용합니다:

auto
플렉스 아이템에 지정되면, auto 키워드는 주 크기 속성의 값을 flex-basis의 사용값으로 가져옵니다. 해당 값이 auto일 경우, 사용값은 content가 됩니다.
content
자동 크기를 플렉스 아이템의 콘텐츠에 따라 결정합니다. (일반적으로 max-content 크기와 동일하지만, 종횡비, 고유 크기 제약, 직교 흐름 등을 처리하기 위한 조정이 있습니다; §9 Flex Layout Algorithm의 세부 사항 참고.)

참고: 이 값은 Flexible Box Layout의 초기 버전에는 없었으므로, 일부 오래된 구현에서는 지원되지 않을 수 있습니다. 동일한 효과는 auto와 width 또는 height를 auto로 지정하여 사용할 수 있습니다.

<‘width’>
기타 모든 값에 대해 flex-basis는 width 및 height와 동일하게 해석됩니다.

flex 단축 속성에서 생략 시, 지정값은 0입니다.

none
none 키워드는 0 0 auto로 확장됩니다.

flex 구성요소의 초기값은 flex: 0 1 auto와 동일합니다.

참고: flex-grow와 flex-basis의 초기값은 flex 단축 속성에서 생략 시의 기본값과 다릅니다. 이는 flex 단축 속성이 일반적인 경우를 더 잘 처리하도록 하기 위함입니다.

단위 없는 0이 flex 팩터 두 개 앞에 오지 않으면 flex 팩터로 해석해야 합니다. 잘못 해석되거나 유효하지 않은 선언을 방지하려면, 저자는 0 <‘flex-basis’> 구성 요소를 단위와 함께 지정하거나 flex 팩터 두 개 앞에 두어야 합니다.

7.1.1. flex의 기본 값

이 섹션은 참고용입니다.

아래 목록은 가장 일반적으로 원하는 효과를 나타내는 네 가지 flex 값의 효과를 요약합니다:

flex: initial
flex: 0 1 auto와 동일합니다. (초기값입니다.) 아이템의 크기는 width/height 속성을 기준으로 합니다. (아이템의 main size property가 auto로 계산되면, 해당 flex 아이템은 콘텐츠 기반으로 크기가 결정됩니다.) 양의 남는 공간이 있을 때는 아이템이 유연하지 않고, 공간이 부족할 때는 최소 크기까지 축소됩니다. 정렬 기능이나 auto 마진을 사용해 주 축 기준으로 플렉스 아이템을 정렬할 수 있습니다.
flex: auto
flex: 1 1 auto와 동일합니다. 아이템의 크기는 width/height 속성을 기준으로 하지만, 완전히 유연하게 되어 주 축에서 남는 공간을 모두 흡수합니다. 모든 아이템이 flex: auto, flex: initial, 또는 flex: none일 경우, 아이템 크기 지정 후 양의 남는 공간이 있으면 flex: auto인 아이템에 균등 분배됩니다.
flex: none
flex: 0 0 auto와 동일합니다. 이 값은 width/height 속성에 따라 아이템 크기를 지정하지만, 완전히 유연하지 않은 플렉스 아이템이 됩니다. initial과 거의 같으나, 플렉스 아이템이 넘침 상황에서도 축소되지 않습니다.
flex: <positive-number>
flex: <positive-number> 1 0과 동일합니다. 플렉스 아이템을 유연하게 만들고 flex 기준값을 0으로 설정해, 아이템이 플렉스 컨테이너의 남는 공간을 지정한 비율대로 차지하게 됩니다. 컨테이너 내 모든 아이템이 이 패턴을 사용하면, 아이템 크기가 flex 팩터에 비례하게 됩니다.

기본적으로, 플렉스 아이템은 최소 콘텐츠 크기(가장 긴 단어나 고정 크기 요소 길이)보다 작아지지 않습니다. 이를 바꾸려면 min-width 또는 min-height 속성을 설정하세요. (§4.5 플렉스 아이템의 자동 최소 크기 참고)

flex-grow 속성은 flex grow 팩터를 <number>로 설정합니다. 음수 값은 유효하지 않습니다.

7.2.2. flex-shrink 속성

이름: flex-shrink
값: <number>
초기값: 1
적용 대상: 플렉스 아이템
상속: 아니오
백분율: 해당 없음
계산값: 지정값
정식 순서: 문법 순서
애니메이션 유형: 숫자

저자는 flex 단축 속성으로 유연성을 제어할 것을 권장합니다. 단축 속성은 flex-shrink를 직접 지정하는 것보다, 지정되지 않은 구성 요소를 일반적인 사용에 맞게 올바르게 초기화합니다.

flex-shrink 속성은 flex shrink 팩터를 <number>로 설정합니다. 음수 값은 유효하지 않습니다.

7.2.3. flex-basis 속성

이름: flex-basis
값: content | <‘width’>
초기값: auto
적용 대상: 플렉스 아이템
상속: 아니오
백분율: 플렉스 컨테이너의 내부 주 크기 기준
계산값: 지정된 키워드 또는 계산된 <length-percentage> 값
정식 순서: 문법 순서
애니메이션 유형: 계산값 유형 기반

저자는 flex 단축 속성으로 유연성을 제어할 것을 권장합니다. 단축 속성은 flex-basis를 직접 지정하는 것보다, 지정되지 않은 구성 요소를 일반적인 사용에 맞게 올바르게 초기화합니다.

flex-basis 속성은 flex 기준값을 지정합니다. width와 height 속성과 동일한 값, 그리고 content 값을 허용합니다.

auto와 content(위에서 정의됨) 이외의 모든 값에 대해, flex-basis는 수평 쓰기 모드에서 width와 동일하게 해석됩니다 [CSS21], 단 값이 width에서 auto로 해석될 경우, flex-basis에서는 content로 해석됩니다. 예를 들어, flex-basis의 백분율 값은 플렉스 아이템의 포함 블록(즉, 플렉스 컨테이너)을 기준으로 해석되고, 그 포함 블록의 크기가 비확정적이면, flex-basis의 사용값은 content가 됩니다. 또 하나의 결과로, flex-basis는 별도 지정이 없는 한 콘텐츠 박스의 크기를 결정합니다. 단, box-sizing [CSS3UI] 등으로 지정된 경우는 예외입니다.

8. 정렬

플렉스 컨테이너의 내용이 flexing을 마치고 모든 플렉스 아이템의 크기가 확정되면, 이제 플렉스 컨테이너 내에서 정렬할 수 있습니다.

margin 속성은 블록 레이아웃의 margin보다 더 강력하게 아이템을 정렬하는 데 사용될 수 있습니다. 플렉스 아이템은 CSS Box Alignment의 정렬 속성도 지원하며, 이를 통해 주 축과 교차 축 모두에서 키워드 기반으로 손쉽게 정렬할 수 있습니다. 이 속성들은 CSS 2.1에서 매우 어려웠던 수평 및 수직 가운데 정렬 등 다양한 정렬을 간단하게 구현할 수 있게 해줍니다.

참고: 정렬 속성은 CSS Box Alignment [CSS-ALIGN-3]에서 정의되었으나, Flexible Box Layout은 관련 정의를 이곳에 재현하여 명세 진행을 지연시킬 수 있는 규범적 의존성을 만들지 않도록 했습니다. 이 속성들은 플렉스 레이아웃에만 적용되며, CSS Box Alignment Level 3가 완성된 후 다른 레이아웃 모드에 대한 효과를 정의할 때까지 한정됩니다. Box Alignment 모듈에서 새로 정의된 값들도 Flexible Box Layout에 적용되며, 즉, Box Alignment 모듈이 완성되면 여기 정의를 대체하게 됩니다.

8.1. auto 마진으로 정렬

이 섹션은 비규범적입니다. 마진이 플렉스 아이템에 미치는 규범적 정의는 플렉스 레이아웃 알고리즘 섹션을 참고하세요.

플렉스 아이템의 auto 마진은 블록 흐름에서의 auto 마진과 매우 유사한 효과를 냅니다:

  • 플렉스 기준값과 유연 길이 계산 중에는 auto 마진이 0으로 처리됩니다.

  • justify-content 및 align-self로 정렬하기 전에, 해당 차원의 양의 남는 공간이 auto 마진에 분배됩니다.

  • 넘치는 박스는 auto 마진을 무시하고 끝 방향으로 넘칩니다.

참고: 남는 공간이 auto 마진에 분배되면, 정렬 속성은 해당 차원에서 아무 효과가 없습니다. 이는 flexing 이후 남은 모든 공간을 마진이 가져가기 때문입니다.

주 축에서 auto 마진의 한 가지 활용은 플렉스 아이템을 별도 "그룹"으로 분리하는 것입니다. 아래 예시는 흔한 UI 패턴, 왼쪽에 일부, 오른쪽에 일부 정렬된 액션 바를 재현하는 방법을 보여줍니다. 
nav > ul {
  display: flex;
}
nav > ul > #login {
  margin-left: auto;
}

<nav>
  <ul>
    <li><a href=/about>About</a>
    <li><a href=/projects>Projects</a>
    <li><a href=/interact>Interact</a>
    <li id="login"><a href=/login>Login</a>
  </ul>
</nav>
아래 그림은 넘침 상황에서 auto 마진과 정렬 속성의 교차축 정렬 차이를 보여줍니다.

8.2. 축 정렬: justify-content 속성

이름: justify-content
값: flex-start | flex-end | center | space-between | space-around
초기값: flex-start
적용 대상: 플렉스 컨테이너
상속: 아니오
백분율: 해당 없음
계산값: 지정된 키워드
정식 순서: 문법 순서
애니메이션 유형: 불연속

justify-content 속성은 플렉스 컨테이너의 현재 줄 주 축을 따라 플렉스 아이템을 정렬합니다. 이는 모든 유연 길이와 auto 마진이 해결된 이후에 적용됩니다. 보통 모든 플렉스 아이템이 유연하지 않거나, 유연하지만 최대 크기에 도달한 경우 남은 여분의 공간을 분배하는 데 사용됩니다. 넘침이 있을 때 아이템의 정렬에도 일부 제어를 가합니다.

flex-start
플렉스 아이템들이 줄의 시작 방향으로 모입니다. 줄의 첫 플렉스 아이템의 main-start 마진 엣지가 줄의 main-start 엣지에 딱 맞게 배치되고, 그 다음 아이템들은 바로 앞 아이템에 딱 붙어서 배치됩니다.
flex-end
플렉스 아이템들이 줄의 끝 방향으로 모입니다. 줄의 마지막 플렉스 아이템의 main-end 마진 엣지가 줄의 main-end 엣지에 딱 맞게 배치되고, 그 이전 아이템들은 바로 다음 아이템에 딱 붙어서 배치됩니다.
center
플렉스 아이템들이 줄의 가운데로 모입니다. 줄의 플렉스 아이템들은 서로 맞닿아 배치되고 줄의 가운데에 정렬됩니다. 남는 공간은 줄의 main-start 엣지와 첫 아이템 사이, 그리고 main-end 엣지와 마지막 아이템 사이에 동일하게 분배됩니다. (여분 공간이 음수면, 플렉스 아이템들이 양쪽으로 똑같이 넘칩니다.)
space-between
플렉스 아이템들이 줄에서 고르게 분배됩니다. 여분 공간이 음수이거나, 줄에 플렉스 아이템이 한 개뿐이면, 이 값은 flex-start와 동일합니다. 그렇지 않으면, 줄의 첫 플렉스 아이템의 main-start 마진 엣지가 줄의 main-start 엣지에 딱 맞게 배치되고, 마지막 플렉스 아이템의 main-end 마진 엣지가 줄의 main-end 엣지에 딱 맞게 배치되며, 나머지 플렉스 아이템들은 인접한 아이템 사이의 간격이 모두 동일하도록 분배됩니다.
space-around
플렉스 아이템들이 줄에서 고르게 분배되며, 양쪽 끝에는 절반 크기의 여백이 들어갑니다. 여분 공간이 음수이거나, 줄에 플렉스 아이템이 한 개뿐이면, 이 값은 center와 동일합니다. 그렇지 않으면, 줄의 플렉스 아이템들은 인접한 플렉스 아이템 사이 간격이 모두 동일하고, 첫/마지막 플렉스 아이템과 플렉스 컨테이너 엣지 사이의 간격은 아이템 사이의 간격의 절반 크기입니다.

플렉스 컨테이너에 세 개의 색상 아이템이 있을 때 justify-content 키워드 5가지의 효과를 보여주는 그림입니다.

8.3. 교차축 정렬: align-items 및 align-self 속성

이름: align-items
값: flex-start | flex-end | center | baseline | stretch
초기값: stretch
적용 대상: 플렉스 컨테이너
상속: 아니오
백분율: 해당 없음
계산값: 지정된 키워드
정식 순서: 문법 순서
애니메이션 유형: 불연속
이름: align-self
값: auto | flex-start | flex-end | center | baseline | stretch
초기값: auto
적용 대상: 플렉스 아이템
상속: 아니오
백분율: 해당 없음
계산값: 지정된 키워드
정식 순서: 문법 순서
애니메이션 유형: 불연속

플렉스 아이템은 플렉스 컨테이너의 현재 줄 교차 축에서 정렬할 수 있습니다. 이는 justify-content와 유사하지만 수직 방향입니다. align-items는 해당 플렉스 컨테이너의 모든 아이템의 기본 정렬을 지정합니다. 익명 플렉스 아이템도 포함합니다. align-self는 개별 플렉스 아이템의 기본 정렬을 덮어쓸 수 있습니다. (익명 플렉스 아이템의 경우 align-self는 항상 연관된 플렉스 컨테이너의 align-items 값과 일치합니다.)

플렉스 아이템의 교차축 마진 중 하나라도 auto라면, align-self 속성은 효과가 없습니다.

값의 의미는 다음과 같습니다:

auto
교차축 정렬 제어를 부모 박스의 align-items 값에 위임합니다. (align-self의 초기값입니다.)
flex-start
플렉스 아이템의 cross-start 마진 엣지가 줄의 cross-start 엣지에 딱 맞게 배치됩니다.
flex-end
플렉스 아이템의 cross-end 마진 엣지가 줄의 cross-end 엣지에 딱 맞게 배치됩니다.
center
플렉스 아이템의 마진 박스가 줄의 교차축 가운데에 정렬됩니다. (플렉스 라인의 교차 크기가 아이템의 크기보다 작으면, 아이템이 양쪽으로 똑같이 넘칩니다.)
baseline
플렉스 아이템이 기준선 정렬에 참여합니다: 줄의 모든 참여 플렉스 아이템이 기준선이 맞춰지고, 기준선과 cross-start 마진 엣지 사이 거리가 가장 큰 아이템이 줄의 cross-start 엣지에 딱 맞게 배치됩니다. 필요한 축에 기준선이 없다면, 아이템의 border box에서 기준선이 합성됩니다.
stretch
플렉스 아이템의 교차 크기 속성이 auto로 계산되고, 교차축 마진이 auto가 아니면, 해당 플렉스 아이템은 늘어남 상태가 됩니다. 사용값은 아이템의 마진 박스와 줄의 교차 크기를 최대한 맞추는 데 필요한 길이입니다. 단, min-height/min-width/max-height/max-width 제약을 존중합니다.

참고: 플렉스 컨테이너의 높이가 제한된 경우, 이 값으로 인해 플렉스 아이템의 내용이 넘칠 수 있습니다.

플렉스 아이템의 cross-start 마진 엣지가 줄의 cross-start 엣지에 딱 맞게 배치됩니다.

네 개의 색상 아이템이 있는 플렉스 컨테이너에서 align-items 키워드 5가지의 효과를 보여주는 그림입니다.

8.4. 플렉스 라인 정렬: align-content 속성

이름: align-content
값: flex-start | flex-end | center | space-between | space-around | stretch
초기값: stretch
적용 대상: 다중 라인 플렉스 컨테이너
상속: 아니오
백분율: 해당 없음
계산값: 지정된 키워드
정식 순서: 문법 순서
애니메이션 유형: 불연속

align-content 속성은 플렉스 컨테이너의 라인을 플렉스 컨테이너 내에서 정렬합니다. 교차축에 남는 공간이 있을 때 적용되며, justify-content가 개별 아이템을 주 축에서 정렬하는 것과 유사합니다. 이 속성은 단일 라인 플렉스 컨테이너에는 효과가 없습니다. 값의 의미는 다음과 같습니다:

flex-start
라인이 플렉스 컨테이너의 시작 방향으로 모입니다. 플렉스 컨테이너의 첫 줄 cross-start 엣지가 플렉스 컨테이너의 cross-start 엣지에 딱 맞게 배치되고, 다음 줄들은 바로 앞 줄에 딱 붙어서 배치됩니다.
flex-end
라인이 플렉스 컨테이너의 끝 방향으로 모입니다. 플렉스 컨테이너의 마지막 줄 cross-end 엣지가 플렉스 컨테이너의 cross-end 엣지에 딱 맞게 배치되고, 이전 줄들은 바로 다음 줄에 딱 붙어서 배치됩니다.
center
라인이 플렉스 컨테이너의 가운데로 모입니다. 플렉스 컨테이너의 줄들은 서로 맞닿아 가운데에 정렬됩니다. 남는 공간은 플렉스 컨테이너의 cross-start 콘텐츠 엣지와 첫 줄 사이, 그리고 cross-end 콘텐츠 엣지와 마지막 줄 사이에 동일하게 분배됩니다. (여분 공간이 음수면, 줄들이 양쪽으로 똑같이 넘칩니다.)
space-between
라인이 플렉스 컨테이너에서 고르게 분배됩니다. 여분 공간이 음수이거나, 플렉스 컨테이너에 플렉스 라인이 한 개뿐이면, 이 값은 flex-start와 동일합니다. 그렇지 않으면, 첫 줄 cross-start 엣지가 플렉스 컨테이너의 cross-start 콘텐츠 엣지에 딱 맞게 배치되고, 마지막 줄 cross-end 엣지가 플렉스 컨테이너의 cross-end 콘텐츠 엣지에 딱 맞게 배치되고, 나머지 줄들은 인접한 줄 사이 간격이 모두 동일하도록 분배됩니다.
space-around
라인이 플렉스 컨테이너에서 고르게 분배되고, 양쪽 끝에는 절반 크기의 여백이 들어갑니다. 여분 공간이 음수면, 이 값은 center와 동일합니다. 그렇지 않으면, 플렉스 컨테이너의 줄들은 인접한 줄 사이 간격이 모두 동일하고, 첫/마지막 줄과 플렉스 컨테이너 엣지 사이의 간격은 줄 사이 간격의 절반 크기입니다.
stretch
줄이 남는 공간을 모두 차지하도록 늘어납니다. 여분 공간이 음수면, 이 값은 flex-start와 동일합니다. 그렇지 않으면, 남는 공간이 모든 줄에 동일하게 분배되어 교차 크기가 커집니다.

참고: 다중 라인 플렉스 컨테이너만이 교차축에 라인을 정렬할 여분 공간을 가지며, 단일 라인 플렉스 컨테이너에서는 유일한 줄이 자동으로 공간을 채웁니다.

align-content 키워드와 다중 라인 플렉스 컨테이너에서의 효과를 보여주는 그림입니다.

8.5. 플렉스 컨테이너 기준선

플렉스 컨테이너 자체가 기준선 정렬에 참여하려면 (예: 플렉스 컨테이너가 외부 플렉스 컨테이너의 플렉스 아이템인 경우), 콘텐츠를 가장 잘 대표할 기준선 위치를 제출해야 합니다. 이를 위해 플렉스 컨테이너의 기준선은 다음과 같이 결정됩니다 (order로 재정렬한 후, flex-direction을 고려함):

first/last 주축 기준선 집합
인라인 축이 플렉스 컨테이너의 주 축과 일치할 때, 기준선은 다음과 같이 결정됩니다:

  1. 플렉스 컨테이너의 시작/끝 플렉스 라인에 있는 플렉스 아이템 중 기준선 정렬에 참여하는 것이 있으면, 플렉스 컨테이너의 첫/마지막 주축 기준선 집합은 해당 정렬 기준선에서 생성됩니다.

  2. 그렇지 않고, 플렉스 컨테이너에 플렉스 아이템이 하나 이상 있으면, 플렉스 컨테이너의 첫/마지막 주축 기준선 집합은 시작/끝 플렉스 아이템의 정렬 기준선에서 생성됩니다. (해당 아이템이 플렉스 컨테이너의 주 축과 평행한 정렬 기준선이 없으면, 먼저 border edge에서 합성됩니다.)

  3. 그 밖의 경우, 플렉스 컨테이너는 첫/마지막 주축 기준선 집합이 없으며, 필요하다면 합성됩니다. 이는 정렬 컨텍스트의 규칙에 따릅니다.

first/last 교차축 기준선 집합
인라인 축이 플렉스 컨테이너의 교차 축과 일치할 때, 기준선은 다음과 같이 결정됩니다:

  1. 플렉스 컨테이너에 플렉스 아이템이 하나 이상 있으면, 플렉스 컨테이너의 첫/마지막 교차축 기준선 집합은 시작/끝 플렉스 아이템의 정렬 기준선에서 생성됩니다. (해당 아이템이 플렉스 컨테이너의 교차 축과 평행한 정렬 기준선이 없으면, 먼저 border edge에서 합성됩니다.)

  2. 그 밖의 경우, 플렉스 컨테이너는 첫/마지막 교차축 기준선 집합이 없으며, 필요하다면 합성됩니다. 이는 정렬 컨텍스트의 규칙에 따릅니다.

위 규칙에 따라 기준선을 계산할 때, 기준선을 제공하는 박스의 overflow 값이 스크롤을 허용하는 경우, 기준선을 결정할 때 박스는 초기 스크롤 위치에 있다고 간주해야 합니다.

테이블 셀의 기준선 결정 시, 플렉스 컨테이너는 라인 박스나 table-row처럼 기준선을 제공합니다. [CSS21]

CSS Writing Modes 3 §4.1 기준선 소개 및 CSS Box Alignment 3 §9 기준선 정렬 상세에서 기준선에 대한 추가 정보를 확인하세요.

9. 플렉스 레이아웃 알고리즘

이 섹션은 플렉스 컨테이너와 그 내용의 정확한 레이아웃 동작을 명확하게 기술한 규범적 알고리즘을 포함합니다. 여기의 알고리즘은 가독성과 이론적 단순화에 초점을 두었으며, 반드시 가장 효율적인 알고리즘일 필요는 없습니다. 구현체는 어떤 알고리즘을 사용해도 되지만, 반드시 여기 기술된 알고리즘과 동일한 결과를 내야 합니다.

참고: 이 섹션은 주로 구현자를 위한 것입니다. 웹페이지를 작성하는 저자는 각 속성 설명만으로 충분하며, CSS 레이아웃의 깊은 내부를 이해하려는 특별한 욕심이 없는 한 이 섹션을 읽을 필요가 없습니다.

아래 섹션들은 플렉스 컨테이너와 그 내용을 레이아웃하는 알고리즘을 정의합니다.

참고: 플렉스 레이아웃은 플렉스 아이템을 order로 변경된 문서 순서로 처리하며, 원래 문서 순서가 아닙니다.

9.1. 초기 설정

  1. §4 플렉스 아이템에 기술된 대로 익명 플렉스 아이템을 생성합니다.

9.2. 라인 길이 결정

  1. 플렉스 아이템을 위한 주 및 교차 공간을 결정합니다. 각 차원별로, 그 차원의 플렉스 컨테이너 콘텐츠 박스가 확정 크기이면, 그 값을 사용합니다; 플렉스 컨테이너가 min 또는 max-content 제약 하에서 크기가 결정되는 경우, 해당 제약이 그 차원의 사용할 수 있는 공간입니다; 그렇지 않으면, 플렉스 컨테이너의 margin, border, padding을 그 차원에서 사용할 수 있는 공간에서 빼고 그 값을 사용합니다. 이 값은 무한 값이 될 수 있습니다.

    예를 들어, 사용 가능한 공간이 float된 auto 크기의 플렉스 컨테이너에서 플렉스 아이템에 대해 계산되는 경우:

    • 플렉스 컨테이너의 포함 블록 너비에서 플렉스 컨테이너의 margin, border, padding(수평 차원)을 뺀 값
    • 수직 차원에서는 무한
  2. 각 아이템의 flex 기준 크기와 가상 주 크기를 결정합니다:
    1. 아이템이 확정적 사용 flex basis를 가진 경우, 그 값이 flex 기준 크기입니다.
    2. 아이템이 ...
      • 고유 종횡비를 갖고,
      • 사용 flex basis가 content이며,
      • 확정적 교차 크기를 가진 경우,
      flex 기준 크기는 내부 교차 크기와 플렉스 아이템의 고유 종횡비로 계산합니다.
    3. 사용 flex basis가 content이거나 사용 가능한 공간에 따라 달라지는 경우, 플렉스 컨테이너가 min-content 또는 max-content 제약 하에서 크기가 결정되는 경우 (예: 자동 테이블 레이아웃 [CSS21]), 해당 제약 내에서 아이템 크기를 결정합니다. flex 기준 크기는 아이템의 결과 주 크기입니다.
    4. 그 밖의 경우, 사용 flex basis가 content이거나 사용 가능한 공간에 따라 달라지고, 사용할 수 있는 주 크기가 무한이며, 플렉스 아이템의 인라인 축이 주 축과 평행하면, 직교 흐름 박스 규칙을 사용해 레이아웃합니다 [CSS3-WRITING-MODES]. flex 기준 크기는 아이템의 max-content 주 크기입니다.

      참고: 예를 들어 영어(수평 쓰기 모드) 문서에 열 플렉스 컨테이너가 있고, 그 안에 일본어(수직 쓰기 모드) 플렉스 아이템이 있는 경우에 발생합니다.

    5. 그 밖의 경우, 사용 가능한 공간 내에서 사용 flex basis를 주 크기 대신 사용해 크기를 결정합니다. content 값은 max-content로 처리합니다. 주 크기가 block axis에 있을 때 등 교차 크기가 주 크기 결정을 위해 필요하고, 플렉스 아이템의 교차 크기가 auto이면서 확정적이 아니면, 이 계산에서는 fit-content를 플렉스 아이템의 교차 크기로 사용합니다. flex 기준 크기는 아이템의 결과 주 크기입니다.

    flex 기준 크기를 결정할 때, 아이템의 min/max 주 크기는 무시합니다 (클램핑 없음). 또한 box-sizing 적용 시 콘텐츠 박스 크기를 0으로 내리는 계산도 무시합니다. (예: 크기를 0으로 지정하고, 패딩 양수, box-sizing: border-box인 아이템은 외부 flex 기준 크기는 0, 즉 내부 flex 기준 크기는 음수가 됩니다.)

    가상 주 크기는 아이템의 flex 기준 크기를 min/max 사용된 주 크기에 따라 클램핑(콘텐츠 박스 크기는 0으로 내림)한 값입니다.

  3. 플렉스 컨테이너의 주 크기를 결정합니다 플렉스 컨테이너가 참여하는 포맷팅 컨텍스트의 규칙을 사용합니다. 이 계산에서 플렉스 아이템의 auto 마진은 0으로 처리됩니다.

9.3. 주 크기 결정

  1. 플렉스 아이템을 플렉스 라인에 모읍니다:
    • 플렉스 컨테이너가 단일 라인이면, 모든 플렉스 아이템을 하나의 플렉스 라인에 모읍니다.
    • 그렇지 않으면, 첫 미수집 아이템부터 시작하여, 연속된 아이템을 하나씩 모으다가 다음 아이템이 플렉스 컨테이너의 내부 주 크기 내에 들어가지 않을 때까지 (또는 강제 개행이 나오기까지, §10 플렉스 레이아웃 단편화 참조) 모읍니다. 만약 첫 미수집 아이템조차 들어가지 않으면, 그것만 줄에 넣습니다.

      이 단계에서, 플렉스 아이템의 크기는 외부 가상 주 크기입니다. (참고: 이 값은 음수가 될 수 있습니다.)

      모든 플렉스 아이템이 플렉스 라인에 수집될 때까지 반복합니다.

      "가능한 만큼 수집"하는 라인은 크기가 0인 플렉스 아이템을 이전 줄 끝에 계속 수집합니다 마지막 0이 아닌 아이템이 줄을 정확히 "채웠더라도" 마찬가지입니다.

  2. 유연 길이 해석을 모든 플렉스 아이템에 대해 수행하여 사용된 주 크기를 찾습니다. §9.7 유연 길이 해석 참조.

9.4. 교차 크기 결정

  1. 각 아이템의 가상 교차 크기를 결정합니다. 사용된 주 크기와 사용 가능한 공간으로 레이아웃을 수행하며, auto는 fit-content로 처리합니다.
  2. 각 플렉스 라인의 교차 크기를 계산합니다.

    플렉스 컨테이너가 단일 라인이고, 확정적 교차 크기를 가진 경우, 플렉스 라인의 교차 크기는 플렉스 컨테이너의 내부 교차 크기입니다.

    그 외의 경우, 각 플렉스 라인에 대해:

    1. 인라인 축이 주 축과 평행이고, align-self가 baseline이며, 교차축 마진이 모두 auto가 아닌 플렉스 아이템을 모두 모읍니다. 각 아이템의 기준선과 가상 외부 cross-start 엣지 사이 거리의 최대값, 그리고 기준선과 가상 외부 cross-end 엣지 사이 거리의 최대값을 각각 구해, 이 두 값을 더합니다.
    2. 이전 단계에서 모이지 않은 모든 아이템 중, 가상 교차 크기의 최대값을 구합니다.
    3. 플렉스 라인의 사용된 교차 크기는, 앞의 두 단계에서 구한 값들과 0 중 가장 큰 값입니다.

      플렉스 컨테이너가 단일 라인이면, 라인의 교차 크기를 컨테이너의 계산된 min/max 교차 크기 내로 클램핑합니다. 만약 CSS 2.1의 min/max-width/height 정의가 더 일반적으로 적용된다면, 이 동작은 자동으로 나올 것입니다.

  3. 'align-content: stretch' 처리. 플렉스 컨테이너에 확정적 교차 크기가 있고, align-content가 stretch인 경우, 플렉스 라인의 교차 크기 합이 플렉스 컨테이너의 내부 교차 크기보다 작으면, 각 플렉스 라인의 교차 크기를 동일한 비율로 증가시켜, 라인들의 교차 크기 합이 플렉스 컨테이너의 내부 교차 크기와 정확히 같아지도록 합니다.
  4. visibility:collapse 아이템 처리. 만약 어떤 플렉스 아이템이 visibility: collapse를 가지면, 해당 아이템이 속한 라인의 교차 크기를 아이템의 strut 크기로 기록하고, 레이아웃을 처음부터 다시 시작합니다.

    두 번째 레이아웃 라운드에서는, 아이템을 라인에 수집할 때, 접힌 아이템은 주 크기가 0인 것처럼 처리합니다. 그 이후의 알고리즘에서는, 접힌 아이템은 완전히 무시합니다 (마치 display:none인 것처럼) 단, 라인 교차 크기 계산 이후에, 어떤 라인의 교차 크기가 해당 라인 내 모든 접힌 아이템 중 가장 큰 strut 크기보다 작으면, 그 라인의 교차 크기를 해당 strut 크기로 설정합니다.

    두 번째 레이아웃 라운드에서는 이 단계를 건너뜁니다.

  5. 각 플렉스 아이템의 사용된 교차 크기 결정. 플렉스 아이템이 align-self: stretch이고, 계산된 교차 크기 속성이 auto이고, 교차축 마진이 모두 auto가 아니면, 사용된 외부 교차 크기는 해당 플렉스 라인의 사용된 교차 크기이고, 아이템의 사용된 min/max 교차 크기로 클램핑합니다. 그 외의 경우, 사용된 교차 크기는 아이템의 가상 교차 크기입니다.

    플렉스 아이템이 align-self: stretch를 가지면, 콘텐츠에 대해 다시 레이아웃을 수행하며, 이 사용된 크기를 확정 교차 크기로 처리하여, 백분율 크기의 자식도 해석할 수 있도록 합니다.

    이 단계는 플렉스 아이템의 주 크기에는 영향을 주지 않습니다. 고유 종횡비가 있어도 마찬가지입니다.

9.5. 주 축 정렬

  1. 남은 여분 공간 분배. 각 플렉스 라인에 대해:
    1. 남은 여분 공간이 양수이고, 해당 라인에 주 축 마진이 auto인 것이 하나 이상 있으면, 그 마진들에 남은 공간을 균등하게 분배합니다. 그렇지 않으면, 모든 auto 마진을 0으로 설정합니다.
    2. justify-content에 따라 주 축 정렬을 수행합니다.

9.6. 교차축 정렬

  1. 교차축 auto 마진 처리. 플렉스 아이템에 auto 교차축 마진이 있으면:
    • 해당 아이템의 외부 교차 크기 (해당 auto 마진을 0으로 처리) 가 플렉스 라인의 교차 크기보다 작으면, 그 차이를 auto 마진에 균등하게 분배합니다.
    • 그렇지 않으면, block-start 또는 inline-start 마진(교차축에 해당하는 것)이 auto이면, 0으로 설정합니다. 반대쪽 마진은 아이템의 외부 교차 크기가 플렉스 라인의 교차 크기와 같아지도록 설정합니다.
  2. 모든 플렉스 아이템을 교차축에서 정렬합니다. 단, 아이템의 교차축 마진이 auto가 아니면 align-self에 따라 정렬합니다.
  3. 플렉스 컨테이너의 사용된 교차 크기 결정:
    • 교차 크기 속성이 확정적 크기면, 그 값을 사용하고, 플렉스 컨테이너의 사용된 min/max 교차 크기로 클램핑합니다.
    • 그렇지 않으면, 플렉스 라인들의 교차 크기 합을 사용하고, 플렉스 컨테이너의 사용된 min/max 교차 크기로 클램핑합니다.
  4. 모든 플렉스 라인 정렬을 align-content에 따라 수행합니다.

9.7. 유연 길이 해석

플렉스 라인 내 아이템의 유연 길이를 해석하려면:

  1. 사용된 flex 팩터 결정. 해당 라인에 있는 모든 아이템의 외부 가상 주 크기를 합산합니다. 합이 플렉스 컨테이너의 내부 주 크기보다 작으면, 이후 알고리즘에서 flex grow 팩터를 사용하고; 그렇지 않으면 flex shrink 팩터를 사용합니다.
  2. 유연하지 않은 아이템 크기 지정. 동결(freeze)하며, 해당 아이템의 목표 주 크기를 가상 주 크기로 설정…
    • flex 팩터가 0인 모든 아이템
    • flex grow 팩터 사용 시: flex 기준 크기가 가상 주 크기보다 큰 아이템
    • flex shrink 팩터 사용 시: flex 기준 크기가 가상 주 크기보다 작은 아이템
  3. 초기 여분 공간 계산. 해당 라인의 모든 아이템의 외부 크기를 합산하고, 이를 플렉스 컨테이너의 내부 주 크기에서 뺍니다. 동결된 아이템에는 외부 목표 주 크기를, 그 외 아이템에는 외부 flex 기준 크기를 사용합니다.
  4. 반복(loop):
    1. 유연 아이템 체크. 해당 라인의 플렉스 아이템이 모두 동결되면, 여분 공간이 분배된 것이므로, 이 반복을 종료합니다.
    2. 남은 여분 공간 계산을 위 초기 여분 공간과 같이 수행합니다. 동결되지 않은 플렉스 아이템의 flex 팩터 합이 1보다 작으면, 초기 여분 공간에 이 합을 곱합니다. 이 값의 크기가 남은 여분 공간의 크기보다 작으면, 이 값을 남은 여분 공간으로 사용합니다.
    3. 여분 공간을 flex 팩터에 비례해 분배.
      남은 여분 공간이 0인 경우
      아무 것도 하지 않음.
      flex grow 팩터 사용하는 경우
      해당 아이템의 flex grow 팩터와, 해당 라인에서 동결되지 않은 모든 아이템의 flex grow 팩터 합의 비율을 구합니다. 아이템의 목표 주 크기를 flex 기준 크기에 남은 공간의 같은 비율을 더한 값으로 설정합니다.
      flex shrink 팩터 사용하는 경우
      해당 라인의 동결되지 않은 모든 아이템에 대해, flex shrink 팩터에 내부 flex 기준 크기를 곱해, 이를 스케일된 flex shrink 팩터로 기록합니다. 해당 아이템의 스케일된 flex shrink 팩터와, 해당 라인에서 동결되지 않은 모든 아이템의 스케일된 flex shrink 팩터 합의 비율을 구합니다. 아이템의 목표 주 크기를 flex 기준 크기에서 남은 여분 공간의 절대값의 같은 비율을 뺀 값으로 설정합니다. 이로 인해 내부 주 크기가 음수가 될 수 있습니다; 다음 단계에서 보정됩니다.
      그 밖의 경우
      아무 것도 하지 않음.
    4. min/max 위반 수정. 동결되지 않은 각 아이템의 목표 주 크기를, 사용된 min/max 사용값 주 크기로 클램핑하고, 콘텐츠 박스 크기를 0으로 내립니다. 아이템의 목표 주 크기가 이로 인해 더 작아졌으면 max 위반, 더 커졌으면 min 위반입니다.
    5. 초과 flex 아이템 동결. 전체 위반 값은 이전 단계에서 조정된 크기의 합 ∑(clamped size - unclamped size)입니다. 전체 위반 값이:
      0
      모든 아이템 동결.
      양수
      min 위반 아이템만 동결.
      음수
      max 위반 아이템만 동결.
    6. 반복의 시작으로 돌아갑니다.
  5. 각 아이템의 사용된 주 크기를 목표 주 크기로 설정합니다.

9.8. 확정 크기와 비확정 크기

CSS Sizing [CSS-SIZING-3]가 확정적 및 비확정적 길이를 정의하지만, Flexbox에는 길이가 확정적으로 간주될 수 있는 추가 사례가 있습니다:

  1. 단일 라인 플렉스 컨테이너가 확정적 교차 크기를 가진 경우, 늘어난 플렉스 아이템의 외부 교차 크기는 플렉스 컨테이너의 내부 교차 크기 (아이템의 min/max 교차 크기로 클램핑)와 같으며, 확정적으로 간주됩니다.
  2. 플렉스 컨테이너가 확정적 주 크기를 가진 경우, 플렉스 아이템의 flexing 이후 주 크기는 확정적으로 처리되며, 같은 줄 내 다른 플렉스 아이템의 비확정적 크기에 의존할 수 있어도 마찬가지입니다.
  3. 플렉스 라인의 교차 크기가 결정되면, auto 크기 플렉스 컨테이너의 아이템도 레이아웃 목적상 확정적으로 간주됩니다. step 11 참고.

참고: 완전히 유연하지 않은 아이템이 확정적 flex basis를 가질 경우, 해당 아이템의 주 크기는 정의상 확정적입니다.

9.9. 고유 크기

고유 크기 결정은 플렉스 컨테이너의 다양한 콘텐츠 기반 자동 크기를 생성하는 데 사용됩니다. 예를 들어 논리적 너비를 콘텐츠에 맞춰 줄이는 경우(fit-content 공식 사용), 논리적 높이를 콘텐츠에 맞춰 지정하는 경우(max-content 크기 사용) 등이 있습니다.

이 섹션의 용어 정의는 [CSS-SIZING-3]를 참고하세요.

9.9.1. 플렉스 컨테이너 고유 주 크기

max-content 주 크기의 플렉스 컨테이너는 플렉스 컨테이너가 max-content 기여값을 플렉스 아이템에 대해 유지하면서, 각 아이템의 유연성이 허용하는 범위 내에서 취할 수 있는 최소 크기입니다:

  1. 각 플렉스 아이템에 대해, 해당 아이템의 외부 flex 기준 크기를 max-content 기여값에서 뺍니다. 결과가 양수이면, 해당 값을 flex grow 팩터를 1로 내린 값으로 나누고; 음수이면, 스케일된 flex shrink 팩터를 1로 내린 값으로 나눕니다. 이것이 아이템의 max-content flex fraction입니다.
  2. 모든 플렉스 아이템을 무한 길이의 라인에 배치합니다.
  3. 각 라인 내에서, 모든 플렉스 아이템 중 가장 큰 max-content flex fraction을 찾습니다. 각 아이템의 flex 기준 크기에 flex grow 팩터(또는 max-content flex fraction이 음수면 스케일된 flex shrink 팩터)와 max-content flex fraction의 곱을 더한 후, 그 결과를 max main size로 클램핑하고 min main size로 내립니다.
  4. 플렉스 컨테이너의 max-content 크기는 한 라인 내 모든 아이템 크기 합 중 가장 큰 값입니다.

min-content 주 크기의 단일 라인 플렉스 컨테이너는 max-content 주 크기와 동일하게 계산하지만, 플렉스 아이템의 min-content 기여값을 사용합니다. 다중 라인 컨테이너의 경우, min-content 기여값 중 가장 큰 값이 플렉스 아이템의 플렉스 컨테이너에서 사용됩니다.

flex 합이 1보다 작은 경우 이 알고리즘의 영향

위 알고리즘은 특히 두 가지 경우에 올바른 동작을 하도록 설계되었으며, 두 경우 간에 플렉스 컨테이너의 크기가 연속적으로 변화하도록 합니다:

  1. 모든 아이템이 유연하지 않은 경우, 플렉스 컨테이너는 모든 아이템의 flex 기준 크기 합으로 크기가 결정됩니다. (유연하지 않은 flex 기준 크기는 width/height의 대체값 역할을 하며, 블록 레이아웃에서 지정된 경우 max-content 기여값의 기준이 됩니다.)

  2. 모든 아이템이 flex 팩터 ≥ 1인 경우, 플렉스 컨테이너는 모든 아이템의 max-content 기여값 합으로 크기가 결정됩니다. (혹은 약간 더 커질 수 있음, 모든 플렉스 아이템이 적어도 자신의 max-content 기여값만큼 크기를 갖고, 유연성에 따라 각 아이템의 크기 비율도 올바르게 맞춰짐)

예를 들어 플렉스 컨테이너에 플렉스 아이템이 하나 있고, flex-basis: 100px;이고 max-content 크기가 200px이면, 아이템이 flex-grow: 0일 때 플렉스 컨테이너(및 플렉스 아이템)는 100px 너비가 되고, 아이템이 flex-grow: 1 이상이면 플렉스 컨테이너(및 플렉스 아이템)는 200px 너비가 됩니다.

라인의 유연성 합이 0과 1 사이일 때 이 두 경우 간의 연속적 동작을 만들기 위한 방법은 여러 가지가 있지만, 모두 단점이 있습니다. 우리는 가장 적은 부작용이 있다고 생각되는 방법을 선택했습니다; 아쉽게도 flex 합이 1 미만일 때 유연성이 "이중 적용"됩니다. 위 예에서 아이템이 flex-grow: .5면, 플렉스 컨테이너는 150px 너비가 되고, 아이템은 그 공간에 맞춰 125px 너비가 됩니다.

9.9.2. 플렉스 컨테이너 고유 교차 크기

min-content/max-content 교차 크기의 단일 라인 플렉스 컨테이너는 모든 플렉스 아이템 중 min-content 기여값 또는 max-content 기여값(각각) 중 가장 큰 값입니다.

다중 라인 플렉스 컨테이너의 경우, min-content/max-content 교차 크기는 교차축 min-content 제약/max-content 제약으로 컨테이너를 크기 지정할 때 결과로 나온 플렉스 라인 교차 크기 합입니다(각각). 단, 플렉스 컨테이너가 flex-flow: column wrap;이면, 먼저 모든 min-content/max-content 교차 크기 기여값 중 가장 큰 값을 구한 뒤, 해당 크기를 사용 가능한 공간으로 하여 레이아웃 시 각 플렉스 아이템에 적용합니다.

참고: column wrap 플렉스 컨테이너에 대한 이 휴리스틱은 플렉스 컨테이너가 취해야 할 크기를 합리적으로 근사해줍니다. 각 플렉스 아이템은 min(해당 아이템의 max-content, 모든 아이템의 max min-content 중 최대값) 크기가 되고, 각 플렉스 라인은 해당 라인의 가장 큰 플렉스 아이템보다 크지 않습니다. 일부 경우에는 완벽하게 맞지 않지만, 완전히 정확하게 하려면 비용이 매우 크기 때문에, 이 방식이 현실적으로 잘 동작합니다.

9.9.3. 플렉스 아이템 고유 크기 기여값

주 크기 min-content 기여값의 플렉스 아이템은, 외부 min-content 크기와 외부 선호 크기(적절히 width/height) 중 더 큰 값이고, 그 값이 auto가 아니라면, flex 기준 크기로 최대값(유연하지 않을 때) / 최소값(축소 불가할 때) 클램핑하고, 그 후 min/max main size로 추가 클램핑합니다.

주 크기 max-content 기여값의 플렉스 아이템은, 외부 max-content 크기와 외부 선호 크기(적절히 width/height) 중 더 큰 값을, flex 기준 크기로 최대값(유연하지 않을 때) / 최소값(축소 불가할 때) 클램핑하고, 그 후 min/max main size로 추가 클램핑합니다.

10. 플렉스 레이아웃 단편화

플렉스 컨테이너는 아이템 사이, 아이템 라인 사이(다중 라인 모드), 그리고 아이템 내부에서 페이지 단위로 나뉠 수 있습니다. break-* 속성은 블록 박스나 인라인 박스와 동일하게 플렉스 컨테이너에 적용됩니다. 이 섹션에서는 해당 속성이 플렉스 아이템과 아이템의 콘텐츠에 어떻게 적용되는지 정의합니다. 더 많은 맥락은 CSS Fragmentation Module [CSS3-BREAK] 참고.

아래의 단절 규칙은 단편화 컨테이너를 “페이지”로 지칭합니다. 동일한 규칙은 다른 단편화 컨텍스트에도 적용됩니다. (필요에 따라 “페이지”를 해당 단편화 컨테이너 유형으로 바꿔서 해석) 이 섹션에서 "row"와 "column" 용어는 플렉스 컨테이너가 단편화 컨텍스트의 블록 흐름 방향과의 상대적 방향을 의미하며, 플렉스 컨테이너 자체의 방향은 아닙니다.

단편화된 플렉스 컨테이너의 정확한 레이아웃은 Flexible Box Layout 이 레벨에서는 정의되지 않습니다. 단, 플렉스 컨테이너 내부 단절은 아래 규칙을 따릅니다 (order로 변경된 문서 순서 사용):

  • row 플렉스 컨테이너에서는, break-before 및 break-after 값이 플렉스 아이템에서 플렉스 라인으로 전파됩니다. 첫 번째 라인의 break-before 값과 마지막 라인의 break-after 값은 플렉스 컨테이너로 전파됩니다.

    참고: break 전파는 (text-decoration 전파처럼) 계산값에는 영향을 주지 않습니다.

  • column 플렉스 컨테이너에서는, 첫 아이템의 break-before 값과 마지막 아이템의 break-after 값이 플렉스 컨테이너로 전파됩니다. 다른 아이템의 강제 단절은 해당 아이템 자체에 적용됩니다.
  • 플렉스 아이템 내부의 강제 단절은 콘텐츠 크기를 증가시키며, 형제 아이템 내부에 강제 단절을 유발하지 않습니다.
  • row 플렉스 컨테이너에서는 Class A 단절 지점이 형제 플렉스 라인 사이에, Class C 단절 지점이 첫/마지막 플렉스 라인과 플렉스 컨테이너 콘텐츠 엣지 사이에 발생합니다. column 플렉스 컨테이너에서는 Class A 단절 지점이 형제 플렉스 아이템 사이에, Class C 단절 지점이 한 줄의 첫/마지막 플렉스 아이템과 컨테이너 콘텐츠 엣지 사이에 발생합니다. [CSS3-BREAK]
  • 플렉스 컨테이너가 단절 후 계속되는 경우, 플렉스 아이템이 사용할 수 있는 공간(단편화 컨텍스트의 블록 흐름 방향)은 이전 페이지의 플렉스 컨테이너 단편이 차지한 공간만큼 줄어듭니다. 플렉스 컨테이너 단편이 차지한 공간은 해당 페이지에서의 콘텐츠 박스 크기입니다. 이 조정으로 사용 가능한 공간이 음수가 되면, 0으로 설정합니다.
  • 플렉스 컨테이너의 첫 번째 단편이 페이지 상단에 없고, 남은 공간에 어떤 플렉스 아이템도 들어가지 않으면, 전체 단편을 다음 페이지로 이동합니다.
  • 다중 라인 column 플렉스 컨테이너가 단절될 때, 각 단편은 자체적으로 플렉스 라인 "스택"을 가지며, 이는 다중 열 컨테이너의 각 단편이 자체 column 박스 행을 갖는 것과 유사합니다.
  • 앞 규칙에 따른 아이템 재배치 외에는, UA는 단편화되지 않은 흐름과 비교해 플렉스 컨테이너의 왜곡을 최소화하려고 해야 합니다.

10.1. 플렉스 단편화 알고리즘 예시

이 참고 섹션에서는 플렉스 컨테이너를 위한 가능한 단편화 알고리즘을 제시합니다. 구현자는 이 알고리즘을 개선하고 CSS Working Group에 피드백을 제공할 것을 권장합니다.

이 알고리즘은 페이지네이션이 항상 앞으로만 진행된다고 가정합니다; 따라서 아래 알고리즘에서는 페이지네이션 이전의 정렬은 대부분 무시됩니다. 고급 레이아웃 엔진은 여러 단편에 걸쳐 정렬을 보장할 수 있습니다.

단일 라인 column 플렉스 컨테이너
  1. 플렉스 레이아웃 알고리즘을(페이지네이션은 고려하지 않고) 교차 크기 결정까지 실행합니다.
  2. 첫 번째 아이템부터 연속된 플렉스 아이템 또는 아이템 단편을 최대한 많이(최소 하나 또는 일부 단편) 페이지에 들어갈 때까지 또는 강제 단절이 나올 때까지 배치합니다.
  3. 이전 단계에서 공간이 부족해지고 남은 공간이 양수이면, UA는 현재 페이지의 분배된 여분 공간을(최대 0까지) 줄여서 다음에 들어갈 수 없는 아이템 또는 단편이 들어갈 수 있도록 할 수 있습니다. 그렇지 않으면, 들어가지 않는 아이템 또는 단편은 다음 페이지로 넘깁니다. UA는 단편의 50% 이상이 남은 공간에 들어갈 수 있으면 당겨오고, 그렇지 않으면 밀어내야 합니다.
  4. 이전 단계에서 배치되지 않은 플렉스 아이템이나 단편이 있으면, 플렉스 레이아웃 알고리즘을 라인 길이 결정에서 교차 크기 결정까지 다음 페이지의 크기로 모든 콘텐츠(이미 배치된 것도 포함)로 다시 실행하고, 이전 단계로 돌아가서 이미 배치되지 않은 첫 아이템 또는 단편부터 시작합니다.
  5. 플렉스 컨테이너의 각 단편마다, 플렉스 레이아웃 알고리즘을 주 축 정렬부터 끝까지 계속합니다.

이 알고리즘의 의도는 column 방향 단일 라인 플렉스 컨테이너가 블록 플로우와 매우 유사하게 페이지네이션되도록 하는 것입니다. 의도 테스트로, justify-content:start이고 유연하지 않은 아이템만 있는 플렉스 컨테이너는 동일한 콘텐츠, 동일한 사용 크기, 동일한 사용 마진을 가진 블록과 동일하게 페이지네이션되어야 합니다.

다중 라인 column 플렉스 컨테이너
  1. 플렉스 레이아웃 알고리즘을 페이지네이션을 고려하여 (플렉스 컨테이너의 최대 라인 길이를 페이지에서 남은 공간으로 제한) 교차 크기 결정까지 실행합니다.
  2. 최대한 많은 플렉스 라인을(최소 한 줄) 배치합니다. 플렉스 컨테이너의 교차 축에 공간이 더 없거나 강제 단절이 나오기까지:
    1. 첫 번째 아이템부터 연속된 플렉스 아이템을 최대한 많이(최소 하나) 페이지에 들어갈 때까지 또는 강제 단절이 나올 때까지 배치합니다. 플렉스 아이템 내의 강제 단절은 무시합니다.
    2. 이 플렉스 컨테이너 단편이 첫 번째이고, 이 라인에 단일 플렉스 아이템만 있고, 그 아이템이 페이지에 남은 공간보다 크며, 플렉스 컨테이너가 이미 페이지 상단에 있지 않으면, 플렉스 컨테이너를 다음 페이지로 옮기고 레이아웃을 처음부터 다시 시작합니다.
    3. 첫 번째 단계에서 배치되지 않은 플렉스 아이템이 있으면, 플렉스 레이아웃 알고리즘을 주 크기 결정에서 교차 크기 결정까지 이전 라인에 배치되지 않은 아이템만으로 다시 실행하고, 이전 단계로 돌아가서 아직 배치되지 않은 첫 아이템부터 시작합니다.
  3. 이전 단계에서 배치되지 않은 플렉스 아이템이 있으면, 플렉스 레이아웃 알고리즘을 라인 크기 결정에서 교차 크기 결정까지 다음 페이지의 크기로 이전에 배치되지 않은 아이템만으로 다시 실행하고, 이전 단계로 돌아가서 아직 배치되지 않은 첫 아이템부터 시작합니다.
  4. 플렉스 컨테이너의 각 단편마다, 플렉스 레이아웃 알고리즘을 주 축 정렬부터 끝까지 계속합니다.

플렉스 아이템이 한 페이지에 완전히 들어가지 않으면, 다중 라인 column 플렉스 컨테이너에서는 단편화되지 않습니다.

단일 라인 row 플렉스 컨테이너
  1. 전체 플렉스 레이아웃 알고리즘을(페이지네이션은 고려하지 않고) 실행하되, align-self가 flex-start 또는 baseline이 아닌 경우 flex-start로 처리합니다.
  2. 들어갈 수 없는 분할 불가 아이템이 페이지에 남은 공간 내에 들어가지 않고, 플렉스 컨테이너가 페이지 상단에 있지 않으면, 플렉스 컨테이너를 다음 페이지로 옮기고 레이아웃을 처음부터 다시 시작합니다.
  3. 각 아이템마다, 페이지 남은 공간에 들어갈 만큼의 콘텐츠를 배치하고, 남은 콘텐츠는 다음 페이지로 단편화합니다. 플렉스 레이아웃 알고리즘을 라인 길이 결정에서 주 축 정렬까지 새 페이지 크기로 모든 콘텐츠(이전 페이지에서 완료된 아이템 포함)로 다시 실행합니다.

    이전 단편에 완전히 들어간 플렉스 아이템도 이후 단편의 주 축에서 공간을 차지합니다.

  4. 플렉스 컨테이너의 각 단편마다, 플렉스 레이아웃 알고리즘을 교차축 정렬에서 끝까지 다시 실행합니다. 첫 번째 단편을 제외한 모든 단편에 대해서는, align-self 및 align-content를 모든 아이템 단편과 라인에 대해 flex-start로 처리합니다.
  5. 어떤 아이템이 원래의 align-self 값에 따라 모든 플렉스 컨테이너 단편의 결합된 교차 크기 내에 완전히 들어갈 수 있으면, 해당 단편으로 옮겨 적절히 정렬할 수 있습니다.
다중 라인 row 플렉스 컨테이너
  1. 플렉스 레이아웃 알고리즘을(페이지네이션은 고려하지 않고) 교차 크기 결정까지 실행합니다.
  2. 최대한 많은 플렉스 라인을(최소 한 줄) 첫 번째부터 페이지에 들어갈 때까지 또는 강제 단절이 나올 때까지 배치합니다.

    한 줄이 페이지에 들어가지 않고, 그 줄이 이미 페이지 상단에 있지 않으면, 줄을 다음 페이지로 옮기고 플렉스 레이아웃 알고리즘을 처음부터 다시 시작합니다. 이때 해당 줄 및 이후 아이템만 사용합니다.

    플렉스 아이템이 강제 단절을 유발하면, 플렉스 레이아웃 알고리즘을 주 크기 결정에서 주 축 정렬까지 해당 줄 및 이후 아이템만 사용하여 다시 실행하고, 단절을 유발한 아이템은 라인 분할 단계에서 자동으로 새 줄을 시작하게 합니다. 이후 이 단계로 계속합니다. 플렉스 아이템 내의 강제 단절은 무시합니다.

  3. 이전 단계에서 배치되지 않은 플렉스 아이템이 있으면, 플렉스 레이아웃 알고리즘을 라인 길이 결정에서 주 축 정렬까지 다음 페이지의 크기로 아직 배치되지 않은 아이템만 사용해 다시 실행합니다. 이전 단계로 돌아가서, 아직 배치되지 않은 첫 줄부터 시작합니다.
  4. 플렉스 컨테이너의 각 단편마다, 플렉스 레이아웃 알고리즘을 교차축 정렬에서 끝까지 계속합니다.

2017년 10월 16일 CR 이후 변경 사항

의견 처리 결과 모음도 제공됩니다.

  • 플렉스 아이템의 block-축 마진과 패딩을 block 차원 기준으로 해석하는 옵션을 제거함; 반드시 인라인 차원 기준으로 해석해야 하며, 블록과 동일하게 처리해야 합니다. (Issue 2085)
  • 플렉스 아이템의 min-content 기여값을 선호 크기로 내림(floor) 처리함(Issue 2353) 그리고 관련 문구를 더 정확하게 다듬음.
    주 크기 min-content 기여값은 플렉스 아이템의 외부 min-content 크기 및 외부 선호 크기(적절히 width/height) 값이 auto가 아닐 때 , flex 기준 크기로 최대값(성장 불가시) / 최소값(축소 불가시) 클램핑하고, 그 후 min/max main size properties로 추가 클램핑합니다.

    주 크기 max-content 기여값은 플렉스 아이템의 외부 max-content 크기와 외부 지정된 선호 크기 (적절히 width/height , ) 값이 확정적일 때 auto가 아닐 때 , flex 기준 크기로 최대값(성장 불가시) / 최소값(축소 불가시) 클램핑하고, 그 후 min/max main size properties로 추가 클램핑합니다.

  • flex-basis: content에 대해 일부 설명(사실상 참고용) 및 상호 참조를 추가함.

    automatic sizing 자동 크기 를 플렉스 아이템의 콘텐츠 기준으로 지정합니다. (일반적으로 max-content 크기와 같으나, 종횡비, 고유 크기 제약, 직교 흐름 등을 처리하기 위한 조정이 있습니다; 세부 사항은 §9 Flex Layout Algorithm 참조.)

  • auto 키워드의 min-width, min-height 정의를 [CSS-SIZING-3]로 이동함. 플렉스 아이템의 자동 최소 크기 정의는 여전히 이곳에 남아 있습니다. (Issue 1920, Issue 2103)
  • auto의 min-width, min-height 계산을 항상 자기 자신으로 처리하도록 변경함—단, CSS2 display 타입에서는 해석된 값이 0으로 남음. (Issue 2230, Issue 2248)

    1. 각 플렉스 아이템에 대해 외부 flex 기준 크기를 max-content 기여값에서 뺍니다 . 그 결과가 0이 아니면, (양수일 때) flex grow 팩터를 1로 내린 값으로 나누고, (음수일 때) 스케일된 flex shrink 팩터로 나누고, 이때 flex shrink 팩터는 1로 내림 처리함. 이것이 아이템의 max-content flex fraction입니다.
  • 플렉스 컨테이너의 교차축 고유 크기 계산 오류 수정, 그리고 다중 라인 column 플렉스 컨테이너에 대해 일반적으로 구현되는 min-content 크기 휴리스틱 명시. (Issue 12)

    다중 라인 플렉스 컨테이너의 경우, min-content/max-content 교차 크기는 교차축 min-content 제약/max-content 제약으로 크기를 지정할 때 나온 플렉스 라인 교차 크기 합입니다(각각). 단, 플렉스 컨테이너가 flex-flow: column wrap;이면, 먼저 모든 min-content/max-content 교차 크기 기여값 중 가장 큰 값을 구하고, 해당 크기를 사용 가능한 공간으로 하여 각 플렉스 아이템을 레이아웃합니다.

주요 변경 및 버그 수정

다음은 2012년 9월 18일 Candidate Recommendation 이후의 주요 변경 사항입니다:

    • overflow가 visible인지 고려. overflow가 명확히 처리된다면 모든 콘텐츠를 보여주기 위한 크기 강제는 혼란스럽고 불필요함.
    • 지정된 width/height도 고려하여, 암시적 최소값이 지정값보다 커지지 않도록 함.

    auto

    flex 아이템의 min main size 속성값으로 사용 시, 이 키워드는 min-content 크기를 최소값으로 지정하여 콘텐츠가 들어가기에 충분히 크도록 합니다.

  • 단일 라인 플렉스 컨테이너 크기의 확정성을 stretched 아이템에도 전달. (Issue 3)

  • 플렉스 컨테이너의 고유 크기 정의.

    플렉스 컨테이너의 주 크기 결정은 주 크기 속성을 사용함. 이 계산에서, 플렉스 컨테이너의 min-content 주 크기는 아이템들의 min-content 기여값의 최댓값, max-content 주 크기는 아이템들의 max-content 기여값의 합. 아이템의 min-content/max-content 주 크기 기여값은 해당 아이템을 min-content/max-content 제약으로 크기 지정할 때의 외부 가상 주 크기. 이 계산에서는 flex 아이템의 'auto' 마진을 '0'으로 처리함.

    max-content 주 크기의 플렉스 컨테이너는 플렉스 컨테이너의 아이템들의 max-content 기여값의 합입니다(주 축 기준). min-content 주 크기의 단일 라인 플렉스 컨테이너는 아이템들의 min-content 기여값의 합이고, 다중 라인 컨테이너는 그 중 최대값입니다.

    min-content 교차 크기 및 max-content 교차 크기의 플렉스 컨테이너는 주어진 사용 가능한 주 축 공간과 무한 사용 가능한 교차 축 공간에서 레이아웃한 후의 플렉스 컨테이너의 교차 크기입니다.

    플렉스 아이템의 주 크기 min-content/max-content 기여값은 가상 주 크기로, 각각 min-content/max-content 제약으로 크기 지정함.

    이 섹션 용어 정의는 [CSS-SIZING-3] 참고.

  • 플렉스 컨테이너의 abspos 자식의 static position을 Grid Layout과 일치시키도록 단순화. (Issue 6)
    플렉스 컨테이너의 절대 위치 자식은 flex 레이아웃에는 재정렬 단계 외에는 참여하지 않음.

    하지만 left/right 또는 top/bottom이 auto일 때, 해당 속성의 사용값은 static position에서 계산됨:

    left/right가 모두 auto면, 플렉스 아이템은 main-start 또는 cross-start 엣지(수평축)를 static position에 맞춰야 함. top/bottom이 모두 auto면, 플렉스 아이템은 main-start 또는 cross-start 엣지(수직축)를 static position에 맞춰야 함.

    주 축에서,

    1. 같은 플렉스 라인에 이후 in-flow 플렉스 아이템이 있으면, static position은 해당 main-start 외부 엣지.
    2. 아니면, 같은 플렉스 라인에 이전 in-flow 플렉스 아이템이 있으면, static position은 해당 main-end 외부 엣지.
    3. 아니면, justify-content 값으로 static position을 0 크기 플렉스 아이템으로 처리.

    교차축에서,

    1. 이전 in-flow 플렉스 아이템이 있으면, static position은 해당 아이템이 속한 cross-start 엣지.
    2. 아니면, static position은 첫 플렉스 라인의 cross-start 엣지.

    static position은 대략적으로 flex-start 정렬 0×0 익명 in-flow 플렉스 아이템 위치와 일치하도록 의도됨. justify-content: space-around나 justify-content: space-between으로 인한 패킹 공간은 해당 가상 아이템 주변에서는 억제됨.

    static position은 절대 위치 자식을 제외하고 전체 flex 레이아웃을 수행한 후, 각 절대 위치 자식을 해당 컨테이너의 유일한 flex item인 것처럼, 자식과 컨테이너 모두 사용 크기의 고정 박스라고 가정하여 위치 지정함.

    예시: 기본적으로 절대 위치 자식의 static position은 main-start/cross-start 모서리에 맞춰짐(플렉스 컨테이너의 justify-content 및 align-content 기본값). 플렉스 컨테이너에 justify-content:center를 지정하면, 자식이 주 축에서 중앙에 정렬됨.
  • 유연 길이 해석 알고리즘을 변경하여 flex 팩터 합이 0에 가까워질 때 연속적인 동작을 하도록 함(합이 1 이상인 경우 변화 없음). (Issue 30) 해당 섹션을 새 섹션으로 대체.

    플렉스 아이템 및 플렉스 컨테이너의 절대 위치 자식 을 order에 따라 재정렬합니다.

  • float가 여전히 계산된 display에 영향을 주는 것(플렉스 아이템 판정 전에 실행되는 box-fixup 규칙에 영향)을 명확히 함. (Issue 7)

    float 및 clear는 플렉스 아이템에 영향을 주지 않음 , 그리고 플로우 밖으로 내보내지 않습니다. 다만 float 속성은 display 속성의 계산값에 영향을 줌으로써 박스 생성에 영향을 줄 수 있습니다.

  • "white space"의 의미를 명확히 함. (Issue 26)

    익명 플렉스 아이템에 white space (즉, white-space 속성에 의해 영향을 받을 수 있는 문자) 만 있으면, display:none처럼 렌더링되지 않습니다.

  • 테이블 익명 박스 생성이 내부 테이블 요소의 계산값 변환 대신 발생함을 명확히 함.
  • 플렉스 아이템 판정과 display-inside / display-outside (display의 새로운 longhands, CSS Display Module Level 3에서 정의됨)와의 상호작용 명확화.

    플렉스 컨테이너를 생성하는 요소의 in-flow 자식의 지정된 display-outside가 inline-level이면, block-level로 계산됩니다. (이는 인라인 display 값을 블록 대응값으로 변환하는 효과가 있습니다.)
    참고: 이 변경은 되돌려짐.
  • overflow가 플렉스 컨테이너에 적용됨을 명확히 함.
  • ::first-line 및 ::first-letter 의사 요소가 플렉스 컨테이너에는 적용되지 않음을 명확히 함(플렉스 컨테이너가 블록 컨테이너가 아니기 때문).
  • stretch가 교차 크기 속성의 계산된 값이 auto일 때만 적용됨을 명확히 함. 퍼센트 교차 크기가 확정 크기 기준이 아니어서 auto로 동작할 때는 stretch되지 않음. (Issue 5)

    플렉스 아이템의 교차 크기 속성이 is 계산된 값이 auto이면, 사용값은 …

  • 플렉스 컨테이너의 주 크기 결정에 포맷팅 컨텍스트의 규칙을 사용함을 명확히 함.
    플렉스 컨테이너의 주 크기 결정은 참여하는 포맷팅 컨텍스트의 규칙을 따라야 함 자신의 주 크기 속성 .
  • 페인팅 시 order로 수정된 문서 순서를 사용함을 명확히 함(이는 order 섹션에 이미 명시되어 있었으나, 페인팅 순서에 대해 명시적으로 서술된 것은 아님).
  • 줄바꿈(line-breaking)이 음수 크기 플렉스 아이템 및 라인 끝의 0 크기 아이템을 정확히 처리하도록 명확화. (Issue 1)

    그 밖의 경우, 첫 미수집 아이템부터 시작하여, 아이템을 하나씩 연속적으로 수집하다가 다음 아이템이 플렉스 컨테이너의 내부 주 크기에 들어가지 않는 첫 순간까지, 또는 강제 단절이 나올 때까지 수집. 만약 첫 미수집 아이템이 들어가지 않으면, 해당 아이템 하나만 라인에 포함 들어갈 수 있는 연속 플렉스 아이템을 최대한 수집하거나 강제 단절이 나올 때까지(최소 하나는 반드시 포함) 플렉스 컨테이너의 내부 주 크기 내에 라인으로 수집 .

    참고: 0 주 크기 아이템은 라인 시작에 오지 않으며, 반드시 컨테이너의 첫 아이템이거나, 강제 단절 뒤에 와야 합니다. "최대 수집" 라인은 them 0 크기 플렉스 아이템 을 이전 라인 끝에 추가하며, 마지막 0이 아닌 아이템이 라인을 정확히 채웠더라도 마찬가지입니다.

  • 플렉스 컨테이너 교차 크기는 여전히 플렉스 컨테이너의 min/max 속성에 의해 클램핑됨을 명확히 함. (Issue 24)
    • 교차 크기 속성이 확정적 크기이면, 그 값을 사용하되, 플렉스 컨테이너의 min/max 교차 크기 속성으로 클램핑 .
    • 그 밖의 경우, 플렉스 라인의 교차 크기 합을 사용하되, 플렉스 컨테이너의 min/max 교차 크기 속성으로 클램핑 .

11. 개인정보 및 보안 고려사항

Flexbox는 새로운 개인정보 누수나, "정확하게 구현하라"라는 것 외의 추가적인 보안 고려사항을 도입하지 않습니다.

준수성

문서 관례

준수 요구사항은 설명적 명제와 RFC 2119 용어의 조합으로 표현됩니다. “MUST”, “MUST NOT”, “REQUIRED”, “SHALL”, “SHALL NOT”, “SHOULD”, “SHOULD NOT”, “RECOMMENDED”, “MAY”, “OPTIONAL” 같은 핵심 단어는 이 문서의 규범적 부분에서 RFC 2119에 명시된 대로 해석해야 합니다. 단, 가독성을 위해 이 명세에서는 모두 대문자로 표기하지 않습니다.

본 명세의 모든 텍스트는 명시적으로 비규범적, 예시, 참고로 표시된 섹션을 제외하고 규범적입니다. [RFC2119]

준수 클래스

이 명세에 대한 준수는 세 가지 클래스에 대해 정의됩니다:

스타일 시트
CSS 스타일 시트.
렌더러
UA로, 스타일 시트의 의미를 해석하고 이를 사용하는 문서를 렌더링함.
저작 도구
UA로, 스타일 시트를 작성함.

스타일 시트가 이 명세를 준수하려면 본 모듈에서 정의된 문법을 사용하는 모든 문이 일반 CSS 문법 및 각 기능별 개별 문법에 따라 유효해야 합니다.

렌더러가 이 명세를 준수하려면 스타일 시트를 관련 명세대로 해석하는 것 외에도, 이 명세에서 정의한 모든 기능을 올바르게 파싱하고 문서를 이에 따라 렌더링해야 합니다. 단, UA가 디바이스의 한계로 인해 문서를 올바르게 렌더링하지 못해도 비준수로 간주하지 않습니다. (예: UA가 흑백 모니터에서 색상을 렌더링할 필요는 없음.)

저작 도구가 이 명세를 준수하려면 본 모듈의 일반 CSS 문법 및 각 기능별 개별 문법에 맞게 문법적으로 올바른 스타일 시트를 작성하고, 본 모듈에서 정의한 스타일 시트의 모든 준수 요구사항을 만족해야 합니다.

CSS의 책임 있는 구현을 위한 요구사항

아래 섹션들은 현재와 미래의 상호운용성을 촉진하는 방식으로 CSS를 책임 있게 구현하기 위한 여러 준수 요구사항을 정의합니다.

부분 구현

저자가 forward-compatible 파싱 규칙을 이용해 대체 값을 지정할 수 있도록, CSS 렌더러는 반드시 사용 가능한 수준의 지원이 없는 at-rule, 속성, 속성 값, 키워드, 기타 문법 구조를 무효로 처리하고 (적절히 무시) 해야 합니다. 특히, UA는 지원되지 않는 속성 값을 부분적으로 무시하고 지원되는 값만 적용해서는 안 됩니다: 한 선언의 어떤 값이라도 무효(지원되지 않는 값)로 간주되면, CSS 규칙에 따라 전체 선언을 무시해야 합니다.

불안정 및 독점 기능 구현

미래 안정적인 CSS 기능과의 충돌을 피하기 위해, CSSWG는 최선의 관행을 따라 불안정 기능 및 독점 확장을 구현할 것을 권장합니다.

CR 단계 기능의 구현

명세가 Candidate Recommendation 단계에 도달하면, 구현자는 명세대로 올바르게 구현되었음을 입증할 수 있는 모든 CR 단계 기능을 unprefixed로 구현해 출시해야 하며, 해당 기능의 prefix 버전 노출은 피해야 합니다.

CSS의 구현 간 상호운용성을 수립·유지하기 위해, CSS Working Group은 비실험적 CSS 렌더러가 어떤 CSS 기능의 unprefixed 구현을 출시하기 전에 W3C에 구현 보고서(및 필요하다면 보고서에 사용된 테스트케이스)를 제출하기를 요청합니다. W3C에 제출된 테스트케이스는 CSS Working Group에 의해 검토·수정될 수 있습니다.

테스트케이스 및 구현 보고서 제출에 대한 추가 정보는 CSS Working Group 웹사이트 http://www.w3.org/Style/CSS/Test/에서 확인 가능합니다. 문의는 public-css-testsuite@w3.org 메일링 리스트로 보내세요.

CR 종료 기준

이 명세가 Proposed Recommendation으로 승격되려면, 각 기능에 대해 최소 두 개의 독립적이고 상호운용 가능한 구현이 있어야 합니다. 각 기능은 서로 다른 제품군에서 구현될 수 있으며, 모든 기능이 단일 제품에서 구현되어야 할 필요는 없습니다. 이 기준을 위한 용어 정의는 다음과 같습니다:

독립적(Independent)
각 구현은 서로 다른 당사자가 개발해야 하며, 다른 구현에서 사용된 코드와 공유, 재사용, 파생해서는 안 됩니다. 명세의 구현에 영향이 없는 코드 부분은 예외입니다.
상호운용 가능(Interoperable)
해당 CSS 공식 테스트케이스를 통과하거나, 구현이 웹 브라우저가 아닐 경우 동등한 테스트를 통과해야 함. 모든 관련 테스트는 해당 UA가 상호운용성을 주장하려면 동등한 테스트가 반드시 작성되어야 합니다. 또한 해당 UA가 상호운용성을 주장하려면 동일한 방식으로 동등 테스트를 통과할 수 있는 추가 UA가 반드시 있어야 하며, 동등 테스트는 동료 검토(peer review) 목적을 위해 공개되어야 합니다.
구현(Implementation)
사용자 에이전트(UA)로서:
  1. 명세를 구현함.
  2. 일반 공개 대상임. 구현은 출시 제품이나 기타 공개 버전(베타, 프리뷰, "nightly build" 등)일 수 있음. 출시되지 않은 제품 릴리스는 기능이 최소 1개월간 구현되어 안정성을 입증해야 함.
  3. 실험적이지 않음(테스트케이스 통과만을 목적으로 특별히 설계된 버전이 아니고, 앞으로 정상적으로 사용될 예정임).

1. 소개

이 섹션은 규범적이지 않습니다.

이 모듈은 두 개의 새로운 <color> 함수를 추가합니다: contrast-color() 및 color-layers().

2. 대비되는 색상 계산: contrast-color() 함수

contrast-color() 함수 표기법은 수동 계산 없이도 지정된 배경색 또는 전경색에 대해 충분히 대비되는 색상을 식별합니다.

구문은 다음과 같습니다:

<contrast-color()> = contrast-color(
  [ [ <color> && [ tbd-fg | tbd-bg ] && <target-contrast>? ] |
    [ <color> && [ tbd-fg | tbd-bg ] && <target-contrast>, <color># ] ] )
<target-contrast> = <wcag2>
테스트
  • contrast-color-001.html (라이브 테스트) (소스)
  • color-computed-contrast-color-function.html (라이브 테스트) (소스)
  • color-invalid-contrast-color-function.html (라이브 테스트) (소스)
  • color-valid-contrast-color-function.html (라이브 테스트) (소스)

유일한 필수 인수는 대비가 계산되는 대상인 기준 색상입니다. 이는 일반적으로(반드시 그런 것은 아니지만) 배경색입니다.

선택적인 <color> 값 목록은 색상 후보를 나타냅니다. 후보가 제공되지 않으면 기본 후보가 사용됩니다: white, black.

tbd-fg 및 tbd-bg 키워드는 대비를 계산할 때 기준 색상의 역할을 나타냅니다: 후보 배경색 목록에 대한 텍스트(text)로서, 또는 후보 텍스트 색상 목록에 대한 배경으로서입니다. (한 쌍의 색상에 대한 유효 대비는 그 사용 방식에 따라 달라집니다.)

기준 색상이 전경인지 배경인지를 지정하는 키워드는 TBD입니다. [이슈 #7359]

<target-contrast> 인수는 사용할 대비 알고리즘을 지정합니다. 색상 후보가 제공되지 않은 경우, <target-contrast>는 생략될 수 있으며, 이 경우 UA가 선택한 알고리즘이 사용됩니다.

<target-contrast> 함수 표기법의 인수는 목표 대비 수준을 나타냅니다. 목표 대비 수준이 있는 여러 대비 알고리즘이 지정될 수 있으며, 이 경우 모든 요구사항이 동시에 적용됩니다. 여러 알고리즘을 지정하는 contrast-color() 함수는 각 알고리즘에 대해 목표 대비 수준을 지정해야 하며, 그렇지 않으면 유효하지 않습니다.

목표 대비 수준이 생략되면, 가장 큰 대비를 가진 색상 후보가 반환됩니다. 그렇지 않으면, 반환되는 색상은 해당 수준을 충족하거나 초과하는 첫 번째 색상 후보이며, 해당하는 후보가 없으면 white 또는 black이 기본값으로 사용됩니다.

2.1. 승리 색상 찾기

2.1.1. 목표 대비가 있는 경우

후보 색상은 목록의 첫 번째 색상부터 시작하여, 자동으로 추가된 white, black으로 끝나도록 순차적으로 테스트됩니다. 지정된 대비 수준을 기준 색상에 대해 통과하는 첫 번째 색상이 승리합니다.

통과하는 후보 색상이 없으면, white 또는 black 중 첫 번째로 지정된 알고리즘에 따라 가장 높은 대비를 가진 색상이 승리합니다. 둘의 대비가 같으면 white가 승리합니다. 

contrast-color(wheat tbd-bg wcag2(aa), bisque, darkgoldenrod, olive, sienna, darkgreen, maroon)

계산은 다음과 같습니다:

  • 배경인 wheat (#f5deb3)는 상대 휘도 0.749를 가집니다

  • bisque (#ffe4c4)는 상대 휘도 0.807과 대비율 1.073을 가집니다

  • darkgoldenrod (#b8860b)는 상대 휘도 0.273과 대비율 2.477을 가집니다

  • olive (#808000)는 상대 휘도 0.200 및 대비율 3.193을 가집니다

  • sienna (#a0522d)는 상대 휘도 0.137과 대비율 4.274를 가집니다

  • darkgreen (#006400 )은 상대 휘도 0.091과 대비율 5.662를 가집니다

  • maroon (#800000)은 상대 휘도 0.046과 대비율 8.333을 가집니다

목표 대비율 4.5를 충족하는 목록의 첫 번째 색상은 darkgreen입니다.

contrast-color(wheat tbd-bg wcag2(5.8), bisque, darkgoldenrod, olive, sienna, darkgreen, maroon)

계산은 다음과 같습니다:

  • 상대 휘도와 대비율은 이전 예제와 같습니다.

목표 대비율 5.8을 충족하는 목록의 첫 번째 색상은 maroon입니다.

contrast-color(wheat tbd-bg wcag2(AA), bisque, darkgoldenrod, olive)

계산은 다음과 같습니다:

  • 상대 휘도와 대비율은 이전 예제와 같습니다.

목록의 어떤 색상도 목표 대비율 4.5를 충족하지 않습니다. white와 wheat인 기준 색상의 대비는 1.314로, 4.5 (AA)보다 작으므로 목표 대비를 통과하지 못합니다. 따라서 black이 반환되며, 그 대비는 15.982 > 4.5입니다.

2.1.2. 목표 대비가 지정되지 않은 경우

후보 색상은 목록의 첫 번째 색상부터 순차적으로 테스트됩니다. 지금까지 테스트한 모든 색상 중 기준 색상에 대해 가장 높은 대비를 가지는 경우, 그 색상은 임시 승자입니다.

목록의 끝에 도달하면 현재 임시 승자가 전체 승자가 됩니다. 따라서 목록의 두 색상이 우연히 같은 대비를 가지는 경우, 더 앞에 있는 색상이 승리합니다.

--myAccent: #b22222;
color: contrast-color(wheat tbd-bg wcag2, tan, sienna, var(--myAccent), #d2691e)

계산은 다음과 같습니다:

  • 배경인 wheat (#f5deb3)는 상대 휘도 0.749를 가집니다

  • tan (#d2b48c)은 상대 휘도 0.482와 대비율 1.501을 가집니다

  • sienna (#a0522d)는 상대 휘도 0.137과 대비율 4.273을 가집니다

  • --myAccent (#b22222)는 상대 휘도 0.107과 대비율 5.081을 가집니다

  • #d2691e는 상대 휘도 0.305와 대비율 2.249를 가집니다

가장 높은 대비율은 5.081이므로 var(--myAccent)가 승리합니다

foo {
  --bg: hsl(200 50% 80%);
  --purple-in-hsl: hsl(300 100% 25%);
  color: contrast-color(var(--bg) tbd-fg wcag2, hsl(200 83% 23%), purple, var(--purple-in-hsl));
}

계산은 다음과 같습니다:

  • --bg는 rgb(179 213 230)이며 상대 휘도 0.628835를 가집니다

  • hsl(200 83% 23%)은 rgb(10 75 107)이며 상대 휘도 0.061575와 대비율 6.08409를 가집니다

  • purple은 rgb(128 0 128)이며 상대 휘도 0.061487과 대비율 6.08889를 가집니다

  • --purple-in-hsl도 rgb(128 0 128)이며 상대 휘도 0.061487과 대비율 6.08889를 가집니다. 이는 purple의 대비보다 크지 않으므로 purple이 승리합니다.

여기의 계산값은 낮은 정밀도로 일찍 반올림하면 잘못된 결과가 나왔을 것임을 보여주기 위해 유효 숫자 여섯 자리로 표시되어 있습니다(0.061575는 0.061487에 매우 가깝고, 6.08409는 6.08889에 매우 가깝습니다).

2.2. 대비 알고리즘

현재는 WCAG 2.1만 지원되지만, 이 알고리즘에는 알려진 문제가 있으며, 특히 어두운 배경에서 문제가 있습니다. 이 모듈의 향후 개정에서는 추가 대비 알고리즘이 도입될 가능성이 높습니다.

2.2.1. WCAG 2.1: wcag2 키워드와 wcag2() 함수

wcag2 키워드와 wcag2() 함수 표기법은 [WCAG21] 휘도 대비 알고리즘의 사용을 나타냅니다. 구문은 다음과 같습니다: 

<wcag2> =  wcag2 | wcag2([<number> | [ aa | aaa ] && large? ])

그 목표 대비 수준 키워드는 다음과 같이 매핑됩니다:

  • aa는 4.5로 계산됩니다

  • aa large (또는 large aa)는 3으로 계산됩니다

  • aaa는 7로 계산됩니다

  • aaa large (또는 large aaa)는 4.5로 계산됩니다

한 쌍의 색상에 대한 대비를 찾으려면, 먼저 그 색상들의 CIE 휘도(Y)를 D65 백색점에 상대적으로 계산합니다. 그런 다음 WCAG 2.1 대비를 계산합니다: contrast = (Yl + 0.05) / (Yd + 0.05) 여기서 Yd는 쌍에서 더 어두운 색상의 휘도이고 Yl은 더 밝은 색상의 휘도입니다. 계수 0.05는 관찰 플레어의 휘도 기여를 나타냅니다.

기준 색상이 다음과 같다고 가정합니다 
color(display-p3 0.38 0.11 0.05)

한편 목록의 첫 번째 색상 후보는 다음과 같습니다

yellow

계산은 다음과 같습니다:

  • color(display-p3 0.38 0.11 0.05)는 color(xyz 0.06191 0.03568 0.00463)이므로 상대 휘도는 0.03568입니다

  • yellow는 rgb(100% 100% 0%)이며, 이는 color(xyz 0.76998 0.92781 0.13853)이므로 상대 휘도는 0.92781입니다

  • 대비는 (0.92781 + 0.05) / (0.03568 + 0.05) = 11.4123입니다

2.2.2. 반투명 색상의 대비

이 섹션은 입력이 불투명 색상이어야 하는 대비 알고리즘에만 적용됩니다.

한 쌍의 색상에 대한 대비를 계산할 때:

  1. 배경색은 먼저 단순 알파 합성(Compositing 1 § 5.1 단순 알파 합성 참조)을 사용하여 불투명한 캔버스 색상 위에 블렌딩되어 불투명한 배경색을 찾습니다.

    #7358 이 계산에 적합한 불투명한 캔버스 색상을 찾습니다. 후보는 다음과 같습니다:

    • alpha = 1인 전경색

    • canvas 시스템 색상

    • 사용된 알고리즘에 대한 대비를 최소화하도록 계산된 다른 색상

  2. 그런 다음 전경색은 이 불투명한 배경색 위에 블렌딩되어 불투명한 전경색을 찾습니다.

3. 여러 색상 레이어링: color-layers() 함수

color-layers() 함수 표기법은 선택적인 <blend-mode>와 이어지는 두 개 이상의 <color> 레이어 목록을 받습니다.

구문은 다음과 같습니다:

<color-layers()> = color-layers([ <blend-mode>, ]? <color># )
테스트
  • color-layers-no-blend-mode.html (라이브 테스트) (소스)
  • color-invalid-color-layers-function.html (라이브 테스트) (소스)
  • color-valid-color-layers-function.html (라이브 테스트) (소스)

이는 이 레이어들을 합성한 결과인 <color>를 반환하며, Compositing 1 § 9.1.4 Source Over 합성 연산자와 지정된 <blend-mode>를 사용합니다.

<blend-mode>가 주어지지 않으면, normal blend-mode가 사용됩니다.

@@normal blend mode와 첫 번째 색상의 alpha가 1이 아닌 두 색상을 사용한 간단한 예제 추가
@@normal blend mode와 첫 두 색상의 alpha가 1이 아닌 세 색상을 사용한 간단한 예제 추가
@@normal blend mode와 둘 다 alpha가 1이 아닌 두 색상을 사용한 간단한 예제 추가
@@overlay blend mode와 첫 번째 색상의 alpha가 1이 아닌 두 색상을 사용한 예제 추가

4. <color> 값 해석

4.1. contrast-color() 값 해석

모든 <color> 매개변수가 각자의 색 공간에서 해당 색상으로 해석되면, 계산값은 승리 색상이며 CSS Color 4 § 15. <color> 값 해석에 따라 해석됩니다. 그렇지 않으면(함수에서 currentColor가 사용된 경우), 계산값은 각 구성요소가 계산된 contrast-color() 함수이며, 따라서 자식 요소로의 상속을 보존합니다.

예를 들어, 다음 값이 주어졌을 때 
contrast-color(rgb(179 213 230) tbd-bg wcag2(AA), cadetblue, hsl(200 83% 23%))

cadetblue와의 대비는 1.97이고, hsl(200 83% 23%)와의 대비는 6.09이며, 이는 AA의 값인 4.5를 초과합니다; 따라서 해석된 hsl 함수의 계산값을 가집니다:

rgb(10 75 107)

예를 들어, 현재 색상 값이 rgb(179 213 230)일 때, 다음 값은 

contrast-color(currentColor tbd-bg wcag2(AA), hsl(200 83% 23%), purple)

다음 계산값을 가집니다

contrast-color(currentColor tbd-bg wcag2(4.5), rgb(10 75 107), rgb(128 0 128))

4.2. color-layers() 값 해석

모든 <color> 매개변수가 각자의 색 공간에서 해당 색상으로 해석되면, 계산값은 합성된 색상이며 CSS Color 4 § 15. <color> 값 해석에 따라 해석됩니다. 그렇지 않으면(함수에서 currentColor가 사용된 경우), 계산값은 명시적인 <blend-mode>를 포함하고 각 구성요소가 계산된 color-layers() 함수이며, 따라서 자식 요소로의 상속을 보존합니다.

    이 명세에 대한 적합성은 세 가지 적합성 클래스에 대해 정의됩니다:

    스타일시트
    CSS 스타일시트.
    렌더러
    스타일시트의 의미를 해석하고 그것을 사용하는 문서를 렌더링하는 UA.

    저작 도구는 일반 CSS 문법과 이 모듈의 각 기능에 대한 개별 문법에 따라 구문적으로 올바르고, 이 모듈에 설명된 스타일시트의 다른 모든 적합성 요구사항을 충족하는 스타일시트를 작성하는 경우 이 명세에 적합합니다.

    부분 구현

    작성자가 순방향 호환 구문 분석 규칙을 활용하여 대체 값을 지정할 수 있도록, CSS 렌더러는 사용할 수 있는 수준의 지원이 없는 모든 @-규칙, 속성, 속성 값, 키워드 및 기타 구문 구조를 유효하지 않은 것으로 취급해야 하며(must), 적절하게 무시해야 합니다. 특히 사용자 에이전트는 하나의 다중 값 속성 선언에서 지원되지 않는 구성요소 값은 선택적으로 무시하고 지원되는 값은 반영해서는 안 됩니다 (must not): 어떤 값이라도 유효하지 않은 것으로 간주되면 (지원되지 않는 값은 그렇게 간주되어야 하므로), CSS는 전체 선언을 무시할 것을 요구합니다.

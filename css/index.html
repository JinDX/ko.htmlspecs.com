CSS 명세

이 페이지에는 CSS WG에서 완료한 모든 명세와 초안이 나와 있습니다. CSS 개발 과정을 따라가고 싶다면, 이곳에서 시작하면 됩니다. 아이디어가 있으신가요? 기여하고 싶으신가요? 이 페이지의 ‘도움을 주고 싶다면’를 참고하세요.

명세는 매뉴얼이 아닙니다. 초안이 잘못 작성되어 있다면, 반드시 불만을 제기해 주세요. 하지만 명세는 특정 독자를 대상으로 합니다. fantasai의 CSS 명세 이해하기를 참고하세요. J. David Eisenberg도 유용한 W3C 명세 읽는 법을 썼습니다. 또는 ‘모듈’, ‘레벨’, ‘스냅샷’ 및 CSS 프로세스에 대해 읽어볼 수도 있습니다.

속성 및 디스크립터 색인

CSS 스냅샷에는 표준 및 안정적인 속성 색인과 의사 클래스 및 의사 요소 그리고 @-규칙이 포함되어 있습니다.

CSS WG는 에디터 초안의 모든 속성 및 디스크립터의 알파벳순 목록을 제공합니다.

이 이름들은 W3C 프로세스 문서의 섹션 6에 정의되어 있습니다. REC는 일반적으로 ‘표준’이라 부릅니다. W3C는 CR 단계부터 일상적인 사용을 권장합니다.

명세를 그룹화하는 비공식 안정성 단계는 이 2007년 CSS 안정성 단계 설명에 정의되어 있습니다.

도움을 주고 싶다면

GitHub를 통해 이슈를 제기하세요. (먼저 GitHub 계정을 만들어야 합니다.) Github에는 CSS 명세와 ‘Houdini’ API의 에디터 초안 복사본이 있습니다.

기여자 가이드라인에서 CSS 명세 개발에 있어서 GitHub 이슈가 어떤 역할을 하는지 자세히 설명합니다.

특정 CSS 모듈에 대해 이슈를 제기한다면, 이슈 제목을 해당 명세 코드(‘이 문서의 상태’ 섹션에 명시됨)로 괄호로 감싸서 접두사로 붙여 주세요. 예: ‘[css3-flexbox] 마진 계산 오류’. 이렇게 하면 에디터가 의견을 더 쉽게 찾고 추적할 수 있습니다.

W3C 회원 기관에 근무한다면, CSS 작업 그룹에 가입해 회의에 참석할 수 있습니다. 참여하려면 평균적으로 주당 1일 정도의 시간을 할애해야 합니다. Chris Lilley와 귀 기관의 W3C AC 대표에게 연락하세요. 그룹의 회의록은 공개되며 CSS WG 블로그에 게시됩니다.

CSS WG의 새 출판물을 최신 상태로 유지하는 방법은 다양합니다. 위의 ‘새 소식?’ 섹션에서 최근 초안을 확인할 수 있으며, Atom 피드도 제공합니다. 출판 소식은 CSS WG 블로그와 Atom 피드, 그리고 그룹의 Mastodon 계정에서도 확인할 수 있습니다. 최초 초안은 모든 W3C 작업 그룹에서 public-review-announce 메일링 리스트와 RSS 피드를 통해 공개됩니다. 최신 W3C 작업 그룹 출판물은 기술 보고서 페이지 상단에서 볼 수 있으며, 이 페이지에도 가 있습니다.

아카이브된 메일링 리스트 www-style@w3.org에는 작업 그룹의 회의 안건과 회의록이 있습니다. 구독할 수 있습니다.

테스트 슈트에 대하여

CSS 작업 그룹은 CSS 테스트 슈트 개발에 많은 시간을 들이고 있습니다. 각 모듈이 공개되는 즉시 테스트 슈트를 제공함으로써 CSS 구현체가 더 빨리 명세를 준수할 수 있고, 명세의 공식 텍스트도 더 쉽게 이해할 수 있습니다.

이슈는 GitHub을 통해 제기하는 것이 가장 좋습니다: Web-platform tests 저장소를 참고하세요.

요약

이 모듈은 <image> 타입과 대체 요소와 관련된 CSS 레벨 4의 기능을 포함합니다. 이 모듈은 CSS 레벨 2 [CSS2]와 이전 명세의 [css-images-3] 기능을 포함하고 확장합니다. "CSS Images Module Level 3" [css-images-3]과 비교해 주요 확장점은 <image> 타입에 image() 표기법, element() 표기법, 그리고 코닉 그라디언트와 같은 여러 기능이 추가된 것입니다.

CSS는 구조화된 문서(예: HTML, XML)의 렌더링을 화면, 인쇄물 등에서 설명하는 언어입니다.

1. 소개

이 섹션은 규범적인 내용이 아닙니다.

이 모듈은 2D 이미지를 표현하는 다양한 방법을 소개합니다. 예를 들어 컬러 폴백이 있는 URL, 코닉 그라디언트, 또는 문서 내 다른 요소의 렌더링 등입니다.

1.1. 값 정의

이 명세는 CSS 속성 정의 규칙과 [CSS2]의 값 정의 문법을 [CSS-VALUES-3]에서 따릅니다. 이 명세서에 정의되지 않은 값 타입은 CSS Values & Units [CSS-VALUES-3]에서 정의됩니다. 다른 CSS 모듈과 조합하면 이러한 값 타입의 정의가 확장될 수 있습니다.

각 속성 정의에 명시된 속성별 값 외에도, 이 명세에서 정의된 모든 속성은 CSS-wide 키워드도 속성값으로 허용합니다. 가독성을 위해 반복해서 명시하지 않았습니다.

2. 2D 이미지 값: <image> 타입

<image> 값 타입은 2D 이미지를 나타냅니다. url 참조, image 표기법, 또는 gradient 표기법일 수 있습니다. 구문은 다음과 같습니다:

<image> = <url> | <image()> | <image-set()> | <cross-fade()> | <element()> | <gradient>

<image>는 다양한 CSS 속성에서 사용할 수 있습니다. 예를 들어 background-image, list-style-image, cursor 속성 [CSS2]에서 속성값의 <url> 구성요소를 대체하는 역할을 합니다.

일부 경우 이미지는 잘못된 경우가 있습니다. 예를 들어 <url>이 올바르지 않은 이미지 형식이거나 로딩에 실패한 리소스를 가리키는 경우입니다. 잘못된 이미지는 투명 단색 이미지로 렌더링되며 자연 크기가 없습니다. 하지만 잘못된 이미지는 일부 컨텍스트에서 에러 처리 절차를 트리거할 수 있습니다. 예를 들어 잘못된 이미지가 list-style-image 속성에 사용된다면, none으로 처리되어, list-style-type이 대신 렌더링됩니다. [CSS2]

이미지가 로딩 중일 때는 로딩 이미지입니다. 로딩 이미지는 잘못된 이미지가 아니지만, 비슷한 동작을 합니다. 투명 단색 이미지로 렌더링되고 자연 크기가 없으며, 폴백 렌더링이 제공되는 컨텍스트에서는 폴백이 렌더링될 수 있지만, 폴백 리소스의 로딩을 트리거해서는 안 됩니다. 반대로 로딩 이미지가 이미 로드된 이미지를 대체하는 경우 (예를 들어 문서나 스타일시트 변경으로 인해) 그리고 UA가 이 정보를 추적 중이라면, 로딩 이미지 대신 이미 로드된 이미지를 계속 렌더링할 수 있습니다.

부분적으로 로드된 이미지(자연 크기는 알려져 있지만 이미지 데이터가 완전히 로드되지 않은 경우)는 로딩 이미지로 취급하거나, 부분 데이터로 렌더링된 로드된 이미지로 처리할 수 있습니다. 예를 들어 UA는 인터레이스된 GIF의 첫 번째 패스 픽셀 데이터가 로드되면 즉시 렌더링하거나, 이미지 헤더(크기 정보가 들어있음)가 파싱되면 바로 렌더링한 후, 추가 데이터가 로딩될 때마다 렌더링을 갱신할 수도 있습니다. 또는 전체 이미지가 완전히 로드될 때까지 기다릴 수 있습니다.

계산된 <image> 값은 지정된 값에서 <url>, <color>, <length> 들이 계산된 값을 의미합니다.

2.1. 이미지 파일 형식

최소한, UA는 <image> 값에서 참조될 때, <image>가 유효한 모든 속성에 대해 다음 이미지 파일 형식을 지원해야 합니다:

  • PNG: [PNG] 명세 참조
  • SVG: [SVG11] 명세 참조, 보안 정적 모드 사용 ([SVG-INTEGRATION] 참고)
  • UA가 애니메이션 <image>를 지원하는 경우, SVG: [SVG11] 명세 참조, 보안 애니메이션 모드 사용 ([SVG-INTEGRATION] 참고)

UA는 추가적인 파일 형식도 지원할 수 있습니다.

2.2. 이미지 참조: url() 표기법

참고: [css-images-3]와 동일합니다.

2.3. 외부 이미지 가져오기

스타일시트를 위한 외부 이미지 가져오기를 실행할 때, url url과 CSSStyleSheet 시트를 받아서, 스타일 리소스 가져오기를 url로 실행합니다. 스타일시트 CSSStyleSheet, 목적지 "image", CORS 모드 "no-cors", 그리고 processResponse는 response res와 null, 실패, 또는 바이트 스트림 byteStream을 받아 다음 단계로 처리합니다: byteStream이 바이트 스트림이면, 해당 바이트 스트림에서 이미지를 로드합니다.

2.4. 해상도/타입 협상: image-set() 표기법

사용자의 기기에 가장 적합한 이미지 해상도를 제공하는 것은 어려운 작업일 수 있습니다. 이상적으로는 사용자가 이미지를 보는 기기와 동일한 해상도의 이미지를 제공해야 하지만, 이는 사용자마다 다를 수 있습니다. 그러나, 사용자가 느린 모바일 연결을 사용할 경우, 큰 고해상도 이미지를 기다리는 대신 저해상도 이미지를 선호할 수도 있습니다. image-set() 함수는 이러한 문제 대부분을 저자가 신경 쓰지 않고, 여러 해상도의 이미지를 제공한 후 UA가 상황에 맞게 가장 적합한 이미지를 선택하도록 할 수 있게 해줍니다.

이 솔루션은 해상도를 파일 크기의 대리(proxy)로 가정합니다. 따라서 벡터 이미지의 다중 해상도 세트나, 벡터와 래스터 이미지를 혼합하는 경우(예: 아이콘)에는 적절히 처리하지 못합니다. 예를 들어, 고해상도에는 벡터, 저해상도에는 픽셀 최적화된 비트맵, 저대역폭일 때는 다시 벡터를 사용(더 높은 해상도지만 파일 크기가 훨씬 작기 때문)하는 식입니다.

image-set()의 구문은 다음과 같습니다:

<image-set()> = image-set( <image-set-option># )
<image-set-option> = [ <image> | <string> ]
                     [ <resolution> || type(<string>) ]

HTML의 picture 요소 기능과 맞추기 위해 "w"와 "h" 치수를 추가해야 합니다.

<string>은 image-set() 안에서 <url>을 나타냅니다.

image-set() 함수는 자체적으로 중첩될 수 없습니다. 직접적으로나 간접적으로 (다른 <image> 타입의 인자로 들어가는 경우 포함).

<image-set-option> 각각은 image-set() 함수가 표현할 수 있는 이미지 후보를 정의하며, 세 부분으로 구성됩니다:

  • 이미지 참조(필수). URL이거나, linear-gradient() 같은 CSS 생성 이미지일 수 있습니다.

  • <resolution> (선택). UA가 어떤 <image-set-option>을 선택할지 결정하는 데 도움을 줍니다. 이미지 참조가 래스터 이미지인 경우, 이미지의 자연 해상도도 지정하며, 다른 데이터 소스가 자연 해상도를 공급하더라도 덮어씁니다.

    지정되지 않은 경우, 어떤 <image-set-option>을 선택할지 결정할 때 1x처럼 동작합니다. 또한 이미지의 자연 해상도도 1x로 기본값을 사용하지만, 다른 데이터 소스가 자연 해상도를 제공하면 그 값을 우선합니다.

  • type( <string> ) 함수(선택), <string>에 이미지의 MIME 타입을 지정합니다.

    <string>이 유효한 MIME 타입 문자열로 파싱했을 때, 유효하지 않거나, 유효하지만 지원되는 이미지 포맷을 지정하지 않으면, <image-set-option>은 유효한 옵션이 아닙니다. (이것은 image-set() 함수의 유효성에는 영향을 주지 않습니다.)

    이미지 자체에는 영향이 없습니다; <image-set-option> 예시 url("picture.png") 1x type("image/jpeg") 는 유효하며 선택되면 링크된 PNG 이미지를 보여줍니다. 비록 JPEG로 선언되었더라도 PNG가 렌더링됩니다.

    지정되지 않으면, <image-set-option>에 영향이 없습니다.

image-set() 함수에는 하나 이상의 <image-set-option> 리스트가 포함되며, 이 중 반드시 하나만 선택해 어떤 이미지를 나타낼지 결정해야 합니다:

  1. 먼저, <image-set-option> 중 type() 값에 알 수 없거나 지원하지 않는 MIME 타입을 지정한 옵션은 리스트에서 제거합니다.

  2. 두 번째로, <image-set-option> 중 이전 옵션과 동일한 <resolution> 값을 가진 옵션도 리스트에서 제거합니다.

  3. 마지막으로, 남은 <image-set-option> 중에서 UA가 적합하다고 판단하는 기준(예: 디스플레이 해상도, 연결 속도 등)에 따라 어떤 이미지를 로드할지 UA가 결정합니다.

  4. image-set() 함수는 최종적으로 선택된 <image>의 <image-set-option>을 나타냅니다.

UA는 페이지 생애주기 동안 <image-set-option> 선택 기준이 충분히 바뀐 경우, image-set()에서 사용할 옵션을 변경할 수 있습니다.

이 예시는 image-set()을 사용해 이미지를 세 가지 버전으로 제공하는 방법을 보여줍니다: "일반" 버전, "고해상도" 버전, 그리고 고품질 인쇄용 초고해상도 버전 (프린터는 매우 높은 해상도를 가질 수 있습니다): 
background-image: image-set( "foo.png" 1x,
                             "foo-2x.png" 2x,
                             "foo-print.png" 600dpi );
이 예시는 type() 함수를 사용해 동일한 이미지의 여러 버전을 새로운 고품질 포맷과 오래된 널리 지원되는 포맷으로 제공하는 방법을 보여줍니다: 
background-image: image-set( "foo.avif" type("image/avif"),
                             "foo.jpg" type("image/jpeg") );

AVIF 이미지는 첫 번째로 제공됩니다. 두 이미지 모두 해상도가 지정되지 않아 기본값 1x이 적용되므로, JPEG 이미지는 두 번째에 오기 때문에 AVIF 이미지를 지원하는 UA에서는 자동으로 제외됩니다.

하지만 오래된 UA에서는 AVIF 이미지는 무시되고 ("image/avif" 파일을 지원하지 않으므로), 대신 JPEG이 선택됩니다.

래스터 이미지는 벡터 이미지나 CSS 생성 이미지와 혼합할 수 있습니다.

예를 들어, 이 코드에서는 고해상도 화면에서는 디테일이 섬세한 이미지를 사용하고, 저해상도 상황에서는 일반 CSS linear-gradient()를 대신 사용합니다:

background-image: image-set( linear-gradient(cornflowerblue, white) 1x,
                             url("detailed-gradient.png") 3x );

2.5. 이미지 폴백 및 주석: image() 표기법

image() 함수는 저자가 다음을 할 수 있도록 합니다:

  • 미디어 프래그먼트를 사용해 이미지의 일부를 잘라내기

  • 단색 이미지를 사용하기

  • 지정된 url의 이미지를 다운로드하거나 디코드할 수 없을 때 단색 이미지로 폴백하기

  • 이미지 메타데이터에 지정된 이미지 방향을 자동으로 존중하기

image() 표기법은 다음과 같이 정의됩니다:

image() = image( <image-tags>? [ <image-src>? , <color>? ]! )
<image-tags> = [ ltr | rtl ]
<image-src> = [ <url> | <string> ]

<string>은 image()에서 사용될 때 <url>을 나타냅니다. CSS에서 URL과 마찬가지로, 상대 URL은 절대 URL로 변환됩니다 (Values & Units [CSS-VALUES-3]에 설명된 대로) 지정된 image() 값이 계산될 때 적용됩니다.

이미지에 EXIF 등 메타데이터에서 지정된 방향 정보가 있다면, UA는 메타데이터에 명시된 대로 이미지를 회전 또는 뒤집어 올바른 방향으로 렌더링해야 합니다.

2.5.1. 이미지 폴백

URL과 <color> 둘 다 image()에 지정된 경우, URL이 잘못된 이미지 또는 로딩 이미지를 나타내면, image() 함수는 URL이 지정되지 않은 것처럼 렌더링합니다. § 2.5.3 단색 이미지에서 지정된 대로 단색 이미지를 생성합니다.

URL만 지정되고 (<color> 미지정), 그 URL이 잘못된 이미지나 로딩 이미지를 나타내면, image() 함수도 동일하게 동작합니다.

폴백 색상은 이미지가 로드되지 않아도 텍스트를 읽을 수 있게 해줍니다. 예를 들어, 아래와 같은 레거시 코드는 이미지가 직사각형이고 투명도가 없는 경우에는 잘 동작합니다: 
body      { color: black; background: white; }
p.special { color: white; background: url("dark.png") black; }

이미지가 로드되지 않을 때도, 배경색이 유지되어 흰색 텍스트를 읽을 수 있습니다. 하지만 이미지에 투명 부분이 있다면, 그 뒤의 검은색이 보여서 원치 않는 결과가 나올 수 있습니다. image() 함수는 이런 문제를 해결합니다: 

body      { color: black; background: white; }
p.special { color: white; background: image("dark.png", black); }

이제 이미지를 정상적으로 로드하면 검은색이 전혀 보이지 않고, 이미지가 로드되지 않을 경우에만 검은색이 나타나서 흰색 텍스트가 흰색 배경 위에 놓이지 않도록 보호해줍니다.

2.5.2. 이미지 프래그먼트

image()에 지정된 URL이 리소스의 일부를 나타낼 때 (예: 미디어 프래그먼트 식별자 사용) 해당 부분만 잘려나와 독립적인 이미지로 사용됩니다.

예를 들어, 아래 이미지와 CSS가 있다고 가정합니다: 

background-image: image('sprites.svg#xywh=40,0,20,20')

...이 경우 해당 요소의 배경은 이미지의 (40px,0px) 위치에서 시작해서 20px 너비와 높이를 갖는 영역, 즉 1/4이 채워진 원만 표시됩니다.

작성자가 CSS의 forward-compat 파싱 규칙을 활용해 이미지 슬라이스 폴백을 제공할 수 있도록, image() 표기법을 지원하는 구현체는 반드시 xywh=#,#,#,# 형식의 미디어 프래그먼트 식별자를 image()로 지정한 이미지에 대해 지원해야 합니다. [MEDIA-FRAGS]

참고로 이미지 프래그먼트는 url() 표기법에서도 사용할 수 있습니다. 하지만 미디어 프래그먼트 표기법을 이해하지 못하는 레거시 UA는 프래그먼트를 무시하고 전체 이미지를 표시합니다.

image() 표기법은 UA가 미디어 프래그먼트를 지원해야 하므로, 작성자는 이미지 프래그먼트 URL을 사용할 때 CSS의 forward-compat 파싱 규칙을 활용해 폴백을 제공할 수 있습니다:

background-image: url('swirl.png'); /* 구버전 UA용 */
background-image: image('sprites.png#xywh=10,30,60,20'); /* 신버전 UA용 */

URL이 구현체가 이해하지 못하거나 해당 이미지 타입에 대해 유효하지 않다고 간주하는 프래그먼트 식별자 문법을 사용하면, 해당 URL은 invalid image로 처리되어야 합니다.

Note: 이 에러 처리는 image()에만 해당하며, URL 정의에는 적용되지 않습니다(레거시 호환성 이유).

2.5.3. 단색 이미지

image() 함수가 <color> 인자만 지정된 경우(URL 없음), 지정된 색상의 단색 이미지로, natural dimensions가 없습니다.

예를 들어, 배경 이미지를 "틴트" 처리하는 간단한 방법으로 반투명 색상을 다른 이미지 위에 덮어 씌울 수 있습니다: 
background-image: image(rgba(0,0,255,.5)), url("bg-image.png");

background-color는 이 목적에는 사용할 수 없습니다. 왜냐하면 생성된 단색은 항상 모든 배경 이미지 아래에 위치하기 때문입니다.

2.5.4. Bidi(양방향) 민감 이미지

<image-src>s를 나열하기 전에, 작성자는 이미지 방향성을 지정할 수 있습니다. 이는 HTML 요소에 dir 속성을 추가하는 것과 비슷합니다. 방향성 이미지를 상위 또는 내부 요소의 direction과 반대 방향에서 사용할 경우, 이미지는 인라인 방향으로 뒤집혀야 합니다 (예: 인라인 방향이 X축이면 scaleX(-1)로 변형한 것처럼).

Note: 선언이 없으면 이미지는 기본적으로 방향성이 없으며, 주변 요소의 방향성과 관계없이 표시됩니다.

리스트에서 콘텐츠 쪽으로 향하는 화살표 이미지를 불릿으로 사용할 수 있습니다. 리스트에 LTR과 RTL 텍스트가 모두 포함될 수 있다면, 불릿은 왼쪽이나 오른쪽에 있을 수 있습니다. 한쪽에 맞춘 이미지가 반대쪽에서는 콘텐츠 밖을 가리킬 수 있습니다. 아래와 같은 코드로 해결할 수 있습니다: 
<ul style="list-style-image: image(ltr 'arrow.png');">
  <li dir='ltr'>My bullet is on the left!</li>
  <li dir='rtl'>MY BULLET IS ON THE RIGHT!</li>
</ul>

렌더링 결과는 다음과 같습니다:

⇒ My bullet is on the left!
  !THGIR EHT NO SI TELLUB YM ⇐

LTR 리스트 아이템에서는 이미지를 그대로 사용합니다. RTL 리스트 아이템에서는 인라인 방향으로 뒤집혀 여전히 콘텐츠 쪽을 가리키게 됩니다.

2.6. 이미지 결합: cross-fade() 표기법

이미지 간 전환을 할 때, CSS에서는 시작과 끝 이미지를 조합한 중간 이미지를 명확하게 참조할 수 있는 방법이 필요합니다. 이 작업은 cross-fade() 함수로 이루어집니다. 이 함수는 결합할 두 이미지를 지정하고, 전환이 얼마나 진행되는지 나타냅니다.

Note: 작성자는 cross-fade() 함수를 단색으로 이미지 틴트 처리, 혹은 이미지를 방사형 그라디언트와 결합해 특정 영역을 강조하는 등 다양한 간단한 이미지 조작에도 사용할 수 있습니다.

cross-fade()의 구문은 다음과 같이 정의됩니다:

cross-fade() = cross-fade( <cf-image># )
<cf-image> = <percentage [0,100]>? && [ <image> | <color> ]

이 함수는 하나 이상의 이미지를 결합해 생성된 이미지를 나타냅니다.

<percentage>는 각 이미지를 결합할 때 얼마나 남기는지 나타냅니다. <percentage> 값은 0%부터 100%까지여야 하며, 이 범위를 벗어나면 무효입니다.

퍼센트가 생략된 경우, 모든 지정된 퍼센트 값을 합산한 뒤 100%에서 빼고, 결과값이 0% 미만이면 바닥값을 적용, 생략된 이미지들에 균등하게 나누어 계산값 시점에 할당합니다.

이것은 계산된 값에 반영되지는 않지만, 모든 인자의 백분율 합이 100%을 초과할 때, 크기/페인팅 처리에서 이 값들을 재조정하여 정확히 100%이 되도록 만듭니다.

반대로, 합이 100% 미만일 때는 크기/페인팅 처리에서 추가로 transparent 인자가 있는 것처럼 동작하며, 남는 백분율 값을 할당하여 합이 100%이 되도록 합니다.

<color> 인자가 제공된 경우, 해당 값은 "자동" 크기를 가지는 단색 이미지를 나타냅니다. (결과 이미지의 크기 결정에는 전혀 관여하지 않습니다. 자세한 내용은 아래의 크기 세부사항 참고)

2.6.1. cross-fade() 크기 계산

cross-fade()로 표현되는 이미지의 크기는 함수에 전달된 <image> 인자들의 크기를 백분율로 가중평균한 값입니다. <color> 인자는 크기에 영향을 주지 않습니다. 계산 방법은 다음과 같습니다:

cross-fade()의 natural dimensions을 결정하려면:

  1. images를 빈 리스트로 둡니다.

  2. cross-fade() 함수의 각 argument가 <image> 값일 경우:

    1. item을 너비, 높이, 백분율로 이루어진 tuple로 만듭니다.

    2. object size negotiation 알고리즘을 해당 <image>에 대해 실행합니다. 이때 cross-fade()가 나타나는 문맥에 맞게 처리하며, item의 너비와 높이를 결과 concrete object size의 너비와 높이로 설정합니다.

    3. item의 백분율을 argument의 백분율로 설정합니다.

  3. images가 비어있으면, natural dimensions을 반환하지 않습니다.

  4. percentage sum을 images의 모든 item들의 백분율 합으로 둡니다.

  5. 각 item에 대해, item의 백분율을 percentage sum으로 나누고, 그 결과값을 item의 백분율로 설정합니다.

    단언: 이제 images의 백분율 합은 100%입니다.

  6. final width와 final height를 0px으로 둡니다.

  7. 각 item에 대해, item의 너비에 백분율을 곱한 값을 final width에 더하고, item의 높이에 백분율을 곱한 값을 final height에 더합니다.

  8. final width와 final height을 natural width, natural height로 반환합니다.

2.6.2. cross-fade() 페인팅

cross-fade()로 표현되는 이미지는 함수 인자들의 가중 평균으로 계산됩니다. 계산 방법은 다음과 같습니다:

cross-fade()의 appearance of a cross-fade()를 결정하려면:

  1. images를 빈 리스트로 둡니다.

  2. size를 너비와 높이로 이루어진 tuple로 두고, concrete object size를 계산하여 초기화합니다. (cross-fade()의 natural dimensions 사용)

  3. cross-fade() 함수의 각 argument에 대해:

    1. item을 이미지와 백분율로 이루어진 tuple로 만듭니다.

    2. argument가 <image>라면, size의 너비와 높이로 리스케일하여 item의 이미지로 설정합니다. 아니면 argument가 <color>라면, item의 이미지를 <color>의 단색 이미지로 하고, size의 크기로 만듭니다.

    3. item의 백분율을 argument의 백분율로 설정합니다.

  4. percentage sum을 images의 모든 item들의 백분율 합으로 둡니다.

  5. percentage sum이 100% 미만이면, images에 단색 투명-검정 이미지를 추가하고, size의 크기로 만들며, 백분율은 100%에서 percentage sum을 뺀 값으로 설정합니다.

    반대로 percentage sum이 100%을 초과하면, 각 item의 백분율을 percentage sum으로 나누어 재설정합니다.

  6. final image를 size의 크기로 만들고, images의 각 item의 이미지를 해당 백분율대로 가중 평균하여 모든 픽셀을 계산합니다. (색상 채널과 알파 채널 모두 평균합니다.) 이 계산에서 각 픽셀의 색상은 pre-multiplied sRGB여야 합니다.

    위 연산의 세부 사항

    이것은 N-way Porter-Duff dissolve 연산을 소스 이미지에 적용하는 것입니다. 위키백과에 따르면 dissolve는 확률적 방법으로 결과 픽셀을 각 소스 이미지의 가중치에 따라 독립적으로 임의 선택하여 만듭니다. 하지만 픽셀 크기가 무한히 작아지면, 이는 pre-multiplied 색 공간에서 색상을 평균내는 것과 같습니다.

    특히 `cross-fade(white 50%, transparent 50%)`는 부분 투명한 단색 흰 이미지를 만듭니다. (불투명 흰색과 투명 검정 픽셀을 단순 평균하면 부분 투명한 회색이 되지만, pre-multiplied 공간에서는 흰색이 됩니다.)

    pre-multiplied 변환에는 정밀도 손실이 있을 수 있고, 그래픽 라이브러리가 이 연산을 네이티브로 지원하지 않을 수도 있지만, 결과 효과만 맞으면 어떤 방법을 써도 괜찮습니다.

    예를 들어, 각 픽셀의 알파 값을 기준으로 백분율을 재조정한 후 색상 채널의 평균을 non-premultiplied 공간에서 계산할 수 있습니다. 예: cross-fade(rgb(255 0 0 / 1) 40%, rgb(0 255 0 / .5) 20%, rgb(0 0 255 / 0) 40%)를 렌더링하려면, 알파 1 / .5 / 0 기준으로 백분율을 40% / 10% / 0%로 재조정하고, 다시 정규화하면 80% / 20% / 0%가 됩니다. 이렇게 하면 원시 색상 채널 값을 평균내어 rgb(204 51 0 / .5) 이미지를 얻을 수 있습니다. (알파 채널은 원래 백분율로 평균냅니다.)

  7. final image를 반환합니다.

2.6.3. 복잡한 cross-fade() 단순화

WG 결의에 따라, 이미지의 "동등성" 개념을 정의하고, 계산 값 단계에서 동일한 이미지를 합쳐 그들의 백분율을 합산해야 합니다.

WG 결의에 따라, 계산 값 단계에서 cross-fade()가 직접 중첩된 경우 백분율을 분배하고 평탄화해서 단순화해야 합니다. 즉, cross-fade(A 10%, cross-fade(B 30%, C 70%) 90%)는 cross-fade(A 10%, B 27%, C 63%)로 변환됩니다.

2.7. 요소를 이미지로 사용하기: element() 표기법

element() 함수는 문서 내의 요소를 이미지로 사용할 수 있게 해줍니다. 참조된 요소의 외형이 바뀌면, 이미지도 그에 따라 바뀝니다. 예를 들어, 슬라이드쇼에서 다음/이전 슬라이드의 실시간 미리보기를 만들거나, 캔버스 요소를 참조하여 고급 그라디언트나 애니메이션 배경을 만드는 데 사용할 수 있습니다.

참고: element() 함수는 참조된 요소의 외관만 재현하며, 실제 내용이나 구조는 재현하지 않습니다. 저자는 이 기능을 장식용으로만 사용해야 하며, 중요한 콘텐츠를 페이지 곳곳에 복제하는 용도로 element()를 사용해서는 안 됩니다. 대신, 요소를 문서에 여러 번 삽입하세요.

element()의 문법은 다음과 같습니다:

element() = element( <id-selector> )

<id-selector>는 ID 선택자입니다 [SELECT].

외부 문서(SVG 페인트 서버 등)의 요소를 참조할 필요가 있을까요? 아니면 그냥 url()만 사용해도 충분할까요?

이 이름은 GCPM의 유사 함수와 충돌합니다. 이 문제를 해결해야 합니다.

요소를 "반사"해서 배경 이미지 또는 가상 요소로 사용하고 싶습니다. 사이클 감지를 방지하기 위해 특별 처리해야 합니다.

overflow:paged일 때, 뷰에서 특정 페이지만 지정하려면 어떻게 해야 할까요?

element() 함수는 인자로 전달된 요소를 참조합니다. ID는 먼저 elementSources 맵에서 찾으며, 해당 섹션에 설명된 대로 동작합니다. 맵에서 찾지 못하면, 문서 전체에서 검색합니다. 여러 요소가 매칭되면, 가장 먼저 매칭된 요소를 참조합니다.

element() 함수로 표현되는 이미지는 그 요소가 문서에 보이는지 여부에 따라 다를 수 있습니다:

렌더링되는 요소이자, 대체 요소의 자손이 아니며, 스태킹 컨텍스트를 생성하는 경우
함수는 참조된 요소의 장식 경계 상자와 동일한 natural size를 가진 이미지를 나타냅니다:
  • CSS 렌더링 모델로 렌더링된 요소의 경우, 장식 경계 상자는 프린시펄 박스의 모든 프래그먼트의 border image area를 포함하는 최소 축 정렬 사각형입니다.
  • SVG 렌더링 모델 요소라면, SVG에서 정의된 장식 경계 상자입니다.

참고: 이미지는 기본적으로 경계 밖을 클리핑하므로, 장식 경계 상자 밖으로 확장되는 데코레이션(예: 그림자 등)은 잘릴 수 있습니다.

이미지는 참조된 요소와 그 자손을 (문서에서의 크기와 동일하게) 무한 투명 캔버스에 렌더링하여 만듭니다. 이때 장식 경계 상자의 가장자리가 이미지의 가장자리에 맞닿게 위치시킵니다.

요소에 어느 정도의 스태킹 컨텍스트가 필요하다는 점이 효율적인 구현에 필요해 보입니다. 완전한 스태킹 컨텍스트가 필요한가요, 아니면 의사 스태킹 컨텍스트면 충분한가요? 평소에도 스태킹 컨텍스트여야 하나, element()로 렌더링할 때만 스태킹 컨텍스트로 처리해도 될까요?

참조된 요소나 조상에 변형(transform)이 적용되어 있으면, 이미지를 렌더링할 때 해당 변형은 무시해야 합니다. [CSS3-TRANSFORMS]

참조된 요소가 여러 페이지에 걸쳐 분할된 경우, 각 페이지의 edge가 초기 포함 블록의 시작 edge에 맞게, 페이지 콘텐츠 영역을 페이지 방향으로 붙인 것처럼 표시합니다. 줄 또는 컬럼에 걸쳐 분할된 요소는 그냥 장식 경계 상자로 렌더링합니다.

구현체는 참조 요소에 대해 기존 비트맵 데이터를 재사용하거나 이미지 크기에 맞춰 품질을 극대화하기 위해 다시 렌더링할 수 있습니다. (예를 들어 참조 요소가 SVG 프래그먼트임을 감지한 경우) 이 경우에도, 이미지 내에서 참조된 요소의 레이아웃이 변경되어서는 안 됩니다. 즉, 이미지는 참조한 요소와 동일하게 보여야 하며, 래스터화 품질만 다를 수 있습니다.

조금 재미있는 예시로, p 요소를 문서 내 다른 곳의 배경으로 재사용할 수 있습니다:

<style>
#src { color: white; background: lime; width: 300px; height: 40px; position: relative; }
#dst { color: black; background: element(#src); padding: 20px; margin: 20px 0; }
</style>
<p id='src'>나는 평범한 요소입니다!</p>
<p id='dst'>나는 이전 요소를 배경으로 사용합니다!</p>

렌더링되지 않는 요소이지만 페인트 소스를 제공하는 경우
함수는 natural dimensions와 페인트 소스의 외형을 가진 이미지를 나타냅니다. 호스트 언어가 페인트 소스의 크기와 외형을 정의합니다.
예를 들어, element() 함수는 HTML 문서 내의 SVG <pattern> 요소를 참조할 수 있습니다: 
<!DOCTYPE html>
<svg>
  <defs>
    <pattern id='pattern1'>
      <path d='...'>
    </pattern>
  </defs>
</svg>
<p style="background: element(#pattern1)">
  나는 패턴을 배경으로 사용합니다!
  패턴이 변경되거나 애니메이션 된다면,
  내 배경도 함께 업데이트됩니다!
</p>

HTML에서는 canvas, img, video 요소가 페인트 소스를 제공합니다. 즉, CSS는 예를 들어 페이지에 표시되지 않는 캔버스를 참조할 수 있습니다: 

<!DOCTYPE html>

</script>
<canvas id='animated-bullet' style='display:none'></canvas>
<ul style="list-style-image: element(#animated-bullet);">
  <li>나는 캔버스를 불릿으로 사용합니다!</li>
  <li>나도 그렇습니다!</li>
  <li>Javascript로 시간이 지나면서 캔버스가 변경되면,

</ul>

함수는 잘못된 이미지를 나타냅니다.

예를 들어, 아래의 모든 element() 사용은 투명한 배경을 반환합니다: 

<!DOCTYPE html>
<p id='one' style="display:none; position: relative;">one</p>

</iframe>

  </li>
  <li style="background: element(#two);">

  </li>

요소가 박스를 가지고 있지 않다면 렌더링되지 않음 상태입니다. 예를 들어, 해당 요소나 조상 요소가 display:none일 때 이런 일이 발생할 수 있습니다. 호스트 언어는 요소가 렌더링되지 않은 것으로 간주되는 추가 조건을 정의할 수 있습니다; 예를 들어, SVG에서 <defs> 요소의 모든 자손은 렌더링되지 않은 것으로 간주됩니다.

element() 함수는 다양한 용도로 사용할 수 있습니다. 예를 들어, 슬라이드쇼에서 이전/다음 슬라이드 미리보기를 표시할 때 사용할 수 있습니다:

  document.querySelector('#next-slide').id = '';
  currentSlide.previousElementSibling.id = 'prev-slide';
  currentSlide.nextElementSibling.id = 'next-slide';
}
</script>
<style>
.slide {
  /* element()로 사용하려면 stacking context가 필요합니다. */
  position: relative;
}
#prev-preview, #next-preview {
  position: fixed;
  ...
}
#prev-preview { background: element(#prev-slide); }
#next-preview { background: element(#next-slide); }
</style>
<a id='prev-preview'>이전 슬라이드</a>
<a id='next-preview'>다음 슬라이드</a>
<section class='slide'>...</section>
<section class='slide current-slide'>...</section>
...

이 예시에서 navigateSlides 함수는 다음/이전 슬라이드의 id를 업데이트하고, 이 값들은 슬라이드 옆에 작은 플로팅 박스로 표시됩니다. element() 함수로 슬라이드를 직접 조작할 수 없으므로(이미지로만 표현됨), 미리보기 박스에 click 핸들러를 추가해 페이지 이동에 활용할 수도 있습니다.

2.7.1. 페인트 소스(Paint Sources)

호스트 언어는 일부 요소가 페인트 소스를 제공한다고 정의할 수 있습니다. 페인트 소스는 고유한 외형을 가지고 있으며, 레이아웃이나 렌더링 없이 concrete object size를 얻을 수 있어, 렌더링되지 않은 상태에서도 이미지로 사용할 수 있습니다.

HTML에서 img, video, canvas 요소가 페인트 소스를 제공합니다.

SVG에서는 paint server를 제공하는 모든 요소가 페인트 소스입니다. 참고: SVG1.1에서 <linearGradient>, <radialGradient>, <pattern> 요소가 페인트 소스를 제공합니다. 이들은 명세에서 설명한 대로 그려지며, 좌표계는 다음과 같이 정의됩니다:

objectBoundingBox
좌표계의 원점은 그려지는 concrete object size의 직사각형 좌상단이고, 너비와 높이도 concrete object size와 같습니다. 하나의 user coordinate가 concrete object size의 너비와 높이입니다.
userSpaceOnUse
좌표계의 원점은 그려지는 concrete object size의 직사각형 좌상단이고, 너비와 높이도 concrete object size와 같습니다. User coordinates는 CSS px 단위와 동일한 크기입니다.

참고: 향후 버전에서는 외부 문서에 있는 페인트 소스를 참조하거나, 스크립트로만 만들어져 문서에 삽입되지 않은 페인트 소스를 참조하는 방법이 정의될 수 있습니다.

2.7.2. 문서 밖 소스 사용: ElementSources 인터페이스

element() 함수는 일반적으로 문서 내 요소를 선택하지만, 페인트 소스를 제공하는 요소는 반드시 문서에 있어야 하는 것은 아닙니다. 예를 들어, HTML canvas 요소는 스크립트로만 생성, 관리, 그릴 수 있으며 문서에 직접 삽입할 필요가 없습니다.

필요한 것은 요소를 참조할 수 있는 방법뿐이며, ID 선택자는 문서 밖의 요소를 선택할 수 없습니다. elementSources Map 객체가 이를 제공합니다. 

partial namespace CSS {
  [SameObject] readonly attribute any elementSources;
};

elementSources 맵에 문자열 키와 페인트 소스를 제공하는 객체 값이 있으면 element() 함수에서 사용할 수 있습니다.

element()가 <id-selector>를 사용할 때, ID 값(앞의 # 문자 제외)은 먼저 elementSources 맵에서 조회됩니다:

  • 조회 결과, 연결된 객체가 페인트 소스를 제공하면, element() 함수는 해당 페인트 소스를 나타냅니다.
  • 조회 결과, 연결된 객체가 페인트 소스를 제공하지 않을 경우, element() 함수는 잘못된 이미지를 나타냅니다.
  • 맵에 ID가 전혀 없다면, 평소처럼 문서에서 찾습니다.

이 ID 셀렉터 재사용은 Moz의 동작과 일치합니다. 저는 구문의 맨 앞에 <custom-ident>를 넣는 걸 피하려고 하는데, 이렇게 하면 구문 공간을 너무 많이 차지하게 됩니다. 또 다른 방법으로는, 값의 맨 앞에 언어 정의 키워드를 따라서 <custom-ident>와 함께 시작하는 것이 있습니다. 예를 들어 element(external fancy)와 같은 것처럼요. 네이밍 제안 환영합니다.

예를 들어, 외부 캔버스를 사용해 멋진 애니메이션 배경을 만들 수 있습니다: 
<script>
var bg = document.createElement('canvas');
bg.height = 200;
bg.width = 1000;
drawFancyBackground(bg);
CSS.elementSources.set('fancy', bg);
</script>
<style>
h1 {
  background-image: element(#fancy);
}
</style>

"fancy" 캔버스에 그려지거나 애니메이션 되면, 모든 H1 요소의 배경도 자동으로 함께 업데이트됩니다.

elementSources 맵은 문서보다 먼저 ID 셀렉터를 확인하므로, 문서에 #fancy와 일치하는 요소가 있어도, 배경은 항상 elementSources 값에서 예측 가능하게 가져오게 됩니다.

2.7.3. 순환 감지(Cycle Detection)

element() 함수는 자기 자신을 배경으로 사용하는 등 의미 없는 순환 관계를 만들 수 있습니다. 이러한 관계는 의존성 그래프를 관리하고 일반적인 사이클 감지 알고리즘을 사용하면 쉽게, 안정적으로 감지 및 해결할 수 있습니다.

의존성 그래프의 에지는 다음과 같이 구성됩니다:

  • 모든 요소는 자신의 자식 요소에 의존합니다
  • 어떤 요소 A가 element() 함수를 사용해 요소 B를 참조하는 속성을 가지고 있다면, A는 B에 의존합니다
  • 호스트 언어가 다른 요소의 렌더링을 참조하는 방법을 정의하면, 참조하는 요소는 참조된 요소에 의존합니다. 예를 들어, SVG에서는 <use> 요소가 참조한 요소에 의존합니다.

그래프에 순환이 존재하면, 해당 사이클에 참여하는 모든 element() 함수는 잘못된 이미지가 됩니다.

3. 그라디언트

그라디언트는 한 색상에서 다른 색상으로 부드럽게 변화하는 이미지입니다. 이는 배경 이미지, 버튼 등에서 미묘한 음영 처리를 위해 자주 사용됩니다. 이 섹션에서 설명하는 gradient 함수는 작성자가 간결한 구문으로 이러한 이미지를 지정할 수 있게 하며, UA가 페이지를 렌더링할 때 이미지를 자동으로 생성할 수 있도록 해줍니다. <gradient>의 구문은 다음과 같습니다: 

<gradient> = [
  <linear-gradient()> | <repeating-linear-gradient()> |
  <radial-gradient()> | <repeating-radial-gradient()> |
  <conic-gradient()>  | <repeating-conic-gradient()> ]

이 명세에서 정의된 다른 <image> 타입과 마찬가지로, 그라디언트는 이미지를 허용하는 모든 속성에서 사용할 수 있습니다. 예시:

  • background: linear-gradient(white, gray);
  • list-style-image: radial-gradient(circle, #006, #00a 90%, #0000af 100%, white 100%)

그라디언트는 concrete object size의 크기를 가진 박스에 그려지며, 이를 gradient box라고 합니다. 그러나 그라디언트 자체는 natural dimensions를 갖지 않습니다.

예를 들어, 그라디언트를 배경으로 사용할 때 기본적으로 그라디언트는 요소의 패딩 박스 크기의 gradient box에 그려집니다. background-size가 100px 200px과 같이 명시적으로 지정되면, gradient box는 100px 너비와 200px 높이를 갖게 됩니다. 마찬가지로 list-style-image로 그라디언트를 사용할 때는 박스가 1em의 정사각형이 되며, 이는 해당 속성의 기본 객체 크기입니다.

그라디언트는 시작점과 끝점을 지정하고, gradient line(그라디언트 타입에 따라 실제로는 선, 반지, 나선 등일 수 있음)에 여러 위치에 색상을 지정합니다. 색상은 이 선을 따라 부드럽게 혼합되며, 각 그라디언트 타입은 gradient line의 색상을 어떻게 실제 그라디언트로 변환할지 정의합니다.

3.1. 선형 그라디언트: linear-gradient() 표기법

이 레벨에서는 <color-interpolation-method> 인자가 linear-gradient()와 repeating-linear-gradient()에 추가되었습니다. 이는 그라디언트 라인에서 색상 보간에 사용할 색 공간과 경로를 지정합니다. 자세한 내용은 CSS Color 4 §  12. 색상 보간을 참고하세요. 

linear-gradient() = linear-gradient(
  [ [ <angle> | to <side-or-corner> ] || <color-interpolation-method> ]? ,
  <color-stop-list>
)
<side-or-corner> = [left | right] || [top | bottom]

3.1.1. 색 공간이 보간에 미치는 영향: 예시

이 섹션은 규범적이지 않습니다.

색 공간이 보간에 미치는 영향은 상당할 수 있습니다.

이 예시에서는 같은 두 색상(#f01, #081) 사이의 선형 그라디언트가 세 가지 색 공간에서 그려집니다. 가운데 그라디언트는 감마 인코딩된 sRGB를 사용하며, 이는 CSS Images 3에서 유일한 선택지였습니다; 결과는 중간 지점이 확실히 너무 어둡게 나타납니다. 위쪽 그라디언트는 CIE Lab을 사용하여 더 지각적으로 균일한 결과를 보여줍니다; 아래쪽 그라디언트는 Oklab으로, 여기서는 CIE Lab과 거의 동일한 결과를 줍니다.

  • linear-gradient(in lab to right, #F01, #081)
  • linear-gradient(in srgb to right, #F01, #081)
  • linear-gradient(in Oklab to right, #F01, #081)

이 예시에서는 같은 두 색상(white, #01E) 사이의 선형 그라디언트가 세 가지 색 공간에서 그려집니다. 가운데 그라디언트는 감마 인코딩된 sRGB를 사용하며, 중간 지점이 여전히 너무 어둡고, 약간 탈색된 느낌이며, 약간 보라색 기운이 있습니다. 위쪽 그라디언트는 CIE Lab을 사용하여 너무 어두운 중간점을 피하지만 상당한 보라색 기운을 가지고 있고, 아래쪽 그라디언트는 Oklab을 사용하여 더 지각적으로 균일한 결과와 함께 보라색 기운이 전혀 없습니다.

  • linear-gradient(in lab to right, white, #01E)
  • linear-gradient(in srgb to right, white, #01E)
  • linear-gradient(in Oklab to right, white, #01E)

이 예시에서는 동일한 두 색상 #44C와 #795 사이의 선형 그라디언트가 세 가지 색 공간에서 그려집니다. 이 예시는 CIE Lab의 색상(색조) 비선형성이 강한 파란색뿐 아니라 모든 푸른 계열 색상에 영향을 준다는 것을 보여줍니다. 가운데 그라디언트는 감마-인코딩된 sRGB를 사용하며, 중간 지점이 다시 너무 어둡게 나타나고 약간 보라색 기운이 돕니다. 윗부분 그라디언트는 CIE Lab을 사용하여, 중간이 너무 어둡지는 않지만, 뚜렷한 보라색 기운이 있습니다. 아랫부분의 그라디언트는 Oklab을 사용하여, 보라색 기운 없이 더 지각적으로 균일한 결과를 보여줍니다.
  • linear-gradient(in lab to right, #44C, #795)
  • linear-gradient(in srgb to right, #44C, #795)
  • linear-gradient(in Oklab to right, #44C, #795)

그라디언트 보간에 직사각형 색 공간이 아닌, 폴라(원형) 색 공간을 선택하면 색상 정지점(hue stop) 간 거리가 멀수록 탈색(색상 손실)을 피할 수 있습니다. 폴라 색 공간에서 보간하면 본질적으로 채도(chroma)를 보존할 수 있지만, 중간 색상이 색 영역(gamut)을 벗어나기 쉽습니다; 이 경우 색 영역으로 되돌리기 위해 감마핑(gamut mapping)이 적용됩니다.

이 예시에서는 동일한 두 색상 #A37과 #595 사이의 선형 그라디언트를 다섯 가지 색 공간(그 중 두 개는 폴라)에서 그립니다. 위에서 아래로: CIE LCH, CIE Lab, sRGB, Oklab, Oklch.

직사각형 색 공간에서는 중간 지점이 회색빛을 띠지만, 폴라 색 공간에서는 중간 색상이 곡선을 따라가며 채도를 보존합니다.

  • linear-gradient(in lch to right, #A37, #595)
  • linear-gradient(in lab to right, #A37, #595)
  • linear-gradient(in srgb to right, #A37, #595)
  • linear-gradient(in Oklab to right, #A37, #595)
  • linear-gradient(in oklch to right, #A37, #595)

3.2. 방사형 그라디언트: radial-gradient() 표기법

이 레벨에서는 <color-interpolation-method> 인자가 radial-gradient()와 repeating-radial-gradient()에 추가되어, 그라디언트 라인에서 색상 보간에 사용할 색 공간과 경로를 지정할 수 있습니다. 자세한 내용은 CSS Color 4 § 12. 색상 보간을 참조하세요. 

radial-gradient() = radial-gradient(
  [ [ [ <rg-ending-shape> || <rg-size> ]? [ at <position> ]? ] || <color-interpolation-method>]? ,
  <color-stop-list>
)
이 예시에서는 color(display-p3 0.918 0.2 0.161)와 #081 사이의 방사형 그라디언트를 세 가지 색 공간에서 그립니다. 색상 정지점(color stop)이 모두 같은 색 공간일 필요는 없다는 점에 주목하세요. 가운데 그라디언트는 감마 인코딩된 sRGB를 사용하며, 중간 지점이 명확히 너무 어둡게 나타납니다. 위쪽 그라디언트는 CIE Lab을 사용하여 더 지각적으로 균일한 결과를 보여줍니다; 아래쪽의 Oklab은 여기서 CIE Lab과 거의 같은 결과를 보여줍니다.
  • radial-gradient(in lab farthest-side at left bottom, color(display-p3 0.918 0.2 0.161), #081)
  • radial-gradient(in srgb farthest-side at left bottom, color(display-p3 0.918 0.2 0.161), #081)
  • radial-gradient(in Oklab farthest-side at left bottom, color(display-p3 0.918 0.2 0.161), #081)

3.3. 코닉 그라디언트: conic-gradient() 표기법

코닉 그라디언트는 원의 중심을 지정하는 것으로 시작합니다. 방사형 그라디언트와 유사하지만, 코닉 그라디언트의 색상 정지점은 중심에서 나온 선이 아니라 원 둘레 주위에 배치됩니다. 이로 인해 중심을 기준으로 회전하며 색상이 부드럽게 전환되고, 중심에서 바깥쪽으로 진행되는 것이 아닌, 중심을 회전하면서 색상이 변합니다.

코닉 그라디언트는 회전 각도, 그라디언트의 중심, 그리고 색상 정지점 목록을 지정하여 만듭니다. 선형 및 방사형 그라디언트와 달리, 색상 정지점은 <length>로 지정하지 않고, 코닉 그라디언트의 색상 정지점은 <angle>로 지정합니다. 중심에서 모든 방향으로 선이 그려지고, 각 선의 색상은 그라디언트 라인과 만나는 지점의 색상과 같습니다.

참고: 이 그라디언트는 "코닉" 또는 "코니컬"이라 불리는데, 색상 정지점이 한쪽에서 다른 쪽보다 훨씬 밝게 설정되면, 위에서 본 원뿔(cone) 모양의 패턴이 만들어지기 때문입니다. "각도(angle) 그라디언트"라고도 불리며, 회전 각도를 변화시켜 만들기 때문이기도 합니다.

이 예시는 conic-gradient(at 25% 30%, white, black 60%)가 어떻게 그려지는지 시각적으로 보여줍니다. 색상 정지점 위치가 항상 각도로 결정되므로, at 25% 30%의 효과는 2차원 평면 이동(translation)만 있을 뿐, 그라디언트 자체에는 영향을 주지 않습니다.

3.3.1. conic-gradient() 구문

코닉 그라디언트의 구문은 다음과 같습니다:

conic-gradient() = conic-gradient(
  [ [ [ from <angle> ]? [ at <position> ]? ] || <color-interpolation-method> ]? ,
  <angular-color-stop-list>
)

인자 설명은 다음과 같습니다:

<angle>
전체 그라디언트가 이 각도만큼 회전합니다. 생략하면 기본값은 0deg 입니다. <angle> 값이 0이면 단위 식별자를 생략할 수 있습니다.
<position>
그라디언트의 gradient center를 결정합니다. <position> 타입(배경 위치 background-position에도 사용됨)은 [CSS-VALUES-3]에서 정의되며, 중심점은 오브젝트 영역(object area) 기준이고, gradient box가 위치 영역입니다. 이 인자가 생략되면 기본값은 center입니다.

코닉 그라디언트에서 0deg에서의 급격한 전환은 보통 바람직하지 않은데, 첫 색상 정지점과 마지막 색상 정지점을 같은 색상으로 설정하여 피하는 경우가 많습니다. 이를 자동으로 처리하는 키워드가 있으면 유용할 것 같습니다.

그라디언트 클리핑을 위한 반지름(내부/외부)을 지원하는 것이 유용할까요? 만약 그렇다면, 이제 특정 반지름이 있으니 색상 정지점 위치에 길이(length)도 지원할 수 있을 것입니다.

타원형 코닉 그라디언트가 실제로 유용할까요? 그래픽 라이브러리에서 지원하고 있을까요?

3.3.2. 색상 정지점 배치

색상 정지점은 원을 따라 gradient line에 배치되며, gradient center를 중심으로 순환합니다. 0%와 100% 위치 모두 0deg에 있습니다. 선형 그라디언트와 마찬가지로, 0deg는 페이지의 상단을 가리키며, 각도가 커질수록 원을 시계 방향으로 움직입니다.

참고: 그라디언트 라인이 나선형(spiral)을 형성하고, 0deg~360deg 구간만 렌더링된다고 생각하는 것이 더 직관적일 수 있습니다. 이렇게 하면 렌더링 영역 밖의 각도에서 "겹침"에 대한 혼동을 피할 수 있습니다.

색상 정지점은 0% 이전 또는 100% 이후에 위치할 수 있습니다; 이러한 영역은 직접적으로 렌더링에 사용되지는 않지만, 이 영역에 있는 색상 정지점이 보간 또는 반복(repetition, repeating gradients 참고)을 통해 렌더링 영역 내 색상에 영향을 줄 수 있습니다. 예를 들어, conic-gradient(red -50%, yellow 150%)은 0deg에서 붉은 오렌지색(#f50)으로 시작하고, 360deg에서 오렌지 노란색(#fa0)으로 전환되는 코닉 그라디언트를 만듭니다.

그라디언트의 임의의 위치의 색상은 먼저 해당 위치를 기준으로 중심에서 시작해 그 위치를 지나는 유일한 선(ray)을 찾은 다음, 이 선이 그라디언트 라인과 만나는 지점의 색상을 사용하는 방식으로 결정됩니다.

3.3.3. 코닉 그라디언트 예시

아래의 모든 conic-gradient() 예시는 별도의 명시가 없는 한 300px 너비, 200px 높이 박스에 적용된 것으로 가정합니다.

아래는 동일한 기본 코닉 그라디언트를 지정하는 다양한 방법입니다: 
background: conic-gradient(#f06, gold);
background: conic-gradient(at 50% 50%, #f06, gold);
background: conic-gradient(from 0deg, #f06, gold);
background: conic-gradient(from 0deg at center, #f06, gold);
background: conic-gradient(#f06 0%, gold 100%);
background: conic-gradient(#f06 0deg, gold 1turn);

아래는 동일한 기본 코닉 그라디언트를 지정하는 다양한 방법입니다. 이 예시는 [0deg, 360deg) 범위를 벗어난 각도를 가진 색상 정지점이 직접 그려지는 것은 아니지만, 그래도 그라디언트의 실제 그려진 부분의 색상에 영향을 줄 수 있음을 보여줍니다. 
background: conic-gradient(white -50%, black 150%);
background: conic-gradient(white -180deg, black 540deg);
background: conic-gradient(hsl(0,0%,75%), hsl(0,0%,25%));

아래는 동일한 회전된 코닉 그라디언트를 지정하는 두 가지 방법입니다. 하나는 회전 각도를 사용하고, 하나는 사용하지 않습니다: 
background: conic-gradient(from 45deg, white, black, white);
background: conic-gradient(hsl(0,0%,75%), white 45deg, black 225deg, hsl(0,0%,75%));

모든 색상 정지점의 각도를 회전 각도만큼 오프셋하는 방식은 작동하지 않으며, 완전히 다른 그라디언트를 생성합니다:

background: conic-gradient(white 45deg, black 225deg, white 405deg);

코닉 그라디언트 위에 방사형(radial) 그라디언트를 오버레이하여 색상/채도 원을 그립니다: 
background: radial-gradient(gray, transparent),
        conic-gradient(red, magenta, blue, aqua, lime, yellow, red);
border-radius: 50%;
width: 200px; height: 200px;

코닉 그라디언트를 사용해 단순한 파이 차트(pie chart)를 그린 예시입니다. 0deg 색상 정지점 위치는 바로 앞의 색상 정지점 위치와 같게 자동 보정(fixup)됩니다. 이렇게 하면 서로 다른 색상의 색상 정지점 사이에 극히 작은(보이지 않는) 전환이 생기게 되며, 실질적으로 단색 구역(segment)이 만들어집니다. 
background: conic-gradient(yellowgreen 40%, gold 0deg 75%, #f06 0deg);
border-radius: 50%;
width: 200px; height: 200px;

3.4. 반복 그라디언트: repeating-linear-gradient(), repeating-radial-gradient(), repeating-conic-gradient() 표기법

linear-gradient(), radial-gradient(), conic-gradient() 이외에도, 본 명세는 repeating-linear-gradient(), repeating-radial-gradient(), repeating-conic-gradient() 값을 정의합니다. 이 표기법들은 동일한 값을 받으며, 각각의 반복되지 않는 버전과 동일하게 해석됩니다.

기본 반복 코닉 그라디언트: 
background: repeating-conic-gradient(gold, #f06 20deg);

색상 정지점을 반복적으로 급격히 전환하면 별모양 배경(starburst-type background)이 만들어집니다: 
background: repeating-conic-gradient(
                hsla(0,0%,100%,.2) 0deg 15deg,
                hsla(0,0%,100%,0) 0deg 30deg
            ) #0ac;

여기서는 반복되는 색상 정지점과 급격한 전환을 사용해 바둑판 무늬(checkerboard)를 만듭니다: 
background: repeating-conic-gradient(black 0deg 25%, white 0deg 50%);
background-size: 60px 60px;

동일한 바둑판 무늬는 반복 없는 코닉 그라디언트로도 만들 수 있습니다:

background: conic-gradient(black 25%, white 0deg 50%, black 0deg 75%, white 0deg);
background-size: 60px 60px;

3.5. 그라디언트 색상 정의

그라디언트의 색상은 색상 정지점(<color> 와 gradient line에서의 위치), 그리고 색상 전환 힌트(두 색상 정지점 사이의 전환 중간 위치) 를 gradient line에 지정하여, 라인의 모든 지점의 색상을 정의합니다. (각 gradient function은 gradient line의 형태와 길이, 시작점과 끝점을 정의합니다. 위의 내용 참고.)

그라디언트 필드 전체의 색상은, gradient line의 특정 지점에 연결되어 각 gradient function에 지정된 대로 결정됩니다. UA는 그라디언트 색상을 약간 "디더링"(dither, 인접 색상 픽셀을 무작위로 섞어서 더 부드럽게) 할 수 있습니다.

3.5.1. 색상 정지점 리스트

색상 정지점과 전환 힌트는 색상 정지점 리스트에 지정됩니다. 이는 2개 이상의 색상 정지점과 선택적 전환 힌트가 번갈아 나열된 리스트입니다: 

<color-stop-list> =
  <linear-color-stop> , [ <linear-color-hint>? , <linear-color-stop> ]#
<linear-color-stop> = <color> && <color-stop-length>?
<linear-color-hint> = <length-percentage>
<color-stop-length> = <length-percentage>{1,2}

<angular-color-stop-list> =
  <angular-color-stop> , [ <angular-color-hint>? , <angular-color-stop> ]#
<angular-color-stop> = <color> && <color-stop-angle>?
<angular-color-hint> = <angle-percentage>
<color-stop-angle> = <angle-percentage>{1,2}

<color-stop> = <color-stop-length> | <color-stop-angle>
참고: <color-stop-list>와 <angular-color-stop-list>는 구조가 완전히 동일합니다. 단지 정지점과 힌트의 위치를 지정할 때 <length>를 받느냐 <angle>를 받느냐의 차이만 있습니다.

철도 다이어그램으로 시각화하면, 두 가지 모두 다음 패턴을 따릅니다:

color stop에 위치가 두 개 지정된 경우, 같은 색상을 가진 color stop 두 개를 각각의 위치에 지정한 것과 동일합니다. 두 위치를 지정하면 색상을 두 번 반복하지 않고도 그라디언트에 단색 "스트라이프"를 쉽게 만들 수 있습니다.

퍼센트 값은 gradient line의 starting point와 ending point 사이의 길이에 대해 해석됩니다. 0%는 시작점, 100%는 끝점에 해당합니다. 길이 값은 gradient line을 따라 starting point에서 ending point 방향으로 측정됩니다.

color stop과 transition hint의 위치는 보통 starting point와 ending point 사이에 지정되지만, 꼭 그래야 하는 것은 아닙니다: gradient line은 양 방향으로 무한히 뻗어 있으므로, gradient line의 어느 곳이든 위치를 지정할 수 있습니다.

color stop의 위치를 생략하면, 자동으로 위치가 할당됩니다. color stop list의 첫 번째 또는 마지막 color stop은 각각 gradient line의 starting point 또는 ending point로 할당됩니다. 그 외의 경우에는, 주변 두 정지점 사이의 중간 위치로 할당됩니다. 연속적으로 위치가 없는 여러 stop이 있을 경우, 주변 위치가 지정된 stop 사이에서 동일 간격으로 배치됩니다. 자세한 내용은 § 3.5.3 Color Stop “Fixup”를 참고하세요.

3.5.2. 그라디언트 라인 색 지정

각 color stop 위치에서, gradient line의 색상은 해당 color stop의 색상입니다. 첫 번째 color stop 이전에는 gradient line의 색상이 첫 번째 color stop의 색상이 되고, 마지막 color stop 이후에는 gradient line의 색상이 마지막 color stop의 색상이 됩니다. 두 color stop 사이에서는, gradient line의 색상이 두 color stop의 색상 사이에서 보간됩니다. 보간은 지정된 색 공간에서 premultiplied alpha 방식으로 이루어집니다. 자세한 내용은 CSS Color 4 § 12.3 Interpolating with Alpha를 참고하세요. gradient 함수에 <color-interpolation-method>가 지정되지 않은 경우, 보간에 사용되는 색 공간은 [css-color-4]에서 정의된 기본 보간 색 공간입니다.

기본적으로 이 보간은 선형이며—두 color stop 사이의 거리의 25%, 50%, 75% 지점에서 각각 25%, 50%, 75%로 두 색상이 혼합됩니다.

하지만 만약 두 color stop 사이에 transition hint가 지정되었다면, 보간은 비선형 방식으로 힌트 값에 따라 결정됩니다:

  1. transition hint의 위치를 두 color stop 사이 거리의 백분율(0~1 사이의 값)로 결정합니다. 0은 첫 번째 color stop에, 1은 두 번째 color stop에 해당합니다. 이 백분율을 H로 둡니다.
  2. 임의의 위치에 대해, 두 color stop 사이의 거리의 백분율을 구해 P로 둡니다.
  3. 해당 위치에서의 색상 가중치 C는 PlogH(.5)로 계산합니다.
  4. 해당 위치의 색상은 두 color stop의 색상을 (1 - C) : C로 선형 혼합합니다.

참고: transition hint는 “중간 색상”—즉, 두 color stop 색상의 50% 혼합—이 어느 위치에 나타날지를 지정합니다. 힌트가 두 color stop 사이의 정확한 중간에 있으면 위의 보간 알고리즘은 일반적인 선형 보간 결과와 같습니다. 힌트가 중간이 아닌 다른 위치에 있으면, 두 color stop 사이를 부드러운 지수 곡선으로 보간하며, “중간 색상”은 힌트에서 지정한 위치에 정확히 나타납니다.

아래는 transition hint가 없는 선형 그라디언트(위)와 red와 blue color stop 사이에 transition hint가 있는 경우(아래)의 비교 예시입니다.

위 - transition hint 없이(기본적으로 중간 위치에서 50% 전환):

background: linear-gradient(to right, red 0%, blue 100%);

아래 - transition hint를 사용한 경우:

background: linear-gradient(to right, red 0%, 25%, blue 100%);

여러 color stop이 같은 위치에 있으면, 리스트에서 먼저 지정된 stop에서 마지막 stop로 극소(보이지 않는) 전환이 발생합니다. 결과적으로, 해당 위치에서 색상이 부드럽게 변하지 않고 즉시 바뀝니다.

3.5.3. 컬러 스톱 “Fixup”

used 위치를 각 color stop에 대해 결정할 때, 다음 단계들을 순서대로 적용해야 합니다:

  1. 첫 번째 color stop에 위치가 없다면, 위치를 0%로 설정합니다. 마지막 color stop에 위치가 없다면, 위치를 100%로 설정합니다.
  2. 어떤 color stop이나 transition hint의 위치가 앞에 있는 color stop이나 transition hint의 지정된 위치보다 작으면, 그 위치를 앞에 있는 color stop이나 transition hint 중 가장 큰 위치와 동일하게 설정합니다.
  3. 아직 위치가 없는 color stop이 있다면, 인접한 위치 미지정 color stops의 묶음마다 앞뒤에 위치가 지정된 color stop 사이에 균등하게 배치되도록 위치를 설정합니다.

이 규칙을 적용한 후, 모든 color stop과 transition hint에는 확정된 위치와 색상이 할당되고, 오름차순으로 정렬됩니다.

참고: px, em, % 등 다양한 단위들을 혼합할 때는 주의해야 합니다. 이렇게 하면 color stop이 의도치 않게 앞의 stop보다 더 앞서게 이동하려 할 수 있습니다. 예를 들어, background-image: linear-gradient(yellow 100px, blue 50%) 규칙은 배경 영역이 최소 200px 높이일 때는 fix-up 없이 동작합니다. 하지만 150px 높이라면, blue color stop의 위치는 75px과 같아져서 yellow color stop보다 앞서게 되고, 100px 위치로 보정됩니다. 또한, 이런 color stop들의 상대적 순서를 레이아웃 없이 알 수 없으므로, 애니메이션이나 트랜지션에서 부드럽게 보간되지 않습니다.

아래는 여러 쌍의 그라디언트입니다. 각 쌍의 후자가 위 규칙을 적용해 수동으로 “고친” 버전이며, 두 그라디언트는 동일하게 렌더링됩니다. 화살표의 숫자는 어떤 fixup 단계가 적용되는지 나타냅니다.

4. 1D 이미지 값: <image-1D> 타입과 stripes() 표기법

<image> 값이 2차원(2D) 이미지를 나타내는 반면, <color>는 0차원(0D) 이미지(어떤 축에서도 변하지 않음)로 볼 수 있습니다. 일부 컨텍스트에서는 1차원(1D) 이미지가 필요합니다. 1D 이미지는 추상적이고 방향이 없는 단일 축 페인트 라인을 따라 색을 지정합니다. <image-1D> 타입은 이런 1D 이미지를 나타내며, stripes() 함수 표기법도 포함됩니다: 

<image-1D> = <stripes()>
<stripes()> = stripes( <color-stripe># )
<color-stripe> = <color> && [ <length-percentage> | <flex> ]?

stripes() 함수는 1D 이미지를 쉼표로 구분된 색상 스트라이프 목록으로 정의하며, 각 스트라이프는 주어진 순서대로 페인트 라인에 나란히 배치됩니다.

각 <color-stripe> 항목은 지정된 <color>와 두께를 갖는 단색 스트라이프를 정의합니다. 두께를 생략하면 1fr이 기본값입니다. 두께 값 해석은 다음과 같습니다:

<percentage [0,100]>
백분율 두께는 total width에 대한 상대값입니다. 0%에서 100%까지(포함)의 값만 유효합니다.
<length [0,∞]>
음수 길이 값은 유효하지 않습니다.
<flex>
<flex>는 total width에 대해 함수 내의 모든 <flex> 항목의 합에 대한 비율로 평가됩니다. <flex>가 아닌 항목의 두께를 빼고(뺀 결과가 0보다 작으면 0으로 바닥 처리), <flex> 값의 합이 1fr보다 작으면, 뺀 결과값을 합계값으로 곱한 뒤 분배합니다.

total width는 stripes() 함수가 사용되는 문맥에 따라 정의됩니다. 스트라이프 합이 total width보다 작으면, paint line의 남은 길이는 transparent black으로 처리되며, 마지막 transparent 인자가 지정된 것처럼 됩니다. 합계가 더 크면, total width를 넘는 모든 스트라이프 또는 그 일부는 잘려집니다.

예를 들어 stripes(red 1fr, green 2fr, blue 100px)에서 total width가 400px이면, 빨간색 스트라이프가 100px, 초록색 스트라이프가 200px이 됩니다. blue의 100px을 400px 전체에서 빼고 남은 300px에서 red가 1, green이 2의 비율로 분배받습니다.

반면 stripes(red .1fr, green .2fr, blue 100px)에서 total width가 400px이면, 빨간색 스트라이프가 30px, 초록색이 60px이 되고, 100px의 blue 다음에 210px의 transparent가 이어집니다. 남은 300px 공간에 <flex> 값의 합(.3)을 곱해 90px만 분배하고, 이 90px은 <flex> 값이 지정한 1:2 비율로 나뉩니다.

(이는 flex layout에서 한 줄에 작은 <flex> 합계를 처리하는 방식과 유사하며, <flex> 값이 0에 가까워질 때도 부드럽게 연속적인 동작을 보장합니다.)

이 함수의 computed value는 각각 computed color와 두께(각각 <flex> 값 또는 계산된 <length-percentage> 값)으로 주어진 스트라이프의 순서 있는 리스트입니다.

5. CSS에서 이미지와 오브젝트 크기 지정

5.1. 오브젝트 크기 지정: object-fit 속성

이름: object-fit
값: fill | none | [contain | cover] || scale-down
초기값: fill
적용 대상: 치환 요소(replaced elements)
상속: 아님
퍼센트(%): 해당 없음
계산된 값: 지정된 키워드
표준 순서: 문법에 따름
애니메이션 타입: 불연속(discrete)

object-fit 속성은 치환 요소의 콘텐츠가 해당 요소의 사용된 높이와 너비 박스에 어떻게 맞춰질지 지정합니다.

fill
치환 콘텐츠가 요소의 콘텐츠 박스를 가득 채우도록 크기가 조정됩니다: 오브젝트의 concrete object size는 요소의 사용된 너비와 높이입니다.
none
치환 콘텐츠가 요소의 콘텐츠 박스에 맞춰 크기가 조정되지 않습니다: 오브젝트의 concrete object size는 기본 크기 알고리즘을 사용해 지정 크기 없이 기본 오브젝트 크기를 치환 요소의 사용된 너비, 높이로 계산합니다.
contain
치환 콘텐츠가 요소의 콘텐츠 박스 내에서 종횡비(aspect ratio)를 유지하며 맞춰지도록 크기가 조정됩니다: concrete object size는 요소의 사용된 너비, 높이에 대해 contain constraint로 계산됩니다.

만약 scale-down 플래그가 사용되면, 콘텐츠 크기를 none 또는 contain으로 계산하여, 더 작은 concrete object size를 선택합니다.

참고: none과 contain 모두 콘텐츠의 natural aspect ratio를 존중하므로 "더 작은"의 개념이 명확하게 정의됩니다.

cover
치환 콘텐츠가 요소의 콘텐츠 박스를 완전히 채우면서 종횡비를 유지하도록 크기가 조정됩니다: concrete object size는 요소의 사용된 너비, 높이에 대해 cover constraint로 계산됩니다.

scale-down 플래그가 사용되면, 콘텐츠 크기를 none 또는 cover로 계산하여, 더 작은 concrete object size를 선택합니다.

참고: none과 cover 모두 콘텐츠의 natural aspect ratio를 존중하므로 "더 작은"의 개념이 명확하게 정의됩니다.

scale-down
contain scale-down과 동일합니다.

콘텐츠가 치환 요소의 콘텐츠 박스를 완전히 채우지 못할 경우, 채워지지 않은 공간에는 치환 요소의 배경이 표시됩니다. 치환 요소는 항상 콘텐츠 박스에 콘텐츠를 잘라내므로, 콘텐츠가 넘치지 않습니다. 오브젝트를 콘텐츠 박스 내에서 위치시키려면 object-position 속성을 참고하세요.

참고: object-fit 속성은 [SMIL10]의 fit 어트리뷰트와 <meetOrSlice> 파라미터, preserveAspectRatio 어트리뷰트 ([SVG11])와 유사한 의미를 가집니다.

참고: object size negotiation 알고리즘에 따라, concrete object size(혹은 여기서는 콘텐츠의 크기)는 오브젝트 자체를 직접 스케일링하는 것이 아니라, 단순히 오브젝트에 보여질 캔버스의 크기 정보를 전달하는 역할입니다. 해당 크기로 어떻게 그릴지는 이미지 포맷에 따라 달라집니다. 특히 래스터 이미지는 항상 지정된 크기로 스케일되고, SVG는 지정된 크기를 "SVG Viewport"(SVG에서 정의된 용어) 크기로 사용한 다음, 루트 <svg> 요소의 여러 어트리뷰트 값을 이용해 그림을 결정합니다.

6. 이미지 처리

6.1. 이미지 해상도 재정의: image-resolution 속성

이미지 해상도란 이미지 픽셀의 단위 길이당 개수를 의미하며, 예를 들어 인치당 픽셀 수입니다. 일부 이미지 포맷은 이미지의 해상도 정보를 기록할 수 있습니다. 이 정보는 포맷팅 과정에서 실제 이미지 크기를 결정할 때 도움이 될 수 있습니다. 하지만 이 정보가 잘못된 경우에는 무시해야 합니다. 기본적으로 CSS는 이미지 픽셀 1개가 CSS px 단위 1개에 해당한다고 가정합니다. 그러나 image-resolution 속성을 통해 다른 해상도를 사용할 수 있습니다.

이름: image-resolution
값: [ from-image || <resolution> ] && snap?
초기값: 1dppx
적용 대상: 모든 요소
상속: 예
퍼센트(%): 해당 없음
계산된 값: 지정된 키워드 및/또는 <resolution> (아래의 snap에 따라 조정될 수 있음)
표준 순서: 문법 순서
애니메이션 타입: 불연속(discrete)

image-set() 표기법은 이미지의 자연 해상도를 변경할 수 있습니다. 이상적으로는 이 속성을 따로 지정하지 않고도 자동으로 적용되는 것이 좋습니다. 어떻게 처리하는 것이 최선일까요? 초기값을 auto로 바꿔 "1dppx, 단 CSS가 다르게 지정한 경우 제외"로 할까요? image-resolution이 CSS에서 다른 방식으로 해상도가 지정된 이미지는 영향을 주지 않도록 할까요? 아니면 image-set()을 무조건 1dppx 이미지를 반환하는 식으로 문구를 다듬을까요?

image-resolution 속성은 요소 내 또는 요소 위에서 사용되는 모든 래스터 이미지의 우선 해상도를 지정합니다. 이는 콘텐츠 이미지 (예: 치환 요소 및 생성된 콘텐츠) 뿐만 아니라 장식 이미지 (background-image 등)에도 영향을 줍니다. 이미지의 우선 해상도는 이미지의 자연 크기를 결정할 때 사용됩니다. 값의 의미는 다음과 같습니다:

<resolution>
우선 해상도를 명시적으로 지정합니다. 여기서 "dot"은 하나의 이미지 픽셀을 의미합니다.
from-image
이미지의 우선 해상도를 이미지 포맷이 지정한 값으로 사용합니다 (자연 해상도). 이미지가 자체 해상도를 지정하지 않으면 명시적으로 지정된 해상도를 사용하며(있다면), 없으면 1dppx를 기본값으로 사용합니다.

참고: CSS Images 3 § 2.1.2 이미지 메타데이터는 사용할 수 있는 메타데이터에 일부 제한을 둡니다.

snap
"snap" 키워드가 있으면, 계산된 <resolution> (있는 경우) 는 지정된 해상도를 가장 가까운 값으로 반올림하여 하나의 이미지 픽셀이 정수 개의 디바이스 픽셀에 매핑되도록 합니다. 해상도가 이미지에서 가져온 경우, 사용된 자연 해상도도 동일하게 조정됩니다.

SVG 등 벡터 포맷은 자연 해상도가 없으므로, 이 속성은 벡터 이미지에는 영향을 주지 않습니다.

프린터는 컴퓨터 모니터보다 훨씬 높은 해상도를 가지는 경우가 많습니다; 이 때문에 화면에서는 괜찮아 보이는 이미지도 인쇄 시 픽셀화되어 보일 수 있습니다. image-resolution 속성을 사용하면 문서에 고해상도 이미지를 삽입하고 적절한 크기를 유지해 화면과 인쇄 모두에서 보기 좋은 결과를 얻을 수 있습니다: 
img.high-res {
  image-resolution: 300dpi;
}

이렇게 설정하면 300dpi에서 폭이 5인치여야 하는 이미지는 실제로 5인치 폭으로 표시됩니다. 이 설정이 없으면, 이미지는 약 15.6인치 폭으로 표시되는데, 이미지는 15000 픽셀 너비이고, CSS는 기본적으로 인치당 96 이미지를 표시하기 때문입니다.

일부 이미지 포맷은 이미지 데이터에 해상도를 인코딩할 수 있습니다. 이 규칙은 UA가 이미지 자체에 포함된 해상도를 사용하도록 지정하며, 없을 경우 CSS px 단위당 1 이미지 픽셀을 기본값으로 사용합니다. 
img { image-resolution: from-image }

아래 두 규칙 모두 UA가 이미지 자체의 해상도를 사용하도록 지정하지만, 만약 이미지에 해상도가 없다면, 해상도는 기본값 1dppx 대신 300dpi로 설정됩니다.

img { image-resolution: from-image 300dpi }
img { image-resolution: 300dpi from-image }
이 규칙을 사용하면 이미지 해상도가 300dpi로 설정됩니다. (이미지 내 해상도 정보가 있다면 무시됨.) 
img { image-resolution: 300dpi }

반대로, 화면 해상도가 96dpi인 상황에서 이 규칙을 사용하면 이미지는 288dpi로 렌더링됩니다 (즉, 이미지 픽셀 3개가 디바이스 픽셀 1개에 매핑됨):

img { image-resolution: 300dpi snap; }

snap 키워드는 해상도가 이미지에서 가져온 경우에도 사용할 수 있습니다:

img { image-resolution: snap from-image; }

이미지가 300dpi를 선언했다면, 위 상황에서 288dpi로 표시되며 (이미지 픽셀 3개가 디바이스 픽셀 1개에 매핑), 72dpi를 선언했다면 96dpi로 렌더링됩니다 (이미지 픽셀 1개가 디바이스 픽셀 1개에 매핑).

7. 보간(Interpolation)

이 섹션에서는 이 명세에서 새롭게 정의된 값 타입 간의 보간 방법을 설명합니다. 이는 CSS 트랜지션(CSS Transitions) 및 애니메이션(CSS Animations)과 같은 모듈에서 사용됩니다.

아래 알고리즘이 단순히 두 값을 "보간"하거나 "트랜지션"하라고만 명시하고 추가 설명이 없다면, 해당 값은 Transitions 명세에 정의된 방식대로 보간해야 합니다. 그 외의 경우, 알고리즘은 보간의 상세 설명에서 변수 t를 참조할 수 있습니다. 이는 0%에서 100%까지 변하는 숫자이며, 트랜지션의 지속 시간, 경과 시간, 사용 중인 타이밍 함수에 따라 트랜지션 진행도를 나타내는 값입니다. 예를 들어, 선형 타이밍 함수와 1초 지속 시간일 때, .3초 후 t는 30%가 됩니다.

7.1. <image> 보간

모든 이미지는 보간될 수 있습니다. 단, 일부 특수 이미지(예: 일부 그라디언트)는 고유의 보간 규칙을 가집니다. 일반적으로 이미지는 start image의 크기로 스케일링하여 두 이미지를 크로스 페이드(cross-fade)로 보간하며, 점차 end image 크기로 이동하는 방식입니다.

구체적으로는, 보간의 각 지점에서 이미지는 cross-fade( (100% - t) start image, end image)와 같습니다.

"background-image: url(foo);"에서 "background-image: none;"처럼 no image로의 특수 보간 케이스가 필요합니다.

7.2. cross-fade() 보간

cross-fade()의 세 구성 요소는 각각 독립적으로 보간합니다. 이로 인해 중첩된 cross-fade() 노테이션이 생길 수 있습니다.

7.3. <gradient> 보간

이 섹션은 검토 및 개선이 필요합니다. 특히 linear-gradient() 처리 방식이 불완전하다고 생각합니다 - 그라디언트 라인의 "길이"(0%~100% 거리)를 시작점과 끝점 사이에서 명시적으로 보간하도록 해야 애니메이션 중에 늘었다 줄었다 하지 않게 할 수 있습니다.

그라디언트 이미지는 CSS 트랜지션 및 애니메이션에서 직접 보간할 수 있어, 한 그라디언트에서 다른 그라디언트로 부드럽게 애니메이션됩니다. 보간 가능한 그라디언트에는 몇 가지 제한이 있습니다:

  1. 시작/끝 그라디언트가 같은 함수로 표현되어야 합니다. (예: linear-gradient()에서 linear-gradient()로는 가능하지만, linear-gradient()에서 radial-gradient()나 repeating-linear-gradient()로는 불가.)

  2. 시작/끝 그라디언트가 동일한 개수의 <color-stop>을 가져야 합니다. 이 목적에서 모든 반복(repeating) 그라디언트는 무한개의 color-stop을 가진 것으로 간주하므로, 반복 그라디언트끼리는 항상 일치합니다.

  3. 두 그라디언트 모두 <length> 와 <percentage> color stop을 혼합해서 사용하면 안 됩니다.

두 그라디언트가 위 조건을 모두 만족하면 아래 설명대로 보간해야 합니다. 세 번째 조건만 실패하면 50%에서 갑자기 전환합니다 (향후 명세에서 다르게 규정하지 않는 한). 처음 두 조건 중 하나라도 실패하면, 일반 이미지처럼 cross-fade()로 보간합니다.

참고: 50%에서의 갑작스런 전환은 콘텐츠가 cross-fade에 의존하지 않도록 하기 위한 것이며, 앞으로 더 똑똑한 보간 규칙을 추가할 수 있습니다.

  1. 시작/끝 그라디언트를 명시적(explicit) 형태로 변환합니다:

    선형 그라디언트:

    • 방향이 <angle>로 지정되어 있으면 이미 명시적 형태입니다.

    • 그 외의 경우, 방향을 [0deg,360deg) 범위의 <angle>로 변환하여 동등한 렌더링이 되도록 합니다.

      시작/끝 그라디언트 모두 키워드로 방향을 지정했고, 두 각도의 절대 차이가 180deg보다 크면, 각도가 더 작은 쪽에 360deg를 더합니다. 예를 들어 "to left"(270deg)에서 "to top"(0deg)으로의 트랜지션은 기대대로 시계 방향 90도 회전하게 하며, 반시계 방향으로 270도 회전하는 결과가 되지 않도록 합니다.

    방사형 그라디언트:

    • 크기가 두 개의 <length> 또는 <percentage>로 지정되어 있으면 이미 명시적 형태입니다.

    • 그 외의 경우, 크기를 동등한 ending-shape가 되도록 두 개의 <length>로 변환합니다. <rg-ending-shape>가 circle로 지정되어 있으면, ellipse로 바꿉니다.

  2. 각 구성 요소와 color-stop을 독립적으로 보간합니다. 선형 그라디언트는 각(angle)만 보간합니다. 방사형 그라디언트는 중심점의 x/y 위치와 축의 x/y 길이를 보간합니다.

  3. color-stop을 보간하려면, 먼저 시작 그라디언트의 각 color-stop을 끝 그라디언트에서 동일 인덱스의 color-stop과 매칭합니다. 반복 그라디언트의 경우, 시작/끝 그라디언트의 첫 번째 지정 color-stop을 같은 인덱스로 간주하며, 나머지 color-stop은 리스트를 반복/이동시키면서 인덱스를 맞춥니다. 각 color-stop 쌍에 대해 위치와 색을 독립적으로 보간합니다.

7.4. stripes() 보간

그라디언트와 유사하게, 두 stripes()도 보간할 수 있어, 한 이미지에서 다른 이미지로 부드러운 애니메이션이 가능합니다. stripes() 보간에는 몇 가지 제한이 있습니다:

  1. 시작/끝 이미지가 동일한 개수의 <color-stripe>를 가져야 합니다.

  2. 두 이미지 모두 <length>, <percentage>, <flex> stripe을 혼합해서 사용하면 안 됩니다.

두 이미지가 두 제약 조건을 모두 만족하면, 아래에 설명된 대로 보간(interpolation)해야 합니다. 두 번째 조건만 실패하는 경우, 50%에서 갑자기 전환되어야 하며 (향후 명세에서 별도 지정하지 않는 한). 첫 번째 제약을 실패하는 경우, 일반 이미지와 마찬가지로 cross-fade()를 사용해 보간해야 합니다.

참고: 50%에서의 갑작스러운 전환은 cross-fading에 의존하지 않도록 하기 위함이며, 이 경우에 대해 더 스마트한 보간 규칙을 앞으로 추가할 수 있습니다.

  1. 이미지의 각 구성 요소와 스트라이프를 독립적으로 보간합니다.

  2. 스트라이프를 보간하려면, 먼저 시작 이미지의 각 스트라이프를 종료 이미지에서 같은 인덱스의 스트라이프와 매칭합니다. 그런 다음 각 스트라이프 쌍에 대해, 두께(thickness)와 색(color)을 각각 독립적으로 보간합니다.

8. 직렬화

이 섹션에서는 이 명세에서 새롭게 도입된 모든 속성과 값 유형의 직렬화 방식을 설명합니다. 이는 CSS 객체 모델 [CSSOM]과의 연동을 위한 것입니다.

이 모듈에서 정의된 어떤 함수든, 각각의 개별 문법에 따라 직렬화하며, 문법에 쓰여진 순서대로, 의미가 변하지 않는다면 구성 요소는 생략하고, 공백으로 구분되는 토큰들은 한 개의 공백으로 연결하며, 직렬화된 쉼표 뒤에는 반드시 한 개의 공백을 둡니다.

cross-fade()의 경우, 항상 <percentage>를 직렬화합니다.

예를 들어, 그라디언트를 다음과 같이 지정하면: 
Linear-Gradient( to bottom, red 0%,yellow,black 100px)

다음과 같이 직렬화해야 합니다:

linear-gradient(rgb(255, 0, 0), rgb(255, 255, 0), rgb(0, 0, 0) 100px)

적합성 클래스(Conformance classes)

이 명세에 대한 적합성은 세 가지 적합성 클래스로 정의됩니다:

style sheet
CSS 스타일 시트
renderer
UA로, 스타일 시트의 의미를 해석하고, 그것을 사용하는 문서를 렌더링하는 사용자 에이전트.

UA로, 스타일 시트를 작성하는 도구.

스타일 시트가 이 명세에 적합하려면, 이 모듈에서 정의된 구문을 사용하는 모든 문(statement)이 일반 CSS 문법과 이 모듈에서 정의된 각 기능의 개별 문법에 따라 유효해야 합니다.

렌더러가 이 명세에 적합하려면, 스타일 시트를 적절한 명세에 따라 해석하는 것 외에도, 이 명세에 정의된 모든 기능을 올바르게 파싱하고 문서를 그에 따라 렌더링해야 합니다. 단, 기기의 제한으로 인해 UA가 문서를 제대로 렌더링하지 못하는 경우, UA는 비적합으로 간주되지 않습니다. (예: UA가 흑백 모니터에서 색상을 렌더링할 필요는 없습니다.)

저작 도구(Authoring tool)가 이 명세에 적합하려면, 이 모듈에서 각 기능별 개별 문법과 일반 CSS 문법에 따라 구문적으로 올바른 스타일 시트를 작성해야 하며, 이 모듈에 설명된 스타일 시트의 모든 적합성 요구사항도 충족해야 합니다.

부분 구현(Partial implementations)

저자는 앞으로의 호환 가능한 파싱 규칙을 활용해 대체 값을 지정할 수 있도록, CSS 렌더러는 반드시 사용 가능한 수준의 지원이 없는 모든 at-rule, 속성, 속성 값, 키워드 및 기타 구문 구조를 무효로 간주하고 (적절히 무시)해야 합니다. 특히 사용자 에이전트는 선택적으로 지원되지 않는 구성 요소 값만 무시하고, 다중 값 속성 선언에서 지원되는 값만 적용해서는 안 됩니다: 만약 어떤 값이 무효(지원되지 않는 값)로 간주된다면, CSS에서는 전체 선언을 무시해야 합니다.

1. 소개

이 절은 비규범적이다.

HID(Human Interface Device, 인간 인터페이스 장치)는 사람에게서 입력을 받거나 사람에게 출력을 제공하는 장치의 한 유형이다. HID는 호스트와 장치 간의 양방향 통신을 위한 표준인 HID 프로토콜을 가리키기도 한다. 이 프로토콜은 설치 절차를 간소화하도록 설계되었다. HID 프로토콜은 원래 USB 장치용으로 개발되었지만 이후 Bluetooth를 포함한 여러 다른 프로토콜에서도 구현되었다.

웹 플랫폼은 이미 많은 HID 장치의 입력을 지원한다. 키보드, 포인팅 장치, 게임패드는 보통 HID 프로토콜로 구현된다. 그러나 이 지원은 HID 입력을 고수준 입력 API로 변환하는 운영체제의 HID 드라이버에 의존한다. 호스트의 HID 드라이버가 충분히 지원하지 않는 장치는 웹페이지에서 접근할 수 없는 경우가 많다. 마찬가지로 호스트의 HID 드라이버가 지원하지 않는 대부분의 장치 출력에도 접근할 수 없다.

관련 해설 문서도 참고한다.

2. 도입 동기가 되는 응용 사례

이 절은 비규범적이다.

2.1. 특수 용도 장치

가장 일반적인 HID 입력 장치 유형은 기존 고수준 입력 API를 통해 웹 플랫폼에서 이미 충분히 지원된다. 예를 들어 마우스 입력은 PointerEvent을 통해, 키보드 입력은 KeyboardEvent을 통해 접근할 수 있다. 이러한 장치의 입력은 호스트의 기본 HID 드라이버로 처리하며, 올바른 동작을 위해 보통 장치별 드라이버나 설정이 필요하지 않다. WebHID는 이처럼 고수준 입력 API로 이미 충분히 지원되는 장치를 위한 것이 아니다.

일부 HID 장치 유형에 대해서는 웹 플랫폼이 특정 기능은 지원하면서 다른 기능의 접근은 제한한다. 예를 들어 [GAMEPAD]는 대부분의 게임 컨트롤러의 입력 기능은 지원하지만 LED 표시등이나 오디오처럼 덜 일반적인 기능은 지원하지 않는다. 이러한 기능은 호스트 API가 충분히 지원하지 않는 경우가 많고, 사용자 에이전트에 지원을 추가하면 상당한 복잡성을 초래할 수 있다. WebHID는 고수준 API가 제공하는 기능이 불완전할 때 응용 프로그램에 대안을 제공한다.

많은 HID 장치는 어떤 웹 플랫폼 API로도 지원되지 않는다. HID 명세는 가상현실 제어 장치, 비행 시뮬레이터, 의료 장비 등을 포함해 HID로 지원할 수 있는 다양한 장치를 설명한다. WebHID는 추가 드라이버나 사용자 에이전트의 수정 없이 이러한 장치를 사용할 수 있게 한다.

2.2. 시제품 제작, 취미 및 교육용 장치

HID는 장치를 사용할 각 호스트마다 별도의 드라이버를 요구하지 않고 호스트의 범용 HID 드라이버를 사용할 수 있어 시제품 제작과 취미용 응용에 매력적이다. 간소화된 설치 절차 덕분에 교육자도 각 호스트의 시스템 설정을 수정하지 않고 교실의 학생들에게 장치를 배포하기 쉽다. 웹 플랫폼을 통해 HID 장치 접근을 제공하면 설치 요구사항을 더욱 줄일 수 있다. 특히 현재 호스트별 전용 응용 프로그램으로만 지원되는 장치에 유용하다.

3. 보안 및 개인정보 보호 고려사항

이 절은 비규범적이다.

3.1. 장치 접근 권한의 악용

HID 주변 장치는 강력한 기능을 노출할 수 있으며, 사용자의 명시적 동의 없이 페이지가 이를 사용하도록 해서는 안 된다. 예를 들어 HID 주변 장치에는 주변 환경 정보를 수집하는 센서가 있을 수 있다. 장치에는 공개하거나 덮어쓰면 안 되는 개인정보가 저장되어 있을 수 있다. 많은 장치는 펌웨어를 업그레이드하는 기능을 노출한다. 운영체제는 보통 응용 프로그램의 HID 장치 접근을 제한하지 않으며, 때로는 이 접근이 장치를 손상시키거나 저장된 데이터를 훼손하는 데 악용될 수 있다.

어떤 경우에는 장치가 웹페이지에서 전혀 접근해서는 안 되는 기능을 노출할 수 있다. 특정 장치는 공급업체 ID와 제품 ID로 식별하고 열거 과정에서 숨겨 차단할 수 있다. 보고서 설명자를 통해 장치가 자체 기능을 설명할 수 있으므로, 공급업체 ID와 제품 ID를 미리 알 수 없어도 이 정보로 장치 유형을 차단할 수 있다. 이를 위해 HID 용도 값, 즉 보고서 설명자 내 컬렉션에 할당된 값을 검사한다. 예를 들어 최상위 컬렉션에 키보드용 HID 용도가 지정된 장치의 접근을 거부하여 키보드와 유사한 장치의 접근을 차단할 수 있다.

악용을 줄이기 위해 사용자가 명시적으로 접근을 허용하기 전에는 페이지에 장치를 제공하지 않는다. 페이지가 먼저 접근을 요청해야 하며, 사용 가능한 모든 장치를 표시하는 선택기에서 사용자가 장치를 선택하면 권한이 부여된다. 페이지에 접근 권한이 부여되면 장치가 사용 중임을 나타내는 표시기를 보여 준다.

3.2. 장치 공격

HID 프로토콜은 매우 유연하며, 그 유연성을 활용하는 다양한 장치가 설계되어 왔다. 따라서 악성 페이지가 장치에 접근하여 장치 자체를 손상시키는 방식도 다양할 수 있다. HID 주변 장치가 사용자 정의 HID 보고서로 펌웨어 업데이트를 받도록 하는 것은 비교적 흔하다. 장치 제조업체는 펌웨어 바이너리의 진위를 검증하도록 펌웨어 업그레이드 절차를 신중하게 설계해야 하며, 장치의 보안을 약화할 수 있는 다운그레이드도 방지하는 것이 좋다. 신뢰할 수 없는 업그레이드는 장치에 새로운 기능을 추가하거나 완전히 다른 유형의 장치로 위장시키는 데 사용될 수 있다.

예상 범위를 벗어난 입력이 제공되면 손상되는 장치도 있다. 예를 들어 페이지가 잘못된 진동 명령을 보내면 게임패드의 진동 기능이 손상될 수 있다.

일반적으로 이러한 공격은 장치에 종속적이며 API 수준에서 완화할 수 없다.

3.3. 호스트 공격

악성 페이지가 장치 접근 권한을 얻으면 경우에 따라 이를 호스트 공격에 사용할 수 있다. 주요 우려 사항은 장치가 신뢰할 수 있는 입력 이벤트를 생성하는 데 사용될 수 있는지 여부이다. 이러한 이벤트는 사용자 의사를 대신 나타내며 더 강력한 웹 플랫폼 기능에 접근하는 데 사용될 수 있다.

마우스와 키보드는 보통 HID 주변 장치로 구현되며 신뢰할 수 있는 입력도 생성할 수 있다. HID 키보드나 마우스에는 입력 시퀀스를 저장했다가 나중에 재생할 수 있는 프로그래밍 가능한 매크로와 같은 고급 기능이 있을 수 있다. 장치 제조업체는 악성 앱이 예상치 못한 입력 시퀀스로 장치를 재프로그래밍하지 못하도록 이러한 기능을 신중히 설계해야 한다. 또한 사용자의 명시적 동의 없이 매크로 재생이 시작되지 않도록 보호해야 한다.

3.4. 완화 대책

보안 및 개인정보 보호 위험을 줄이기 위해 사용자 에이전트는 장치 접근 요청에 선택기 기반 흐름을 구현할 것을 권장한다. 페이지가 HID 장치 접근을 요청하면 사용자 에이전트는 페이지가 장치에 접근하려 한다는 사실을 알리는 대화 상자를 표시하는 것이 좋다. 대화 상자에는 연결된 HID 장치의 목록을 표시하고 페이지에 노출할 장치를 선택하도록 요청하는 것이 좋다. 실수로 클릭할 가능성을 줄이기 위해 대화 상자는 두 번의 별도 상호작용을 요구하는 것이 좋다. 첫 번째는 목록에서 장치를 선택하는 동작이고, 두 번째는 선택을 확인하고 대화 상자를 닫는 동작이다.

6. HID 인터페이스

[Exposed=(DedicatedWorker,ServiceWorker,Window), SecureContext]
interface HID : EventTarget {
    attribute EventHandler onconnect;
    attribute EventHandler ondisconnect;
    Promise<sequence<HIDDevice>> getDevices();
    [Exposed=Window] Promise<sequence<HIDDevice>> requestDevice(
        HIDDeviceRequestOptions options);
};

참고: 사용자 에이전트 구현은 조건부 노출을 선택할 수 있다. 대상은 hid 속성(소유 객체: Navigator)이며, 관련 전역 객체(소유 객체: Navigator)가 ServiceWorkerGlobalScope인 경우에 해당한다. 예를 들어 브라우저 확장 컨텍스트가 이에 해당하며, [browserext]에서 설명한다.

HID의 인스턴스는 다음 표에서 설명하는 내부 슬롯을 갖도록 생성한다:

내부 슬롯 초깃값 설명(비규범적)
[[devices]] 비어 있는 순서 있는 집합 하나의 순서 있는 집합 구성 요소: HIDDevice 인스턴스. 다음을 나타낸다: HID 인터페이스 현재 시스템에서 사용할 수 있는 인터페이스이다.
onconnect 속성, 자료형: EventHandler
onconnect 해당 속성은 이벤트 처리기 IDL 속성 이며 다음의 connect 이벤트 유형에 대응한다.
ondisconnect 속성, 자료형: EventHandler
ondisconnect 해당 속성은 이벤트 처리기 IDL 속성 이며 다음의 disconnect 이벤트 유형에 대응한다.
다음의 HID 인터페이스 를 시스템에서 사용할 수 있게 되면 다음 단계를 실행한다:
하나의 HID 인터페이스 는 HID 프로토콜로 장치와 통신하기 위한 논리적 인터페이스이다. 각 HID 인터페이스 에는 정확히 하나의 보고서 설명자 가 있으며, 이는 해당 인터페이스가 지원하는 보고서 집합을 설명한다. 하나의 물리적 장치는 노출할 수 있다 : 둘 이상의 HID 인터페이스. 장치에 여러 개의 HID 인터페이스 가 있으면 각 인터페이스에 대해 이 단계들을 한 번씩 실행한다.

예를 들어 USB 장치는 인터페이스의 집합으로 구현되며 각 인터페이스는 인터페이스 클래스를 지정할 수 있다. 장치에 HID 클래스를 사용하는 USB 인터페이스가 여러 개 있으면 각 인터페이스는 별개의 HID 인터페이스로 열거된다.

  1. device을(를) HIDDevice(으)로 둔다.

  2. device.[[vendorId]]의 값을 해당 인터페이스를 노출하는 장치의 공급업체 ID로 설정한다.

  3. device.[[productId]]의 값을 해당 인터페이스를 노출하는 장치의 제품 ID로 설정한다.

  4. device.[[productName]]의 값을 해당 인터페이스를 노출하는 장치의 제품 이름으로 설정한다.

  5. device.[[collections]]의 값을 보고서 설명자 파싱의 결과로 설정한다.

장치 필터는 다음이 만든 선택기 대화 상자에서 사용자에게 표시할 장치 목록을 좁히는 데 사용한다: requestDevice(). 필터가 없으면 어느 제외 필터에도 일치하지 않는 모든 연결된 장치를 포함한다. 필터가 하나 이상 있으면 필터 하나 이상에 일치하고 어느 제외 필터에도 일치하지 않는 장치를 포함한다.

모든 HIDDeviceFilter 멤버는 선택 사항이다. 각 멤버는 규칙 하나를 지정한다. HIDDeviceFilter에 일치하려면 모든 규칙을 만족해야 한다. 비어 있는 HIDDeviceFilter는 어떤 장치에나 일치한다.

장치 ID 규칙은 공급업체 ID와 제품 ID를 기준으로 장치를 선택하는 데 사용한다. 이는 응용 프로그램이 특정 장치에서만 작동하도록 설계되었거나 공급업체 고유 기능에 의존할 때 유용하다. vendorId 규칙을 포함하면 필터는 지정된 공급업체 ID를 갖는 장치에만 일치한다. productId 규칙도 포함하면 필터는 지정된 공급업체 ID와 제품 ID를 갖는 장치에만 일치한다. productId는 vendorId 규칙 없이 지정되면 무시한다.

용도 규칙은 HID 용도, 즉 장치의 최상위 컬렉션에 할당된 값을 기준으로 장치를 선택하는 데 사용한다. 이는 응용 프로그램이 표준 장치 유형과 작동하도록 설계되었을 때 유용하다. 장치에 일치하려면 장치의 컬렉션 중 적어도 하나는 모든 용도 규칙에 일치해야 한다. usagePage 규칙을 포함하면 필터는 장치에 지정된 용도 페이지를 갖는 컬렉션이 있을 때만 일치한다. usage 규칙도 포함하면 필터는 지정된 용도 페이지와 용도 ID를 갖는 장치에만 일치한다. usage는 usagePage 규칙 없이 지정되면 무시한다.

장치 ID 규칙과 용도 규칙은 결합할 수 있다. 예를 들어 응용 프로그램은 특정 공급업체의 장치 중에서도 특정 장치 클래스를 구현한 장치에만 일치시키려 할 수 있다.

    readonly attribute DataView data;
};
device 속성, 자료형: HIDDevice, 읽기 전용
다음의 HIDDevice 인스턴스이며, 다음을 나타낸다: HID 인터페이스 입력 보고서를 보낸 인터페이스이다.
reportId 속성, 자료형: octet, 읽기 전용
이 보고서의 1바이트 식별 접두사. 단, 다음의 HID 인터페이스가 다음을 하지 않는 경우에는 0이다: 보고서 ID 사용.
data 속성, 자료형: DataView, 읽기 전용
다음의 DataView 입력 보고서의 데이터를 포함한다. 단, 다음의 reportId 바이트는 제외한다. 이는 다음의 HID 인터페이스 보고서 ID 사용 시에 해당한다.

10. HIDCollectionInfo 딕셔너리

dictionary HIDCollectionInfo {
    unsigned short usagePage;
    unsigned short usage;
    octet type;
    sequence<HIDCollectionInfo> children;
    sequence<HIDReportInfo> inputReports;
    sequence<HIDReportInfo> outputReports;
    sequence<HIDReportInfo> featureReports;
};

장치가 시스템에 처음 연결되면 시스템은 보고서 설명자를 장치가 노출하는 각 HID 인터페이스에서 가져와야 한다. 보고서 설명자는 바이트 시퀀스이며, 이를 장치가 지원하는 각 보고서의 배치를 설명하는 계층적 자료구조로 확장할 수 있다. 이 자료구조의 원소를 항목이라고 한다. 서로 관련된 항목의 그룹을 컬렉션이라고 한다.

HIDCollectionInfo 객체는 보고서 설명자 내의 단일 컬렉션을 나타낸다. 컬렉션에 중첩된 컬렉션이 있으면 이를 children의 원소로 포함한다.

inputReports, outputReports 및 featureReports 속성에는 시퀀스가 들어 있다. 그 원소인 HIDReportInfo는 이 컬렉션에 기술된 각 보고서의 정보를 제공한다. 최상위 컬렉션에서는 HIDReportInfo가 보고서를 구성하는 모든 항목의 평탄화된 뷰를 나타낸다. 평탄화된 뷰는 중첩 컬렉션의 항목을 최상위 컬렉션의 항목과 원래 순서대로 섞어 놓는다. 중첩 컬렉션에서는 HIDReportInfo에 그 컬렉션과 그 안의 중첩 컬렉션에 포함된 항목만 들어 있다.

usagePage 멤버, 자료형: unsigned short
다음의 용도 페이지 구성 요소. 해당 구성 요소가 속하는 것은 다음이다: HID 용도 이 컬렉션과 관련된 용도이다.

HID 용도는 응용 프로그램이 항목이나 컬렉션의 목적과 의미를 식별하도록 해석할 수 있는 상수이다. HID 용도는 unsigned long 값이며, 상위 비트의 unsigned short 자료형 용도 페이지와 하위 비트의 unsigned short 자료형 용도 ID로 구성된다. 표준 HID 용도 값은 [USBIF-HID-CLASS] 및 USB Implementers Forum에서 발행한 다른 문서에서 설명한다.

HID 용도(장치가 노출하는 최상위 컬렉션에 지정된 값)는 일반적인 장치 유형을 식별하는 데 사용한다.

usage 멤버, 자료형: unsigned short
다음의 용도 ID 구성 요소. 해당 구성 요소가 속하는 것은 다음이다: HID 용도 이 컬렉션과 관련된 용도이다.

용도 ID는 개별 HID 용도를 해당 용도 페이지에서 선택하는 데 사용한다. 관례적으로 용도 ID 0x01부터 0x1F까지는 최상위 컬렉션용으로 예약되어 있다.

type 멤버, 자료형: octet
다음을 나타내는 값: 컬렉션 유형.
컬렉션 유형 값
물리적 0x00
응용 0x01
논리적 0x02
보고서 0x03
명명된 배열 0x04
용도 전환 0x05
용도 수정 0x06
향후 사용을 위해 예약됨 0x07부터 0x7F까지
공급업체 정의 0x80부터 0xFF까지

각 컬렉션 유형은 묶인 항목 간의 서로 다른 관계 유형을 설명한다. 자세한 내용은 [USBIF-HID-CLASS]의 6.2.2.6절에서 컬렉션 유형을 참고한다.

children 멤버, 시퀀스 자료형:<HIDCollectionInfo>
다음의 시퀀스 구성 요소: HIDCollectionInfo 이 컬렉션 안에 중첩된 컬렉션을 나타낸다.
inputReports 멤버, 시퀀스 자료형:<HIDReportInfo>
다음의 시퀀스 구성 요소: HIDReportInfo 이 컬렉션에 기술된 입력 보고서를 나타낸다.
outputReports 멤버, 시퀀스 자료형:<HIDReportInfo>
다음의 시퀀스 구성 요소: HIDReportInfo 이 컬렉션에 기술된 출력 보고서를 나타낸다.
featureReports 멤버, 시퀀스 자료형:<HIDReportInfo>
다음의 시퀀스 구성 요소: HIDReportInfo 이 컬렉션에 기술된 기능 보고서를 나타낸다.

다음의 HID 인터페이스 보고서 ID를 사용한다 각 보고서 전송에 1바이트 식별 접두사를 붙이는 경우에 해당한다. 다음의 reportId 멤버는 이 보고서의 접두사이다. 이는 인터페이스가 다음과 같을 때 해당한다: 보고서 ID를 사용한다, 그렇지 않으면 0이다.

true 항목이 수정할 수 없는 정적 읽기 전용 필드이면 이 값이며, 또는 false 항목이 수정 가능한 장치 데이터를 포함하는 보고서 필드를 정의하면 이 값이다.
isLinear 멤버, 자료형: boolean
true 항목이 측정값과 보고값 사이의 선형 관계를 나타내면 이 값이며, 또는 false 데이터가 어떤 방식으로든 처리되었으면 이 값이다.
isRange 멤버, 자료형: boolean
true 항목이 다음에서 용도를 할당하면 이 값이다: HID 용도 범위. 이 범위는 다음으로 정의한다: usageMinimum 및 usageMaximum, 또는 false 항목에 다음이 있으면 이 값이다: 시퀀스 구성 요소: HID 용도 값. 포함 위치: usages.
isVolatile 멤버, 자료형: boolean
true 호스트 상호작용 없이 항목 값이 바뀔 수 있으면 이 값이며, 또는 false 호스트만 항목 값을 변경하는 것이 좋으면 이 값이다.

기능 항목과 출력 항목에만 사용한다.

hasNull 멤버, 자료형: boolean
true 항목에 의미 있는 데이터를 보내지 않는 널 상태가 있으면 이 값이며, 또는 false 널 상태가 없으면 이 값이다. 널 상태에서는 항목이 지정된 다음 범위를 벗어나는 값을 보고한다: logicalMinimum 및 logicalMaximum.
hasPreferredState 멤버, 자료형: boolean
true 사용자가 제어 장치를 물리적으로 조작하지 않을 때 돌아가는 기본 상태가 있으면 이 값이며, 또는 false 기본 상태가 없으면 이 값이다.
wrap 멤버, 자료형: boolean
true 항목 값이 상한이나 하한에 도달했을 때 반대편 끝으로 순환하면 이 값이며, 또는 false 항목 값이 순환하지 않으면 이 값이다.
usages 멤버, 자료형: sequence<unsigned long>
만약 isRange 이(가) true 이거나 이 항목과 관련된 다음의 HID 용도 값이 없으면 usages 는 undefined여야 한다.

isRange이(가) false이면 usages은(는) 시퀀스이며 이 항목과 관련된 HID 용도 값을 원소로 갖는다.

usageMinimum 멤버, 자료형: unsigned long
만약 isRange 이(가) true 이면 usageMinimum 에는 최소의 다음 값이 들어 있다: HID 용도 값. 이 항목과 관련된 용도 범위 내의 값이다.

isRange이(가) false이면 usageMinimum은(는) undefined여야 한다.

usageMaximum 멤버, 자료형: unsigned long
만약 isRange 이(가) true 이면 usageMaximum 에는 최대의 다음 값이 들어 있다: HID 용도 값. 이 항목과 관련된 용도 범위 내의 값이다.

isRange이(가) false이면 usageMaximum은(는) undefined여야 한다.

reportSize 멤버, 자료형: unsigned short
각 보고서 데이터 필드의 크기(비트 단위). 다음의 reportSize 는 0보다 커야 한다.
reportCount 멤버, 자료형: unsigned short
이 항목에 대해 보고서에 포함되는 필드 수. 다음의 reportCount 는 0보다 커야 한다.
unitExponent 멤버, 자료형: byte
단위 지수 값. 항목에 단위 정의가 없으면 0이다.
unitSystem 멤버, 자료형: HIDUnitSystem
다음의 HIDUnitSystem 열거형 값으로, 단위 정의에 사용할 단위계를 지정한다. 또는 "none" 항목에 단위 정의가 없으면 이 값이다.

단위 정의에 있는 길이 단위(센티미터, 라디안, 인치 또는 도)의 지수 값. 항목에 단위 정의가 없으면 0이다.

unitFactorTemperatureExponent 멤버, 자료형: byte

logicalMaximum 멤버, 자료형: long
논리 단위로 나타낸 이 항목의 최댓값. 변수 항목이나 배열 항목이 보고할 최댓값이다.

이 항목의 물리적 범위의 최댓값. 이는 다음을 나타낸다: logicalMaximum 에 단위를 적용한 값이다.

이 항목과 관련된 문자열. 문자열이 없으면 비어 있는 시퀀스 를 사용한다.

13. HIDUnitSystem 열거형

[USBIF-HID-CLASS]의 6.2.2.7절은 SI 선형, SI 회전, 영국식 선형, 영국식 회전이라는 네 가지 표준 단위계를 정의한다. 각 항목은 이 네 단위계 중 하나나 공급업체 정의 단위계를 사용하거나, 단위계를 사용하지 않는다.

enum HIDUnitSystem {
    "none", "si-linear", "si-rotation", "english-linear",
    "english-rotation", "vendor-defined", "reserved"
};
"none"
단위계 없음. 항목에 단위 정의가 없음을 나타낸다.
"si-linear"
SI 선형 단위계는 센티미터, 그램, 초, 켈빈, 암페어, 칸델라를 사용한다.
"si-rotation"
SI 회전 단위계는 라디안, 그램, 초, 켈빈, 암페어, 칸델라를 사용한다.
"english-linear"
영국식 선형 단위계는 인치, 슬러그, 초, 화씨도, 암페어, 칸델라를 사용한다.
"english-rotation"
영국식 회전 단위계는 도, 슬러그, 초, 화씨도, 암페어, 칸델라를 사용한다.
"vendor-defined"
공급업체가 정의한 단위계.
"reserved"
장치가 단위계에 예약된 값을 사용했음을 나타낸다.

14. 사용 예

페이지에서 접근할 수 있는 장치 목록을 가져온다. 기본적으로 페이지에는 어떤 장치의 접근 권한도 부여되지 않았으므로 접근 가능한 장치가 없다. 
document.addEventListener('DOMContentLoaded', async () => {
  let devices = await navigator.hid.getDevices();
  devices.forEach(device => {
    console.log(`HID: ${device.productName}`);
  });
});
HID 장치의 연결 및 연결 해제에 대한 이벤트 수신기를 등록한다. 
navigator.hid.addEventListener('connect', ({device}) => {
  console.log(`HID connected: ${device.productName}`);
});

navigator.hid.addEventListener('disconnect', ({device}) => {
  console.log(`HID disconnected: ${device.productName}`);
});
장치 접근 권한이 부여되기 전에는 장치에 대해 다음을 통한 접근이 불가능하다: getDevices() . 그때까지 연결 이벤트도 발생하지 않는다. 페이지는 할 수 있다 : 다음을 사용하여 권한을 요청할 수 있다: requestDevice(). 이 예에서 페이지는 다음 값을 가진 장치에 대한 접근을 요청한다: 공급업체 ID 0xABCD. 장치는 반드시 다음 값을 가진 컬렉션도 갖춰야 한다: 용도 페이지 소비자 (0x000C) 및 용도 ID 소비자 제어 (0x0001). 다음 값을 가진 장치는 제품 ID 0x1234 오작동하는 것으로 보고되었다. 
let requestButton = document.getElementById("request-hid-device");
requestButton.addEventListener("click", async () => {
  let device;

이 명세서는 Touch Events 커뮤니티 그룹에서 발행했습니다. 이것은 W3C 표준이 아니며 W3C 표준 트랙에 있지 않습니다.

또한 W3C 커뮤니티 최종 명세 계약(FSA)에 따라 다른 조건이 적용된다는 점을 유의하세요.

이 명세의 버전은 Touch Events Level 1에 대한 수정 및 개선을 포함하며, 이전에 발표된 Touch Event Extensions의 기능을 통합합니다.

현재 Touch Events 명세에 대해 추가 작업을 계속할 계획은 없습니다. 이 문서는 원래의 Touch Events Level 1 명세 출시 이후 사용자 에이전트에서 이루어진 추가 및 변경사항을 반영하기 위해 유지되어 왔습니다. 커뮤니티 그룹은 Touch Events를 레거시 API로 간주하며 — 작성자들은 대신 Pointer Events를 채택할 것을 강력히 권장합니다.

Touch Events 명세서는 터치 감지 표면과의 하나 이상의 접촉 지점을 나타내는 저수준 이벤트 집합과, 그 접촉 지점들이 표면 및 그 위에 표시되거나 연결된 DOM 요소들(예: 터치 스크린이나 디스플레이가 없는 드로잉 태블릿의 경우)과 관련하여 변화하는 동작을 정의합니다. 또한 스타일러스 기능을 고려하여 펜 태블릿 장치(예: 드로잉 태블릿)에 대해서도 다룹니다.

소개

웹 애플리케이션에서 터치 입력을 제공하는 단말에서 실행되는 사용자 에이전트는 일반적으로 상호작용 가능한 웹 애플리케이션에 접근할 수 있도록 해석된 마우스 이벤트를 사용합니다. 그러나 이러한 해석된 이벤트는 물리적 터치 입력을 기반으로 정규화된 데이터이므로 의도한 사용자 경험을 제공하는 데 한계가 있습니다. 또한 마우스 이벤트의 제약 때문에 장치 능력과 무관하게 동시 입력을 처리하는 것이 불가능합니다: 시스템 수준의 제약과 레거시 호환성 때문입니다.

반면, 네이티브 애플리케이션은 제공된 시스템 API를 통해 두 경우 모두를 처리할 수 있습니다.

Touch Events 명세서는 웹 애플리케이션이 직접 터치 이벤트와 다중 터치 포인트를 처리할 수 있도록 인터페이스를 정의하여 이 문제에 대한 해결책을 제공합니다.

이 명세서는 단일 제품에 적용되는 적합성 기준을 정의합니다: 해당 인터페이스를 구현하는 사용자 에이전트입니다.

WindowProxy는 [[!HTML5]]에 정의되어 있습니다.

WebIDL 적합성

이 명세서의 IDL 블록은 WebIDL 명세서 [[!WEBIDL]]에 정의된 적합한 IDL 단편입니다.

적합한 사용자 에이전트는 또한 이 명세의 IDL 단편에 대해 적합한 JavaScript 구현이어야 하며, 다음과 같은 예외가 있습니다:

  • Web IDL 섹션 4.4.6는 IDL 속성이 인터페이스 프로토타입 객체의 접근자 속성으로 반영될 것을 요구합니다. 대신 사용자 에이전트는 관련 인터페이스를 구현하는 플랫폼 객체에 데이터 속성으로 IDL 속성을 반영할 수 있습니다. 이러한 데이터 속성은 접근자 속성의 getter와 setter를 호출할 때 나타나는 것과 동일한 동작을 가져야 합니다.

참고: IDL 속성을 반영하는 두 방법 모두 플랫폼 객체에서 단순히 속성을 읽고 쓰는 방식으로 동작합니다. 예를 들어 Touch 객체 aTouch에 대해 aTouch.target을 평가하면 Touch 객체의 EventTarget이 반환됩니다. 사용자 에이전트가 IDL 속성을 접근자 속성으로 구현하면 접근자 호출이 EventTarget을 반환합니다. 사용자 에이전트가 데이터 속성으로 구현하되 접근자와 동일한 동작을 제공하면, 객체는 자신의 속성으로 target을 가지며 그 값이 EventTarget 의 인스턴스가 됩니다.

Touch 인터페이스

이 인터페이스는 터치 이벤트의 개별 터치 포인트를 설명합니다. Touch 객체는 불변이며; 생성된 후에는 그 속성이 변경되어서는 안 됩니다.

enum TouchType {
    "direct",
    "stylus"
};

dictionary TouchInit {
    required long        identifier;
    required EventTarget target;
             double      clientX = 0;
             double      clientY = 0;
             double      screenX = 0;
             double      screenY = 0;
             double      pageX = 0;
             double      pageY = 0;
             float       radiusX = 0;
             float       radiusY = 0;
             float       rotationAngle = 0;
             float       force = 0;
             double      altitudeAngle = 0;
             double      azimuthAngle = 0;
             TouchType   touchType = "direct";
};

[Exposed=Window]
interface Touch {
    constructor(TouchInit touchInitDict);
    readonly        attribute long        identifier;
    readonly        attribute EventTarget target;
    readonly        attribute double      screenX;
    readonly        attribute double      screenY;
    readonly        attribute double      clientX;
    readonly        attribute double      clientY;
    readonly        attribute double      pageX;
    readonly        attribute double      pageY;
    readonly        attribute float       radiusX;
    readonly        attribute float       radiusY;
    readonly        attribute float       rotationAngle;
    readonly        attribute float       force;
    readonly        attribute float       altitudeAngle;
    readonly        attribute float       azimuthAngle;
    readonly        attribute TouchType   touchType;
};
identifier

각 터치 포인트에 대한 식별 번호입니다.

터치 포인트가 활성화될 때, 활성화된 다른 어떤 터치 포인트와도 구분되는 identifier가 할당되어야 합니다. 터치 포인트가 활성 상태인 동안, 해당 터치 포인트를 참조하는 모든 이벤트는 동일한 identifier를 할당해야 합니다.

target

터치 포인트가 처음 표면에 놓였을 때 시작된 EventTarget입니다. 이후 터치 포인트가 해당 요소의 상호작용 영역 밖으로 이동하더라도 이 값은 처음 시작된 요소를 가리킵니다.

일부 구현은 거친(coarse) 입력의 부정확성을 보정하기 위해 대상 요소를 변경합니다. 따라서 대상 요소가 이벤트 좌표에 직접 있는 요소와 반드시 일치하지 않을 수 있습니다. 거친 입력을 대상으로 지정하거나 중복 제거하는 방법은 이 명세의 범위를 벗어납니다.

screenX

화면을 기준으로 한 해당 지점의 수평 좌표(픽셀 단위)

screenY

화면을 기준으로 한 해당 지점의 수직 좌표(픽셀 단위)

clientX

뷰포트를 기준으로 한 해당 지점의 수평 좌표(스크롤 오프셋 제외, 픽셀 단위)

clientY

뷰포트를 기준으로 한 해당 지점의 수직 좌표(스크롤 오프셋 제외, 픽셀 단위)

pageX

뷰포트를 기준으로 한 해당 지점의 수평 좌표(스크롤 오프셋 포함, 픽셀 단위)

pageY

뷰포트를 기준으로 한 해당 지점의 수직 좌표(스크롤 오프셋 포함, 픽셀 단위)

radiusX

rotationAngle로 표시된 축을 따라 접촉 영역(예: 손가락, 스타일러스)을 가장 잘 둘러싸는 타원의 반지름을 CSS 픽셀 단위로 나타낸 값입니다(스크린과 동일한 스케일). 알려지지 않은 경우 0. 값은 음수가 될 수 없습니다.

radiusY

rotationAngle로 표시된 축에 수직인 축을 따라 접촉 영역을 가장 잘 둘러싸는 타원의 반지름을 CSS 픽셀 단위로 나타낸 값입니다(스크린과 동일한 스케일). 알려지지 않은 경우 0. 값은 음수가 될 수 없습니다.

rotationAngle

radiusX와 radiusY로 설명되는 타원이 시계 방향으로 중심을 기준으로 회전한 각도(도 단위). 알려지지 않은 경우 0. 값은 0 이상이고 90 미만이어야 합니다.

만약 radiusX와 radiusY가 원형이면 rotationAngle은 영향을 주지 않습니다. 이 경우 사용자 에이전트는 0을 사용할 수 있으며, 또는 허용 범위 내의 다른 값을 사용할 수 있습니다. (예: 갑작스러운 변화 방지를 위해 이전 터치 이벤트의 rotationAngle 값을 재사용할 수 있습니다.)

force

적용된 압력의 상대값으로 0에서 1 범위입니다. 0은 압력 없음, 1은 터치 장치가 감지할 수 있는 최대 압력입니다. 알려지지 않은 경우 0. force 값이 알려진 환경에서 force가 나타내는 절대 압력과 압력 감도의 단계는 환경마다 다를 수 있습니다.

altitudeAngle

트랜스듀서(예: 펜/스타일러스)의 고도(라디안 단위), 범위는 [0,π/2]. 0은 표면과 평행(X-Y 평면), π/2는 표면에 수직입니다. 기울기나 각도를 보고하지 않는 하드웨어/플랫폼의 경우 값은 반드시 0이어야 합니다.

여기서 정의된 altitudeAngle의 기본값은 0입니다. 이는 Pointer Events - Level 3 명세에서 altitudeAngle의 기본값이 π/2로 정의되어 트랜스듀서를 표면에 수직으로 위치시키는 것과 다릅니다.
azimuthAngle

트랜스듀서(예: 펜/스타일러스)의 방위각(라디안 단위), 범위는 [0, 2π]. 0은 X 값 증가 방향(정면에서 내려다볼 때 "3시" 방향)을 향하는 캡을 가진 트랜스듀서를 나타내며, 값은 시계방향으로 증가합니다(π/2는 "6시", π는 "9시", 3π/2는 "12시"). 트랜스듀서가 표면에 완전히 수직(즉 altitudeAngle이 π/2인 경우)일 때, 값은 반드시 0이어야 합니다. 기울기나 각도를 보고하지 않는 하드웨어/플랫폼의 경우 값은 반드시 0이어야 합니다.

touchType

터치를 트리거한 장치의 유형입니다.

TouchType

가능한 터치 입력 유형들을 나타내는 열거형입니다.

direct

화면에 직접 닿는 손가락의 터치.

stylus

스타일러스 또는 펜 장치의 터치.

TouchList 인터페이스

이 인터페이스는 터치 이벤트의 개별 접촉 지점 목록을 정의합니다. TouchList 객체는 불변이며; 생성된 후 그 내용은 변경되어서는 안 됩니다.

TouchList 객체의 지원되는 속성 인덱스([[!WEBIDL]])는 목록 길이보다 하나 작은 값까지의 범위에 있는 숫자들입니다.

[Exposed=Window]
interface TouchList {
    readonly        attribute unsigned long length;
    getter Touch? item (unsigned long index);
};
length

목록에 포함된 Touch 객체의 수를 반환합니다.

item

목록에서 지정된 인덱스의 Touch를 반환하거나, 인덱스가 목록 길이보다 크거나 같으면 null을 반환합니다.

TouchEvent 인터페이스

이 인터페이스는 touchstart, touchend, touchmove, touchcancel 이벤트 타입을 정의합니다. TouchEvent 객체는 불변이며; 생성되고 초기화된 이후에는 그 속성이 변경되어서는 안 됩니다. TouchEvent는 [[!DOM-LEVEL-3-EVENTS]]에 정의된 UIEvent 인터페이스를 상속합니다.

TouchEventInit 딕셔너리는 스크립트에서 신뢰할 수 없는(합성) 터치 이벤트를 생성하기 위해 TouchEvent 인터페이스의 생성자에 사용됩니다. 이는 [[!DOM-LEVEL-3-EVENTS]]에 정의된 EventModifierInit 딕셔너리를 상속합니다. 이벤트 생성 절차는 [[!DOM4]]에 정의되어 있습니다. 예제는 예시를 참조하세요.

dictionary TouchEventInit : EventModifierInit {
            sequence<Touch> touches = [];
            sequence<Touch> targetTouches = [];
            sequence<Touch> changedTouches = [];
};

[Exposed=Window]
interface TouchEvent : UIEvent {
    constructor(DOMString type, optional TouchEventInit eventInitDict = {});
    readonly        attribute TouchList touches;
    readonly        attribute TouchList targetTouches;
    readonly        attribute TouchList changedTouches;
    readonly        attribute boolean   altKey;
    readonly        attribute boolean   metaKey;
    readonly        attribute boolean   ctrlKey;
    readonly        attribute boolean   shiftKey;
    getter boolean getModifierState (DOMString keyArg);
};
touches

A list of Touch objects for every point of contact currently touching the surface.

targetTouches

A list of Touch objects for every point of contact that is touching the surface and started on the element that is the target of the current event.

changedTouches

A list of Touch objects for every point of contact which contributed to the event.

For the touchstart event this must be a list of the touch points that just became active with the current event. For the touchmove event this must be a list of the touch points that have moved since the last event. For the touchend and touchcancel events this must be a list of the touch points that have just been removed from the surface, with the last known coordinates of the touch points before they were removed.

altKey

true if the alt (Alternate) key modifier is activated; otherwise false

metaKey

true if the meta (Meta) key modifier is activated; otherwise false. On some platforms this attribute may map to a differently-named key modifier.

ctrlKey

true if the ctrl (Control) key modifier is activated; otherwise false

shiftKey

true if the shift (Shift) key modifier is activated; otherwise false

getModifierState(keyArg)

Queries the state of a modifier using a key value. Returns true if it is a modifier key and the modifier is activated, false otherwise.

TouchEvent 구현자 메모

사용자 에이전트는 주어진 TouchEvent에서 사용 가능한 모든 Touch 객체가 이벤트가 디스패치된 동일한 문서에 연결되도록 보장해야 합니다. 이를 구현하기 위해 사용자 에이전트는 현재의 터치 활성 문서 개념을 유지해야 합니다. 최초 터치 시 이는 터치가 생성된 대상 문서로 설정됩니다. 모든 활성 터치 포인트가 해제되면 터치 활성 문서는 지워집니다. 모든 TouchEvent는 현재 터치 활성 문서로 디스패치되며, 각 Touch 객체는 해당 문서의 DOM 요소(및 좌표)만을 참조해야 합니다. 터치가 현재의 터치 활성 문서 외부에서 완전히 시작된 경우, 해당 터치는 완전히 무시됩니다.

사용 예

아래 예제는 TouchEvent에 정의된 서로 다른 TouchList 멤버들 간의 관계를 보여줍니다.

touches 및 targetTouches의 예

이 예제는 touches와 targetTouches 멤버 간의 유용성과 관계를 보여줍니다. 다음 코드는 터치 가능한 요소와 문서에 있는 터치 포인트 수에 따라 다른 출력이 생성됩니다:

<div id="touchable">This element is touchable.</div>

<script>
document.getElementById('touchable').addEventListener('touchstart', function(ev) {

    if (ev.touches.item(0) == ev.targetTouches.item(0))
    {
        /**
         * If the first touch on the surface is also targeting the
         * "touchable" element, the code below should execute.
         * Since targetTouches is a subset of touches which covers the
         * entire surface, TouchEvent.touches >= TouchEvents.targetTouches
         * is always true.
         */

        document.write('Hello Touch Events!');
    }

    if (ev.touches.length == ev.targetTouches.length)
    {
        /**
         * If all of the active touch points are on the "touchable"
         * element, the length properties should be the same.
         */

        document.write('All points are on target element')
    }

    if (ev.touches.length > 1)
    {
        /**
         * On a single touch input device, there can only be one point
         * of contact on the surface, so the following code can only
         * execute when the terminal supports multiple touches.
         */

        document.write('Hello Multiple Touch!');
    }

}, false);
</script>

changedTouches의 예

이 예제는 changedTouches의 유용성과 다른 TouchList 멤버들과의 관계를 보여줍니다. 아래 코드는 터치 가능한 요소에서 터치 포인트가 제거될 때마다 트리거됩니다:

<div id="touchable">This element is touchable.</div>

<script>
document.getElementById('touchable').addEventListener('touchend', function(ev) {

    /**
     * Example output when three touch points are on the surface,
     * two of them being on the "touchable" element and one point
     * in the "touchable" element is lifted from the surface:
     *
     * Touch points removed: 1
     * Touch points left on element: 1
     * Touch points left on document: 2
     */

    document.write('Touch points removed: ' + ev.changedTouches.length);
    document.write('Touch points left on element: ' + ev.targetTouches.length);
    document.write('Touch points left on document: ' + ev.touches.length);

}, false);
</script>

스크립트에서 합성된 TouchEvent 발생시키기

이 예제는 스크립트에서 TouchEvent를 생성하고 발생시키는 방법을 보여줍니다.

if (Touch.length < 1 || TouchEvent.length < 1)
  throw "TouchEvent constructors not supported";

var touch = new Touch({
    identifier: 42,
    target: document.body,
    clientX: 200,
    clientY: 200,
    screenX: 300,
    screenY: 300,
    pageX: 200,
    pageY: 200,
    radiusX: 5,
    radiusY: 5
});

var touchEvent = new TouchEvent("touchstart", {
    cancelable: true,
    bubbles: true,
    composed: true,
    touches: [touch],
    targetTouches: [touch],
    changedTouches: [touch]
});

document.body.dispatchEvent(touchEvent);

TouchEvent 타입 목록

다음 표는 이 명세에서 정의된 TouchEvent 이벤트 타입의 요약을 제공합니다. 모든 이벤트는 버블링 단계를 수행해야 합니다. 모든 이벤트는 구성(composed)된 [[WHATWG-DOM]] 이벤트여야 합니다.

이벤트 타입 동기 / 비동기 버블링 구성(composed) 신뢰된 근접 이벤트 대상 타입 인터페이스 취소 가능성 기본 동작
touchstart 동기 예 예 Document, Element TouchEvent 상황에 따라 다름 정의되지 않음
touchend 동기 예 예 Document, Element TouchEvent 상황에 따라 다름 상황에 따라 다름: 사용자 에이전트는 마우스 및 클릭 이벤트를 디스패치할 수 있음
touchmove 동기 예 예 Document, Element TouchEvent 상황에 따라 다름 정의되지 않음
touchcancel 동기 예 예 Document, Element TouchEvent 아니요 없음

터치 이벤트의 취소 가능성

터치 이벤트를 취소하면 스크롤(스크립트 실행과 병행하여 발생할 수 있음)을 방지하거나 중단할 수 있습니다. 최대 스크롤 성능을 위해, 사용자 에이전트는 스크롤과 관련된 각 터치 이벤트가 취소되는지 확인하기 위해 처리 완료를 기다리지 않을 수 있습니다. 이러한 경우 사용자 에이전트는 cancelable 속성이 false인 터치 이벤트를 생성할 수 있으며, 이는 preventDefault로 스크롤을 방지하거나 중단할 수 없음을 나타냅니다. 그렇지 않으면 cancelable은 true입니다.

특히, 사용자 에이전트는 이벤트에 대해 비-패시브 리스너가 없음을 관찰한 경우 해당 이벤트에 대해 취소 불가능한 터치 이벤트만 생성해야 합니다.

touchstart 이벤트

사용자 에이전트는 사용자가 터치 표면에 터치 포인트를 놓을 때 이 이벤트 타입을 디스패치해야 합니다.

이 이벤트의 대상은 Element여야 합니다. 터치 포인트가 프레임 내에 있는 경우, 이벤트는 해당 프레임의 자식 브라우징 컨텍스트의 요소로 디스패치되어야 합니다.

이 이벤트가 취소되면, 동일한 활성 터치 포인트와 관련된 모든 터치 이벤트로 인해 발생하는 기본 동작(마우스 이벤트나 스크롤 포함)을 방지해야 합니다.

touchend 이벤트

사용자 에이전트는 사용자가 터치 표면에서 터치 포인트를 제거할 때 이 이벤트 타입을 디스패치해야 합니다. 여기에는 터치 포인트가 화면 밖으로 드래그되어 물리적으로 표면을 떠나는 경우도 포함됩니다.

이 이벤트의 대상은 터치 포인트가 처음 표면에 놓였을 때 시작된 동일한 Element여야 합니다. 이후 해당 터치 포인트가 대상 요소의 상호작용 영역 밖으로 이동했더라도 마찬가지입니다.

제거된 터치 포인트는 changedTouches 속성에 포함되어야 하며, touches 및 targetTouches 속성에는 포함되어서는 안 됩니다.

이 이벤트가 취소된 경우, 이 이벤트를 포함하는 터치 이벤트 시퀀스는 클릭으로 해석되어서는 안 됩니다.

touchmove 이벤트

사용자 에이전트는 사용자가 터치 포인트를 표면을 따라 이동시킬 때 이 이벤트 타입을 디스패치해야 합니다.

이 이벤트의 대상은 터치 포인트가 처음 표면에 놓였을 때 시작된 동일한 Element여야 합니다. 이후 해당 터치 포인트가 대상 요소의 상호작용 영역 밖으로 이동했더라도 마찬가지입니다.

touchmove 이벤트를 전송하는 빈도는 구현에 따라 다르며 하드웨어 능력 및 기타 구현 세부사항에 따라 달라질 수 있습니다.

사용자 에이전트는 동일한 활성 터치 포인트와 관련된 적어도 하나의 touchmove 이벤트가 취소되지 않았음이 확인될 때까지 어떤 touchmove 이벤트로 인해 발생하는 기본 동작을 억제해야 합니다. 동일한 활성 터치 포인트와 관련된 적어도 하나의 touchmove 이벤트가 취소되지 않았음이 확인된 이후에도 기본 동작이 억제되는지는 구현에 따라 다릅니다.

touchcancel 이벤트

사용자 에이전트는 터치 포인트가 구현 특정 방식으로 방해될 때 이 이벤트 타입을 디스패치해야 합니다. 예를 들어 동기 이벤트나 UA에서 발생한 동작이 터치를 취소하는 경우, 또는 터치 포인트가 문서 창을 벗어나 네이티브 UI나 플러그인으로 관리되는 문서 외 영역으로 들어간 경우 등이 해당됩니다. 또한 사용자 에이전트는 터치 표면에 장치나 구현이 저장하도록 구성된 것보다 더 많은 터치 포인트가 놓일 때 이 이벤트를 디스패치할 수 있으며, 이 경우 TouchList에서 가장 오래된 Touch 객체를 제거해야 합니다.

이 이벤트의 대상은 터치 포인트가 처음 표면에 놓였을 때 시작된 동일한 Element여야 합니다. 이후 해당 터치 포인트가 대상 요소의 상호작용 영역 밖으로 이동했더라도 마찬가지입니다.

제거된 터치 포인트는 changedTouches 속성에 포함되어야 하며, touches 및 targetTouches 속성에는 포함되어서는 안 됩니다.

재타깃팅(Retargeting)

다음 섹션은 [[!WHATWG-DOM]]에 정의된 재타깃팅 단계를 설명합니다.

Touch 객체는 관련된 unadjustedTarget(null 또는 EventTarget)을 가집니다. 달리 명시되지 않는 한 이것은 null입니다.

TouchEvent의 재타깃팅 단계는 다음 단계를 실행해야 합니다:

  1. touchEvent의 touches, targetTouches, 및 changedTouches 멤버에 있는 각 Touch touch에 대해:

    1. touch의 unadjustedTarget이 null인 경우 이를 touch의 target으로 설정합니다.

    2. touch의 target을 touchEvent의 target에 대해 재타깃팅을 수행한 결과로 설정합니다.

레거시 터치 이벤트 API의 조건부 노출

사용자 에이전트는 레거시 터치 이벤트 API 노출라는 불리언 값을 가지며 그 값은 구현 정의입니다.

기존 웹 콘텐츠는 이러한 API의 존재를 터치 가능한 "모바일" 기기라는 신호로 사용하는 경우가 많아, 터치 기능이 있어도 비-모바일 장치에 이 API를 노출하면 일부 웹 콘텐츠에 대해 최적이 아닌 사용자 경험을 초래할 수 있습니다.

GlobalEventHandlers 믹스인에 대한 확장

다음 섹션은 이벤트 핸들러 등록을 용이하게 하기 위해 [[!HTML5]]에 정의된 기존 GlobalEventHandlers 믹스인에 대한 확장을 설명합니다. 레거시 터치 이벤트 API 노출이 false인 사용자 에이전트는 이 믹스인을 구현해서는 안 됩니다.

partial interface mixin GlobalEventHandlers {
                    attribute EventHandler ontouchstart;
                    attribute EventHandler ontouchend;
                    attribute EventHandler ontouchmove;
                    attribute EventHandler ontouchcancel;
};

ontouchend

ontouchmove

touchmove 이벤트 타입에 대한 이벤트 핸들러 IDL 속성입니다.

ontouchcancel

마우스 이벤트 및 click과의 상호작용

사용자 에이전트는 동일한 사용자 입력에 대해 터치 이벤트와 함께(터치를 위해 설계되지 않은 웹 콘텐츠와의 호환성을 위해) 마우스 이벤트 [[!DOM-LEVEL-2-EVENTS]]를 디스패치할 수 있습니다. 만약 단일 사용자 동작에 대해 터치 이벤트와 마우스 이벤트를 모두 디스패치한다면, touchstart 이벤트 타입이 해당 동작에 대한 어떤 마우스 이벤트보다 먼저 디스패치되어야 합니다. 만약 touchstart, touchmove, 또는 touchend가 취소된 경우, 사용자 에이전트는 해당 터치 이벤트의 방지된 결과로 발생할 수 있는 어떤 마우스 이벤트도 디스패치하지 않아야 합니다.

웹 애플리케이션이 터치 이벤트를 처리할 수 있으면 이벤트를 취소하여 대응되는 마우스 이벤트를 사용자 에이전트가 디스패치할 필요가 없게 할 수 있습니다. 웹 애플리케이션이 터치 입력 장치용으로 특별히 작성되지 않았다면, 대신 후속 마우스 이벤트에 반응하게 됩니다.

사용자 에이전트는 일반적으로 단일 손가락 활성 제스처(탭, 롱 프레스 등)에 대해서만 마우스 및 클릭 이벤트를 디스패치합니다. 터치 포인트의 이동이 포함되거나 다중 터치(두 개 이상의 활성 터치 포인트)가 포함된 제스처는 일반적으로 터치 이벤트만 생성합니다.

사용자 에이전트가 터치 이벤트 시퀀스를 탭 제스처로 해석하면, 해당 터치 입력의 touchend 위치에서 mousemove, mousedown, mouseup, 및 click 이벤트를(그 순서로) 디스패치해야 합니다. 문서의 내용이 터치 이벤트 처리 중에 변경되었다면, 사용자 에이전트는 마우스 이벤트를 터치 이벤트와 다른 대상에 디스패치할 수 있습니다.

추가적인 터치 및 마우스 이벤트의 기본 동작 및 순서는 다른 곳에 명시된 경우를 제외하고는 구현에 따라 정의됩니다.

어떤 구현에서는 요소의 활성화(예: 탭)가 다음 이벤트 시퀀스를 생성하는 것이 일반적입니다(구현에 따라 약간 다를 수 있음):

  1. touchstart
  2. 손가락의 이동에 따라 0개 이상의 touchmove 이벤트
  3. touchend
  4. mousemove (레거시 마우스 전용 코드와의 호환성)
  5. mousedown
  6. mouseup
  7. click

그러나 인터랙션 중에 touchstart, touchmove, 또는 touchend 이벤트가 취소되었다면, 마우스나 클릭 이벤트는 발생하지 않으며 결과 이벤트 시퀀스는 단순히:

  1. touchstart
  2. 손가락의 이동에 따라 0개 이상의 touchmove 이벤트
  3. touchend

사용자 에이전트가 Touch Events를 지원한다고 해서 터치스크린이 유일한 입력 메커니즘이라는 의미는 아닙니다. 특히 터치 가능 노트북이나 외부 입력 장치가 연결된 전통적 "터치 전용" 장치(휴대폰, 태블릿 등)의 경우, 사용자는 터치스크린을 트랙패드, 마우스 또는 키보드와 함께 사용할 수 있습니다. 따라서 개발자는 "터치 또는 마우스/키보드" 조건부 코드로 이벤트 리스너를 바인딩하는 것을 피해야 합니다. 이는 터치 전용 인터랙션을 만들고 다른 입력 메커니즘을 사용하는 사용자를 배제할 수 있습니다.


// 조건부 "터치 OR 마우스/키보드" 바인딩 - 사용하지 마세요

if ('ontouchstart' in window) {
  // 터치용 이벤트 리스너 설정
  target.addEventListener('touchend', ...);
  ...
} else {
  // 마우스/키보드용 이벤트 리스너 설정
  target.addEventListener('click', ...);
  ...
}

대신 개발자는 다양한 입력 형태를 동시에 처리해야 합니다.


// 동시 "터치 AND 마우스/키보드" 바인딩 예

// 터치용 이벤트 리스너 설정
target.addEventListener('touchend', function(e) {
  // 호환 마우스 이벤트 및 클릭 방지
  e.preventDefault();
  ...
});
...

// 마우스/키보드용 이벤트 리스너 설정
target.addEventListener('click', ...);
...

터치 이벤트(터치 이벤트 자체 및 호환 마우스 이벤트로 인한 중복 처리)를 두 번 처리하지 않으려면, 개발자는 터치 이벤트를 취소하여 추가 마우스나 클릭 이벤트의 생성을 억제해야 합니다. 또는 터치 이벤트로 생성된 마우스 이벤트를 감지하는 방법으로 InputDeviceCapabilities API를 참조하십시오.

용어 해설(Glossary)

활성 터치 포인트
사용자가 화면에 올려 놓고 사용자 에이전트가 추적 중인 터치 포인트입니다. 터치 포인트는 사용자 에이전트가 그 등장을 알리는 touchstart 이벤트를 처음 디스패치할 때 활성화됩니다. 터치 포인트는 사용자 에이전트가 그 터치 포인트가 표면에서 제거되었거나 더 이상 추적되지 않음을 알리는 touchend 또는 touchcancel 이벤트를 디스패치한 이후에는 활성 상태가 아닙니다.
터치 포인트
포인터(예: 손가락이나 스타일러스)가 인터페이스의 대상 표면과 교차하는 좌표 지점입니다. 이는 터치스크린에 닿는 손가락이거나 종이에 디지털 펜으로 쓰는 경우에 적용될 수 있습니다.
취소된 이벤트
기본 동작이 preventDefault()로 방지되었거나, 이벤트 핸들러에서 false를 반환했거나, [[!DOM-LEVEL-3-EVENTS]] 및 [[!HTML5]]에 정의된 다른 수단으로 방지된 이벤트입니다.

감사의 말

이 명세의 기초로 사용된 모델을 개발한 WebKit 엔지니어들, WebKit 터치 이벤트 요약을 제공한 Neil Roberts (SitePen), 정리 및 제안을 해준 Peter-Paul Koch (PPK), ReSpec.js 명세 작성 도구를 개발한 Robin Berjon, 그리고 WebEvents WG의 많은 기여에 감사드립니다.

명세 개발 과정에서 추가 의견을 제공해 주셔서 꾸준한 개선에 기여한 많은 다른 분들께도 감사드립니다. 그들 중에는 Matthew Schinckel, Andrew Grieve, Cathy Chan, Boris Zbarsky, Patrick H. Lauke, Simon Pieters 등이 포함됩니다. 누락된 이름이 있다면 알려주시기 바랍니다.

그룹은 이 명세의 테스트 스위트 기여자로 Matt Brubeck, Olli Pettay, Art Barstow, Cathy Chan, Rick Byers를 인정합니다.

  • 좌표를 long에서 double 타입으로 업그레이드

초록

Touch Events 사양은 터치 감지 표면과 접촉하는 하나 이상의 지점 및 해당 표면과 그 위에 표시된 DOM 요소 (예: 터치스크린) 또는 그 표면과 연결된 DOM 요소(예: 디스플레이가 없는 그래픽 태블릿)를 기준으로 한 해당 지점의 변화를 나타내는 저수준 이벤트 집합을 정의합니다. 또한 스타일러스 기능을 고려하여 그래픽 태블릿과 같은 펜 태블릿 장치도 다룹니다.

1. 소개

이 섹션은 비규범적입니다.

웹 애플리케이션을 사용하기 위한 터치 입력을 제공하는 단말기에서 실행되는 사용자 에이전트는 일반적으로 해석된 마우스 이벤트를 사용하여 사용자가 대화형 웹 애플리케이션에 접근할 수 있도록 합니다. 그러나 이러한 해석된 이벤트는 물리적 터치 입력을 기반으로 정규화된 데이터이므로 의도한 사용자 경험을 제공하는 데 한계가 있는 경향이 있습니다. 또한 마우스 이벤트의 제약, 즉 시스템 수준의 제한과 레거시 호환성 때문에 장치의 기능과 관계없이 동시 입력을 처리할 수 없습니다.

반면 네이티브 애플리케이션은 제공되는 시스템 API를 사용하여 두 경우를 모두 처리할 수 있습니다.

Touch Events 사양은 웹 애플리케이션이 터치 이벤트를 직접 처리할 수 있도록 하는 인터페이스와, 이를 지원하는 장치에서 여러 터치 지점을 처리할 수 있도록 하는 인터페이스를 명시함으로써 이 문제에 대한 해결책을 제공합니다.

2. 적합성

비규범적이라고 표시된 섹션뿐만 아니라 이 사양의 모든 작성 지침, 다이어그램, 예제 및 참고 사항은 비규범적입니다. 이 사양의 그 밖의 모든 내용은 규범적입니다.

이 문서의 핵심 단어 MUST는 여기에서와 같이 모두 대문자로 표시되는 경우에만 BCP 14 [RFC2119] [RFC8174]에 설명된 대로 해석해야 합니다.

이 사양은 하나의 제품, 즉 이 사양에 포함된 인터페이스를 구현하는 사용자 에이전트에 적용되는 적합성 기준을 정의합니다.

WindowProxy는 [HTML5]에 정의되어 있습니다.

2.1 WebIDL 적합성

이 사양의 IDL 블록은 WebIDL 사양 [WEBIDL]에서 정의한 적합한 IDL 조각입니다.

적합한 사용자 에이전트는 다음 예외를 제외하고 이 사양의 IDL 조각에 대한 적합한 JavaScript 구현이어야 합니다.

  • Web IDL의 섹션 4.4.6에서는 IDL 속성이 인터페이스 프로토타입 객체의 접근자 속성으로 반영되어야 한다고 요구합니다. 대신 사용자 에이전트는 관련 인터페이스를 구현하는 플랫폼 객체의 데이터 속성으로 IDL 속성을 반영할 수 있습니다. 이러한 데이터 속성은 가져오거나 설정할 때 플랫폼 객체에서 접근자 속성의 getter와 setter를 호출했을 때 나타나는 것과 동일하게 동작해야 합니다.

참고: IDL 속성을 반영하는 두 방식 모두 플랫폼 객체에서 속성을 단순히 가져오고 설정하는 방식이 동작하도록 합니다. 예를 들어 Touch 객체 aTouch가 주어졌을 때 aTouch.target을 평가하면 Touch 객체에 대한 EventTarget이 반환됩니다. 사용자 에이전트가 IDL 속성을 접근자 속성으로 구현하는 경우, 속성 접근은 EventTarget을 반환하는 getter를 호출합니다. 사용자 에이전트가 IDL 속성을 접근자 속성과 동일한 동작을 하는 플랫폼 객체의 데이터 속성으로 구현하는 경우, 객체에는 값이 EventTarget 객체인 target이라는 자체 속성이 있는 것처럼 나타나며, 속성 접근은 이 값을 반환합니다.

3. Touch 인터페이스

이 인터페이스는 터치 이벤트의 개별 터치 지점을 설명합니다. Touch 객체는 변경할 수 없으며, 생성된 후에는 그 속성이 변경되어서는 안 됩니다.

WebIDLenum TouchType {
    "direct",
    "stylus"
};

dictionary TouchInit {
    required long        identifier;
    required EventTarget target;
             double      clientX = 0;
             double      clientY = 0;
             double      screenX = 0;
             double      screenY = 0;
             double      pageX = 0;
             double      pageY = 0;
             float       radiusX = 0;
             float       radiusY = 0;
             float       rotationAngle = 0;
             float       force = 0;
             double      altitudeAngle = 0;
             double      azimuthAngle = 0;
             TouchType   touchType = "direct";
};

[Exposed=Window]
interface Touch {
    constructor(TouchInit touchInitDict);
    readonly        attribute long        identifier;
    readonly        attribute EventTarget target;
    readonly        attribute double      screenX;
    readonly        attribute double      screenY;
    readonly        attribute double      clientX;
    readonly        attribute double      clientY;
    readonly        attribute double      pageX;
    readonly        attribute double      pageY;
    readonly        attribute float       radiusX;
    readonly        attribute float       radiusY;
    readonly        attribute float       rotationAngle;
    readonly        attribute float       force;
    readonly        attribute float       altitudeAngle;
    readonly        attribute float       azimuthAngle;
    readonly        attribute TouchType   touchType;
};
identifier

각 터치 지점의 식별 번호입니다.

터치 지점이 활성화되면 다른 모든 활성 터치 지점과 구별되는 identifier가 할당되어야 합니다. 터치 지점이 활성 상태를 유지하는 동안 이를 참조하는 모든 이벤트는 동일한 identifier를 할당해야 합니다.

target

터치 지점이 처음 표면에 놓였을 때 시작된 EventTarget입니다. 이후 터치 지점이 해당 요소의 대화형 영역 밖으로 이동했더라도 이 값은 그대로 유지됩니다.

참고

일부 구현에서는 거친 입력의 부정확성을 보정하기 위해 대상 요소를 변경합니다. 따라서 대상 요소가 반드시 이벤트 좌표에 직접 위치한 요소인 것은 아닙니다. 거친 입력의 대상을 지정하거나 모호성을 해소하는 데 사용되는 방법은 이 사양의 범위를 벗어납니다.

screenX

화면을 기준으로 한 지점의 수평 좌표이며 픽셀 단위입니다.

screenY

화면을 기준으로 한 지점의 수직 좌표이며 픽셀 단위입니다.

clientX

스크롤 오프셋을 제외하고 뷰포트를 기준으로 한 지점의 수평 좌표이며 픽셀 단위입니다.

clientY

스크롤 오프셋을 제외하고 뷰포트를 기준으로 한 지점의 수직 좌표이며 픽셀 단위입니다.

pageX

스크롤 오프셋을 포함하여 뷰포트를 기준으로 한 지점의 수평 좌표이며 픽셀 단위입니다.

pageY

스크롤 오프셋을 포함하여 뷰포트를 기준으로 한 지점의 수직 좌표이며 픽셀 단위입니다.

radiusX

rotationAngle로 표시되는 축을 따라 접촉 영역(예: 손가락, 스타일러스)을 가장 가깝게 둘러싸는 타원의 반지름이며, screenX와 동일한 배율의 CSS 픽셀([CSS-VALUES]에서 정의됨) 단위입니다. 알려진 값이 없으면 0입니다. 값은 음수여서는 안 됩니다.

radiusY

rotationAngle로 표시되는 축에 수직인 축을 따라 접촉 영역(예: 손가락, 스타일러스)을 가장 가깝게 둘러싸는 타원의 반지름이며, screenY와 동일한 배율의 CSS 픽셀( [CSS-VALUES]에서 정의됨) 단위입니다. 알려진 값이 없으면 0입니다. 값은 음수여서는 안 됩니다.

rotationAngle

radiusX와 radiusY로 설명되는 타원이 중심을 기준으로 시계 방향으로 회전한 각도(도 단위)입니다. 알려진 값이 없으면 0입니다. 값은 0 이상이고 90 미만이어야 합니다.

radiusX와 radiusY로 설명되는 타원이 원형이면 rotationAngle은 아무런 영향을 주지 않습니다. 이 경우 사용자 에이전트는 값으로 0을 사용할 수 있으며, 허용된 범위 내의 다른 값을 사용할 수도 있습니다. (예를 들어 갑작스러운 변화를 방지하기 위해 사용자 에이전트는 이전 터치 이벤트의 rotationAngle 값을 사용할 수 있습니다.)

force

적용된 압력의 상대값으로, 0에서 1 사이의 범위입니다. 여기서 0은 압력이 없음을 의미하고, 1은 터치 장치가 감지할 수 있는 최대 압력 수준을 의미합니다. 알려진 값이 없으면 0입니다. 힘을 알 수 있는 환경에서는 force 속성이 나타내는 절대 압력과 압력 단계의 민감도가 달라질 수 있습니다.

altitudeAngle

변환기(예: 펜/스타일러스)의 고도각(라디안 단위)이며 범위는 [0,π/2]입니다. 여기서 0은 표면(X-Y 평면)과 평행함을 의미하고, π/2는 표면과 수직임을 의미합니다. 기울기 또는 각도를 보고하지 않는 하드웨어 및 플랫폼의 경우 값은 MUST 0이어야 합니다.

참고
여기에서 altitudeAngle에 대해 정의된 기본값은 0입니다. 이는 Pointer Events - 레벨 3 [POINTEREVENTS] 사양의 altitudeAngle 속성 정의와 다릅니다. 해당 속성의 기본값은 π/2이며, 이는 변환기가 표면에 수직인 상태를 나타냅니다.
azimuthAngle

변환기(예: 펜/스타일러스)의 방위각(라디안 단위)이며 범위는 [0, 2π]입니다. 여기서 0은 X-Y 평면에서 변환기의 끝부분이 X 값이 증가하는 방향(위에서 똑바로 내려다보았을 때 "3시 방향")을 가리키는 것을 나타내며, 시계 방향으로 진행할수록 값이 점진적으로 증가합니다("6시 방향"에서 π/2, "9시 방향"에서 π, "12시 방향"에서 3π/2). 변환기가 표면에 완전히 수직인 경우 (altitudeAngle이 π/2) 값은 MUST 0이어야 합니다. 기울기 또는 각도를 보고하지 않는 하드웨어와 플랫폼의 경우 값은 MUST 0이어야 합니다.

touchType

터치를 트리거하는 데 사용된 장치의 유형입니다.

TouchType

가능한 여러 터치 입력 유형을 나타내는 열거형입니다.

direct

화면에서 손가락으로 직접 수행하는 터치입니다.

stylus

스타일러스 또는 펜 장치로 수행하는 터치입니다.

4. TouchList 인터페이스

이 인터페이스는 터치 이벤트의 개별 접촉 지점 목록을 정의합니다. TouchList 객체는 변경할 수 없으며, 생성된 후에는 그 내용이 변경되어서는 안 됩니다.

TouchList 객체의 지원되는 속성 인덱스([WEBIDL])는 0에서 목록 길이보다 1 작은 값까지의 숫자입니다.

WebIDL[Exposed=Window]
interface TouchList {
    readonly        attribute unsigned long length;
    getter Touch? item (unsigned long index);
};
length

목록에 있는 Touch 객체의 수를 반환합니다.

item

목록에서 지정한 인덱스에 있는 Touch를 반환하거나, 인덱스가 목록의 길이보다 작지 않으면 null을 반환합니다.

5. TouchEvent 인터페이스

이 인터페이스는 touchstart, touchend, touchmove 및 touchcancel 이벤트 유형을 정의합니다. TouchEvent 객체는 변경할 수 없으며, 생성되고 초기화된 후에는 그 속성이 변경되어서는 안 됩니다. TouchEvent는 [DOM-LEVEL-3-EVENTS]에 정의된 UIEvent 인터페이스를 상속합니다.

TouchEventInit 딕셔너리는 신뢰할 수 없는 (합성) 터치 이벤트를 생성할 수 있는 메커니즘을 제공하기 위해 TouchEvent 인터페이스의 생성자에서 사용됩니다. 이 딕셔너리는 [DOM-LEVEL-3-EVENTS]에 정의된 EventModifierInit 딕셔너리를 상속합니다. 이벤트를 생성하는 단계는 [DOM4]에 정의되어 있습니다. 신뢰할 수 없는 터치 이벤트를 발생시키는 방법을 보여주는 샘플 코드는 예제를 참조하세요. 

WebIDLdictionary TouchEventInit : EventModifierInit {
            sequence<Touch> touches = [];
            sequence<Touch> targetTouches = [];
            sequence<Touch> changedTouches = [];
};

[Exposed=Window]
interface TouchEvent : UIEvent {
    constructor(DOMString type, optional TouchEventInit eventInitDict = {});
    readonly        attribute TouchList touches;
    readonly        attribute TouchList targetTouches;
    readonly        attribute TouchList changedTouches;
    readonly        attribute boolean   altKey;
    readonly        attribute boolean   metaKey;
    readonly        attribute boolean   ctrlKey;
    readonly        attribute boolean   shiftKey;
    getter boolean getModifierState (DOMString keyArg);
};
touches

현재 표면에 닿아 있는 모든 접촉 지점에 대한 Touch 객체의 목록입니다.

targetTouches

표면에 닿아 있으며 현재 이벤트의 대상인 요소에서 시작된 모든 접촉 지점에 대한 Touch 객체의 목록입니다.

changedTouches

이벤트 발생에 기여한 모든 접촉 지점에 대한 Touch 객체의 목록입니다.

touchstart 이벤트의 경우 현재 이벤트로 인해 방금 활성화된 터치 지점의 목록이어야 합니다. touchmove 이벤트의 경우 마지막 이벤트 이후 이동한 터치 지점의 목록이어야 합니다. touchend 및 touchcancel 이벤트의 경우, 표면에서 방금 제거된 터치 지점의 목록이어야 하며, 제거되기 전 터치 지점의 마지막으로 알려진 좌표를 포함해야 합니다.

altKey

alt(Alternate) 키 수정자가 활성화되어 있으면 true이고, 그렇지 않으면 false입니다.

metaKey

meta(Meta) 키 수정자가 활성화되어 있으면 true이고, 그렇지 않으면 false입니다. 일부 플랫폼에서는 이 속성이 다른 이름의 키 수정자에 매핑될 수 있습니다.

ctrlKey

ctrl(Control) 키 수정자가 활성화되어 있으면 true이고, 그렇지 않으면 false입니다.

shiftKey

shift(Shift) 키 수정자가 활성화되어 있으면 true이고, 그렇지 않으면 false입니다.

getModifierState(keyArg)

키 값을 사용하여 수정자의 상태를 조회합니다. 수정자 키이고 해당 수정자가 활성화되어 있으면 true를 반환하고, 그렇지 않으면 false를 반환합니다.

5.1 TouchEvent 구현자 참고 사항

이 섹션은 비규범적입니다.

참고

사용자 에이전트는 주어진 Touch에서 사용할 수 있는 모든 TouchEvent 객체가 모두 해당 TouchEvent가 디스패치된 동일한 문서와 연결되도록 해야 합니다. 이를 구현하기 위해 사용자 에이전트는 현재 touch-active 문서라는 개념을 유지해야 합니다. 첫 번째 터치 시 이 값은 터치가 생성된 대상 문서로 설정됩니다. 모든 활성 터치 지점이 해제되면 touch-active 문서가 지워집니다. 모든 TouchEvent는 현재 touch-active 문서로 디스패치되며, 여기에 포함된 각 Touch 객체는 해당 문서의 DOM 요소(및 좌표)만 참조합니다. 터치가 현재 touch-active 문서의 완전히 바깥에서 시작되면 해당 터치는 완전히 무시됩니다.

5.2 사용 예제

이 섹션은 비규범적입니다.

아래 예제에서는 TouchEvent에 정의된 여러 TouchList 멤버 간의 관계를 보여줍니다.

5.2.1 TouchEvent의 touches 및 targetTouches

이 예제에서는 TouchEvent 인터페이스에 정의된 touches와 targetTouches 멤버의 유용성과 관계를 보여줍니다. 다음 코드는 터치 가능한 요소와 문서의 터치 지점 수에 따라 서로 다른 출력을 생성합니다:

예제 1 
<div id="touchable">이 요소는 터치할 수 있습니다.</div>

<script>
document.getElementById('touchable').addEventListener('touchstart', function(ev) {

    if (ev.touches.item(0) == ev.targetTouches.item(0))
    {
        /**
         * 표면의 첫 번째 터치가 "touchable" 요소도 대상으로 하는 경우
         * 아래 코드가 실행되어야 합니다.
         * targetTouches는 전체 표면을 포함하는 touches의 하위 집합이므로
         * TouchEvent.touches >= TouchEvents.targetTouches는
         * 항상 참입니다.
         */

        document.write('Touch Events 안녕하세요!');
    }

    if (ev.touches.length == ev.targetTouches.length)
    {
        /**
         * 모든 활성 터치 지점이 "touchable" 요소에 있는 경우
         * length 속성은 동일해야 합니다.
         */

        document.write('모든 지점이 대상 요소에 있습니다')
    }

    if (ev.touches.length > 1)
    {
        /**
         * 단일 터치 입력 장치에서는 표면에 하나의 접촉 지점만
         * 존재할 수 있으므로 다음 코드는 단말기가 멀티 터치를
         * 지원하는 경우에만 실행될 수 있습니다.
         */

        document.write('멀티 터치 안녕하세요!');
    }

}, false);
</script>

5.2.2 TouchEvent의 changedTouches

이 예제에서는 changedTouches의 유용성과 TouchEvent 인터페이스의 다른 TouchList 멤버와의 관계를 보여줍니다. 이 코드는 정의된 터치 가능 요소에서 터치 지점이 제거될 때마다 트리거되는 예제입니다:

예제 2 
<div id="touchable">이 요소는 터치할 수 있습니다.</div>

<script>
document.getElementById('touchable').addEventListener('touchend', function(ev) {

    /**
     * 표면에 세 개의 터치 지점이 있고 그중 두 개가 "touchable"
     * 요소에 있으며 "touchable" 요소의 한 지점이
     * 표면에서 떨어졌을 때의 출력 예제:
     *
     * 제거된 터치 지점: 1
     * 요소에 남은 터치 지점: 1
     * 문서에 남은 터치 지점: 2
     */

    document.write('제거된 터치 지점: ' + ev.changedTouches.length);
    document.write('요소에 남은 터치 지점: ' + ev.targetTouches.length);
    document.write('문서에 남은 터치 지점: ' + ev.touches.length);

}, false);
</script>

5.2.3 스크립트에서 합성 TouchEvent 발생시키기

이 예제에서는 스크립트에서 TouchEvent를 생성하고 발생시키는 방법을 보여줍니다.

예제 3 
if (Touch.length < 1 || TouchEvent.length < 1)
  throw "TouchEvent constructors not supported";

var touch = new Touch({

5.3 TouchEvent 유형 목록

이 섹션은 비규범적입니다.

다음 표는 이 사양에서 정의된 TouchEvent 이벤트 유형을 요약합니다. 모든 이벤트는 버블링 단계를 수행해야 합니다. 모든 이벤트는 composed [WHATWG-DOM] 이벤트여야 합니다.

이벤트 유형 동기 / 비동기 버블링 단계 Composed 신뢰할 수 있는 근접 이벤트 대상 유형 인터페이스 취소 가능 기본 동작
touchstart 동기 예 예 Document, Element TouchEvent 경우에 따라 다름 정의되지 않음
touchend 동기 예 예 Document, Element TouchEvent 경우에 따라 다름 경우에 따라 다름: 사용자 에이전트는 마우스 및 클릭 이벤트를 디스패치할 수 있습니다
touchmove 동기 예 예 Document, Element TouchEvent 경우에 따라 다름 정의되지 않음
touchcancel 동기 예 예 Document, Element TouchEvent 아니요 없음

5.4 터치 이벤트의 취소 가능성

터치 이벤트를 취소하면 스크롤(스크립트 실행과 동시에 진행될 수 있음)을 방지하거나 중단할 수 있습니다. 최대한의 스크롤 성능을 위해 사용자 에이전트는 스크롤과 관련된 각 터치 이벤트가 취소되는지 확인하기 위해 이벤트가 처리될 때까지 기다리지 않을 수 있습니다. 이러한 경우 사용자 에이전트는 cancelable 속성이 false인 터치 이벤트를 생성해야 하며, 이는 preventDefault를 사용하여 스크롤을 방지하거나 중단할 수 없음을 나타냅니다. 그렇지 않으면 cancelable은 true가 됩니다.

특히 사용자 에이전트는 해당 이벤트에 대해 비수동 리스너가 없음을 관찰하는 경우 취소할 수 없는 터치 이벤트만 생성해야 합니다.

5.5 touchstart 이벤트

사용자 에이전트는 사용자가 터치 표면에 터치 지점을 놓았음을 나타내기 위해 이 이벤트 유형을 디스패치해야 합니다.

이 이벤트의 대상은 Element여야 합니다. 터치 지점이 프레임 내에 있는 경우 이벤트는 해당 프레임의 자식 탐색 컨텍스트에 있는 요소로 디스패치되어야 합니다.

이 이벤트가 취소되면, 마우스 이벤트나 스크롤을 포함하여 동일한 활성 터치 지점과 관련된 모든 터치 이벤트로 인해 발생하는 모든 기본 동작을 방지해야 합니다.

5.6 touchend 이벤트

사용자 에이전트는 사용자가 터치 표면에서 터치 지점을 제거했음을 나타내기 위해 이 이벤트 유형을 디스패치해야 합니다. 여기에는 화면 바깥으로 드래그되는 경우처럼 터치 지점이 물리적으로 터치 표면을 벗어나는 경우도 포함됩니다.

이 이벤트의 대상은 터치 지점이 처음 표면에 놓였을 때 시작된 동일한 Element여야 하며, 이후 터치 지점이 대상 요소의 대화형 영역 밖으로 이동했더라도 마찬가지입니다.

제거된 터치 지점은 TouchEvent의 changedTouches 속성에 포함되어야 하며, touches 및 targetTouches 속성에는 포함되어서는 안 됩니다.

이 이벤트가 취소되면, 이 이벤트를 포함하는 모든 터치 이벤트 시퀀스는 클릭으로 해석되어서는 안 됩니다.

5.7 touchmove 이벤트

사용자 에이전트는 사용자가 터치 표면을 따라 터치 지점을 이동했음을 나타내기 위해 이 이벤트 유형을 디스패치해야 합니다.

이 이벤트의 대상은 터치 지점이 처음 표면에 놓였을 때 시작된 동일한 Element여야 하며, 이후 터치 지점이 대상 요소의 대화형 영역 밖으로 이동했더라도 마찬가지입니다.

사용자 에이전트가 touchmove 이벤트를 전송하는 빈도는 구현에서 정의되며, 하드웨어 기능과 기타 구현 세부 사항에 따라 달라질 수 있음에 유의하세요.

사용자 에이전트는 동일한 활성 터치 지점과 관련된 touchmove 이벤트 중 적어도 하나가 취소되지 않을 때까지 모든 touchmove 이벤트로 인해 발생하는 기본 동작을 억제해야 합니다. 동일한 활성 터치 지점과 관련된 touchmove 이벤트 중 적어도 하나가 취소되지 않은 후의 touchmove 이벤트에 대해 기본 동작을 억제할지는 구현에 따라 달라집니다.

5.8 touchcancel 이벤트

사용자 에이전트는 UA에서 발생한 동기 이벤트나 동작이 터치를 취소하는 경우 또는 터치 지점이 문서 창을 벗어나 사용자 상호작용을 처리할 수 있는 비문서 영역(예: UA의 네이티브 사용자 인터페이스 또는 플러그인이 관리하는 문서 영역)으로 이동하는 경우와 같이 구현별 방식으로 터치 지점이 중단되었음을 나타내기 위해 이 이벤트 유형을 디스패치해야 합니다. 사용자가 장치 또는 구현이 저장하도록 구성된 수보다 더 많은 터치 지점을 터치 표면에 놓는 경우에도 사용자 에이전트는 이 이벤트 유형을 디스패치할 수 있으며, 이 경우 TouchList에서 가장 이른 Touch 객체를 제거해야 합니다.

이 이벤트의 대상은 터치 지점이 처음 표면에 놓였을 때 시작된 동일한 Element여야 하며, 이후 터치 지점이 대상 요소의 대화형 영역 밖으로 이동했더라도 마찬가지입니다.

제거된 터치 지점은 TouchEvent의 changedTouches 속성에 포함되어야 하며, touches 및 targetTouches 속성에는 포함되어서는 안 됩니다.

6. 재대상 지정

다음 섹션에서는 [WHATWG-DOM]에 정의된 재대상 지정 단계를 설명합니다.

Touch 객체에는 연결된 unadjustedTarget(null 또는 EventTarget)이 있습니다. 달리 명시되지 않는 한 이 값은 null입니다.

TouchEvent의 재대상 지정 단계는 touchEvent가 주어졌을 때 다음 단계를 실행해야 합니다:

  1. touchEvent의 touches, targetTouches 및 changedTouches 멤버에 있는 각 Touch touch에 대해:

    1. touch의 unadjustedTarget이 null이면 touch의 unadjustedTarget을 touch의 target으로 설정합니다.
    2. touch의 target을 touchEvent의 target에 대해 touch의 unadjustedTarget을 재대상 지정한 결과로 설정합니다.

7. 레거시 터치 이벤트 API의 조건부 노출

사용자 에이전트에는 값이 구현에서 정의되는 연결된 불리언 레거시 터치 이벤트 API 노출이 있습니다.

참고

기존 웹 콘텐츠는 이러한 API의 존재 여부를 사용자 에이전트가 터치를 지원하는 "모바일" 장치라는 신호로 사용하는 경우가 많습니다. 따라서 터치를 지원하더라도 모바일 장치가 아닌 장치에 이러한 API를 노출하면 해당 웹 콘텐츠에서 최적이 아닌 사용자 경험이 발생할 수 있습니다.

8. GlobalEventHandlers 믹스인 확장

다음 섹션에서는 이벤트 핸들러 등록을 용이하게 하기 위해 [HTML5]에 정의된 기존 GlobalEventHandlers 믹스인의 확장을 설명합니다. 레거시 터치 이벤트 API 노출이 false인 사용자 에이전트에서는 이 믹스인을 구현해서는 안 됩니다. 

WebIDLpartial interface mixin GlobalEventHandlers {
                    attribute EventHandler ontouchstart;
                    attribute EventHandler ontouchend;
                    attribute EventHandler ontouchmove;
                    attribute EventHandler ontouchcancel;
};
ontouchstart

ontouchend

9. 마우스 이벤트 및 click과의 상호작용

사용자 에이전트는 동일한 사용자 입력에 대한 응답으로 터치 이벤트와 (터치용으로 설계되지 않은 웹 콘텐츠와의 호환성을 위해) 마우스 이벤트 [DOM-LEVEL-2-EVENTS]를 모두 디스패치할 수 있습니다. 사용자 에이전트가 하나의 사용자 동작에 대한 응답으로 터치 이벤트와 마우스 이벤트를 모두 디스패치하는 경우, touchstart 이벤트 유형은 해당 동작에 대한 모든 마우스 이벤트 유형보다 먼저 디스패치되어야 합니다. touchstart, touchmove 또는 touchend가 취소된 경우, 사용자 에이전트는 방지된 터치 이벤트의 결과로 발생하게 되는 어떠한 마우스 이벤트도 디스패치하지 않아야 합니다.

참고

웹 애플리케이션이 터치 이벤트를 처리할 수 있는 경우 이벤트를 취소할 수 있으며, 사용자 에이전트는 이에 대응하는 마우스 이벤트를 디스패치할 필요가 없습니다. 웹 애플리케이션이 터치 입력 장치를 위해 특별히 작성되지 않았다면 대신 이후의 마우스 이벤트에 반응합니다.

참고

사용자 에이전트는 일반적으로 한 손가락 활성화 제스처(탭 및 길게 누르기 등)에 대해서만 마우스 및 클릭 이벤트를 디스패치합니다. 터치 지점의 이동이나 두 개 이상의 활성 터치 지점을 사용하는 멀티 터치 상호작용이 포함된 제스처는 일반적으로 터치 이벤트만 생성합니다.

사용자 에이전트가 일련의 터치 이벤트를 탭 제스처로 해석하는 경우, 해당 터치 입력의 touchend 이벤트 위치에서 mousemove, mousedown, mouseup 및 click 이벤트를 (이 순서대로) 디스패치해야 합니다. 터치 이벤트를 처리하는 동안 문서의 내용이 변경된 경우 사용자 에이전트는 터치 이벤트와 다른 대상으로 마우스 이벤트를 디스패치할 수 있습니다.

다른 곳에서 명시된 경우를 제외하고, 이후 발생하는 모든 터치 및 마우스 이벤트의 기본 동작과 순서는 구현에서 정의됩니다.

참고

요소의 활성화(예: 일부 구현에서의 탭)는 일반적으로 다음과 같은 이벤트 시퀀스를 생성합니다(특정 사용자 에이전트의 동작에 따라 약간 달라질 수 있습니다):

  1. touchstart
  2. 손가락의 이동에 따라 0개 이상의 touchmove 이벤트
  3. touchend
  4. mousemove (레거시 마우스 전용 코드와의 호환성을 위해)
  5. mousedown
  6. mouseup
  7. click

그러나 이 상호작용 중 touchstart, touchmove 또는 touchend 이벤트 중 하나라도 취소된 경우 마우스 또는 클릭 이벤트는 발생하지 않으며, 결과 이벤트 시퀀스는 단순히 다음과 같습니다:

  1. touchstart
  2. 손가락의 이동에 따라 0개 이상의 touchmove 이벤트
  3. touchend
참고

사용자 에이전트가 Touch Events를 지원한다고 해서 터치스크린이 반드시 사용자가 사용할 수 있는 유일한 입력 메커니즘이라는 의미는 아닙니다. 특히 터치를 지원하는 노트북이나 외부 입력 장치가 연결된 기존의 "터치 전용" 장치(예: 휴대전화 및 태블릿)의 경우, 사용자는 터치스크린을 트랙패드, 마우스 또는 키보드와 함께 사용할 수 있습니다. 이러한 이유로 개발자는 "터치 또는 마우스/키보드 중 하나"라는 조건부 코드로 이벤트 리스너를 바인딩하지 않아야 합니다. 그렇게 하면 사이트/애플리케이션이 터치 전용이 되어 사용자가 다른 입력 메커니즘을 사용할 수 없게 됩니다.

예제 4 

// 조건부 "터치 또는 마우스/키보드" 이벤트 바인딩
// 이렇게 하지 마세요. 상호작용이 터치 전용이 됩니다
// 터치와 마우스/키보드를 모두 지원하는 장치에서

if ('ontouchstart' in window) {
  // 터치용 이벤트 리스너 설정
  target.addEventListener('touchend', ...);
  ...
} else {
  // 마우스/키보드용 이벤트 리스너 설정
  target.addEventListener('click', ...);
  ...
}

대신 개발자는 서로 다른 형태의 입력을 동시에 처리해야 합니다.

예제 5 

// 동시 "터치 및 마우스/키보드" 이벤트 바인딩

// 터치용 이벤트 리스너 설정
target.addEventListener('touchend', function(e) {
  // 호환성 마우스 이벤트 및 클릭 방지
  e.preventDefault();
  ...
});
...

// 마우스/키보드용 이벤트 리스너 설정
target.addEventListener('click', ...);
...

터치에서 동일한 상호작용을 두 번(한 번은 터치 이벤트로, 한 번은 호환성 마우스 이벤트로) 처리하지 않으려면 개발자는 터치 이벤트를 반드시 취소하여 이후의 마우스 또는 클릭 이벤트가 생성되지 않도록 해야 합니다. 또는 터치 이벤트의 결과로 생성된 마우스 이벤트를 감지하는 방법은 InputDeviceCapabilities API를 참조하세요.

10. 용어집

활성 터치 지점
현재 화면에 있고 사용자 에이전트가 추적하고 있는 터치 지점입니다. 터치 지점은 사용자 에이전트가 그 출현을 나타내는 touchstart 이벤트를 처음 디스패치할 때 활성 상태가 됩니다. 사용자 에이전트가 터치 지점이 표면에서 제거되었거나 더 이상 추적되지 않음을 나타내는 touchend 또는 touchcancel 이벤트를 디스패치한 후에는 더 이상 활성 상태가 아닙니다.
터치 지점
포인터(예: 손가락 또는 스타일러스)가 인터페이스의 대상 표면과 교차하는 좌표 지점입니다. 이는 터치스크린을 손가락으로 터치하거나 디지털 펜으로 종이에 쓰는 경우에 적용될 수 있습니다.
취소된 이벤트
preventDefault()를 사용하거나 이벤트 핸들러에서 false를 반환하거나, [DOM-LEVEL-3-EVENTS] 및 [HTML5]에 정의된 다른 방법을 통해 기본 동작이 방지된 이벤트입니다.

그 밖에도 많은 분들이 사양 개발 과정에서 추가 의견을 제공하여 지속적인 개선에 기여했습니다. 그중에는 Matthew Schinckel, Andrew Grieve, Cathy Chan, Boris Zbarsky, Patrick H. Lauke, Simon Pieters가 있습니다. 실수로 이름을 누락했다면 알려주시기 바랍니다.

그룹은 이 사양의 테스트 스위트에 기여한 다음 분들께 감사를 표합니다: Matt Brubeck, Olli Pettay, Art Barstow, Cathy Chan 및 Rick Byers.

B. 지난 게시 이후 변경 사항

이 섹션은 비규범적입니다.

다음은 2013년 10월 10일 권고안이 게시된 이후 이루어진 주요 변경 사항을 요약한 것입니다. 전체 커밋 기록도 확인할 수 있습니다.

  • PointerEvents에 맞게 altitudeAngle/azimuthAngle 설명을 다시 작성하고 그림 추가
  • getModifierState 정의 추가
  • Touch에 force 속성 추가
  • Touch에 radiusX 및 radiusY 속성 추가
  • Touch에 rotationAngle 속성 추가
  • 좌표를 long 대신 double 유형으로 변경
  • preventDefault 시 touchmove 동작 업데이트
  • touchend 이벤트 취소의 효과 명확화
  • TouchEvent 및 Touch의 생성자 추가
  • 레거시 이벤트 초기화 함수 initTouchEvent 추가
  • 취소할 수 없는 터치 이벤트에 대한 지원을 추가하고 스크롤 성능에 미치는 영향 설명
  • 모든 이벤트가 "composed"여야 함을 명시.
  • 조건부 "터치 또는 마우스/키보드" 이벤트 처리를 피하는 것에 관한 참고 사항
  • TouchEvent의 재대상 지정 단계 추가
  • touchType, altitudeAngle, azimuthAngle 추가(Safari iOS 10.3 스타일러스 확장)
  • 생성자에 [Exposed=Window] 추가
  • UA가 터치 대상을 조정할 수 있음을 언급하는 참고 사항 추가
  • 레거시 이벤트 초기화 함수(createTouch 및 createTouchList) 제거 및 initTouchEvent / createTouchList에 관한 참고 사항 제거
  • 레거시 터치 이벤트 API를 조건부로 노출
  • TouchEvent에 getModifierState 정의 추가

요약

Push API는 푸시 메시지를 웹 애플리케이션에 푸시 서비스를 통해 전송할 수 있게 해줍니다. 애플리케이션 서버는 웹 애플리케이션이나 사용자 에이전트가 비활성 상태일 때에도 언제든지 푸시 메시지를 보낼 수 있습니다. 푸시 서비스는 사용자 에이전트에 신뢰성 있고 효율적으로 전달함을 보장합니다. 푸시 메시지는 웹 애플리케이션의 오리진에서 실행되는 서비스 워커에 전달되며, 메시지의 정보를 사용해 로컬 상태를 업데이트하거나 사용자에게 알림을 표시할 수 있습니다.

이 명세는 웹 푸시 프로토콜과 함께 사용하도록 설계되었으며, 애플리케이션 서버 또는 사용자 에이전트가 푸시 서비스와 어떻게 상호작용하는지 설명합니다.

1. 소개

이 섹션은 규범적이지 않습니다.

Push API를 사용하면 웹 애플리케이션이 사용자 에이전트와 비동기적으로 통신할 수 있습니다. 이를 통해 애플리케이션 서버는 사용자가 웹 애플리케이션을 열 때까지 기다리지 않고, 시간에 민감한 정보가 알려지는 즉시 사용자 에이전트에 해당 정보를 제공할 수 있습니다.

여기에서 정의한 바와 같이, 푸시 서비스는 언제든지 푸시 메시지를 전달하는 기능을 지원합니다.

특히 푸시 메시지는 해당 웹 애플리케이션이 현재 브라우저 창에서 활성 상태가 아니더라도 웹 애플리케이션에 전달됩니다. 이는 사용자가 웹 애플리케이션을 닫더라도 푸시 메시지가 수신될 때 웹 애플리케이션을 다시 시작할 수 있어 여전히 이점을 얻을 수 있는 사용 사례와 관련됩니다. 예를 들어 푸시 메시지는 수신 중인 WebRTC 통화를 사용자에게 알리는 데 사용될 수 있습니다.

사용자 에이전트가 일시적으로 오프라인 상태일 때도 푸시 메시지를 전송할 수 있습니다. 이를 지원하기 위해 푸시 서비스는 사용자 에이전트를 위한 메시지를 사용자 에이전트가 사용 가능해질 때까지 저장합니다. 이는 웹 애플리케이션이 사용자가 오프라인 상태인 동안 발생한 변경 사항을 파악하는 사용 사례를 지원하며, 사용자 에이전트에 관련 정보를 적시에 제공할 수 있도록 합니다. 푸시 메시지는 사용자 에이전트에 연결할 수 있게 되어 메시지를 전달할 수 있을 때까지 푸시 서비스에 의해 저장됩니다.

Push API는 사용자 에이전트가 웹 애플리케이션을 적극적으로 사용하고 있는 동안에도 푸시 메시지가 안정적으로 전달되도록 보장합니다. 예를 들어 사용자가 웹 애플리케이션을 적극적으로 사용하고 있거나 웹 애플리케이션이 활성 워커, 프레임 또는 백그라운드 창을 통해 애플리케이션 서버와 활발하게 통신하는 경우가 이에 해당합니다. 이는 Push API의 주된 사용 사례가 아닙니다. 웹 애플리케이션은 애플리케이션 서버와 지속적인 통신을 유지할 필요를 피하기 위해 빈도가 낮은 메시지에 Push API를 사용하도록 선택할 수 있습니다.

푸시 메시징은 사용자 에이전트와 웹 애플리케이션 사이에 활성 통신 채널이 아직 설정되어 있지 않은 경우에 가장 적합합니다. 푸시 메시지를 전송하려면 Fetch API 또는 [WebSockets]와 같은 보다 직접적인 통신 방법에 비해 훨씬 더 많은 리소스가 필요합니다. 푸시 메시지는 일반적으로 직접 통신보다 지연 시간이 길며 사용 제한이 적용될 수도 있습니다. 대부분의 푸시 서비스는 전송할 수 있는 푸시 메시지의 크기와 수량을 제한합니다.

2. 의존성

웹 푸시 프로토콜 [RFC8030]은 사용자 에이전트 또는 애플리케이션 서버와 푸시 서비스 간의 통신을 가능하게 하는 프로토콜을 설명합니다. 다른 프로토콜을 대신 사용할 수도 있지만, 본 명세는 해당 프로토콜의 사용을 가정합니다. 대체 프로토콜도 호환되는 의미론을 제공해야 합니다.

Content-Encoding HTTP 헤더는 [RFC9110]의 8.4절에서 설명하며, push message의 페이로드에 적용된 콘텐츠 코딩을 나타낸다.

3. 개념

3.1 애플리케이션 서버

애플리케이션 서버는 웹 애플리케이션의 서버 측 구성 요소를 의미합니다.

3.2 푸시 메시지

푸시 메시지는 애플리케이션 서버에서 웹 애플리케이션으로 전송되는 데이터입니다.

푸시 메시지는 해당 메시지가 제출된 활성 워커와 연결된 푸시 구독에 전달됩니다. 서비스 워커가 현재 실행 중이 아니면, 전달을 위해 워커가 시작됩니다.

3.3 선언적 푸시 메시지

선언적 푸시 메시지는 푸시 메시지이며, 데이터가 사용자 에이전트가 이해할 수 있는 JSON 문서입니다. 사용자 에이전트는 각 수신되는 푸시 메시지를 기회적으로 파싱하여, 선언적 푸시 메시지인지 선언적 푸시 메시지 파서를 통해 판단합니다.

선언적 푸시 메시지는 서비스 워커의 개입 없이 알림을 생성하고 표시할 수 있습니다. 그럼에도 불구하고, 애플리케이션 서버가 원하면 서비스 워커가 개입할 수 있습니다. 이러한 경우, 푸시 메시지의 선언적 특성은 예를 들어 저장소 압박으로 서비스 워커가 제거된 경우 백업 역할을 합니다. 또한 알림 데이터를 전달하는 보다 객체 지향적인 방법을 제공합니다.

예시 1 
{
  "web_push": 8030,
  "notification": {
    "title": "Ada emailed ‘London’",
    "lang": "en-US",
    "dir": "ltr",
    "body": "Did you hear about the tube strikes?",
    "navigate": "https://email.example/message/12"
  }
}

3.3.1 멤버

선언적 푸시 메시지는 다음과 같은 멤버를 갖습니다:

web_push (필수)

반드시 8030이어야 하는 정수입니다. 선언적 푸시 메시지와 다른 JSON 문서를 구분하는 데 사용합니다.

notification (필수)

다음과 같은 멤버로 구성된 JSON 객체이며, 모두 알림 API의 기능과 유사하지만 때로는 조금 더 엄격한 타입을 가집니다. title을 제외한 모든 멤버는 NotificationOptions 딕셔너리에서 파생되었고, 동기화하여 유지해야 합니다. [NOTIFICATIONS]

title (필수)

문자열.

dir

"auto", "ltr", 또는 "rtl".

lang

언어 태그를 담는 문자열.

body

문자열.

navigate (필수)

URL을 담는 문자열.

tag

문자열.

image

URL을 담는 문자열.

icon

URL을 담는 문자열.

badge

URL을 담는 문자열.

vibrate

32비트 부호 없는 정수의 배열.

timestamp

64비트 부호 없는 정수.

renotify

불리언.

silent

불리언.

requireInteraction

불리언.

비고

NotificationOptions 딕셔너리와 일관성을 위해 require_interaction이 아닌 이름을 사용합니다.

data

임의의 JSON 값.

actions

다음과 같은 멤버를 가진 JSON 객체의 배열로, 모두 NotificationAction 딕셔너리에서 파생되었고 동기화하여 유지해야 합니다.

action (필수)

문자열.

title (필수)

문자열.

navigate (필수)

URL을 담는 문자열.

icon

URL을 담는 문자열.

mutable

불리언. true일 때 Notification 객체를 포함하는 push 이벤트가 서비스 워커(있는 경우)로 전달됩니다. 이 객체는 선언적 푸시 메시지에 의해 기술됩니다.

3.3.2 파서

선언적 푸시 메시지 파서 결과는 튜플이며, notification(알림)과 mutable(불리언)로 구성됩니다.

선언적 푸시 메시지 파서는 바이트 시퀀스 bytes, origin origin, URL baseURL, 그리고 EpochTimeStamp fallbackTimestamp를 받아 아래 단계들을 실행합니다. 실패 또는 선언적 푸시 메시지 파서 결과를 반환합니다.

  1. message를 JSON 바이트를 Infra 값으로 파싱의 결과로 합니다. 예외가 발생하면 실패를 반환합니다.

  2. message가 map이 아니면 실패를 반환합니다.

  3. message["web_push"]가 존재하지 않거나 8030이 아니면 실패를 반환합니다.

  4. message["notification"]이 존재하지 않으면 실패를 반환합니다.

  5. notificationInput을 message["notification"]으로 합니다.

  6. notificationInput이 map이 아니면 실패를 반환합니다.

  7. notificationInput["title"]이 존재하지 않거나 문자열이 아니면 실패를 반환합니다.

  8. notificationInput["navigate"]이 존재하지 않거나 문자열이 아니면 실패를 반환합니다.

  9. notificationTitle을 notificationInput["title"]으로 합니다.

  10. notificationOptions를 NotificationOptions 딕셔너리로 합니다.

  11. notificationInput["dir"]이 존재하고 "auto", "ltr", "rtl" 중 하나라면, notificationOptions["dir"] 에 notificationInput["dir"]을 설정합니다.

  12. notificationInput["lang"]이 존재하고 문자열이면, notificationOptions["lang"] 에 notificationInput["lang"]을 설정합니다.

  13. notificationInput["body"]이 존재하고 문자열이면, notificationOptions["body"] 에 notificationInput["body"]을 설정합니다.

  14. notificationOptions["navigate"] 에 notificationInput["navigate"](변환됨)을 설정합니다.

  15. notificationInput["tag"]이 존재하고 문자열이면, notificationOptions["tag"] 에 notificationInput["tag"]을 설정합니다.

  16. notificationInput["image"]이 존재하고 문자열이면, notificationOptions["image"] 에 notificationInput["image"](변환됨)을 설정합니다.

  17. notificationInput["icon"]이 존재하고 문자열이면, notificationOptions["icon"] 에 notificationInput["icon"](변환됨)을 설정합니다.

  18. notificationInput["badge"]이 존재하고 문자열이면, notificationOptions["badge"] 에 notificationInput["badge"](변환됨)을 설정합니다.

  19. notificationInput["vibrate"]가 존재하고 각 항목이 32비트 부호 없는 정수인 리스트라면, notificationOptions["vibrate"] 에 notificationInput["vibrate"]을 설정합니다.

  20. notificationInput["timestamp"]가 존재하고 64비트 부호 없는 정수라면, notificationOptions["timestamp"] 에 notificationInput["timestamp"]을 설정합니다.

  21. notificationInput["renotify"]가 존재하고 불리언이면, notificationOptions["renotify"] 에 notificationInput["renotify"]을 설정합니다.

  22. notificationInput["silent"]가 존재하고 불리언이면, notificationOptions["silent"] 에 notificationInput["silent"]을 설정합니다.

  23. notificationInput["requireInteraction"]가 존재하고 불리언이면, notificationOptions["requireInteraction"] 에 notificationInput["requireInteraction"]을 설정합니다.

  24. notificationInput["data"]가 존재하면, notificationOptions["data"] 에 Infra 값을 JSON 호환 JavaScript 값으로 변환한 결과를 설정합니다.

  25. notificationInput["actions"]가 존재하고 리스트라면:

    1. notificationActions를 « »로 합니다.

    2. 각 actionInput에 대해 notificationInput["actions"]:

      1. actionInput["action"]이 존재하지 않거나 문자열이 아니면 continue.

      2. actionInput["title"]이 존재하지 않거나 문자열이 아니면 continue.

      3. actionInput["navigate"]이 존재하지 않거나 문자열이 아니면 continue.

      4. actionNavigate를 actionInput["navigate"](변환됨)으로 합니다.

      5. notificationAction을 NotificationAction 딕셔너리로, «[ "action" → actionInput["action"], "title" → actionInput["title"], "navigate" → actionNavigate ]»로 합니다.

      6. actionInput["icon"]이 존재하고 문자열이면 notificationAction["icon"] 에 actionInput["icon"](변환됨)을 설정합니다.

      7. Append notificationAction을 notificationActions에 추가합니다.

    3. notificationOptions["actions"] 에 notificationActions을 설정합니다.

  26. notification을 알림 생성의 결과로, notificationTitle, notificationOptions, origin, baseURL, fallbackTimestamp를 인자로 하여 생성합니다. 예외가 발생하면 실패를 반환합니다.

  27. notification의 navigation URL이 null이면 실패를 반환합니다.

  28. notification의 actions의 navigation URL 중 하나라도 null이면 실패를 반환합니다.

  29. mutable을 false로 합니다.

  30. message["mutable"]가 존재하고 불리언이면, mutable을 message["mutable"]로 설정합니다.

  31. (notification, mutable)을 반환합니다.

3.4 푸시 구독

푸시 구독은 웹 애플리케이션을 대신하여 사용자 에이전트와 푸시 서비스 사이에 설정된 메시지 전달 컨텍스트입니다.

푸시 구독에는 연결된 범위가 있으며, 이는 URL입니다.

푸시 구독은 연결된 창에서 액세스 가능한 범위를 가진 것으로 간주되며, 이때 해당 범위의 경로는 목록이고 그 크기가 1이며, 범위의 경로[0]은 빈 문자열입니다.

참고

즉, 경로 구성 요소가 URL에서 "/"로 직렬화됩니다.

푸시 구독에는 연결된 푸시 엔드포인트가 있습니다. 이는 푸시 서비스가 노출하며 애플리케이션 서버가 푸시 메시지를 보낼 수 있는 절대 URL이어야 합니다. 푸시 엔드포인트는 푸시 구독을 고유하게 식별해야 합니다.

푸시 구독에는 연결된 구독 만료 시간이 있을 수 있습니다. 설정된 경우, 이는 1970년 1월 1일 00:00:00 UTC 이후의 밀리초 단위 시간으로, 해당 구독이 비활성화되는 시간이어야 합니다. 사용자 에이전트는 구독이 만료되기 전에 푸시 구독을 갱신하려고 시도하는 것이 좋습니다.

푸시 구독에는 [RFC8291]에 따라 P-256 ECDH 키 쌍과 인증 비밀을 위한 내부 슬롯이 있습니다. 이러한 슬롯은 푸시 구독을 생성할 때 채워져야 합니다.

사용자 에이전트가 어떤 이유로든 푸시 구독의 키를 변경해야 하고 푸시 구독의 연결된 서비스 워커 등록이 null이 아닌 경우, 갱신을 푸시 구독에 대해 반드시 수행해야 합니다.

푸시 구독을 생성하려면, PushSubscriptionOptionsInit optionsDictionary가 주어졌을 때:

  1. subscription을 새로운 PushSubscription으로 설정합니다.
  2. options을 새로 생성된 PushSubscriptionOptions 객체로 설정하고, 해당 속성을 optionsDictionary의 대응하는 멤버 및 값으로 초기화합니다.
  3. subscription의 options 속성을 options으로 설정합니다.
  4. 새로운 P-256 ECDH 키 쌍을 생성합니다 [ANSI-X9-62]. 비공개 키를 subscription의 내부 슬롯에 저장합니다. 이 값은 애플리케이션에서 사용할 수 있게 해서는 안 됩니다. 공개 키도 내부 슬롯에 저장되며, getKey() 메서드를 PushSubscription에서 "p256dh" 인수와 함께 호출하여 가져올 수 있습니다.
  5. [RFC8291]에 정의된 옥텟 시퀀스인 새로운 인증 비밀을 생성합니다. 인증 비밀을 subscription의 내부 슬롯에 저장합니다. 이 키는 getKey() 메서드를 PushSubscription에서 "auth" 인수와 함께 호출하여 가져올 수 있습니다.
  6. 새로운 푸시 구독을 요청합니다. options의 applicationServerKey 속성이 설정되어 있는 경우 이를 포함합니다. 모든 예외를 다시 던집니다.
  7. 푸시 구독 요청이 성공적으로 완료되면:
    1. subscription의 endpoint 속성을 푸시 구독의 푸시 엔드포인트로 설정합니다.
    2. 푸시 구독에서 제공된 경우, subscription의 expirationTime을 설정합니다.
  8. subscription을 반환합니다.

3.4.1 서비스 워커 등록과의 관계

푸시 구독의 연관된 서비스 워커 등록은 서비스 워커 등록 중에서 scope URL이 동일한 푸시 구독의 scope를 가진 경우 해당 서비스 워커 등록입니다. 없다면 null입니다.

Note

푸시 구독의 연관된 서비스 워커 등록이 null이 될 수 있는 경우는 window-accessible scope를 가진 경우뿐입니다.

반대로, 서비스 워커 등록의 연관된 푸시 구독은 푸시 구독 중 scope가 동일한 서비스 워커 등록의 scope URL을 가진 경우 해당 푸시 구독입니다. 없다면 null입니다.

3.4.2 구독 갱신

사용자 에이전트 또는 푸시 서비스는 예를 들어 특정 기간이 경과했다는 등의 이유로 연결된 서비스 워커 등록이 null이 아닌 푸시 구독을 언제든지 갱신하도록 선택할 수 있습니다.

이 경우 사용자 에이전트는 현재 푸시 구독을 생성할 때 제공된 PushSubscriptionOptions가 주어졌을 때 푸시 구독을 생성하는 단계를 반드시 실행하고, 새로운 푸시 구독의 범위를 원래 구독의 범위로 설정해야 합니다. 새로운 푸시 구독은 원래 구독과 다른 키 쌍을 반드시 가져야 합니다.

성공하면 사용자 에이전트는 이어서 푸시 구독과 연결된 서비스 워커 등록을 registration으로, 초기 푸시 구독을 나타내는 PushSubscription 인스턴스를 oldSubscription으로, 그리고 새로운 PushSubscription 인스턴스로 나타낸 새로운 푸시 구독을 newSubscription으로 하여 "pushsubscriptionchange" 이벤트를 발생시켜야 합니다.

변경 사항이 애플리케이션 서버에 전파될 시간을 확보하기 위해, 사용자 에이전트는 갱신 후 잠시 동안 이전 푸시 구독의 메시지를 계속 수락할 수 있습니다. 갱신된 푸시 구독에 대한 메시지가 수신된 이후에는, 모든 이전 푸시 구독을 비활성화해야 합니다.

사용자 에이전트가 푸시 구독을 갱신할 수 없는 경우, 주기적으로 갱신을 다시 시도하는 것이 좋습니다. 예를 들어 만료되어 푸시 구독을 더 이상 사용할 수 없게 되면, 사용자 에이전트는 서비스 워커 등록을 푸시 구독과 연결된 registration으로, 비활성화되는 PushSubscription 인스턴스로 나타낸 푸시 구독을 oldSubscription으로, 그리고 null을 newSubscription으로 하여 "pushsubscriptionchange" 이벤트를 발생시켜야 합니다.

3.4.3 구독 비활성화

푸시 구독이 비활성화되면, 사용자 에이전트와 푸시 서비스는 모두 저장된 해당 세부 정보의 모든 사본을 삭제해야 합니다. 이후 이 푸시 구독에 대한 푸시 메시지는 전달되어서는 안 됩니다.

창에서 액세스 가능한 범위가 없는 푸시 구독은 연결된 서비스 워커 등록이 등록 해제될 때 비활성화되어야 합니다. 다만 푸시 구독은 더 일찍 비활성화될 수 있습니다.

참고

창에서 액세스 가능한 범위가 없는 푸시 구독은 서비스 워커 등록이 지워질 때 제거됩니다.

3.5 푸시 서비스

푸시 서비스라는 용어는 애플리케이션 서버가 웹 애플리케이션에 푸시 메시지를 보낼 수 있게 하는 시스템을 의미합니다. 푸시 서비스는 자신이 관리하는 푸시 엔드포인트 또는 엔드포인트를 해당 푸시 구독에 제공합니다.

사용자 에이전트는 푸시 서비스에 연결하여 푸시 구독을 생성합니다. 사용자 에이전트는 선택적으로 사용 가능한 푸시 서비스의 선택을 제한할 수 있습니다. 그 이유는 서비스 가용성(특정 국가나 네트워크, 직장 환경 등에서 방화벽에 의해 서비스가 차단되는 경우 포함), 신뢰성, 배터리 수명에 미치는 영향, 특정 푸시 서비스로 메타데이터를 유도하거나 회피하는 계약 등 성능 관련 우려가 있을 수 있습니다.

3.6 권한

Push API는 강력한 기능이며, 이름은 "push"로 식별됩니다.

Permissions 명세와의 통합을 위해, 이 명세에서는 PushPermissionDescriptor permission descriptor type을 정의합니다. 

WebIDLdictionary PushPermissionDescriptor : PermissionDescriptor {
  boolean userVisibleOnly = false;
};

userVisibleOnly는 userVisibleOnly와 동일한 의미를 가집니다.

{name: "push", userVisibleOnly: false}는 더 강력한 권한이며, {name: "push", userVisibleOnly: true}보다 우선합니다.

4. 보안 및 개인정보 보호 고려사항

푸시 메시지의 내용은 암호화됩니다 [RFC8291]. 그러나 푸시 서비스에는 여전히 애플리케이션 서버가 푸시 구독을 통해 사용자 에이전트에 보내는 메시지의 메타데이터가 노출됩니다. 여기에는 메시지의 시점, 빈도 및 크기가 포함됩니다. 사용자 에이전트가 허용하지 않을 수도 있는 푸시 서비스 변경 이외에 알려진 유일한 완화 방법은 패딩을 사용하여 겉으로 보이는 메시지 크기를 늘리는 것입니다.

푸시 메시지가 웹 애플리케이션과 동일한 출처를 가진 애플리케이션 서버에 의해 전송되었다는 보장은 없습니다. 애플리케이션 서버는 자신의 재량에 따라 푸시 구독을 사용하는 데 필요한 세부 정보를 제3자와 공유할 수 있습니다.

다음 요구 사항은 가능한 한 사용자의 개인정보 보호와 보안을 보호하고, 그 목표를 충족하는 범위에서 애플리케이션 서버와 사용자 간 통신의 무결성을 보호하기 위한 것입니다.

Push API는 개발자가 제공한 이벤트 핸들러를 실행하기 위해 서비스 워커 등록과 연결된 서비스 워커를 깨워야 할 수 있습니다. 이로 인해 네트워크 트래픽과 같은 리소스 사용이 발생할 수 있으며, 사용자 에이전트는 이를 푸시 구독을 생성한 웹 애플리케이션에 귀속시키는 것이 좋습니다.

사용자 에이전트는 권한을 획득하거나 권한 상태를 결정할 때 PushSubscriptionOptions를 고려할 수 있습니다.

권한이 취소되면 사용자 에이전트는 해당 권한으로 생성된 구독에 대해 "pushsubscriptionchange" 이벤트를 발생시킬 수 있습니다. 이때 서비스 워커 등록과 연결된 푸시 구독을 registration으로, 푸시 구독을 나타내는 PushSubscription 인스턴스를 oldSubscription으로, null을 newSubscription으로 사용합니다. 사용자 에이전트는 영향을 받는 구독을 병렬로 비활성화해야 합니다.

푸시 엔드포인트는 푸시 서비스 이외의 행위자가 사용자의 기기, 신원 또는 위치와 같은 사용자에 관한 정보를 추론할 수 있도록 노출해서는 안 됩니다. 정확한 요구 사항은 [RFC8030]의 개인정보 보호 고려 사항을 참조하십시오.

비활성화된 푸시 구독의 푸시 엔드포인트는 새로운 푸시 구독에 재사용해서는 안 됩니다. 이렇게 하면 사용자가 제거할 수 없는 영구적인 식별자가 생성되는 것을 방지할 수 있습니다. 또한 한 푸시 구독의 세부 정보를 재사용하여 다른 푸시 구독으로 푸시 메시지를 보내는 것도 방지합니다.

5. 푸시 프레임워크

이 섹션은 규범적이지 않습니다.

푸시 메시지는 애플리케이션 서버에서 웹 애플리케이션으로 다음과 같이 전송됩니다:

  • 애플리케이션 서버가 푸시 서비스에 [RFC8030]로 푸시 메시지 전달을 요청합니다. 이 요청에는 푸시 엔드포인트가 포함되어 있으며, 이는 푸시 구독에 포함됩니다.
  • 푸시 서비스가 메시지를 특정 사용자 에이전트에 전달하며, 메시지 내에서 푸시 엔드포인트를 식별합니다.
  • 사용자 에이전트가 적절한 Service Worker를 식별하고 필요 시 활성화하며, 푸시 메시지를 해당 Service Worker로 전달합니다.

이 전체 프레임워크를 통해 애플리케이션 서버는 서비스 워커를 애플리케이션 서버의 이벤트에 응답하여 활성화할 수 있습니다. 이러한 이벤트에 대한 정보는 푸시 메시지에 포함될 수 있으며, 이를 통해 웹 애플리케이션은 네트워크 요청을 시작할 필요 없이 이러한 이벤트에 적절하게 대응할 수 있습니다.

이 섹션은 규범적이지 않습니다.

5.3 푸시 서비스 사용

PushSubscription에 포함된 필드는 애플리케이션 서버가 푸시 메시지를 보내는 데 필요한 모든 정보를 담고 있습니다. Push API와 호환되는 푸시 서비스는 웹 푸시 프로토콜을 준수하는 푸시 엔드포인트를 제공합니다. 이러한 파라미터와 속성에는 다음과 같은 항목이 포함됩니다:

  • 푸시 엔드포인트는 PushSubscription의 URL이며, 애플리케이션 서버가 웹 애플리케이션에 푸시 메시지 전달을 요청할 수 있게 해줍니다.
  • getKey() 메서드는 PushSubscription에서 푸시 메시지의 암호화와 인증에 사용되는 키 자료를 가져오는 데 사용됩니다. 이 함수가 호출될 때마다 해당 키의 값을 담은 새로운 ArrayBuffer를 반환하며, 지정한 키가 존재하지 않으면 null을 반환합니다. "p256dh" 값을 전달하면 타원 곡선 디피-헬만 (ECDH) 공개 키를 푸시 구독에 대해 가져옵니다. auth 값을 전달하면 애플리케이션 서버가 메시지 인증에 사용하는 인증 시크릿을 반환합니다. 이 키들은 애플리케이션 서버가 푸시 구독에 대해 메시지를 암호화하고 인증하는 데 사용되며, [RFC8291]에 설명되어 있습니다.

6. PushManagerAttribute 믹스인

본 명세는 Window와 ServiceWorkerRegistration 객체에 대해 PushManagerAttribute 믹스인을 확장합니다. [HTML] [SERVICE-WORKERS] 

WebIDL[SecureContext]
interface mixin PushManagerAttribute {
  readonly attribute PushManager pushManager;
};
Window includes PushManagerAttribute;
ServiceWorkerRegistration includes PushManagerAttribute;

Window와 ServiceWorkerRegistration 객체는 연관된 PushManager 객체를 가집니다.

pushManager getter의 단계는 this의 연관된 PushManager 객체를 반환하는 것입니다.

Window 객체에서 PushManager의 service worker registration은 null입니다.

ServiceWorkerRegistration 객체에서 PushManager의 service worker registration은 서비스 워커 등록 객체가 나타내는 ServiceWorkerRegistration 객체입니다.

7. PushManager 인터페이스

PushManager 인터페이스는 푸시 서비스에 액세스하기 위한 작업을 정의합니다. 

WebIDL[Exposed=(Window,Worker), SecureContext]
interface PushManager {
  [SameObject] static readonly attribute FrozenArray<DOMString> supportedContentEncodings;

  Promise<PushSubscription> subscribe(optional PushSubscriptionOptionsInit options = {});
  Promise<PushSubscription?> getSubscription();
  Promise<PermissionState> permissionState(optional PushSubscriptionOptionsInit options = {});
};

PushManager에는 연결된 서비스 워커 등록이 있으며, 이는 null이거나 서비스 워커 등록입니다.

supportedContentEncodings 속성은 푸시 메시지의 페이로드를 암호화하는 데 사용할 수 있는 지원되는 콘텐츠 코딩의 시퀀스를 노출합니다. 콘텐츠 코딩은 푸시 서비스에 푸시 메시지의 전송을 요청할 때 Content-Encoding 헤더 필드를 사용하여 표시됩니다.

사용자 에이전트는 [RFC8291]에 정의된 aes128gcm 콘텐츠 코딩을 반드시 지원해야 하며, 호환성을 위해 초안의 이전 버전에 정의된 콘텐츠 코딩을 지원할 수 있습니다.

7.1 subscribe() 메서드

subscribe() 메서드 단계는 다음과 같습니다:

  1. promise를 새로운 promise로 한다.
  2. global을 this의 관련 전역 객체로 한다.
  3. scope를 null로 한다.
  4. registration을 null로 한다.
  5. 만약 this의 service worker registration이 null이라면:
    1. scope에 "/"와 global의 연관된 Document의 URL을 사용하여 basic URL parser를 실행한 결과를 할당한다.
  6. 그 외의 경우:
    1. Assert: this의 service worker registration이 service worker registration임을 보장한다.
    2. registration에 this의 service worker registration을 할당한다.
  7. 만약 scope가 failure거나, URL인데 scheme이 "https"가 아니라면, 글로벌 태스크를 큐에 등록하여 networking 태스크 소스를 global로 사용하고, reject promise에 "NotAllowedError" DOMException을 전달하고 이 단계들을 종료한다.
  8. 만약 options["userVisibleOnly"] 값이 false이고, 사용자 에이전트가 true여야 한다고 요구한다면, 글로벌 태스크를 큐에 등록하여 networking 태스크 소스를 global로 사용하고, reject promise에 "NotAllowedError" DOMException을 전달하고 이 단계들을 종료한다.
  9. 만약 options["applicationServerKey"] 값이 null이고, push service가 non-null이어야 함을 요구하는 경우, 글로벌 태스크를 큐에 등록하여 networking 태스크 소스를 global로 사용하고, reject promise에 "NotSupportedError" DOMException을 전달하고 이 단계들을 종료한다.
  10. 만약 options["applicationServerKey"] 값이 non-null이라면:
    1. 만약 options["applicationServerKey"] 값이 문자열이면, 그 값을 ArrayBuffer로, options["applicationServerKey"] 값을 base64url 인코딩 [RFC7515]로 디코딩한 옥텟 시퀀스로 바꾼 ArrayBuffer로 세팅한다.
    2. 만약 디코딩에 실패하면 글로벌 태스크를 큐에 등록하여 networking 태스크 소스 를 global로 사용하고, reject promise에 "InvalidCharacterError" DOMException를 전달하고 이 단계들을 종료한다.
    3. options["applicationServerKey"] 값이 P-256 곡선 위의 유효한 점을 설명하는지 확인한다. 값이 유효하지 않으면 글로벌 태스크를 큐에 등록 하여 networking 태스크 소스를 global로 사용하고, reject promise에 "InvalidAccessError" DOMException을 전달하고 이 단계들을 종료한다.
  11. 다음 단계들을 병렬로 수행한다:
    1. subscription을 null로 한다.
    2. scope가 non-null이라면:
      1. push subscription 중에 window-accessible scope를 가지며 scope 가 scope와 동일한 경우, subscription에 해당하는 push subscription을 할당한다.
    3. 그 외의 경우:
      1. Assert: registration 값이 non-null임을 보장한다.
      2. registration의 active worker가 null이면 글로벌 태스크를 큐에 등록하여 networking 태스크 소스를 global로 사용하고, reject promise에 "InvalidStateError" DOMException 를 전달하고 이 단계들을 종료한다.
      3. 만약 registration의 associated push subscription 값이 null이 아니라면, subscription에 registration의 associated push subscription을 할당한다.
      4. scope에 registration의 scope URL을 할당한다.
    4. permission을 "push" 사용 권한 요청의 결과로 한다.
    5. 만약 permission이 "denied"라면, 글로벌 태스크를 큐에 등록하여 user interaction 태스크 소스를 global로 사용하고 reject promise에 "NotAllowedError" DOMException 을 전달하고 이 단계들을 종료한다.
    6. 만약 subscription이 null이 아니라면:
      1. subscription에 오류가 있다면, 글로벌 태스크를 큐에 등록하여 networking 태스크 소스를 global로 사용하고, reject promise에 "AbortError" DOMException 를 전달하고 이 단계들을 종료한다.
      2. options 인자와 subscription의 options 속성을 비교한다. BufferSource 값은 참조가 아니라 내용을 비교하여 동일성을 판단한다.
      3. options의 속성 중 subscription과 값이 다른 것이 있으면, 글로벌 태스크를 큐에 등록하여 networking 태스크 소스 를 global로 사용하고, reject promise에 "InvalidStateError" DOMException 를 전달하고 이 단계들을 종료한다.
      4. 글로벌 태스크를 큐에 등록하여 networking 태스크 소스를 global로 사용하고, resolve promise에 subscription을 전달하고 이 단계들을 종료한다.
    7. Assert: subscription은 null이고 scope은 URL이다.
    8. subscription에 create a push subscription을 options와 함께 시도한 결과를 할당한다. 생성 중 exception이 발생하면, 글로벌 태스크를 큐에 등록하여 networking 태스크 소스를 global로 사용하고, reject promise에 해당 exception을 전달하고 이 단계들을 종료한다.
    9. subscription의 scope에 scope를 할당한다.
    10. 글로벌 태스크를 큐에 등록하여 networking 태스크 소스를 global로 사용하고, resolve promise에 subscription에 대응하는 PushSubscription을 전달한다.
  12. promise를 반환한다.

getSubscription() 메서드 단계는 다음과 같습니다:

  1. promise에 새로운 promise를 할당합니다.
  2. global에 this의 관련 글로벌 객체를 할당합니다.
  3. windowScope를 null로 설정합니다.
  4. registration을 null로 설정합니다.
  5. 만약 this의 서비스 워커 등록이 null이라면, windowScope를 기본 URL 파서로 "/"와 global의 연관 Document의 URL을 넘겨 실행한 결과로 설정합니다.
  6. 그 외의 경우:
    1. Assert: this의 서비스 워커 등록은 서비스 워커 등록입니다.
    2. registration을 this의 서비스 워커 등록으로 설정합니다.
  7. 다음 단계들을 병렬로 실행합니다:
    1. subscription을 null로 설정합니다.
    2. 만약 windowScope가 null이 아니라면:
      1. 푸시 구독 중 scope가 windowScope인 것이 있다면, subscription을 해당 푸시 구독으로 설정합니다.
    3. 그 외의 경우:
      1. Assert: registration은 null이 아님.
      2. 만약 registration의 연관된 푸시 구독이 null이 아니라면, subscription을 registration의 연관된 푸시 구독으로 설정합니다.
    4. 만약 subscription이 null이면, promise를 null로 resolve합니다.
    5. subscription에 오류가 있으면, promise를 "AbortError" 이름의 DOMException으로 reject하고 단계 종료.
    6. PushSubscription에 해당하는 subscription으로 promise를 resolve합니다.
  8. promise를 반환합니다.

permissionState() 메서드 단계는 다음과 같다:

  1. promise를 새로운 프로미스로 한다.

  2. global을 this의 관련 전역 객체로 한다.

  3. 병렬로:

    1. state를 "push"의 권한 상태로 한다.

    2. 전역 태스크를 큐에 할당한다. 네트워킹 태스크 소스에서 global로 promise를 state로 resolve한다.

  4. promise를 반환한다.

푸시 서비스를 사용할 권한은 영속적일 수 있으며, 유효한 권한이 있으면 이후 구독에 대해 다시 확인할 필요가 없습니다.

권한이 필요하다면 반드시 subscribe() 메서드를 호출하여 요청해야 합니다.

7.2 PushSubscriptionOptions 인터페이스 

WebIDL[Exposed=(Window,Worker), SecureContext]
interface PushSubscriptionOptions {
  readonly attribute boolean userVisibleOnly;
  [SameObject] readonly attribute ArrayBuffer? applicationServerKey;
};

userVisibleOnly 속성은 get 시 초기화된 값을 반환합니다.

applicationServerKey 속성은 get 시 초기화된 값을 반환합니다.

존재하는 경우, applicationServerKey 값에는 반드시 [DSS]에서 정의된 P-256 타원 곡선의 점이 포함되어야 하며, 인코딩은 [ANSI-X9-62] 부록 A에서 설명된 미압축(uncompressed) 형식(즉, 0x04 옥텟으로 시작하는 65 옥텟)이어야 한다. DOMString으로 제공되는 경우, 해당 값은 반드시 [RFC7515]에 따라 base64url 인코딩으로 인코딩되어야 한다.

사용자 에이전트는 필요에 따라 applicationServerKey 가 존재하지 않고, push service가 동작상 필요로 하는 경우 구독 시도를 거부할 수 있다.

applicationServerKey 값은 [RFC8291]에서 메시지 암호화에 사용된 값과 반드시 달라야 한다.

7.3 PushSubscriptionOptionsInit 딕셔너리 

WebIDLdictionary PushSubscriptionOptionsInit {
  boolean userVisibleOnly = false;
  (BufferSource or DOMString)? applicationServerKey = null;
};

userVisibleOnly 멤버가 true로 설정된 경우, 해당 푸시 구독은 사용자에게 가시적으로 효과가 나타나는 푸시 메시지(예: 웹 알림 표시)만을 위해 사용됨을 나타냅니다. [NOTIFICATIONS]

PushSubscriptionOptionsInit는 푸시 구독과 연관된 추가 옵션을 나타냅니다. 사용자 에이전트는 사용자에게 명시적 권한을 요청할 때 이러한 옵션을 고려할 수 있습니다. 옵션이 고려되면, 사용자 에이전트는 해당 옵션을 수신되는 푸시 메시지에 반드시 적용해야 합니다.

이러한 옵션은 선택사항이며, 사용자 에이전트는 일부 옵션만 지원할 수 있습니다. 사용자 에이전트는 지원하지 않는 옵션을 노출해서는 안 됩니다.

한 번 설정된 푸시 구독의 옵션은 변경할 수 없습니다. 기존 푸시 구독은 unsubscribe를 통해 해지한 뒤, 새로운 옵션으로 푸시 구독을 만들 수 있습니다.

applicationServerKey 멤버는 사용자 에이전트가 푸시 서비스와 푸시 구독을 설정할 때 사용됩니다. applicationServerKey 옵션에는 애플리케이션 서버용 타원 곡선 공개키가 포함되어 있습니다. 이 키는 애플리케이션 서버가 푸시 구독에 푸시 메시지를 전송할 때 자신을 인증하기 위해 사용합니다 ([RFC8292]에 정의됨). 푸시 서비스는 해당 개인키로 인증 토큰을 생성하지 않은 푸시 메시지를 모두 거부합니다.

8. PushSubscription 인터페이스

PushSubscription 객체는 푸시 구독을 나타냅니다. 

WebIDL[Exposed=(Window,Worker), SecureContext]
interface PushSubscription {
  readonly attribute USVString endpoint;
  readonly attribute EpochTimeStamp? expirationTime;
  [SameObject] readonly attribute PushSubscriptionOptions options;
  ArrayBuffer? getKey(PushEncryptionKeyName name);
  Promise<boolean> unsubscribe();

  PushSubscriptionJSON toJSON();
};

dictionary PushSubscriptionJSON {
  USVString endpoint;
  EpochTimeStamp? expirationTime = null;
  record<DOMString, USVString> keys;
};

endpoint 속성을 가져올 때, 사용자 에이전트는 푸시 엔드포인트를 푸시 구독과 연결된 것으로 반환해야 합니다. 사용자 에이전트는 입력에 따라 달라지는 분기를 포함하지 않는 직렬화 방법(즉, 상수 시간인 방법)을 반드시 사용해야 합니다.

expirationTime 속성을 가져올 때, 사용자 에이전트는 구독 만료 시간이 푸시 구독과 연결되어 있으면 이를 반환하고, 그렇지 않으면 null을 반환해야 합니다.

options 속성을 가져올 때, 사용자 에이전트는 PushSubscriptionOptions 객체를 반환하여 푸시 구독과 연결된 옵션을 나타내야 합니다.

getKey() 메서드는 메시지를 암호화하고 인증하는 데 사용할 수 있는 키 자료를 가져옵니다. getKey()가 호출되면 다음 절차를 따릅니다:

  1. name 인수로 지정된 키에 해당하는 내부 슬롯을 찾습니다.
  2. 슬롯을 찾지 못한 경우 null을 반환합니다.
  3. 변수 key를 새로 인스턴스화된 ArrayBuffer 인스턴스로 초기화합니다.
  4. 내부 슬롯에 비대칭 키 쌍이 포함되어 있으면 key의 내용을 해당 키 쌍의 공개 키를 직렬화한 값으로 설정합니다. 이는 이름을 정의하는 명세에 설명된 직렬화 형식을 사용합니다. 예를 들어 [RFC8291]에서는 "p256dh" 공개 키가 [ANSI-X9-62] 부록 A에 정의된 비압축 형식(즉, 0x04 옥텟으로 시작하는 65 옥텟 시퀀스)을 사용하여 인코딩되도록 규정합니다.
  5. 그렇지 않고 내부 슬롯에 대칭 키가 포함되어 있으면 key의 내용을 내부 슬롯 값의 복사본으로 설정합니다. 예를 들어 auth 매개변수에는 사용자 에이전트가 애플리케이션 서버에서 보낸 메시지를 인증하는 데 사용하는 옥텟 시퀀스가 포함됩니다.
  6. key를 반환합니다.

"p256dh" 및 "auth"라는 이름의 키를 반드시 지원해야 하며, 그 값은 사용자 에이전트가 [RFC8291]에 따라 수신한 푸시 메시지를 복호화하는 데 필요한 값과 일치해야 합니다.

unsubscribe() 메서드는 호출될 때 다음 단계를 반드시 실행해야 합니다:

  1. promise을 새로운 프로미스로 설정합니다.
  2. promise을 반환하고 다음 단계를 비동기적으로 계속합니다.
  3. 푸시 구독이 이미 비활성화된 경우, promise을 false로 이행하고 이 단계를 종료합니다.
  4. 다음 단계를 병렬로 실행합니다:
    1. 비활성화합니다. 푸시 구독을. 사용자 에이전트는 푸시 구독에 대해 더 이상의 푸시 메시지를 전달해서는 안 됩니다.

      사용자 에이전트가 예를 들어 네트워크 장애로 인해 푸시 서비스에 푸시 구독을 비활성화하도록 요청하지 못한 경우, 합리적인 기간 동안 푸시 서비스에 대한 요청을 다시 시도하는 것이 좋습니다.

  5. promise을 true로 이행합니다.

toJSON() 메서드는 호출될 때 다음 단계를 반드시 실행해야 합니다:

  1. json을 새로운 PushSubscriptionJSON 딕셔너리로 설정합니다.
  2. json["endpoint"]를 endpoint 속성을 가져온 this의 결과로 설정합니다.
  3. json["expirationTime"]을 expirationTime 속성을 가져온 this의 결과로 설정합니다.
  4. keys를 새로운 빈 record<DOMString, USVString> 인스턴스로 설정합니다.
  5. PushSubscription의 내부 슬롯에 있는 키에 해당하는 각 식별자 i에 대해, 키 이름 순으로:
    1. 내부 슬롯이 비대칭 키 쌍에 해당하면, b를 키 이름 i에 해당하는 공개 키의 인코딩된 값으로 설정하며, 키 이름에 대해 정의된 인코딩을 사용합니다(getKey() 참조).
    2. 그렇지 않으면 b를 getKey가 반환한 값으로 설정합니다.
    3. s를 b의 패딩 없는 URL 안전 base64 인코딩 [RFC4648]을 USVString으로 나타낸 것으로 설정합니다. 사용자 에이전트는 b의 값에 따라 분기하지 않는 직렬화 방법을 반드시 사용해야 합니다.
    4. keys[i]를 s로 설정합니다.
  6. json["keys"]를 keys로 설정합니다.
  7. json을 반환합니다.

PushSubscriptionJSON 딕셔너리는 PushSubscription의 JSON 유형을 나타냅니다. ECMAScript에서는 JSON.stringify() 함수를 통해 JSON 문자열로 변환할 수 있습니다.

keys 레코드에는 지원되는 각 PushEncryptionKeyName 항목에 대해 그 값을 URL 안전 base64로 인코딩한 표현 [RFC4648]이 포함됩니다.

PushSubscription의 옵션은 직렬화되지 않는다는 점에 유의하십시오.

8.1 PushEncryptionKeyName 열거형

푸시 메시지 암호화에 사용되는 암호화 키는 getKey() 메서드 또는 PushSubscription의 직렬화기를 통해 웹 애플리케이션에 제공됩니다. 각 키는 PushEncryptionKeyName 열거형의 값으로 이름이 지정됩니다. 

WebIDLenum PushEncryptionKeyName {
  "p256dh",
  "auth"
};

p256dh 값은 [RFC8291]에 기술된 P-256 ECDH 디피-헬만 공개키를 가져오는 데 사용됩니다.

auth 값은 [RFC8291]에 기술된 인증 시크릿을 가져오는 데 사용됩니다.

9. PushMessageData 인터페이스 

WebIDL[Exposed=ServiceWorker, SecureContext]
interface PushMessageData {
  ArrayBuffer arrayBuffer();
  Blob blob();
  Uint8Array bytes();
  any json();
  USVString text();
};

PushMessageData 객체는 생성될 때 bytes (바이트 시퀀스)를 갖으며, 이는 생성 시 설정됩니다.

arrayBuffer() 메서드는 ArrayBuffer 객체를 반환하며, 내용은 this의 bytes입니다. ArrayBuffer 객체 생성 중 발생한 예외는 재throw됩니다.

blob() 메서드는 Blob 객체를 새로 반환하며, 내용은 this의 bytes입니다.

bytes() 메서드는 Uint8Array 객체를 새로 반환하며, 내부적으로 ArrayBuffer의 내용은 this의 bytes입니다. ArrayBuffer 객체 생성 중 발생한 예외는 재throw됩니다.

json() 메서드는 JSON 바이트를 자바스크립트 값으로 파싱한 결과를 this의 bytes에 대해 반환합니다.

text() 메서드는 UTF-8 디코드 결과를 this의 bytes에 대해 반환합니다.

object에서 바이트 시퀀스를 추출하려면 다음 단계를 실행합니다:

  1. bytes를 빈 바이트 시퀀스로 설정합니다.
  2. object의 타입에 따라 분기합니다:
    BufferSource
    bytes를 object의 내용을 복사한 값으로 설정합니다.
    USVString
    object에 utf-8 인코드 실행 결과를 bytes로 설정합니다.
  3. bytes를 반환합니다.

10.1 ServiceWorkerGlobalScope 인터페이스 확장

onpushsubscriptionchange 속성은 이벤트 핸들러 IDL 속성이며, 해당 이벤트 핸들러 이벤트 타입은 "pushsubscriptionchange"입니다.

  1. eventInitDict의 data 멤버가 없으면, 이벤트의 data 속성에 null을 할당하고 이 단계를 종료합니다.
  2. b를 eventInitDict의 "data" 멤버에서 바이트 시퀀스를 추출한 결과로 설정합니다.
  3. 이벤트의 data 속성에 PushMessageData 인스턴스를 새로 생성하여, bytes를 b로 할당합니다.

data 속성은 초기화된 값을 반환해야 합니다.

notification 속성은 초기화된 값을 반환해야 합니다.

10.3 푸시 메시지 수신

사용자 에이전트가 푸시 메시지를 푸시 서비스로부터 수신하면, 다음 단계를 반드시 실행해야 합니다.

  1. subscription을 푸시 메시지에 대응하는 활성 푸시 구독으로 설정합니다.

  2. registration을 subscription의 연결된 서비스 워커 등록으로 설정합니다.

  3. bytes를 null로 설정합니다.

  4. 푸시 메시지에 페이로드가 포함되어 있으면:

    1. subscription과 연결된 키 쌍의 비공개 키 및 [RFC8291]에 설명된 절차를 사용하여 푸시 메시지의 페이로드를 복호화합니다. bytes를 결과로 얻은 바이트 시퀀스로 설정합니다.

    2. 어떤 이유로든 푸시 메시지 페이로드를 복호화할 수 없는 경우, 확인 처리를 푸시 메시지에 수행하고 이 단계를 중단합니다.

      참고

      푸시 구독과 연결된 키 쌍을 사용하여 성공적으로 복호화되지 않은 푸시 메시지에 대해서는 push 이벤트가 발생하지 않습니다.

  5. bytes가 null이 아니면:

    1. baseURL을 subscription의 범위로 설정합니다.

    2. origin을 baseURL의 출처로 설정합니다.

    3. fallbackTimestamp를 현재 거칠게 조정된 벽시계 시간으로 설정합니다.

    4. declarativeResult를 bytes, origin, baseURL 및 fallbackTimestamp가 주어졌을 때 선언적 푸시 메시지 파서를 실행한 결과로 설정합니다.

    5. declarativeResult가 실패가 아니면:

      1. notification을 declarativeResult의 알림으로 설정합니다.

      2. notification의 서비스 워커 등록을 registration으로 설정합니다.

      3. notificationShown을 false로 설정합니다.

      4. declarativeResult의 변경 가능 여부가 true이고 registration이 null이 아니면:

        1. result를 registration, null 및 notification을 나타내는 새로운 Notification 객체가 주어졌을 때 푸시 이벤트를 발생시킨 결과로 설정합니다.

        2. result가 실패가 아니면, notificationShown을 result의 알림 표시 여부로 설정합니다.

      5. notificationShown이 false이면, notification이 주어졌을 때 알림 표시 단계를 실행합니다.

      6. 확인 처리를 푸시 메시지에 수행하고 이 단계를 중단합니다.

  6. registration이 null이면 이 단계를 중단합니다.

  7. data를 바이트가 bytes가 null이 아닌 경우 bytes이고, 그렇지 않으면 null인 새로운 PushMessageData 객체로 설정합니다.

  8. result를 registration, data 및 null이 주어졌을 때 푸시 이벤트를 발생시킨 결과로 설정합니다.

  9. result가 실패이고 동일한 푸시 메시지가 서비스 워커 등록에 여러 번 전달되었지만 매번 실패했다면, 확인 처리를 푸시 메시지에 수행합니다.

  10. result가 실패가 아니면, 확인 처리를 푸시 메시지에 수행합니다.

푸시 이벤트 결과는 알림 표시 여부(불리언)로 구성된 튜플입니다.

서비스 워커 등록 registration, PushMessageData 객체 또는 null인 data, 그리고 알림 또는 null인 notification이 주어졌을 때 푸시 이벤트를 발생시키려면 다음 단계를 실행합니다. 이 단계는 실패 또는 푸시 이벤트 결과를 반환합니다.

  1. notificationResult를 null로 설정합니다.

  2. registration의 showNotification()이 성공적으로 호출되었는지 여부를 false로 설정합니다.

  3. 다음 속성을 사용하여 registration에서 PushEvent를 사용하는 "push"라는 이름의 기능 이벤트를 발생시킵니다:

    data
    data
    notification
    notification

    그런 다음 dispatchedEvent와 함께 다음 단계를 병렬로 실행합니다:

    1. dispatchedEvent의 수명 연장 프로미스에 있는 모든 프로미스가 해결될 때까지 기다립니다.

    2. 이들이 성공적으로 해결되지 않으면 notificationResult를 실패로 설정합니다.

    3. 그렇지 않으면 notificationResult를 registration의 showNotification()이 성공적으로 호출되었는지 여부로 설정합니다.

  4. notificationResult가 null이 아니게 될 때까지 기다립니다.

  5. notificationResult가 실패이면 실패를 반환합니다.

  6. 단언: notificationResult는 불리언입니다.

  7. (notificationResult)를 반환합니다.

푸시 메시지 pushMessage가 주어졌을 때 푸시 메시지를 확인 처리한다는 것은 [RFC8030]에 따라 pushMessage의 수신을 확인 처리하는 것을 의미합니다.

푸시 메시지를 확인 처리하면 푸시 서비스가 메시지 전달을 중지하고 애플리케이션 서버에 성공을 보고하게 됩니다. 이를 통해 동일한 푸시 메시지가 푸시 서비스에 의해 무기한 재시도되는 것을 방지합니다.

또한 확인 처리는 애플리케이션 서버가 푸시 메시지가 성공적으로 전달되었음을 나타내는 전달 확인서를 잘못 수신할 수도 있음을 의미합니다. 따라서 확인 처리하기 전에 여러 번의 거부를 허용해야 합니다. 최소 세 번의 시도를 허용하는 것이 권장됩니다.

10.4 pushsubscriptionchange 이벤트

pushsubscriptionchange 이벤트는 푸시 구독에 대한 변경이 애플리케이션의 제어 외부에서 발생했음을 나타냅니다. 예를 들면 갱신, 철회, 손실 등이 해당됩니다.

"pushsubscriptionchange" 이벤트 발행은 서비스 워커 등록 registration, newSubscription, oldSubscription이 주어졌을 때, 사용자 에이전트가 "pushsubscriptionchange"라는 기능적 이벤트를 PushSubscriptionChangeEvent 타입으로 registration에 대해 아래 속성으로 발행합니다:

newSubscription
newSubscription
oldSubscription
oldSubscription
참고

새로운 푸시 구독의 세부 정보를 애플리케이션 서버로 보낼 때 [WEB-BACKGROUND-SYNC]와 같은 보다 안정적인 동기화 메커니즘을 사용하는 것을 고려하십시오. 사용자는 fetch가 실패할 수 있는 불안정한 네트워크 환경에 놓일 수 있습니다.

10.4.1 PushSubscriptionChangeEvent 인터페이스 

WebIDL[Exposed=ServiceWorker, SecureContext]

  constructor(DOMString type, optional PushSubscriptionChangeEventInit eventInitDict = {});
  readonly attribute PushSubscription? newSubscription;
  readonly attribute PushSubscription? oldSubscription;
};

newSubscription 속성은 get 시 초기화된 값을 반환합니다.

oldSubscription 속성은 get 시 초기화된 값을 반환합니다.

10.4.2 PushSubscriptionChangeEventInit 인터페이스 

WebIDLdictionary PushSubscriptionChangeEventInit : ExtendableEventInit {
  PushSubscription newSubscription = null;
  PushSubscription oldSubscription = null;
};

newSubscription 멤버는 푸시 구독에 대한 세부 정보를 제공하며, 이는 pushsubscriptionchange 이벤트 호출 시 유효합니다. 예를 들어 웹 애플리케이션이 명시적 권한을 잃어 새 푸시 구독을 설정할 수 없는 경우 값은 null이 됩니다.

oldSubscription 멤버는 더 이상 사용 하면 안 되는 푸시 구독에 대한 세부 정보를 제공합니다. 예를 들어 부분적인 데이터베이스 손상으로 인해 사용자 에이전트가 전체 세부 정보 집합을 제공할 수 없는 경우 값은 null이 됩니다.

11. 접근성

Push API는 푸시 서비스에서 받은 데이터를 직접적으로 표시하는 방법을 제공하지 않습니다. 대신 Push API는 다른 API, 주로 Notifications API Standard에 의존하여 사용자가 정보를 확인할 수 있게 합니다. 따라서 Push API 자체에는 접근성 요구사항이 없습니다. 하지만 [NOTIFICATIONS] 등 명세에서는 알림을 접근성 있게 표시하는 방법에 대한 가이드라인을 제공합니다.

또한, 접근성 있는 인터페이스를 제공하려면 푸시 메시지가 전달할 수 있는 것보다 더 많은 정보를 전달해야 할 수도 있습니다. 푸시 메시지는 소량의 콘텐츠나 식별자를 전달하는 데 가장 적합합니다. 더 큰 리소스는 서버에서 따로 가져와야 합니다.

12. 준수

비규범 섹션뿐만 아니라, 이 명세에 포함된 모든 작성 지침, 도표, 예시, 비고는 모두 비규범적입니다. 이 명세의 그 밖의 모든 내용은 규범적입니다.

이 문서에서 MAY, MUST, MUST NOT, SHOULD, SHOULD NOT과 같은 핵심 단어는 BCP 14 [RFC2119] [RFC8174] 에서 설명된 대로 해석되어야 하며, 반드시 대문자로 표시된 경우에만 해당합니다.

이 명세는 하나의 제품에 적용되는 준수 기준을 정의합니다. 즉, 이 명세에 포함된 인터페이스를 구현하는 사용자 에이전트가 그 대상입니다.

개요

이 명세서는 설치된 웹 애플리케이션이 애플리케이션 배지를 설정할 수 있는 API를 정의합니다. 애플리케이션 배지는 일반적으로 기기의 홈 화면이나 애플리케이션 독에서 애플리케이션 아이콘과 함께 표시됩니다.

이 문서의 상태

이 섹션은 이 문서가 발행된 시점의 상태를 설명합니다. 현재 W3C 발행 문서 목록과 이 기술 보고서의 최신 개정판은 W3C 표준 및 초안 색인에서 확인할 수 있습니다.

이 문서는 작업 중인 초안입니다.

이 문서는 Web Applications Working Group에서 권고안 경로를 사용하여 워킹 드래프트로 발행되었습니다.

워킹 드래프트로 발행된다고 해서 W3C 및 회원의 승인을 의미하지는 않습니다.

이 문서는 W3C 특허 정책에 따라 운영되는 그룹에서 작성되었습니다. W3C는 공개 특허 공개 목록을 그룹의 결과물과 관련하여 유지합니다. 해당 페이지에는 특허 공개 방법에 대한 안내도 포함되어 있습니다. 특정 특허가 필수 청구항을 포함한다고 판단되는 경우, 해당 정보를 W3C 특허 정책 6절에 따라 공개해야 합니다.

1. 사용 예시

이 섹션은 규범적이지 않습니다.

예제 1: 앱 아이콘에 읽지 않은 수 표시 
async function updateMailBadge() {
  // API 지원 여부 확인
  if (!navigator.setAppBadge) return;

  const unreadCount = await getUnreadMailCount();

  // 앱 배지 설정 시도
  try {
    await navigator.setAppBadge(unreadCount);
  } catch (e) {
    // 배지 미지원 또는 사용자가 앱의 배지 설정을 차단함
  }
}

배지는 운영체제의 애플리케이션 아이콘에 표시될 수 있습니다. 동일한 애플리케이션 내에서 여러 번 API 호출로 배지를 설정 또는 지우기 하면, 가장 최근의 호출이 적용되며 애플리케이션이 종료된 이후에도 계속 표시될 수 있습니다.

예제 2: 앱 아이콘에 준비 상태 표시 
async function showPlayerTurn(playerTurnId) {
  if (playerTurnId === localPlayerId)
    await navigator.setAppBadge();
  else
    await navigator.clearAppBadge();
}

일부 운영체제에서는 배지 설정에 사용자의 권한이 필요할 수 있습니다. 이 경우, 개발자는 "notifications" 권한 상태를 먼저 조회해야 하며, 권한이 없다면 Notification.requestPermission()을 통해 권한 요청을 해야 합니다.

예제 3: 권한 확인 
async function checkPermission() {
  permission = await navigator.permissions.query({
    name: "notifications",
  });
  const button = document.getElementById("permission-button");
  if (permission.state === "prompt") {
    // 사용자에게 권한 요청 안내 표시
    button.hidden = false;
    button.addEventListener("click", async () => {
      await Notification.requestPermission();
      checkPermission();
    }, { once: true });
    return;
  }
  button.hidden = true;
}

2. 모델

배지(badge)는 설치된 웹 애플리케이션이 사용자에게 주의가 필요할 수 있는 새로운 활동이 있음을 알리거나, 읽지 않은 횟수와 같은 적은 양의 정보를 나타내는 방법으로 사용됩니다.

배지(badge)는 다음 값(values) 중 하나를 가질 수 있습니다.

특수 값 "nothing":
현재 설정(set)된 배지(badge)가 없음을 나타냅니다.
특수 값 "flag":
배지(badge)가 설정(set)되었지만 특정 값을 포함하지 않음을 나타냅니다.
숫자(number) 값:
배지(badge)가 0보다 큰 숫자 값으로 설정(set)되었음을 나타냅니다.

설치된 웹 애플리케이션은 연결된 배지(badge)를 가지며, 이는 "nothing"으로 초기화됩니다.

사용자 에이전트는 재량에 따라 애플리케이션의 배지(badge)를 "nothing"으로 설정(MAY)하거나 (예: 시스템 규칙에 따라) 다시 설정할 수 있습니다.

3. 배지 표시

애플리케이션의 배지(badge)가 설정(set)되면, 사용자 에이전트 또는 운영 체제는 사용자의 운영 체제에서 애플리케이션의 기본 아이콘 표현과 함께 애플리케이션의 배지(badge)를 표시해야 합니다(SHOULD)(예: 장치의 홈 화면에 있는 애플리케이션 아이콘 위에 작은 오버레이로 표시).

사용자 에이전트는 사용자로부터 명시적 권한을 요구하여 배지(badge)를 설정(set)할 수 있습니다(MAY). 사용자 에이전트가 그러한 권한을 요구하는 경우, 권한 부여를 "알림(notifications)" 권한에 연결해야 합니다(SHOULD).

배지(badge)가 설정(set)되어 "flag"로 설정된 경우, 사용자 에이전트 또는 운영 체제는 특정하지 않은 기호(예: 색상이 있는 원)로 표시기를 표시해야 합니다(SHOULD).

배지(badge)의 값이 설정(set)되어 "nothing"으로 설정된 경우, 사용자 에이전트 또는 운영 체제는 더 이상 표시하지 않아 배지(badge)를 지워야 합니다(SHOULD).

배지(badge)가 설정(set)되어 숫자(number)로 설정된 경우, 사용자 에이전트 또는 운영 체제는 다음을 수행합니다.

  • 사용자의 글꼴 및 형식 설정에 따라 숫자를 형식화하고 표시해야 합니다(SHOULD). 예를 들어, 장치의 홈 화면에 있는 애플리케이션 아이콘 위에 원 안에 숫자로 표시합니다.
  • 배지(badge)에 숫자를 표시하는 플랫폼의 규칙에 맞는 방식으로 배지(badge)의 숫자(number) 값(value)을 단순화하거나 저하시킬 수 있습니다(MAY). 예를 들어, 플랫폼은 값이 '100'인 배지(badge)를 '99+'로 표시하도록 선택할 수 있습니다.
  • 사용자의 로캘 설정에 따라 숫자를 지역화해야 합니다(SHOULD). 예를 들어, 값(value) '7'은 로캘 'en'(영어)에서는 '7'로 표시되지만 'ar'(아랍어)에서는 '٧'로 표시되어야 합니다.
  • 플랫폼이 배지(badge)에 숫자를 표시하는 것을 지원하지 않는 경우, 숫자(number) 값(value)을 "flag"로 처리하거나 플랫폼에 가장 적합한 표현으로 처리할 수 있습니다(MAY).

5. 애플리케이션 배지 설정

플랫폼 객체 context의 애플리케이션 배지 설정을 선택적 unsigned long long contents 값으로 수행하려면:

  1. global을 context의 관련 글로벌 객체로 한다.
  2. 만약 global이 Window 객체라면:
    1. document를 global의 연관된 Document로 한다.
    2. document가 완전히 활성화됨이 아니면, 거부된 promise를 반환하고 오류는 "InvalidStateError" DOMException로 한다.
    3. document의 관련 설정 객체의 origin이 same origin-domain이 아니면, 거부된 promise를 반환하고 오류는 "SecurityError" DOMException로 한다.
  3. promise를 새로운 promise로 한다.
  4. 병렬로:
    1. 만약 사용자 에이전트가 명시적 권한을 필요로 한다면 애플리케이션 배지 설정에 대해:
      1. permissionState를 "notifications" 권한의 현재 권한 상태 가져오기 결과로 한다.
      2. permissionState가 "granted"가 아니라면, 글로벌 태스크 큐잉을 user interaction task source에서 global에 대해 promise 거부를 NotAllowedError로 하고 이 알고리즘을 종료한다.
    2. contents에 따라 분기:
      contents가 전달되지 않은 경우:
      배지를 "flag"로 설정한다.
      contents가 0인 경우:
      배지를 "nothing"으로 설정한다.
      contents가 전달된 경우:
      배지를 contents로 설정한다.
    3. 글로벌 태스크 큐잉을 DOM 조작 태스크 소스에서 global에 대해 promise 해결을 undefined로 한다.
  5. promise를 반환한다.

6. 개인정보 보호 고려 사항

이 API는 의도적으로 쓰기 전용입니다. 사이트가 이전에 설정한 배지 값을 읽어올 방법이 없으므로, 애플리케이션 배지를 저장소나 핑거프린팅 메커니즘으로 사용할 수 없습니다.

7. 보안 고려 사항

사용자 에이전트 또는 운영체제는 MAY 배지 지우기를 badge에 임의로 적용할 수 있으며, 시스템 규칙(예: 시스템 초기화 시)을 따를 수 있습니다.

Issue 68: 배지 설정 기능의 속도 제한

@grorg가 webkit-dev에서 제기함:

브라우저가 빠르게 연속된 set/clear 연산(예: 깜빡이는 배지 생성)을 무시해야 하는 방식에 대한 명세 텍스트도 있으면 좋겠습니다. 예를 들어 1분에 한 번만 배지 작업이 허용되는 식입니다.

이 부분은 다뤄야 합니다. UI와 관련된 내용이므로 요구가 아니라 권고가 될 수 있습니다.

"최종 일관성" 보장도 필요합니다. 즉, 마지막에 기록된 값이 결국 사용자에게 표시돼야 한다는 것입니다. 만약 "3"을 설정했다가 10초 후 "12"를 설정했는데, 속도 제한 때문에 "12"가 표시되지 않고 "3"만 계속 보이는 상황은 방지해야 합니다. 규칙은 "UI가 N초 이상 업데이트되지 않았다면 새 값으로 업데이트. 그렇지 않으면 마지막 업데이트 이후 경과 시간만큼 기다린 뒤 새 값으로 UI 업데이트"가 되어야 합니다.

8. 접근성 고려 사항

이 섹션은 규범적이지 않습니다.

Issue 24: 접근성 섹션 추가

브라우저가 배지 표시를 제어할 경우, 접근성 가이드라인 정의가 가능해야 합니다.

9. 적합성

비규범적임으로 표시된 섹션 외에도, 모든 작성 가이드라인, 다이어그램, 예시 및 노트는 이 명세서에서 비규범적입니다. 이 명세서의 그 외 모든 내용은 규범적입니다.

이 문서에서 MAY, MUST, SHOULD, SHOULD NOT과 같은 주요 용어는 BCP 14 [RFC2119] [RFC8174] 에 설명된 대로 해석되어야 하며, 반드시 대문자로 표시될 때만 적용됩니다.

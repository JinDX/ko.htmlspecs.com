개요

CBOR는 간결한 이진 데이터 직렬화 및 메시징 형식입니다. 이 명세는 Linked Data를 직렬화하기 위한 CBOR 기반 형식인 CBOR-LD 1.0을 정의합니다. 이 인코딩은 오늘날 수억 개의 시스템에 배포된 기존 JSON-LD 생태계를 활용하도록 설계되어, Linked Data를 위한 효율적인 인코딩 방식을 찾는 이들에게 간결한 직렬화 형식을 제공합니다. 의미론적 압축 방식을 활용함으로써, 범용 압축 방식보다 60% 이상 더 나은 압축률을 달성할 수 있습니다. 이 형식은 주로 저장 공간과 대역폭이 제한된 프로그래밍 환경에서 Linked Data를 사용하고, 상호 운용 가능한 의미론적 와이어 수준 프로토콜을 구축하며, CBOR 기반 저장 엔진에 Linked Data를 효율적으로 저장하기 위한 방법으로 의도되었습니다.

1.3 설계 목표와 근거

이 절은 비규범적입니다.

CBOR-LD는 다음 설계 목표를 충족합니다.

단순성
구현은 기존 JSON-LD 구현을 바탕으로 간단히 구현할 수 있어야 합니다.
효율적인 저장
인코딩 과정은 매우 간결한 Linked Data 이진 형식을 생성해야 합니다.
일반화된 알고리즘
인코딩 알고리즘은 일반화되어야 합니다.
의미론적 압축
인코딩 형식은 Linked Data URL(용어 및 값)의 압축을 최대화해야 합니다. 여기에 집중함으로써 알고리즘이 범용 압축 알고리즘보다 더 나은 압축률을 달성할 수 있습니다.
원시 이진
Base 인코딩된 이진 값과 기타 압축 가능한 데이터 유형은, 가능하다면 일반성을 희생하지 않고 Base 인코딩 형식에서 원시 이진 형식으로 변환되어야 합니다.

마찬가지로, 다음은 목표가 아닙니다.

  • 이론적 순수성.
  • CBOR-LD만을 위한 새로운 압축/확장 알고리즘 생성.
  • 지구상의 모든 용어를 위한 대규모 중앙 집중식 레지스트리.
  • JSON-LD에서 CBOR-LD로, 그리고 다시 되돌아오는 라운드트립에 대규모 명세 변경이나 복잡한 구현이 필요한 데이터 형식.

이 명세를 작업하는 동안 다음과 같은 지뢰밭이 확인되었습니다.

  • 해싱이 빠르다고 널리 믿어지지만, 작은 문자열 집합에서는 문자열 비교보다 느립니다. 이는 해싱하려면 전체 문자열을 소비해야 하기 때문입니다. 문자열 비교를 수행하는 경우, 바이트 단위 비교가 실패하는 즉시 중단할 수 있습니다. 즉, 두 값을 처리할 때 문자열 비교는 처리를 중단할 수 있지만 해싱은 그럴 수 없습니다. 대부분의 전역 충돌 저항 해시는 256비트이지만, 32바이트 값은 크며 많은 경우 충돌 저항성을 희생하지 않고도 더 잘할 수 있습니다 (blake2b-8과 같은 해싱 알고리즘은 그렇게 할 수 없음).
  • JSON-LD 데이터를 사전 처리해야 하는 것은 무엇이든 시작부터 부적합합니다 -- 비용이 많이 들며, 이는 데이터에 의미론을 인코딩한다는 뜻입니다. 이것이 어떤 경우에는 더 나은 압축으로 이어질 수 있지만, 허용 가능한 투자 대비 수익을 제공하지 않으면서 프로세서의 복잡성을 증가시킵니다.
  • 범위가 지정된 컨텍스트는 더 일반화된 해결책에서 가장 어려운 부분입니다. 알고리즘이 범위를 더 깊이 이해해야 할수록, 문제는 더 조합론적으로 변하고 가능한 압축 값도 더 많아져 압축 크기에 악영향을 줍니다. 핵심은 기존 JSON-LD 처리 알고리즘의 결정성을 활용하고, JSON-LD 처리에 영향을 주지 않을 때에만 지름길을 취하는 것입니다.

2. 기본 개념

이 절은 비규범적입니다.

높은 수준에서, CBOR-LD는 JSON-LD를 위한 간결한 이진 직렬화이며 추가 압축을 위해 다음 메커니즘을 허용합니다.

  • 의미 압축: JSON-LD 문서에서 사용하는 JSON-LD 컨텍스트를 구문 분석하여 JSON-LD 용어에서 정수로의 매핑을 동적으로 생성합니다. 이러한 매핑은 역변환 가능한 방식으로 생성됩니다.
  • 형식화된 값 압축(코덱): 데이터 형식에 대한 사전 이해를 바탕으로 형식화된 값을 역변환 가능한 방식으로 동적으로 압축합니다(예: URL에서 스킴 문자열 제거).
  • 형식화된 값 압축(레지스트리 사전): 사용 사례별 형식화된 값 압축에 사용할 정적 사전을 생성하며, 이러한 사전은 CBOR-LD 레지스트리 항목에 나열됩니다.

코덱은 유형 지정 값을 일반적인 방식으로 압축하기 위한 기본 원시 요소입니다. 의미론적 압축은 JSON-LD 용어를 압축하기 위한 것입니다. 레지스트리 사전은 특정 사용 사례에 맞춘 방식으로 유형 지정 값을 압축하기 위한 것입니다. 이들 각각은 선택 사항입니다 — CBOR-LD는 이러한 압축 전략 중 어느 것과도, 모두와도, 또는 전혀 없이도 사용할 수 있습니다. 함께 볼 때, 특정 사용 사례에 사용되는 이러한 전략들의 집합을 처리 모델이라고 합니다.

3. 의미론적 압축

이 절은 비규범적입니다.

의미론적 압축은 간결한 CBOR-LD 페이로드를 만들기 위한 강력한 도구입니다. 핵심 아이디어는 외부 JSON-LD 컨텍스트 객체의 정보 내용을 사용하여 JSON-LD 용어를 압축하는 것입니다. 이러한 외부 컨텍스트 객체는 페이로드의 생성자와 소비자 모두가 사용할 수 있으므로, 이는 역변환 가능한 방식으로 수행됩니다.

일반적인 의미론적 압축 과정은 JSON-LD Document를 가져와 다음을 수행하는 것입니다.

  1. JSON-LD를 압축할 수 있는지 확인합니다(JSON-LD 문서에서 URI를 통해 컨텍스트를 참조하는 @context 값을 찾습니다. 임베디드 컨텍스트 값은 압축할 수 없습니다).
  2. JSON-LD 컨텍스트를 처리하여 CBOR-LD term-codec map — 압축 가능한 모든 용어의 목록 — 을 만듭니다. 목록을 정렬합니다(Unicode 코드 포인트 순서로). 0부터 시작해 하나씩 증가시키며 각 용어에 바이트 값을 연결합니다.
  3. JSON-LD Document를 CBOR-LD로 인코딩합니다. 이는 모든 키를 term-codec map의 해당 용어에 연결된 바이트 값으로 바꾸는 것으로 이루어집니다.
  4. 원래 JSON-LD가 필요한 경우, CBOR-LD에서 JSON-LD로의 디코딩은 모든 CBOR 바이트 값을 term-codec map의 해당 키로 바꾸는 것으로 이루어집니다.

4. CBOR-LD용 CBOR 태그

CBOR-LD 페이로드는 이진 수준에서 그러한 것으로 식별 가능해야 합니다. CBOR는 기본적으로 "tag" 기능을 통해 이를 지원합니다 — 이진 데이터의 나머지 부분을 전역 레지스트리를 통해 설명하는 헤더 값입니다.

CBOR 태그 0xCB1D(태그 값 51997)는 CBOR-LD에 사용되도록 IANA CBOR 태그 레지스트리에 등록되었습니다. 이 태그 값 바로 뒤에 오는 데이터는 압축된 페이로드를 만드는 데 사용된 레지스트리 항목을 식별합니다.

CBOR-LD 페이로드는 태그 0xCB1D가 붙은 항목이 두 요소 배열이 되도록 구조화되어야 MUST 하며, 첫 번째 요소는 major type 0 integer여야 MUST 합니다. 이 정수는 CBOR-LD Registry Entry ID입니다. 이진 구조는 tag([registryEntryId, payload])입니다.

그런 다음 CBOR-LD Registry Entry ID의 값은 CBOR-LD Registry에서 CBOR-LD Registry Entry를 조회하는 데 사용됩니다.

4.1 CBOR-LD Registry

단일 CBOR 태그 값을 사용하면서도 소비 시 서로 다른 압축 테이블 자료가 필요한 CBOR-LD의 가능한 사용 사례를 무제한으로 확장할 수 있도록, 다음을 정의합니다.

CBOR-LD Registry는 CBOR-LD 페이로드의 소비자에게 압축 해제에 필요한 term-codec map을 재구성하는 데 필요한 정보를 제공하는 전역 목록입니다. CBOR-LD Registry Entry는 다음을 포함합니다.

  • Registry Entry ID: 양의 정수.
  • Use Case: 이 항목이 사용될 CBOR-LD 페이로드의 유형.
  • typeTables: 이 레지스트리 항목과 함께 사용할 레지스트리 사전을 포함하는 배열.
  • processingModel: 이 레지스트리 항목에 사용되는 처리 모델. 처리 모델은 다음을 지정합니다.
    • 동적 JSON-LD 용어 압축에 의미론적 압축이 사용되는지 여부,
    • 동적 유형 지정 값 압축에 사용되는 코덱.
    default 처리 모델은 의미론적 압축을 사용하며 이 문서에 명시된 코덱을 포함합니다.
  • provisional: 해당 항목이 임시 항목인지 여부를 나타내는 불리언. 임시 항목은 변경되거나 제거될 수 있습니다.

문자열 "callerProvidedTable"은 typeTables에 나타날 수 있으며, 이 사용 사례에서는 전역적으로 정의되지 않은 Type Table이 필요함을 나타냅니다.

4.1.1 레지스트리

현재 CBOR-LD Registry는 여기에서 찾을 수 있습니다.

항목을 등록하려면 README의 지침을 따르십시오. 레지스트리는 W3C JSON-LD Community Group이 소유합니다.

5. 알고리즘

이 절에서는 JSON-LD를 CBOR-LD로 변환하고 그 반대로 변환하는 데 필요한 알고리즘을 명시합니다. 이 절에 있는 알고리즘의 대부분은 의미론적 압축 기능과 관련되어 있으며, CBOR-LD 페이로드가 의미론적 압축을 사용하지 않는 경우 CBOR-LD와 JSON-LD 간 변환에는 사용되지 않습니다.

5.1 인코딩 및 디코딩

5.1.1 JSON-LD에서 CBOR-LD로의 인코딩 알고리즘

이 알고리즘은 map typeTable, 정수 registryEntryId, 그리고 JSON-LD 문서 jsonldDocument를 입력으로 받아, 16진수 문자열 cborldBytes를 반환합니다.

  1. registryEntryId를 5.6.1 CBOR 태그 구조 가져오기 알고리즘에 전달한 결과로 prefix를 설정합니다.
  2. state를 빈 map으로 설정합니다.
  3. registryEntryId와 연결된 레지스트리 항목이 의미론적 압축을 요구하는 경우:
    1. state.strategy를 "compression"으로 설정합니다.
    2. state.typeTable을 typeTable로 설정합니다.
    3. state.registryEntryId를 registryEntryId로 설정합니다.
    4. state를 5.2.1 변환 알고리즘 초기화에 전달한 결과로 설정합니다.
    5. state와 jsonldDocument를 inputDocument로 5.2.2 문서 변환 알고리즘에 전달한 결과로 output을 설정합니다.
    6. suffix를 output의 CBOR 인코딩으로 설정합니다.
  4. 그렇지 않으면, suffix를 jsonldDocument의 CBOR 인코딩으로 설정합니다.
  5. cborldBytes를 prefix를 앞에 붙인 suffix의 16진수 인코딩으로 설정합니다.
  6. cborldBytes를 반환합니다.

5.1.2 CBOR-LD에서 JSON-LD로의 디코딩 알고리즘

이 알고리즘은 CBOR-LD 페이로드 cborldBytes를 입력으로 받아, JSON-LD 문서 jsonldDocument를 반환합니다.

  1. cborldBytes를 5.6.2 레지스트리 항목 ID 가져오기 알고리즘에 전달한 결과로 result를 설정합니다.
  2. state.registryEntryId를 result.registryEntryId로 설정하고 suffix를 result.suffix로 설정합니다.
  3. state를 빈 맵으로 설정합니다.
  4. state.registryEntryId와 연결된 레지스트리 항목이 의미 압축을 사용하는 경우:
    1. state.strategy를 "decompression"으로 설정합니다.
    2. registryEntryId와 연결된 CBOR-LD Varint 레지스트리 항목의 typeTables 배열에 있는 각 항목 type: map에 대해, 해당 항목을 state.typeTable에 추가하고, state.reverseTypeTable에서 type의 값을 inverseMap으로 설정합니다. 여기서 inverseMap은 매핑이 반전된 map입니다.
    3. state를 5.2.1 변환 초기화 알고리즘에 전달한 결과로 설정합니다.
    4. suffix를 바이트에서 맵으로 디코딩한 결과로 input을 설정합니다.
    5. state와 input을 inputDocuments로 5.2.2 문서 변환 알고리즘에 전달한 결과로 jsonldDocument를 설정합니다.
  5. 그렇지 않으면 cborldBytes를 구문 분석한 결과로 jsonldDocument를 설정합니다.
  6. jsonldDocument를 반환합니다.

5.2 변환 알고리즘

이 절의 알고리즘은 데이터 형식 간 입력을 추상적으로 변환하기 위한 "converter"의 동작을 설명합니다. 이 절의 뒤에서 정의되는 "compression" 및 "decompression" 전략과 같은 "strategy"와 함께 사용될 때, 이러한 알고리즘은 구체적인 데이터 형식 간 변환을 위해 인스턴스화될 수 있습니다. "compression" 전략은 JSON-LD에서 CBOR-LD로 변환하며, "decompression" 전략은 CBOR-LD에서 JSON-LD로 변환합니다.

5.2.1 변환 알고리즘 초기화

이 알고리즘은 map state를 받고 반환합니다.

  1. state를 5.4.1 컨텍스트 로더 알고리즘 초기화에 전달한 결과로 설정합니다.
  2. 빈 map termMap과 previousActiveContext를 5.3.1 활성 컨텍스트 알고리즘 초기화에 전달한 결과로 state.initialActiveContext를 설정합니다.
  3. state.typesEncodedAsBytes를 빈 set으로 설정합니다.
  4. "none", "http://www.w3.org/2001/XMLSchema#date", "http://www.w3.org/2001/XMLSchema#dateTime", 및 "url"을 state.typesEncodedAsBytes에 추가합니다.
  5. state를 반환합니다.

5.2.2 문서 변환 알고리즘

이 알고리즘은 맵 state와 맵 또는 맵 배열 inputDocuments를 입력으로 받아 각각 맵 또는 맵 배열 outputMaps를 반환합니다.

  1. inputDocuments가 배열이면, inputs를 inputDocuments로 설정합니다. 그렇지 않으면, inputs를 [inputDocuments]로 설정합니다.
  2. outputMaps를 빈 배열로 설정합니다.
  3. inputs 안의 input마다:
    1. output을 빈 map으로 설정합니다.
    2. state, input, output, 그리고 state.initialActiveContext를 activeContext로 5.2.3 일반 변환 알고리즘에 전달한 결과로 result를 설정합니다.
    3. result.output을 outputMaps에 추가합니다.
    4. state를 result.state로 설정합니다.
  4. inputDocuments가 배열이면 outputMaps를 반환합니다. 그렇지 않으면, outputMaps의 첫 번째 요소를 반환합니다.

5.2.3 일반 변환 알고리즘

이 알고리즘은 map input, output, state, 그리고 activeContext를 입력으로 받아, map state와 output을 포함하는 map을 반환합니다.

  1. state.strategy가 "compression"으로 설정되어 있으면:
    1. state, activeContext, input, 그리고 output을 전달하여 5.2.5.1 압축을 위한 컨텍스트 변환 알고리즘의 결과로 contextConversionResult를 설정합니다.
    2. activeContext를 contextConversionResult.activeContext로, output을 contextConversionResult.output으로, 그리고 state를 contextConversionResult.state로 설정합니다.
  2. 그렇지 않으면, state, activeContext, input, 그리고 output을 전달하여 5.2.6.1 압축 해제를 위한 컨텍스트 변환 알고리즘에서 나온 result의 result.activeContext로 activeContext를, result.state로 state를 설정합니다.
  3. state.strategy가 "compression"으로 설정되어 있으면, state, activeContext, input, 그리고 output을 전달하여 5.2.5.4 압축을 위한 객체 유형 가져오기 알고리즘에서 나온 result에 대해 state를 result.state로, objectTypes를 result.objectTypes로 설정합니다.
  4. 그렇지 않으면, state를 result.state로, objectTypes를 result.objectTypes로 설정합니다. 여기서 result는 state, activeContext, input, 그리고 output을 전달하여 5.2.6.4 압축 해제를 위한 객체 유형 가져오기 알고리즘에서 나온 결과입니다.
  5. activeContext와 objectTypes를 5.3.4 유형 범위 컨텍스트 적용 알고리즘에 전달한 결과로 activeContext를 설정합니다.
  6. state.strategy가 "compression"으로 설정되어 있으면, state, input, 그리고 activeContext를 전달하여 5.2.5.3 압축을 위한 입력 항목 가져오기 알고리즘에서 나온 result에 대해 state를 result.state로, termEntries를 result.termEntries로 설정합니다.
  7. 그렇지 않으면, state를 result.state로, output을 result.output으로, 그리고 termEntries를 result.termEntries로 설정합니다. 여기서 result는 state, input, output, 그리고 activeContext를 전달하여 5.2.6.3 압축 해제를 위한 입력 항목 가져오기 알고리즘에서 나온 결과입니다.
  8. termEntries 안의 [termInfo, value]마다:
    1. term을 termInfo.term으로 설정합니다.
    2. activeContext와 term을 5.3.3 속성 범위 컨텍스트 적용 알고리즘에 전달한 결과로 valueActiveContext를 설정합니다.
    3. plural을 termInfo.plural의 값으로, termType을 termInfo.def 안의 @type 값으로 설정합니다.
    4. plural이 true로 설정되어 있으면, values를 value의 값으로 설정합니다. 그렇지 않으면, values를 value의 값을 단일 요소로 포함하는 배열로 설정합니다.
    5. outputs를 빈 배열로 설정합니다.
    6. values 안의 unconvertedValue마다:
      1. state, termType, unconvertedValue를 value로, 그리고 valueActiveContext를 activeContext로 전달하여 5.2.4 값 변환 알고리즘의 결과로 result를 설정합니다.
      2. state를 result.state로 설정하고, result.output을 outputs에 추가합니다.
    7. plural이 true로 설정되어 있으면, outputValues를 outputs로 설정합니다. 그렇지 않으면, outputValues를 outputs의 첫 번째 요소로 설정합니다.
    8. state.strategy가 "compression"으로 설정되어 있으면, termInfo.termId의 값을 output에서 outputValues로 매핑하도록 설정합니다. 그렇지 않으면, termInfo.term의 값을 outputValues로 output에서 매핑하도록 설정합니다.
  9. result를 빈 map으로 설정합니다.
  10. result.state를 state로, result.output을 output으로 설정합니다.
  11. result를 반환합니다.

5.2.4 값 변환 알고리즘

이 알고리즘은 map state, activeContext, termInfo와 값 value 및 termType을 받습니다. map state와 output을 포함하는 result 객체를 반환합니다.

  1. value가 null이면, null을 반환합니다.
  2. state.strategy가 "compression"으로 설정되어 있으면, state, termType, termInfo, 그리고 value를 5.2.5.2 압축을 위한 값 변환 알고리즘에 전달한 결과로 output을 설정합니다.
  3. 그렇지 않으면, state, termType, termInfo, 그리고 value를 5.2.6.2 압축 해제를 위한 값 변환 알고리즘에 전달한 결과로 output을 설정합니다.
  4. output이 정의되어 있으면, state와 output을 포함하는 map인 result를 반환합니다.
  5. value가 배열이면:
    1. outputs를 빈 배열로 설정합니다.
    2. value의 각 element마다:
      1. activeContext, state, termInfo, termType, 그리고 element를 value로 전달하여 5.2.4 값 변환 알고리즘의 결과를 result라 합니다. state를 result.state로 설정하고 result.output을 outputs에 추가합니다.
    3. result를 빈 map으로 설정합니다. result.state를 state로, result.output을 outputs로 설정합니다.
    4. result를 반환합니다.
  6. output을 빈 map으로 설정합니다.
  7. state, activeContext, value를 input으로, 그리고 output을 전달하여 5.2.3 일반 변환 알고리즘의 결과로 result를 설정합니다.
  8. result를 반환합니다.

5.2.5 압축 전략 알고리즘

이 절의 알고리즘은 앞서 정의한 "conversion" 알고리즘과 함께 사용되어 JSON-LD를 CBOR-LD로 변환하는 "compression" 전략을 정의합니다.

5.2.5.1 압축을 위한 컨텍스트 변환 알고리즘

이 알고리즘은 map state, activeContext, input, 그리고 output을 입력으로 받아, map output, state, 그리고 activeContext를 포함하는 map result를 반환합니다.

  1. state, activeContext, 그리고 input을 전달하여 5.3.2 임베디드 컨텍스트 적용 알고리즘의 결과로 applyEmbeddedResult를 설정합니다.
  2. activeContext를 applyEmbeddedResult.activeContext로, state를 applyEmbeddedResult.state로 설정합니다.
  3. "@context"가 input에 항목을 가지고 있지 않으면:
    1. result를 빈 map으로 설정합니다.
    2. result.state를 state로, result.activeContext를 activeContext로 설정합니다.
    3. result를 반환합니다.
  4. context를 input의 "@context" 값으로 설정합니다.
  5. encodedContexts를 빈 배열로 설정합니다.
  6. context가 배열이면 isArray를 true로 설정하고 contexts를 context로 설정합니다. 그렇지 않으면, isArray를 false로 설정하고 contexts를 [context]로 설정합니다.
  7. contexts 안의 contextValue마다:
    1. state.typeTable과 contextValue를 전달하여 5.5.1.1 컨텍스트 인코더 생성의 결과로 encoderData를 설정합니다.
    2. encoderData가 빈 map이면, contextValue를 encodedContexts에 추가합니다.
    3. 그렇지 않으면, encoderData의 값을 encodedContexts에 추가합니다.
  8. isArray가 true이면, id를 state.keywordsMap의 "@context" 값에 1을 더한 값으로 설정하고, output의 id 값을 encodedContexts로 설정합니다.
  9. 그렇지 않으면, id를 state.keywordMap의 "@context" 값으로 설정하고, output의 id 값을 encodedContexts의 첫 번째 요소로 설정합니다.
  10. result.output을 output으로, result.state를 state로, 그리고 result.activeContext를 activeContext로 설정합니다.
  11. result를 반환합니다.
5.2.5.2 압축을 위한 값 변환 알고리즘

이 알고리즘은 map state 및 termInfo, 그리고 값 valueToEncode 및 termType을 입력으로 받아 map encoderData를 반환합니다.

  1. valueToEncode가 객체이면, 반환합니다.
  2. 그렇지 않으면, state, termInfo, valueToToEncode, 그리고 termType을 전달하여 5.5.2.1 값 인코더 생성의 결과로 result를 설정합니다.
  3. result를 반환합니다.
5.2.5.3 압축을 위한 입력 항목 가져오기 알고리즘

이 알고리즘은 map state, activeContext, 그리고 input을 입력으로 받아 map state와 배열 entries를 반환합니다.

  1. entries를 빈 배열로 초기화합니다.
  2. input의 키들을 사전순으로 정렬한 배열 keys를 설정합니다.
  3. keys 안의 key마다:
    1. key가 "@context"이면, 계속합니다.
    2. value를 input 안의 key 값으로 설정합니다.
    3. value가 배열이면, plural을 true로 설정합니다. 그렇지 않으면, plural을 false로 설정합니다.

5.3 활성 컨텍스트 처리

이 절의 알고리즘은 JSON-LD 문서와 연결된 컨텍스트 문서의 어떤 구성 요소가 압축 또는 압축 해제 중 어느 시점에 사용되는지 결정하는 방법을 설명합니다. 이러한 알고리즘에는 CBOR-LD에서 임베디드, 유형 범위, 그리고 속성 범위 컨텍스트를 적용하는 방법이 포함됩니다. 이는 이 명세의 뒤에서 정의되는 컨텍스트 로딩 알고리즘과 대비되며, 해당 알고리즘은 CBOR-LD 압축 기법의 핵심인 용어에서 정수로의 매핑을 구성하는 방법을 설명합니다. 함께 볼 때, 활성 컨텍스트 처리와 컨텍스트 로딩 알고리즘은 CBOR-LD로 변환하거나 CBOR-LD에서 변환할 때 JSON-LD 컨텍스트 문서를 어떻게 처리해야 하는지 명시합니다.

5.4.2 컨텍스트 로드 알고리즘

이 알고리즘은 map state와 context map 또는 URL contextIdentifier를 받아, map state와 entry를 포함하는 map인 result를 반환합니다.

  1. state.contextMap이 contextIdentifier에 대한 항목을 가지고 있으면:
    1. result를 빈 map으로 초기화합니다.
    2. result.state를 state로 설정합니다.
    3. result.entry를 state.contextMap 안의 contextIdentifier 값으로 설정합니다.
    4. result를 반환합니다.
  2. context가 문자열이면:
    1. 연결된 컨텍스트 객체를 가져오고, context를 그 객체 안의 "@context" 값으로 설정합니다.
    2. contextUrl을 contextIdentifier의 값으로 설정합니다.
  3. 그렇지 않으면, context를 contextIdentifier로 설정합니다.
  4. state, context, 그리고 설정되어 있다면 contextUrl을 5.4.3 컨텍스트 추가 알고리즘에 전달한 결과로 result를 설정합니다.
  5. result를 반환합니다.

5.4.3 컨텍스트 추가 알고리즘

이 알고리즘은 map state, 컨텍스트 객체 context, 그리고 컨텍스트 URL contextUrl을 받아, map state와 entry를 포함하는 map인 result를 반환합니다.

  1. context가 "@import" 항목을 가지고 있으면:
    1. importUrl을 `context 안의 "@import" 값으로 설정합니다.
    2. state.contextMap이 importUrl에 대한 항목을 가지고 있지 않으면:
      1. importUrl과 연결된 컨텍스트 객체를 가져오고, importContext를 그 객체 안의 "@context" 값으로 설정합니다.
      2. state, importContext를 context로, 그리고 importUrl을 contextUrl로 전달하여 5.4.3 컨텍스트 추가 알고리즘의 결과로 importedContextAdditionResult를 설정합니다.
      3. state를 importedContextAdditionResult.state로, importEntry를 importedContextAdditionResult.entry로 설정합니다.
    3. 그렇지 않으면, importEntry를 state.contextMap 안의 importUrl 값으로 설정합니다.
    4. context를 context의 모든 항목과 importEntry.context를 포함하는 map으로 설정합니다.
  2. termMap을 빈 map으로 설정합니다.
  3. entry를 context와 termMap을 포함하는 객체로 설정합니다.
  4. sortedTerms를 context 안의 키들을 사전순으로 정렬한 결과로 설정합니다.
  5. "@protected"가 context에 항목을 가지고 있으면 isProtected를 true로, 그렇지 않으면 false로 설정합니다.
  6. sortedTerms 안의 term마다:
    1. term이 state.keywordsMap에 항목을 가지고 있으면, 이 반복문의 다음 반복으로 진행합니다.
    2. definition을 context 안의 term 값으로 설정합니다.
    3. definition이 null이면, 이 반복문의 다음 반복으로 진행합니다.
    4. definition이 문자열이면:
      1. newDefinition을 빈 map으로 설정합니다.
      2. newDefinition 안의 "@id" 값을 definition으로 설정합니다.
      3. definition의 값을 newDefinition으로 설정합니다.
    5. definition 안의 protected 값을 isProtected로 설정합니다.
    6. termMap 안의 term 값을 definition으로 설정합니다.
    7. term이 state.termToId에 항목을 가지고 있지 않으면:
      1. termId를 state.nextTermId로 설정합니다.
      2. state.nextTermId를 2만큼 증가시킵니다.
      3. state.termToId 안의 term 값을 termId로 설정합니다.
      4. state.idToTerm 안의 termId 값을 term으로 설정합니다.
  7. contextUrl이 정의되어 있으면, state.contextMap 안의 contextUrl 값을 entry로 설정합니다.
  8. 그렇지 않으면, state.contextMap 안의 context 값을 entry로 설정합니다.
  9. result를 빈 map으로 설정합니다.
  10. result.state를 state로, result.entry를 entry로 설정합니다.
  11. result를 반환합니다.

5.5 코덱

이 절의 코덱은 JSON-LD의 개별 값이 CBOR로, 그리고 그 반대로 어떻게 변환되어야 하는지 정확히 명시합니다. 이들은 이전 절의 알고리즘에서 사용되며, CBOR-LD가 원시 타입과 비원시 타입을 모두 CBOR로 효율적으로 인코딩할 수 있게 합니다.

5.5.1 컨텍스트 코덱

5.5.1.1 컨텍스트 인코더 생성

이 알고리즘은 map typeTable과 값 contextValue를 입력으로 받아 map encoderData를 반환합니다.

  1. encoderData를 빈 map으로 초기화합니다.
  2. contextValue가 문자열이 아니면, 반환합니다.
  3. 그렇지 않으면, contextTable을 typeTable 안의 "context" 값으로 설정합니다.
  4. encoderData.context를 contextValue로, 그리고 encoderData.contextTable을 contextTable로 설정합니다.
  5. encoderData를 반환합니다.
5.5.1.2 컨텍스트 인코딩

이 알고리즘은 map encoderData를 받아, CBOR 이진 데이터를 반환합니다.

  1. encoderData.context가 encoderData.contextTable에 항목을 가지고 있으면, encoderData 안의 encoderData.context 값을 Major Type 0(부호 없는 정수) 객체로 CBOR 인코딩하여 반환합니다.
  2. 그렇지 않으면, encoderData.context 값을 Major Type 3 (텍스트 문자열) 객체로 CBOR 인코딩하여 반환합니다.
5.5.1.3 컨텍스트 디코더 생성

이 알고리즘은 map reverseTypeTable을 받아 map encoderData를 반환합니다.

  1. reverseContextTable을 reverseTypeTable 안의 "context" 값으로 설정합니다.
  2. decoderData를 빈 map으로 초기화합니다.
  3. decoderData.reverseContextTable을 reverseContextTable의 값으로 설정하고 decoderData를 반환합니다.
5.5.1.4 컨텍스트 디코딩

이 알고리즘은 map decoderData와 값 value를 입력으로 받아 값을 반환합니다.

  1. value가 숫자가 아니면, value를 반환합니다.
  2. 그렇지 않고 decoderData.reverseContextTable이 value에 대한 항목을 가지고 있으면, 그 항목의 값을 반환합니다.
  3. 그렇지 않으면, 오류 ERR_UNDEFINED_COMPRESSED_CONTEXT를 던집니다.

5.5.2 값 코덱

5.5.2.1 값 인코더 생성

이 알고리즘은 map state와 termInfo, 그리고 값 termType 및 valueToEncode를 입력으로 받아 map encoderData 또는 valueToEncode를 반환합니다.

  1. isUrl을 false로 설정합니다.
  2. termInfo.term이 "@id" 또는 "@type"이면, isUrl을 true로 설정합니다.
  3. termInfo.def 안의 "@id" 값이 "@id" 또는 "@type"이면, isUrl을 true로 설정합니다.
  4. termType이 "@id" 또는 "@vocab"이면, isUrl을 true로 설정합니다.
  5. isUrl이 true이면, tableType을 "url"로 설정합니다.
  6. 그렇지 않고 termType이 정의되어 있으면, tableType을 termType으로 설정합니다.
  7. 그렇지 않으면, tableType을 "none"으로 설정합니다.
  8. state.typeTable이 tableType에 대한 항목을 가지고 있으면:
    1. subTable을 state.typeTable 안의 tableType 값으로 설정합니다.
    2. subTable이 valueToEncode에 대한 항목을 가지고 있으면:
      1. intValue를 subTable 안의 valueToEncode 값으로 설정합니다. includeSign을 false로 설정합니다.
      2. state.typesEncodedAsBytes가 tableType에 대한 항목을 가지고 있으면, convertToBytes를 true로 설정합니다. 그렇지 않으면, convertToBytes를 false로 설정합니다.
    3. 그렇지 않고 tableType이 "none"이 아니며 valueToEncode가 정수이면:
      1. intValue를 valueToEncode의 값으로 설정합니다.
      2. convertToBytes와 includeSign을 true로 설정합니다.
    4. intValue가 정의되어 있으면:
      1. encoderData를 빈 map으로 초기화합니다.
      2. encoderData.intValue를 intValue의 값으로, encoderData.convertToBytes를 convertToBytes의 값으로, 그리고 encoderData.includeSign을 includeSign의 값으로 설정합니다.
      3. encoderData를 반환합니다.
  9. tableType이 state.processingModeTypeEncoders에 항목을 가지고 있으면, 해당 항목의 코덱과 연결된 Create Encoder 알고리즘을 호출한 결과로 encoderData를 설정합니다.
  10. encoderData가 정의되어 있으면, encoderData를 반환합니다.
  11. valueToEncode를 반환합니다.
5.5.2.2 값 인코딩

이 알고리즘은 map encoderData를 받아, CBOR 이진 데이터를 반환합니다.

  1. encoderData.convertToBytes가 true이면:
    1. includeSign 값을 사용하여 정수의 이진 표현이 부호 있는지 부호 없는지를 결정하면서, intValue를 바이트로 변환한 결과로 bytes를 설정합니다.
    2. bytes를 Major Type 2(바이트 문자열) 객체로 CBOR 인코딩하여 반환합니다.
  2. 그렇지 않으면, intValue를 Major Type 0(부호 없는 정수) 객체로 CBOR 인코딩하여 반환합니다.
5.5.2.3 값 디코더 생성

이 알고리즘은 map state와 termInfo, 그리고 값 termType 및 valueToDecode를 입력으로 받아 map decoderData를 반환합니다.

  1. isUrl을 false로 설정합니다.
  2. termInfo.term이 "@id" 또는 "@type"이면, isUrl을 true로 설정합니다.
  3. termInfo.def 안의 "@id" 값이 "@id" 또는 "@type"이면, isUrl을 true로 설정합니다.
  4. termType이 "@id" 또는 "@vocab"이면, isUrl을 true로 설정합니다.
  5. isUrl이 true이면, tableType을 "url"로 설정합니다.
  6. 그렇지 않고 termType이 정의되어 있으면, tableType을 termType으로 설정합니다.
  7. 그렇지 않으면, tableType을 "none"으로 설정합니다.
  8. state.reverseTypeTable이 tableType에 대한 항목을 가지고 있으면:
    1. subTable을 state.reverseTypeTable 안의 tableType 값으로 설정합니다.
    2. useTable을 false로 설정합니다.
    3. valueToDecode가 바이트 배열이고 state.typesEncodedAsBytes가 tableType에 대한 항목을 가지고 있으면:
      1. useTable을 true로 설정합니다.
      2. intValue를 valueToDecode 바이트의 부호 없는 정수 변환으로 설정합니다.
    4. 그렇지 않고 valueToDecode가 정수이고 state.typesEncodedAsBytes가 tableType에 대한 항목을 가지고 있지 않으면:
      1. useTable을 true로 설정합니다.
      2. intValue를 valueToDecode로 설정합니다.
    5. useTable이 true이면:
      1. intValue가 subTable에 없으면, 오류 ERR_UNKNOWN_COMPRESSED_VALUE를 던집니다.
      2. 그렇지 않으면, decoded를 subTable 안의 intValue 값으로 설정합니다.
    6. 그렇지 않고 valueToDecode가 바이트 배열이며 tableType이 "none"이 아니면, decoded를 valueToDecode의 정수 변환으로 설정합니다.
    7. decoded가 정의되어 있으면, decoderData를 빈 map으로 초기화하고, decoderData.decoded를 decoded의 값으로 설정한 뒤 decoderData를 반환합니다.
  9. tableType이 state.processingModeTypeDecoders에 항목을 가지고 있으면, 해당 항목의 코덱과 연결된 Create Decoder 알고리즘을 호출한 결과로 DecoderData를 설정합니다.
  10. decoderData가 정의되어 있으면, decoderData를 반환합니다.
  11. 그렇지 않고 valueToDecode가 배열이 아니면, decoderData를 빈 map으로 초기화하고, decoderData.decoded를 valueToDecode로 설정한 뒤 decoderData를 반환합니다.
5.5.2.4 값 디코딩

이 알고리즘은 map decoderData를 받아 값을 반환합니다.

  1. decoderData.decoded를 반환합니다.

5.6 CBOR 태그 처리

5.6.1 CBOR 태그 구조 가져오기 알고리즘

이 알고리즘은 정수 registryEntryId를 입력으로 받아 바이트 문자열 prefix를 반환합니다.
  1. registryEntryBytes를 registryEntryID의 CBOR 인코딩으로 설정합니다.
  2. prefix를 바이트 문자열 0xD9CB1D82의 끝에 registryEntryBytes를 덧붙인 결과로 설정합니다.
  3. prefix를 반환합니다.

5.6.2 레지스트리 항목 ID 가져오기 알고리즘

이 알고리즘은 인코딩된 CBOR-LD 페이로드 cborldBytes를 입력으로 받아, 디코딩할 주 데이터인 suffix와, suffix를 압축 해제하는 데 사용해야 하는 registryEntryId 값을 반환합니다.

  1. cborldbytes의 CBOR 태그가 0xCB1D(태그 값 51997)가 아니면, ERR_NON_CBOR_LD_TAG 오류를 던집니다.
  2. 태그가 붙은 항목이 첫 번째 요소가 CBOR 정수인 두 요소 배열이 아니면, ERR_INVALID_PAYLOAD_STRUCTURE 오류를 던집니다.
  3. registryEntryId의 값을 태그가 붙은 배열의 인덱스 0에 있는 정수 값으로 설정합니다.
  4. suffix의 값을 배열의 두 번째 요소 값으로 설정합니다.
  5. result를 빈 map으로 설정합니다.
  6. result.suffix를 suffix의 값으로, 그리고 result.registryEntryId를 registryEntryId의 값으로 설정합니다.
  7. result를 반환합니다.

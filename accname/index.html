요약

이 문서는 user agents가 웹 콘텐츠 언어로부터 이름과 설명을 접근 가능한 객체로부터 어떻게 결정하는지 설명합니다. 이 정보는 접근성 API를 통해 노출되어 보조 기술이 이러한 객체를 식별하고 이름이나 설명을 사용자에게 제공할 수 있도록 합니다. 이름과 설명이 결정되는 알고리즘을 문서화함으로써 다양한 접근성 API 간의 상호운용적 속성 노출을 촉진하고, 저자 의도에 맞게 정보가 나타나도록 돕습니다.

접근 가능한 이름 및 설명 계산 사양은 여러 콘텐츠 기술 전반에 적용되는 지원을 정의합니다. 여기에는 일반 목적의 WAI-ARIA [WAI-ARIA] 역할, 상태, 속성 및 개별 콘텐츠 언어에 특화된 기능에 의해 제공되는 접근 가능한 이름과 설명이 포함됩니다.

이 문서는 WAI-ARIA 1.0 사용자 에이전트 구현 가이드 [WAI-ARIA-IMPLEMENTATION] W3C 권고안의 접근 가능한 이름 및 설명 지침을 대체합니다. 이 문서는 WAI-ARIA 제품군의 일부이며 WAI-ARIA 개요에 설명되어 있습니다.

1. 소개

이 섹션은 현행 표준이 아닙니다.

User agents는 DOM [DOM]에서 정보를 얻어 접근성 트리라는 병렬 구조를 생성합니다. 이 트리는 접근 가능한 객체들로 구성됩니다. 접근 가능한 객체는 자신의 역할, 상태, 속성에 대한 정보를 제공합니다. 예를 들어, 역할이 menuitem이고, 현재 enabled 상태이며, haspopup 속성이 있어 하위 메뉴로 연결됨을 나타내는 접근 가능한 객체가 있습니다.

이 문서에서 설명하는 접근 가능한 객체의 두 속성은 접근 가능한 이름과 접근 가능한 설명입니다. 이름은 객체의 목적을 알려주는 짧은 레이블입니다. 예를 들어 메뉴 항목에 대한 접근 가능한 이름은 New로, 해당 메뉴 항목이 새 문서, 새 창 등을 생성한다는 것을 의미합니다.

설명은 접근 가능한 객체의 성격을 더 명확하게 설명하는 짧은 설명입니다. 이름만으로 충분하다면 설명이 꼭 필요하지는 않지만, 설명이 있으면 사용자가 객체의 용도를 더 잘 이해하는 데 도움이 됩니다.

접근성 API는 현재 접근 가능한 이름과 설명에 대해 평면적이고 구조화되지 않은 문자열만을 지원합니다. 따라서 이름/설명 계산의 결과도 평면 문자열입니다.

"접근 가능한 이름"과 "접근 가능한 설명"이라는 용어는 접근 가능한 객체의 속성임을 접근성 API에 의해 노출된다는 점을 강조하기 위해 사용합니다. 하지만 이후에는 간단히 "이름"과 "설명"으로 표현합니다.

2. 준수

현행 표준이 아닌 섹션뿐만 아니라, 본 명세서의 모든 작성 지침, 다이어그램, 예시, 참고 사항도 현행 표준이 아닙니다. 그 외의 모든 내용은 현행 표준입니다.

키워드 MUST는 [RFC2119]에 설명된 대로 해석되어야 합니다.

2.1 RFC-2119 키워드

RFC-2119 키워드는 대문자로 표기하며 class="rfc2119" 속성이 있는 strong 요소에 포함됩니다. 위에 표시된 키워드가 사용되었으나 이 형식을 따르지 않은 경우, RFC 2119의 공식적인 의미를 전달하지 않고 단순히 설명(즉, 참고용)으로 사용됩니다. 이러한 사용은 본 명세서에서 최대한 피하고 있습니다.

2.2 규범적 및 정보 제공 섹션

섹션이 규범적인지 비규범적(정보 제공)인지의 표시는 해당 섹션 전체와 하위 섹션에도 적용됩니다.

정보 제공 섹션은 명세를 이해하는 데 유용한 정보를 제공합니다. 이러한 섹션에는 권장 관행의 예시가 포함될 수 있지만, 이 명세에 적합하기 위해 반드시 이러한 권장 사항을 따를 필요는 없습니다.

3. 중요 용어

일부 용어는 본문에서 정의되지만, 아래 정의들은 이 문서 전체에서 사용됩니다.

접근성 API

운영 체제 및 기타 플랫폼은 객체와 이벤트에 대한 정보를 보조 기술에 노출하는 인터페이스 집합을 제공합니다. 보조 기술은 이러한 인터페이스를 사용하여 해당 위젯에 대한 정보를 얻고 상호작용합니다. 접근성 API의 예로는 Microsoft Active Accessibility [MSAA], Microsoft User Interface Automation [UI-AUTOMATION], MSAA와 UIA Express [UIA-EXPRESS], Mac OS X 접근성 프로토콜 [AXAPI], Linux/Unix 접근성 툴킷 [ATK] 및 Assistive Technology Service Provider Interface [AT-SPI], 그리고 IAccessible2 [IAccessible2] 등이 있습니다.

접근성 트리

사용자 인터페이스(UI)의 구조를 나타내는 접근 가능한 객체의 트리입니다. 접근성 트리의 각 노드는 접근성 API를 통해 노출된 UI의 요소(예: 푸시 버튼, 체크 박스, 컨테이너 등)를 나타냅니다.

접근 가능한 설명

접근 가능한 설명은 인터페이스 요소와 관련된 추가 정보를 제공하며, 접근 가능한 이름을 보완합니다. 접근 가능한 설명은 시각적으로 인지될 수도 있고 아닐 수도 있습니다.

접근 가능한 이름

접근 가능한 이름은 사용자 인터페이스 요소의 이름입니다. 각 플랫폼 접근성 API는 접근 가능한 이름 속성을 제공합니다. 접근 가능한 이름의 값은 사용자 인터페이스 요소의 가시적(예: 버튼의 표시 텍스트) 또는 비가시적(예: 아이콘을 설명하는 텍스트 대체값) 속성에서 파생될 수 있습니다. 관련 항목: 접근 가능한 설명.

접근 가능한 이름 속성의 간단한 예는 "OK" 버튼입니다. 텍스트 "OK"가 접근 가능한 이름입니다. 버튼이 포커스를 받으면, 보조 기술은 플랫폼의 역할 설명과 접근 가능한 이름을 연결해서 읽어줄 수 있습니다. 예를 들어, 스크린 리더는 "푸시 버튼 OK" 또는 "OK 버튼"이라고 읽을 수 있습니다. 연결 순서와 역할 설명("버튼", "푸시 버튼", "클릭 가능한 버튼" 등)은 플랫폼 접근성 API 또는 보조 기술에 의해 결정됩니다.

접근 가능한 객체

플랫폼 접근성 트리의 노드입니다. 접근 가능한 객체는 상태, 속성, 이벤트를 보조 기술에서 사용할 수 있도록 노출합니다. 마크업 언어(예: HTML 및 SVG) 및 WAI-ARIA에서는 마크업 요소와 그 속성이 접근 가능한 객체로 표현됩니다.

보조 기술

하드웨어 및/또는 소프트웨어로서:

  • 웹 콘텐츠를 검색 및 렌더링하기 위해 사용자 에이전트가 제공하는 서비스를 활용함
  • 사용자 에이전트 또는 웹 콘텐츠 자체와 API를 통해 상호 작용함
  • 사용자 에이전트가 제공하는 것 이상의 서비스를 제공하여 장애가 있는 사용자가 웹 콘텐츠와 상호작용할 수 있도록 돕는다

이 정의는 다른 문서에서 사용되는 정의와 다를 수 있습니다.

이 문서의 맥락에서 중요한 보조 기술의 예시는 다음과 같습니다:

  • 스크린 확대기: 렌더링된 텍스트와 이미지를 확대하여 시각적 가독성을 높임
  • 스크린 리더: 합성 음성 또는 점자 디스플레이를 통해 정보를 전달함
  • 텍스트-음성 변환 소프트웨어: 텍스트를 합성 음성으로 변환함
  • 음성 인식 소프트웨어: 음성 제어 및 받아쓰기를 가능하게 함
  • 대체 입력 기술(헤드 포인터, 화면 키보드, 단일 스위치, 흡입/분출 장치 등): 키보드 입력을 시뮬레이션함
  • 대체 포인팅 장치: 마우스 포인팅 및 클릭을 시뮬레이션함
속성(Attribute)

본 명세서에서 속성은 마크업 언어에서와 같이 사용됩니다. 속성은 요소에 추가되는 구조적 특징으로, 해당 객체가 나타내는 상태와 속성에 대한 정보를 제공합니다.

클래스(Class)

유사한 특성을 공유하는 인스턴스 객체의 집합입니다.

요소(Element)

본 명세서에서 요소는 마크업 언어에서와 같이 사용됩니다. 요소는 마크업 언어에서 객체의 데이터 프로필을 포함하는 구조적 구성 요소입니다.

이벤트(Event)

다른 객체에 상태의 변화를 알리기 위해 사용되는 프로그래밍 메시지입니다. 웹 페이지에 대한 사용자 입력은 상호작용을 설명하고 문서 객체의 상태 변화를 알릴 수 있는 추상 이벤트를 통해 처리되는 경우가 많습니다. 일부 프로그래밍 언어에서는 이벤트를 알림(notification)이라고도 합니다.

숨김(Hidden)

요소가 모든 사용자에게 보이지 않거나 인지되지 않거나, 상호작용할 수 없는 경우를 나타냅니다. 요소가 렌더링되지 않거나 명시적으로 숨김 처리된 경우, 해당 요소 또는 그 상위 요소가 숨김으로 간주됩니다.

참고(Informative)

정보 제공을 위한 내용이며 준수에 필수적이지 않습니다. 준수에 필요한 내용은 현행 표준으로 지칭됩니다.

노드(Node)

DOM 트리 또는 접근성 트리에서 객체의 기본 유형입니다. DOM 노드는 요소 또는 텍스트 노드 등으로 구체화됩니다. 접근성 트리의 노드는 접근 가능한 객체입니다.

현행 표준(Normative)

준수에 필수적입니다. 반대로, 참고(Informative) 또는 "현행 표준이 아님(non-normative)"으로 식별된 내용은 준수에 필수적이지 않습니다.

객체(Object)

사용자 인터페이스 맥락에서, 지각적 사용자 경험의 항목은 하나 이상의 요소로 마크업 언어에서 표현되며, 사용자 에이전트에 의해 렌더링됩니다.

프로그래밍 맥락에서는, 유사 객체의 일반적 특성을 정의하는 하나 이상의 클래스 및 인터페이스의 인스턴스입니다. 접근성 API의 객체는 하나 이상의 DOM 객체를 나타낼 수 있습니다. 접근성 API는 DOM 인터페이스와는 별개의 인터페이스를 정의합니다.
인지(Perceivable)

사용자가 감지할 수 있는 방식으로 제공됨을 의미합니다. 본 문서의 관련 참조: WCAG 2.1 원칙 1: 콘텐츠는 인지 가능해야 함 [WCAG21].

속성(Property)

주어진 속성 중 객체의 본질에 필수적이거나 객체와 연관된 데이터 값을 나타내는 것. 속성의 변경은 객체의 의미나 표현에 상당한 영향을 줄 수 있습니다. 일부 속성(예: aria-multiline)은 상태보다 변경 빈도가 낮으나, 빈도 차이는 규칙이 아닙니다. aria-activedescendant, aria-valuenow, aria-valuetext와 같은 일부 속성은 자주 변경될 수 있습니다. 상태와 속성의 구분을 참고하세요.

역할(Role)

주요 유형 표시자입니다. 이러한 의미론적 연결로 도구가 해당 유형의 다른 객체에 대한 사용자 기대와 일치하는 방식으로 객체를 표시하고 상호작용을 지원할 수 있습니다.

의미론(Semantics)

사람이 이해하는 의미를, 객체의 표현을 컴퓨터가 처리할 수 있도록 정의한 것. 예를 들어 요소 및 속성 등을 구조적으로 표현하고, 다양한 사람이 해당 객체를 일관되게 이해할 수 있도록 합니다.

상태(State)

상태는 속성의 동적 형태로, 객체의 특성이 사용자 동작이나 자동화 처리에 따라 변할 수 있음을 표현합니다. 상태는 객체의 본질을 변경하지 않으며, 객체 또는 사용자 상호작용 가능성과 관련된 데이터를 나타냅니다. 상태와 속성의 구분을 참고하세요.

텍스트 노드(Text node)

DOM 노드의 한 유형으로, 속성 또는 요소의 텍스트 내용을 나타냅니다. 텍스트 노드는 자식 노드를 가지지 않습니다.

툴팁 속성(Tooltip attribute)

데스크탑 사용자 에이전트에서 마우스 오버 등의 동작에 반응하여 툴팁을 생성하는 모든 호스트 언어 속성입니다.

사용자 에이전트(User Agent)

웹 콘텐츠를 검색, 렌더링 및 최종 사용자 상호작용을 지원하는 모든 소프트웨어입니다. 이 정의는 다른 문서에서 사용되는 정의와 다를 수 있습니다.

위젯(Widget)

사용자가 상호작용할 수 있는 개별 사용자 인터페이스 객체입니다. 위젯은 하나의 값이나 동작만을 가진 단순 객체(예: 체크박스, 메뉴 항목)부터 여러 하위 객체를 포함하는 복잡한 객체(예: 트리, 그리드)까지 다양합니다.

4. 이름 및 설명

이름 및 설명 계산의 시작점은 DOM 요소입니다. 출력은 단어 하나 또는 공백으로 구분된 토큰 문자열 등과 같이 평면적이고 구조화되지 않은 문자열입니다. 예시로 저장과 디스크에서 다시 불러오기가 있습니다.

중요한 요소는 요소의 역할이며, 이는 어떤 콘텐츠가 이름 문자열에 기여하는지를 결정합니다. 역할에는 nameFrom RDF 속성이 있으며, 두 가지 값이 있습니다:

author
이름은 aria-label, aria-labelledby 속성과 같은 명시적 마크업 기능에서 저자가 제공한 값, 또는 HTML의 alt나 title 속성, SVG의 desc 요소 등 호스트 언어의 라벨링 메커니즘에서 생성됩니다.
contents
이름은 텍스트 노드에서 생성됩니다. 일부 역할에서는 "author" 외에 추가로 허용될 수 있지만, "content"는 우선순위가 높은 "author" 기능이 제공되지 않을 때만 사용됩니다. 우선순위는 접근 가능한 이름 및 설명 계산 알고리즘에 의해 정의됩니다.

접근성 강화 인터넷 애플리케이션(WAI-ARIA) 1.1 [WAI-ARIA] 명세는 author로부터 이름과 content로부터 이름을 지원하는 역할 목록을 제공합니다.

4.1 이름 계산

User agents 필수로 아래 접근 가능한 이름 및 설명 계산 섹션에 제시된 규칙에 따라 접근 가능한 이름을 계산해야 합니다.

4.2 설명 계산

aria-describedby가 존재할 경우, user agents 필수로 현재 요소에 있는 aria-describedby 속성에 참조된 요소들의 텍스트 대체값을 연결하여 접근 가능한 설명을 계산해야 합니다. 참조된 요소들의 텍스트 대체값은 아래 접근 가능한 이름 및 설명 계산 섹션에 제시된 여러 방법으로 계산됩니다.

4.3 접근 가능한 이름 및 설명 계산

접근 가능한 이름 및 설명 계산은 접근 가능한 이름과 접근 가능한 설명 모두를 생성하는 데 사용됩니다. 다양한 요소, 노드, 마크업 조합에 대해 각기 다른 규칙이 제공됩니다. 텍스트 대체값은 필요에 따라 요소 내 모든 관련 콘텐츠를 기반으로 구축됩니다. 이는 2B와 2F 단계(재귀적임)를 통해 자식이나 참조된 노드에서 텍스트를 가져오는 전체 규칙 집합을 사용하여 이루어집니다.

이 계산의 목적은 대체 표현을 위한 인지 가능한 레이블 또는 설명을, 공백으로 구분된 평면 문자열 형태로 생성하는 것입니다.

4.3.1 용어 정의

Root node
텍스트 대체값을 찾기 위한 DOM 노드 또는 요소.
Current node
텍스트 등가값을 계산하기 위해 현재 탐색 중인 DOM 노드. 초기에는 root node이지만, 이후 단계에서는 root node의 자손이거나 다른 참조된 노드일 수 있음.
Flat string
캐리지 리턴, 줄바꿈, 탭, 폼피드가 모두 하나의 공백으로 대체되고, 여러 공백은 하나로 줄어든 문자 데이터 문자열. 마크업 없이 문자 데이터만 포함.
Total accumulated text
current node를 제외한 지금까지 계산된 텍스트 등가값.
Accumulated text
아래에서 설명된 단계 또는 단계의 순서에서 임시로 저장되는 누적 텍스트.
Result
아래 단계 중 하나에서 계산된 텍스트 등가값.
Append the result, without a space, to X
  • X가 비어 있다면 result를 X에 복사.
  • X가 비어 있지 않다면 result를 X의 끝에 복사.
Append the result, with a space, to X
  • X가 비어 있다면 result를 X에 복사.
  • X가 비어 있지 않다면 X 끝에 공백을 추가한 후 result를 X에 추가.
Prepend result, without a space, to X
  • X가 비어 있다면 result를 X에 복사.
  • X가 비어 있지 않다면 result를 X의 시작에 복사.
Prepend the result, with a space, to X
  • X가 비어 있다면 result를 X에 복사.
  • X가 비어 있지 않다면 result를 X의 시작에 복사하고, 복사 후 공백을 추가.

특정 요소의 텍스트 대체값은 다음과 같이 계산됩니다:

  1. 초기화: root node를 지정된 요소로, current node를 root node로, total accumulated text를 빈 문자열("")로 설정.
  2. current node의 텍스트 대체값을 계산:
    1. current node가 숨김 상태이고, aria-labelledby 또는 aria-describedby에 직접 참조되지 않으며, 호스트 언어의 텍스트 대체 요소(예: HTML의 label) 또는 속성에 직접 참조되지 않은 경우, 빈 문자열을 반환.
      설명:

      기본적으로 보조 기술은 숨김 정보를 전달하지 않지만, 저자가 aria-labelledby 또는 aria-describedby를 사용해 숨김 텍스트를 접근 가능한 이름 또는 접근 가능한 설명의 일부로 명시적으로 포함할 수 있습니다.

    2. 그 외의 경우:
      • 이름을 계산 중이고, current node에 하나 이상의 유효한 IDREF를 가진 aria-labelledby 속성이 있으며, current node가 이미 aria-labelledby 탐색에 포함되지 않았다면, 해당 IDREF들을 순서대로 처리:
      • 또는 설명을 계산 중이고, current node에 하나 이상의 유효한 IDREF를 가진 aria-describedby 속성이 있으며, current node가 이미 aria-describedby 탐색에 포함되지 않았다면, 해당 IDREF들을 순서대로 처리:
        1. accumulated text를 빈 문자열로 설정.
        2. 각 IDREF에 대해:
          1. IDREF가 참조하는 노드를 current node로 설정.
          2. current node의 텍스트 대체값을 2단계부터 계산. result를 해당 텍스트 대체값으로 설정.
          3. result를 accumulated text에 공백과 함께 추가.
        3. accumulated text를 반환.
      예시:

      다음 예시는 "current node가 이미 aria-labelledby 탐색에 포함되지 않았다"는 조항의 의미를 보여줍니다.

      • element1의 접근 가능한 이름은 "hello"입니다. 이는 aria-labelledby의 첫 번째 탐색으로 element3로 이어집니다.
      • element2는 접근 가능한 이름이 없습니다. 계산은 aria-labelledby의 첫 번째 탐색으로 element1로 이어지지만, element1의 aria-labelledby는 이후 따라가지 않습니다.
      예시 1
      <element1 id="el1" aria-labelledby="el3" />
<element2 id="el2" aria-labelledby="el1" />
<element3 id="el3"> hello </element3>
    3. 그 외의 경우, 이름을 계산 중이고 current node에 aria-label 속성이 있고 그 값이 빈 문자열이 아니거나, 공백을 제거해도 빈 문자열이 아니라면:
      • 재귀에 의해 current node를 탐색하고, current node가 2E 단계에서 정의된 임베디드 컨트롤이면, aria-label을 무시하고 2E로 이동.
      • 그 외의 경우, aria-label의 값을 반환.
      예시:

      다음 예시는 노드가 자신을 참조하는 aria-labelledby를 가질 때 aria-labelledby와 aria-label의 상호작용을 보여줍니다. <span role="button"> 요소의 접근 가능한 이름은 각각 "Delete Documentation.pdf"와 "Delete HolidayLetter.pdf"입니다.

      예시 2
      <h1>Files</h1>
<ul>
  <li>
    <a id="file_row1" href="./files/Documentation.pdf">Documentation.pdf</a>
    <span role="button" tabindex="0" id="del_row1" aria-label="Delete" aria-labelledby="del_row1 file_row1"></span>
  </li>
  <li>
    <a id="file_row2" href="./files/HolidayLetter.pdf">HolidayLetter.pdf</a>
    <span role="button" tabindex="0" id="del_row2" aria-label="Delete" aria-labelledby="del_row2 file_row2"></span>
  </li>
</ul>
    4. 그 외의 경우, current node의 네이티브 마크업이 속성(예: title) 또는 요소(예: HTML label)로 텍스트 대체값을 정의하는 경우, 해당 대체값을 호스트 언어에서 정의한 flat string 형태로 반환. 단, 해당 요소가 표현용(role="presentation" 또는 role="none")으로 지정된 경우는 제외.
      설명:

      예를 들어 HTML의 img 요소의 alt 속성은 텍스트 대체 문자열을 정의하며, label 요소는 참조된 폼 요소에 대한 텍스트를 제공합니다. SVG2에서는 desc와 title 요소가 부모 요소에 대한 설명을 제공합니다.

    5. 그 외의 경우, current node가 다른 위젯의 라벨(HTML의 label 요소나 aria-labelledby로 직접 참조된 모든 요소) 내에 포함된 컨트롤이고, 사용자가 임베디드 컨트롤의 값을 조정할 수 있는 경우, 다음과 같이 텍스트 대체값에 임베디드 컨트롤을 포함:
      • 임베디드 컨트롤의 역할이 textbox이면, 해당 값을 반환.
      • 임베디드 컨트롤의 역할이 메뉴 button이면, 버튼의 텍스트 대체값을 반환.
      • 임베디드 컨트롤의 역할이 combobox 또는 listbox이면, 선택된 option의 텍스트 대체값을 반환.
      • 임베디드 컨트롤이 range 역할(예: spinbutton 또는 slider)이면:
        • aria-valuetext 속성이 있으면 해당 값을 반환,
        • 그 외에 aria-valuenow 속성이 있으면 해당 값을 반환,
        • 그 외에는 호스트 언어 속성에서 지정한 값을 사용.
      예시:

      텍스트 입력 필드가 포함된 체크박스 라벨을 예로 들어보면, "화면을 [입력값]번 깜박임"이 있습니다. 사용자가 임베디드 textbox에 "5"를 입력했다면, 전체 라벨은 "화면을 5번 깜박임"이 됩니다. 예시:

      예시 3
      <div role="checkbox" aria-checked="false">Flash the screen <span role="textbox" aria-multiline="false"> 5 </span> times</div>
    6. 그 외의 경우, current node의 역할이 content로부터 이름을 허용하거나, current node가 aria-labelledby, aria-describedby로 참조되었거나, 호스트 언어의 텍스트 대체 요소(예: HTML의 label)이거나 그러한 요소의 자손인 경우:
      1. accumulated text를 빈 문자열로 설정.
      2. current node에 연결된 CSS 생성 텍스트 콘텐츠를 확인해 accumulated text에 포함. CSS :before 및 :after 의사 요소 [CSS2]는 콘텐츠 모델을 가진 요소에 텍스트 콘텐츠를 제공할 수 있음.
        • :before 의사 요소의 경우, User agents 필수로 CSS 텍스트 콘텐츠를 current node의 텍스트 콘텐츠 앞에 공백 없이 붙임.
        • :after 의사 요소의 경우, User agents 필수로 CSS 텍스트 콘텐츠를 current node의 텍스트 콘텐츠 뒤에 공백 없이 붙임.
      3. current node의 각 자식 노드에 대해:
        1. 자식 노드를 current node로 설정.
        2. current node의 텍스트 대체값을 2단계부터 계산하고 result로 설정.
        3. result를 accumulated text에 추가.
      4. accumulated text를 반환.

      중요: 하위 트리의 각 노드는 한 번만 처리됩니다. 만약 하위 노드에서 텍스트가 수집됐는데, 해당 노드가 다른 IDREF에서 다시 참조되는 경우, 두 번째 이후 참조는 따라가지 않습니다. 이는 무한 루프를 방지하기 위한 것입니다.

      설명:

      이 단계는 자식 노드에도 적용될 수 있으므로 계산은 재귀적으로 이루어지고, current node의 하위 트리 전체에서 텍스트가 수집됩니다. 하지만, 하위 노드의 텍스트 대체값은 위 B~D 단계에서 설명된 더 높은 우선순위의 마크업(즉 "Namefrom: author" 속성)에 의해 결정될 수 있습니다.

    7. 그 외의 경우, current node가 텍스트 노드라면, 해당 텍스트 내용을 반환.
    8. 그 외의 경우, current node가 접근 가능한 이름 또는 접근 가능한 설명이 계산 중인 요소의 자손이며, 자손을 포함한다면, 2F.i로 진행.
    9. 그 외의 경우, current node에 툴팁 속성이 있다면, 해당 값을 반환.
      설명:

      툴팁 속성은 서브트리 콘텐츠 등 다른 결과가 없을 때만 사용됩니다.

    위 각 단계의 result를 total accumulated text에 공백과 함께 추가합니다.

모든 단계가 끝나면, total accumulated text가 계산을 시작한 요소의 접근 가능한 이름 또는 접근 가능한 설명으로 사용됩니다.

5. 접근 가능한 이름 및 설명 매핑

이름 및 설명의 접근성 API 매핑 정보와 labelled-by/label-for, described-by/description-for 등 관계에 관한 정보는 핵심 접근성 API 매핑 명세 [CORE-AAM-1.1]에 문서화되어 있습니다. aria-label, aria-labelledby, aria-describedby에 대한 매핑 표 항목을 참고하세요.

1. 소개

이 섹션은 표준이 아닙니다.

현재 HTMLVideoElement를 Picture-in-Picture 창(requestPictureInPicture())에 넣는 웹 API가 존재합니다. 이로 인해 웹사이트가 맞춤형 picture-in-picture 경험(PiP)을 제공하는 데 제한이 있습니다. 우리는 항상 최상위에 표시되는 창에서 웹사이트가 전체 Document를 제공할 수 있도록 이 기능을 확장하고자 합니다.

이 새로운 창은 기존 open() 메서드를 통해 동일 출처로 빈 창을 여는 것과 비슷하지만 몇 가지 차이점이 있습니다:

  • PiP 창은 다른 창 위에 떠 있습니다.

  • PiP 창은 열었던 창보다 오래 지속되지 않습니다.

  • 웹사이트는 PiP 창의 위치를 설정할 수 없습니다.

  • PiP 창은 탐색될 수 없으며, `window.history` 또는 `window.location`으로 새 문서로 변경하면 PiP 창이 닫힙니다.

2. 의존성

이 명세의 IDL 조각은 Web IDL 명세에 명시된 대로, 규격을 준수하는 IDL 조각으로 해석해야 합니다. [WEBIDL]

3. 보안 고려사항

3.1. 보안 컨텍스트

이 API는 [SECURE-CONTEXTS]에 한정됩니다.

3.2. 스푸핑

사용자 에이전트는 DocumentPictureInPicture 창에서 악의적인 웹사이트가 다른 창 위에 띄우는 기능을 악용하여 다른 웹사이트나 시스템 UI를 스푸핑하는 것을 막기 위해 충분한 UI를 제공해야 합니다.

3.2.1. 위치 지정

사용자 에이전트는 웹사이트가 창의 위치를 설정하지 못하도록 해야 하며, 이는 사용자가 창을 다른 페이지의 UI 일부로 오인할 수 있는 위치를 일부러 지정할 수 없게 하기 위함입니다. 특히 moveTo()와 moveBy() API는 document picture-in-picture 창에서 비활성화되어야 합니다.

3.2.2. 출처 가시성

사용자 에이전트는 DocumentPictureInPicture 창을 제어하는 출처를 사용자에게 항상 명확히 보여주어야 하며, 사용자가 콘텐츠가 어디서 오는지 인식할 수 있어야 합니다. 예를 들면, 사용자 에이전트는 창의 제목 표시줄에 웹사이트의 출처를 표시할 수 있습니다.

3.2.3. 최대 크기

사용자 에이전트는 항상 최상위에 표시되는 창으로 화면 전체를 덮거나 PiP 창에 사용자가 갇히는 상황, 그리고 사용자의 데스크탑이 스푸핑되는 것을 막기 위해 document picture-in-picture 창의 최대 크기를 제한해야 합니다.

3.3. IFrame

이 API는 최상위 이동 가능 객체에서만 사용할 수 있습니다. 그러나 DocumentPictureInPicture Window 자체에는 HTMLIFrameElement가 포함될 수 있으며, 교차 출처 HTMLIFrameElement도 포함될 수 있습니다.

4. 개인정보 보호 고려사항

4.1. 지문 채취

PiP 창을 닫았다가 다시 열 때 이전 PiP 창의 크기와 위치를 재사용하면 사용자 경험이 더 원활해질 수 있습니다. 그러나 사용자 에이전트는 서로 다른 출처에 대해 크기/위치 정보를 재사용하지 않는 것이 좋습니다. 이것이 사용자의 지문 채취(식별)에 악용될 수 있기 때문입니다.

5. API

[Exposed=Window]
partial interface Window {
  [SameObject, SecureContext] readonly attribute DocumentPictureInPicture
    documentPictureInPicture;
};

[Exposed=Window, SecureContext]
interface DocumentPictureInPicture : EventTarget {
  [NewObject] Promise<Window> requestWindow(
    optional DocumentPictureInPictureOptions options = {});
  readonly attribute Window window;
  attribute EventHandler onenter;
};

dictionary DocumentPictureInPictureOptions {
  [EnforceRange] unsigned long long width = 0;
  [EnforceRange] unsigned long long height = 0;
  boolean disallowReturnToOpener = false;
  boolean preferInitialWindowPlacement = false;
};

[Exposed=Window, SecureContext]
interface DocumentPictureInPictureEvent : Event {
  constructor(DOMString type, DocumentPictureInPictureEventInit eventInitDict);
  [SameObject] readonly attribute Window window;
};

dictionary DocumentPictureInPictureEventInit : EventInit {
  required Window window;
};

DocumentPictureInPicture 객체는 웹사이트가 새로운 항상 최상위 Window를 생성 및 열거나, 그것과 관련된 창 열기 및 닫기 이벤트를 리스닝할 수 있게 해줍니다.

각 Window 객체는 documentPictureInPicture API라 불리는 새로운 DocumentPictureInPicture 인스턴스를 Window와 함께 생성합니다.

documentPictureInPicture getter 단계:

  1. this의 documentPictureInPicture API를 반환한다.

각 DocumentPictureInPicture 객체는 last-opened window와 관련되어 있는데, 이는 Window 객체이며 최초에는 null이며, requestWindow() 메서드 단계에서 설정됩니다.

window getter 단계:

  1. win을 this의 last-opened window로 한다.

  2. win이 null이 아니고 win의 closed 속성이 false이면 win을 반환한다.

  3. null을 반환한다.

requestWindow(options) 메서드 단계:

  1. Document Picture-in-Picture 지원이 false이면, "NotSupportedError" DOMException을 throw한다.

  2. this의 relevant global object의 navigable가 최상위 이동 가능 객체가 아니면, "NotAllowedError" DOMException을 throw한다.

  3. this의 relevant global object의 navigable의 Is Document Picture-in-Picture 불린 값이 true이면 "NotAllowedError" DOMException을 throw한다.

  4. this의 relevant global object에 순간 활성화가 없으면, "NotAllowedError" DOMException을 throw한다.

  5. options["width"]가 존재하고 0보다 크지만 options["height"]가 존재하지 않거나 값이 0이면, RangeError를 throw한다.

  6. options["height"]가 존재하고 0보다 크지만 options["width"]가 존재하지 않거나 값이 0이면, RangeError를 throw한다.

  7. 사용자 활성화 소모를 this의 relevant global object에 대해 실행한다.

  8. win을 this의 last-opened window로 한다. win이 null이 아니고 win의 closed 속성이 false이면 닫기를 win의 navigable에 대해 실행한다.

  9. 사용자 에이전트는 기존 picture-in-picture 창 닫기를 선택적으로 수행할 수 있다.

  10. pip traversable을 새로운 최상위 이동 가능 객체 생성 결과로 한다. 이는 this의 relevant global object의 navigable의 활성 브라우징 컨텍스트와 "_blank"를 사용한다.

생성된 Document의 URL은 `about:blank`이지만, 문서 기본 URL은 requestWindow()를 호출한 주체의 값으로 fallback 됩니다. 일부 브라우저는 일반 `about:blank` 팝업에 이 fallback 동작을 구현하지 않습니다. 명세에서 지정된 대로 이 상속이 반드시 이루어지게끔 구현해야 하며, 그렇지 않으면 상호 운용 문제를 초래할 수 있습니다.

  1. pip traversable의 활성 문서의 모드를 this의 relevant global object의 연결된 Document의 모드와 동일하게 설정한다.

  2. pip traversable의 Is Document Picture-in-Picture 불린 값을 true로 설정한다.

  3. options["width"]가 존재하고 값이 0보다 크면:

    1. 너무 크거나 너무 작으면 사용자 친화적인 창 크기에 맞게 값을 clamp 또는 무시할 수 있다.

    2. pip traversable의 활성 브라우징 컨텍스트 창의 viewport의 좌/우 간격이 options["width"] 픽셀이 되도록 크기 지정할 수 있다.

  4. options["height"]가 존재하고 값이 0보다 크면:

    1. 너무 크거나 너무 작으면 사용자 친화적인 창 크기에 맞게 값을 clamp 또는 무시할 수 있다.

    2. pip traversable의 활성 브라우징 컨텍스트 창의 viewport의 상/하 간격이 options["height"] 픽셀이 되도록 크기 지정할 수 있다.

options["preferInitialWindowPlacement"]가 존재하고 true이면, 사용자 에이전트는 이전에 닫힌 pip traversable 창의 위치나 크기를 고려하기보다는 13·14단계와 유사한 동작을 선호하도록 힌트로 사용할 수 있습니다.

  1. options["disallowReturnToOpener"]가 존재하고 true이면, 사용자 에이전트는 사용자가 opener 창으로 돌아갈 수 있게 하는 UI를 picture-in-picture 창에서 표시하지 않아야 합니다.

동영상 및 문서 picture-in-picture 모두에 대해, 사용자 에이전트는 사용자가 원래 페이지로 돌아가고 picture-in-picture 창을 닫을 수 있는 버튼을 종종 띄웁니다. 동영상 PiP에서는(동영상이 본문으로 돌아감) 주로 자연스럽지만, 문서 PiP 창에서는 항상 맞는 선택은 아닙니다. disallowReturnToOpener는 해당 기능이 웹사이트의 문서 PiP UX에 적합한지를 웹사이트가 사용자 에이전트에 알려주는 힌트입니다.

  1. pip traversable의 활성 브라우징 컨텍스트 창을 다른 창 위에 떠있게 구성한다.

  2. this의 last-opened window를 pip traversable의 active window로 설정한다.

  3. 글로벌 작업 큐를 DOM 조작 작업 소스에 등록한다. this의 relevant global object를 받아 enter 이벤트를 DocumentPictureInPictureEvent로 this에 fire해서, window 속성을 pip traversable의 active window로 초기화한다.

  4. pip traversable의 active window를 반환한다.

창의 크기는 웹사이트에서 설정할 수 있지만, 초기 위치는 사용자 에이전트의 재량에 맡겨집니다.

enter

DocumentPictureInPicture에서 PiP 창이 열릴 때 발생합니다.

6. 개념

6.1. 문서 Picture-in-Picture 지원

각 사용자 에이전트는 문서 Picture-in-Picture 지원 불린 값을 가지며, 그 값은 구현에 따라 다름(사용자 설정에 따라 달라질 수 있음)입니다.

6.2. DocumentPictureInPicture 창

각 최상위 이동 가능 객체는 문서 Picture-in-Picture 여부 불린을 가지며, 기본 값은 false이고, requestWindow() 단계에서 true로 설정될 수 있습니다.

6.3. 문서 Picture-in-Picture 창 닫기

합의가 충분히 이루어진 후 close에 병합하십시오.

close의 2단계를, "toUnload에 대해 unloading이 사용자가 취소했는지 확인 결과 true이면, 반환한다."에서 다음과 같이 수정:

  1. traversable의 문서 Picture-in-Picture 여부가 true이면, 이 단계를 건너뛴다. 아니면, unloading이 사용자가 취소했는지 확인이 true라면 반환한다.

6.4. 기존 PiP 창 닫기

기존 picture-in-picture 창 닫기 방법:

  1. 사용자 에이전트의 최상위 이동 가능 객체 집합의 각 top-level traversable에 대해:

    1. top-level traversable의 문서 Picture-in-Picture 여부가 true라면 close top-level traversable를 실행한다.

    2. top-level traversable의 활성 문서의 pictureInPictureElement 값이 null이 아니면 PiP 종료 알고리즘을 top-level traversable의 활성 문서로 실행한다.

    3. top-level traversable의 활성 문서의 하위 이동 가능 객체들 각각에 대해:

      1. navigable의 활성 문서의 pictureInPictureElement 값이 null이 아니면 PiP 종료 알고리즘을 navigable의 활성 문서로 실행한다.

6.5. 단일 PiP 창

어떤 최상위 이동 가능 객체도 한 번에 하나의 문서 picture-in-picture 창만 열어야 합니다. 최상위 이동 가능 객체의 활성 창의 documentPictureInPicture API의 last-opened window가 null이 아닐 때 또 다른 문서 picture-in-picture 창을 열려고 할 경우, 사용자 에이전트는 기존 last-opened window를 requestWindow() 단계에 따라서 닫아야 합니다.

하지만, 모든 최상위 이동 가능 객체에 대해 PiP 창을 하나만 허용할지는 구현과 플랫폼에 따라 다릅니다. 따라서 Picture-in-Picture 요청이 있을 때, 최상위 이동 가능 객체 중 문서 Picture-in-Picture 여부가 true이거나 활성 문서의 pictureInPictureElement가 null이 아닐 때의 동작은 구현에 맡깁니다: 사용자 에이전트는 기존 picture-in-picture 창 닫기를 할 수도 있고, 여러 PiP 창을 생성할 수도 있습니다.

6.6. 원본 또는 PiP 문서가 파기될 때 PiP 창 닫기

연관된 문서 Picture-in-Picture 창 닫기 방법 (주어진 Document document):

  1. navigable을 document의 node navigable로 한다.

  2. navigable가 최상위 이동 가능 객체가 아니면 이 단계를 중단한다.

  3. navigable의 문서 Picture-in-Picture 여부가 true이면 close navigable를 실행하고, 단계를 중단한다.

  4. win을 navigable의 활성 창의 documentPictureInPicture API의 last-opened window로 한다.

  5. win이 null이 아니고 win의 closed 속성이 false이면 close win의 navigable를 실행한다.

합의가 충분하면 destroy에 병합하십시오.

destroy의 끝에 10단계 추가:

  1. 연관된 문서 Picture-in-Picture 창 닫기를 document로 실행한다.

이 단계는 열린 문서 Picture-in-Picture 창이 있는 페이지가 닫히면 PiP 창도 함께 닫히도록 보장합니다.

6.7. 원본 또는 PiP 문서가 탐색될 때 PiP 창 닫기

합의가 충분하면 navigate에 병합하십시오.

navigate의 16.3단계를 수정, "Queue a global task on the navigation and traversal task source given navigable’s active window to abort navigable’s active document.", 그리고 바로 다음에 16.4단계 삽입:

  1. 글로벌 작업 큐에 탐색 및 이동작업 소스의 navigable의 활성 창을 지정하여 abort navigable의 활성 문서 및 연관된 문서 Picture-in-Picture 창 닫기를 navigable의 활성 문서로 실행.

  2. navigable가 최상위 이동 가능 객체이고 문서 Picture-in-Picture 여부가 true라면 단계를 중단한다.

열린 문서 Picture-in-Picture 창이 있는 페이지가 탐색되면 그 PiP 창도 함께 닫히도록 보장합니다. 또한 PiP 창의 문서가 탐색되면 해당 PiP 창이 닫힙니다.

6.8. PiP 창 크기 조정

문서 picture-in-picture 창을 프로그래밍적으로 크기 조정하는 것은 유용하지만, 항상 최상위로 띄우는 성격상 윈도우 크기를 너무 자유롭게 조정하면 사용자에게 불편하거나 방해가 되는 식으로 남용될 수 있습니다. 이런 문제를 완전히 막지 않으면서도 window resize API의 활용을 제한하려면 document picture-in-picture 창에서는 해당 API가 사용자 제스처를 소모하도록 해야 합니다.

합의가 충분할 때 resizeTo() 에 병합하십시오.

resizeTo() 3단계 이후에 다음 단계를 추가하세요. "만약 target이 사용자 동작이 아닌 스크립트로 생성된 보조 브라우징 컨텍스트가 아니라면 반환한다.":

  1. target의 최상위 이동 가능 객체의 문서 Picture-in-Picture 여부가 true라면:

    1. this의 relevant global object가 순간 활성화를 갖지 않으면 "NotAllowedError" DOMException을 throw함.

    2. 사용자 활성화 소모를 this의 relevant global object에 실행.

합의가 충분하면 resizeBy() 에 병합하십시오.

3단계 이후에 resizeBy() 에 다음 단계를 추가하세요. "만약 target이 사용자 동작이 아닌 스크립트로 생성된 보조 브라우징 컨텍스트가 아니라면 반환한다.":

  1. target의 최상위 이동 가능 객체의 문서 Picture-in-Picture 여부가 true라면:

    1. this의 relevant global object가 순간 활성화를 갖지 않으면 "NotAllowedError" DOMException을 throw함.

    2. 사용자 활성화 소모를 this의 relevant global object에 실행.

6.9. Opener 창 포커싱

picture-in-picture 창에서 opener 탭을 다시 포커스하는 기능은 종종 유용합니다. 예를 들어 창 크기가 작아서 사용자가 원하는 경험을 제공하지 못할 때 오프너 탭으로 포커스하는 것이 필요할 수 있습니다. focus() API를 수정해서 picture-in-picture 창이 오프너를 포커스할 때 시스템 포커스를 받을 수 있도록 합니다.

합의가 충분할 때 focus() 에 병합하십시오.

focus() 3단계 이후에 신규 단계 추가, "Run the 포커싱 단계를 current에 실행한다.":

  1. current가 최상위 이동 가능 객체인 경우:

    1. pipWindow를 current의 활성 창의 documentPictureInPicture API의 last-opened window로 한다.

    2. pipWindow가 null이 아니고 pipWindow의 relevant global object가 순간 활성화를 가지고 있으면:

      1. 사용자 활성화 소모를 pipWindow의 relevant global object에 실행.

      2. current에게 시스템 포커스를 부여한다.

오프너에 시스템 포커스를 주는 것은 반드시 문서 Picture-in-Picture 창을 닫아야 한다는 의미는 아닙니다. 웹사이트는 포커스 후 Picture-in-Picture 창을 닫고 싶으면 직접 close() 를 호출하면 됩니다.

6.10. CSS display-mode

CSS display mode 미디어 특성 picture-in-picture는 웹 개발자가 picture-in-picture 모드(웹 앱의 일부가 PiP로 보여질 때)에만 적용되는 CSS 규칙을 작성할 수 있게 합니다.

6.11. 사용자 활성화 전달

문서 picture-in-picture 창 특성상, 윈도우 내 버튼 등의 이벤트 핸들러가 실제로는 오프너 컨텍스트에서 실행되는 경우가 자주 있습니다. 이 때문에 웹사이트가 활성화 소모 API를 호출할 때 불편할 수 있습니다. 문서 picture-in-picture 창에는 순간 활성화가 있지만 오프너에는 없을 때가 있기 때문입니다.

이를 쉽게 하기 위해 활성화 알림 단계를 수정하여, document picture-in-picture 창에서 사용자 활성화가 발생하면 오프너에도 사용자 활성화를 트리거하게 합니다. 또한 오프너에서 사용자 활성화가 발생하면 문서 picture-in-picture 창의 동일 출처 프레임도 활성화되도록(동일 출처 하위 프레임 활성화 방식과 유사하게) 합니다.

합의가 충분하면 활성화 알림 단계에 병합하십시오.

활성화 알림의 4단계 이후에 3단계 추가, "Extend windows with the active window of each of document의 하위 이동 가능 객체 (단, 이동 가능 객체의 활성 문서의 origin이 동일 출처일 때만):

  1. document의 node navigable의 최상위 이동 가능 객체의 문서 Picture-in-Picture 여부가 true이면 extend windows에 document의 node navigable의 최상위 이동 가능 객체의 활성 브라우징 컨텍스트의 opener browsing context의 활성 창을 추가.

  2. document picture-in-picture window를 document의 node navigable의 최상위 이동 가능 객체의 활성 창의 documentPictureInPicture API의 last-opened window로 한다.

  3. document picture-in-picture window가 null이 아니면 extend windows에 document picture-in-picture window의 연결된 문서의 하위 이동 가능 객체 각각의 이동 가능 객체 중 활성 문서의 origin이 document picture-in-picture window의 연결된 문서의 origin과 동일 출처인 경우만 추가.

또한 이 활성화를 제대로 소모해야 오프너와 PiP 창 둘 다에서 중복 사용되지 않습니다. 이를 위해 사용자 활성화 소모 절차에 오프너가 Picture-in-Picture 창에서 활성화 소모시 오프너의 활성화도 소모하고, 오프너에서 소모 시 연관된 Picture-in-Picture 창의 활성화도 함께 소모하는 절차를 추가합니다.

합의가 충분하면 사용자 활성화 소모 단계에 병합하십시오.

사용자 활성화 소모의 3단계 이후에 3단계 추가, "Let navigables be the 포함 하위 이동 가능 객체 of top의 활성 문서.":

  1. top의 문서 Picture-in-Picture 여부가 true이면 extend navigables에 top의 활성 브라우징 컨텍스트의 opener browsing context의 활성 문서를 추가.

  2. document picture-in-picture window를 top의 활성 창의 documentPictureInPicture API의 last-opened window로 한다.

  3. document picture-in-picture window가 null이 아니면 extend navigables에 document picture-in-picture window의 연결된 문서의 포함 하위 이동 가능 객체를 추가.

7. 예시

이 섹션은 규범적이지 않습니다

7.1. 비디오 플레이어를 PiP로 추출하기

7.1.1. HTML

<body>
  <div id="player-container">
    <div id="player">
      <video id="video" src="foo.webm"></video>
      <!-- 여기에 추가적인 플레이어 요소. -->
    </div>
  </div>
  <input type="button" onclick="enterPiP();" value="PiP 진입" />
</body>

7.1.2. JavaScript

// picture-in-picture 창을 가리키는 핸들.
let pipWindow = null;

function enterPiP() {
  const player = document.querySelector('#player');

  // 창을 비디오에 맞는 크기로 지정.
  const pipOptions = {
    width: player.clientWidth,
    height: player.clientHeight,
  };

  documentPictureInPicture.requestWindow(pipOptions).then((pipWin) => {pipWindow = pipWin;

    // 플레이어가 PiP로 이동했음을 암시하는 스타일 적용.
    playerContainer.classList.add('pip-mode');

    // 플레이어를 PiP 창으로 옮김.
    pipWindow.document.body.append(player);

    // PiP 종료 이벤트를 듣고 비디오 복구.
    pipWindow.addEventListener('pagehide', onLeavePiP.bind(pipWindow), { once: true });
  });
}

// PiP 창이 닫힐 때 호출됨.
function onLeavePiP() {
  if (this !== pipWindow) {
    return;
  }

  // 컨테이너에서 PiP 스타일 해제.
  const playerContainer = document.querySelector('#player-container');
  playerContainer.classList.remove('pip-mode');

  // 플레이어를 본 창에 다시 추가.
  const player = pipWindow.document.querySelector('#player');
  playerContainer.append(player);

  pipWindow = null;
}

7.2. PiP 창의 요소 접근하기

const video = pipWindow.document.querySelector('#video');
video.loop = true;

7.3. PiP 창에서 이벤트 리스닝

더 개선된 picture-in-picture 경험을 위해 사이트에서는 버튼 등 사용자 입력에 반응해야 하는 컨트롤을 직접 정의하고 싶을 때가 많습니다.

const pipDocument = pipWindow.document;
const video = pipDocument.querySelector('#video');
const muteButton = pipDocument.document.createElement('button');
muteButton.textContent = '음소거 토글';
muteButton.addEventListener('click', () => {
  video.muted = !video.muted;
});
pipDocument.body.append(muteButton);

7.4. PiP 종료

사이트는 사용자가 창의 닫기 버튼을 클릭하지 않아도 DocumentPictureInPicture Window 를 닫고 싶을 수 있습니다. 이는 close() 메서드로 할 수 있습니다: 

// PiP 창을 닫고 onLeavePiP() 리스너가 동작함.
// 리스너 참조.
pipWindow.close();

7.5. PiP 창이 닫힐 때 요소 꺼내기

PiP 창이 어떤 이유로 닫히든(사이트가 닫든 사용자가 창을 닫든) 사이트는 PiP 창에서 요소를 다시 꺼내야 할 때가 많습니다. 이러한 처리는 pagehide 이벤트 핸들러에서 할 수 있습니다. onLeavePiP() 핸들러는 위의 비디오 플레이어 예시에 있으며 아래에 복사되었습니다:

// PiP 창이 닫힐 때 호출됨.
function onLeavePiP() {
  if (this !== pipWindow) {
    return;
  }

  // 컨테이너에서 PiP 스타일 해제.
  const playerContainer = document.querySelector('#player-container');
  playerContainer.classList.remove('pip-mode');

  // 플레이어를 본 창에 다시 추가.
  const player = pipWindow.document.querySelector('#player');
  playerContainer.append(player);

  pipWindow = null;
}

7.6. PiP 창 프로그래밍적 크기 조정

문서 picture-in-picture 창에서는 resizeTo() 및 resizeBy() API를 지원하지만 PiP 창에서의 사용자 제스처가 필요합니다:

const expandButton = pipWindow.document.createElement('button');
expandButton.textContent = 'PiP 창 확대';
expandButton.addEventListener('click', () => {
  // PiP 창의 너비 20px, 높이 30px 확대.
  pipWindow.resizeBy(20, 30);
});
pipWindow.document.body.append(expandButton);

7.7. Opener 탭으로 돌아가기

focus() API로 picture-in-picture 창에서 오프너 탭을 사용자 제스처로 포커스할 수 있습니다:

const returnToTabButton = pipWindow.document.createElement('button');
returnToTabButton.textContent = '오프너 탭으로 이동';
returnToTabButton.addEventListener('click', () => {
  window.focus();
});
pipWindow.document.body.append(returnToTabButton);

7.8. CSS picture-in-picture display mode 사용

아래 예시는 PiP 창에서 body 엘리먼트의 margin을 제거하고, 타이틀의 폰트 크기를 더 작게 하여 PiP 창의 컨텐츠에 더 잘 맞추는 방법을 보여줍니다:

@media all and (display-mode: picture-in-picture) {
  body {
    margin: 0;
  }
  h1 {
    font-size: 0.8em;
  }
}

7.9. Opener로 돌아가기 버튼 숨기기

대부분의 사용자 에이전트는 비디오 및 문서 picture-in-picture 창에서 오프너로 돌아가고 창을 닫는 버튼을 표시하는데, 모든 사이트의 문서 PiP UX에 이 버튼이 항상 적합하지는 않습니다. disallowReturnToOpener 옵션을 사용하여 버튼을 숨길 수 있습니다.

await documentPictureInPicture.requestWindow({
  disallowReturnToOpener: true
});

7.10. 초기 창 배치 우선

문서 picture-in-picture 창이 열려 있을 때 사용자가 직접 크기 조정/위치 옮기기를 할 수도 있습니다. 창을 닫았다가 나중에 다시 열면 사용자 에이전트는 이전 위치와 크기를 새로운 창의 배치 힌트로 사용할 수 있습니다.

사이트는 preferInitialWindowPlacement 값을 true로 지정하여 이전 위치/크기를 사용하지 않아야 한다는 힌트를 사용자 에이전트에게 줄 수 있습니다. 예를 들어 이전과 무관한 PiP 창을 요청할 때 이렇게 할 수 있으며, 이 경우 새 창은 기본 위치, 기본 크기나 사이트가 지정한 크기 힌트를 사용하게 됩니다.

await documentPictureInPicture.requestWindow({
  preferInitialWindowPlacement: true
});

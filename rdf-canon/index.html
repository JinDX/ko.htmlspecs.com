개요

RDF [RDF11-CONCEPTS]는 세계에 대한 주장을 표현하는 그래프 기반 데이터 모델을 설명하고, 그 정보 그래프에 대한 추론의 토대를 제공합니다. 때로는 그래프 집합 간 차이를 비교하거나 디지털 서명하거나 해시 알고리즘으로 그래프의 짧은 식별자를 생성해야 합니다. 이 문서는 이러한 작업을 가능하게 하는 RDF 데이터셋 정규화 알고리즘을 설명합니다.

1. 소개

이 절은 비규범적입니다.

데이터 과학자는 특정 목표를 달성하는 맥락에서 정규화를 논합니다. 같은 정보를 여러 방식으로 표현할 수 있으므로, 이를 하나의 표준 표현으로 변환해야 할 때가 많습니다. 표준 표현이 있으면 두 데이터 집합의 차이를 쉽게 판별하고, 특정 집합에 대해 암호학적으로 강한 해시 식별자를 생성하거나 나중에 검증할 디지털 서명을 할 수 있습니다.

구체적으로 이 명세는 그래프들의 집합인 RDF 데이터셋의 정규화를 다룹니다. 방향 그래프는 같은 정보를 여러 방식으로 표현할 수 있으므로, 앞서 언급한 목표와 그 밖에 우연히 발견될 수 있는 목적을 달성하려면 정규화가 필요합니다.

알고리즘의 시간 복잡도 측면에서 대부분의 RDF 데이터셋 은 상당히 빠르게 정규화할 수 있습니다. 하지만 전역적으로 고유한 식별자가 없는 노드를 포함하면 더 어렵습니다. 이런 데이터셋의 정규화에는 그래프 동형 문제가 나타나며, 최악의 경우 빠르게 풀기 어렵다고 여겨집니다. 다행히 현실의 기존 데이터가 최악의 경우가 되는 일은 거의 없으며, 새 데이터도 이를 피하도록 모델링할 수 있습니다. 문제가 있는 데이터셋( 7.1 데이터셋 오염참조)을 탐지한 소프트웨어는 실제 입력이 아닌 서비스 거부 공격 시도로 간주하여 중단할 수 있습니다.

이 문서는 RDF 데이터셋 의 정규 직렬화 형식을 입력 RDF 데이터셋 으로부터 생성하는 알고리즘을 설명합니다. 이를 RDF 정규화 알고리즘 버전 1.0 또는 RDFC-1.0이라고 합니다.

참고

RDF 1.1 개념과 추상 구문 [RDF11-CONCEPTS]는 언어 태그가 있는 문자열의 표현을 명확히 하지 않습니다. 언어 태그 의 xx-YY 형태는 대소문자를 구별하지 않습니다. 구현은 모두 소문자인 xx-yy를 쓰거나 원래 형태 xx-YY를 유지하거나 [BCP47] 표기 관례를 따를 수 있어, 서로 다른 정규 형식과 해시값을 만들 수 있습니다.

  • 정규화 알고리즘은 언어 태그 xx-YY 의 대소문자를 구별하지 않는 RDF 1.1 정의에 기반합니다. 사용자가 이 문제를 인식하지 못하면 서로 다른 정규화 결과를 얻을 수 있습니다.
  • 사용자 공동체는 소문자 언어 태그를 쓰기로 합의하는 것이 좋으며, 일부 구현이 언어 태그를 정규화하여 해시값에 영향을 줄 수 있음에 유의해야 합니다.
  • 향후 RDF의 발전으로 이 문제가 규정되면 RDF 환경이 이에 맞춰야 할 수 있으며, RDFC-1.0의 갱신으로 이어질 수도 있습니다.

1.1 데이터셋 정규화의 용도

그래프나 데이터셋 정규화가 중요한 여러 사용 사례가 있습니다:

  • 한 직렬화가 다른 직렬화와 동형인지 판별하기.
  • 직렬화나 형식과 무관하게 그래프(데이터셋)에 디지털 서명하기.
  • 두 그래프(데이터셋)를 비교하여 차이 찾기.
  • RDF 소스를 원격 갱신할 때 변경 집합 전달하기.

이러한 사용 사례의 상당수에는 정규화 알고리즘이 필요하지만 그것만으로 충분하지는 않을 수 있습니다. RDF 그래프와 데이터셋에서 빈 노드 를 사용해 온 역사는 길며, 이로 인해 불가피한 복잡성이 생깁니다. 빈 노드는 여러 목적으로 사용됩니다:

  • 노드의 잘 알려진 식별자를 모르거나 문서 작성자가 그 노드에 모호하지 않은 이름을 붙이지 않기로 한 경우,
  • 노드가 그래프의 여러 부분을 연결하는 데 쓰이고 노드 자체는 관심 대상이 아닌 경우(예: RDF 컬렉션 , [RDF11-MT]),
  • 누군가 의도적으로 어려운 그래프 위상을 만들려는 경우.

또한 RDF 의미론에 따르면 RDF 문서를 역직렬화하면 고유한 빈 노드가 생성됩니다. 다만 매번 해당 빈 노드 가 같은 자원을 식별한다고 판단할 수 있으면 예외입니다. 빈 노드 식별자 는 구체적인 RDF 구문의 일부이며 영속성이나 이식성을 의도하지 않기 때문입니다. 추상 RDF 모델에서 빈 노드는 식별자가 없습니다(일부 RDF 저장소 구현은 안정적이고 이식 가능한 식별자를 사용할 수 있습니다). 자세한 내용은 빈 노드 ([RDF11-CONCEPTS])를 참조하세요.

RDF 는 스콜렘 IRI를 통해 빈 노드를 외부에서 식별할 수 있게 발행하도록 허용합니다. 특정 RDF 저장소는 구체 구문에서 빈 노드를 IRI로 대체하여 그 저장소 안에서 같은 노드를 반복해서 식별할 수 있습니다. 하지만 다른 RDF 저장소나 다른 구체 표현에서 같은 그래프를 다루는 데에는 일반적으로 유용하지 않습니다. 어느 경우든 한 저장소나 직렬화에 정의된 안정적인 빈 노드 식별자 는 임의의 것이며 보통 사용 맥락과 연결할 수 없습니다.

이 명세는 같은 RDF 그래프(데이터셋)의 서로 다른 직렬화에 대해 안정적인 빈 노드 식별자 를 반복 생성하는 알고리즘을 정의합니다. 각 직렬화가 개별적인 빈 노드 식별자 를 사용해도, 각 빈 노드 를 연결된 노드에 근거하여 식별합니다. 따라서 결과 정규화된 데이터셋의 정규 직렬화를 해시하여 그래프 서명을 얻고 동형 판별과 디지털 서명에 이용할 수 있습니다. 이 명세는 그러한 그래프 서명 자체를 정의하지 않습니다.

그래프(데이터셋)의 다른 부분이 바뀌어도 빈 노드 식별자는 안정적일 수 있으므로, 때로는 두 그래프의 차이를 계산할 수 있습니다. 예를 들어 빈 노드가 없는 트리플만 바꾸거나 기존 빈 노드와 자기동형으로 혼동되지 않는 새 빈 노드를 추가하는 경우입니다. 생성되는 식별자를 바꾸는 정보가 있다면 차이 결과가 실제보다 더 많은 변경을 나타낼 수 있습니다. 또한 원래 데이터셋이 N-Quads 문서라면 원래 식별자와 정규화된 데이터셋에서 발급한 식별자를 연결할 수 있습니다.

참고

이 명세에서 다른 해시 알고리즘 을 사용할 수 있지만, 애플리케이션은 대체 해시 함수의 장단점을 신중히 따져야 합니다. 특히 관련 알고리즘을 명시하지 않는 정규 N-Quads 형식 이나 발급된 식별자 맵 의 표현에서 중요합니다. 같은 출력을 재현해야 하는 사용 사례에서는 정규 N-Quads 형식을 생성할 때 쓴 내부 해시 알고리즘을 명확히 표현하거나 전달할 것으로 기대됩니다.

  • RDF 데이터셋 정규화 알고리즘을 구현하려는 소프트웨어 개발자.

2. 적합성

비규범적으로 표시된 절뿐 아니라 모든 작성 지침, 도표, 예제와 참고도 비규범적입니다. 나머지 내용은 모두 규범적입니다.

이 문서의 키워드 MUST, MUST NOT, SHOULD 는 여기에 표시된 것처럼 모두 대문자인 경우에만 BCP 14 [RFC2119] [RFC8174]에 따라 해석합니다.

적합한 처리기는 이 명세의 알고리즘에 따라 정규 N-Quads 형식 을 입력 데이터셋 으로부터 생성할 수 있는 시스템입니다.

이 명세의 알고리즘은 규범적입니다. 같은 정규 식별자를 일관되게 재현하려면 구현은 명시된 단계를 엄격히 따라야 합니다( MUST ).

참고

구현 자는 RDF 데이터셋 정규화 테스트 모음을 통과하여 적합성을 부분적으로 확인할 수 있습니다. 그러나 모든 테스트를 통과해도 완전한 적합성을 뜻하지 않으며, 테스트에서 확인하는 측면에 대한 적합성만 뜻합니다.

3. 용어

3.1 이 명세에서 정의하는 용어

정규 N-Quads 형식
쿼드의 정규 표현은 A. N-Quads의 정규 형식에 정의됩니다. 정규 N-Quads 형식 의 쿼드는 그래프 이름이 있으면 주어와 같은 방식으로 표현하며, 각 쿼드는 하나의 LF (줄 바꿈, 코드 포인트 U+000A)로 끝납니다.
정규화 함수
정규화 함수 는 RDF 데이터셋 을 동형 데이터셋 [RDF11-CONCEPTS]으로 매핑합니다. 두 데이터셋은 동형일 때, 그리고 그때만 같은 정규 결과를 만듭니다. RDFC-1.0 은 정규화 함수를 구현합니다. 합리적인 시간 안에 종료하지 못하게 구성된 데이터셋( 7.1 데이터셋 오염참조) 의 경 우에는 부분 정규화 함수로 볼 수 있습니다.
정규화된 데이터셋
정규화된 데이터셋 은 다음의 조합입니다:
  • RDF 데이터셋 , 즉 입력 데이터셋,
  • 입력 빈 노드 식별자 맵 . 입력 데이터셋의 빈 노드 를 빈 노드 식별자로 매핑하는 것, 그리고
  • 발급된 식별자 맵 . 정규 발급기 가 제공하며 입력 데이터셋의 식별자를 정규 식별자로 매핑하는 것
정규화된 데이터셋 의 구체적인 직렬화는MUST 요구 사항으로 모든 빈 노드 를 정규 빈 노드 식별자로 표시해야 합니다.
전파 경로
빈 노드에서 시작하는 각 연관 언급 의 특정 나열입니다. 전이적으로 관련된 언급 을 재귀적으로 포함하다가 이름 있는 노드 또는 특정 식별자 발급기 가 이미 표시한 빈 노드에 도달하면 멈춥니다. 전파 경로는 RDFC-1.0 에서 문자열로 인코딩하고 처리합니다. (구성 방법은 4.8 N차 쿼드 해시 참조 .)
해시
메시지 다이제스트의 소문자 16진수 표현.
해시 알고리즘
기본 해시 알고리즘은 RDFC-1.0에서 사용하는 SHA-256 [FIPS-180-4].

구현은 MUST 요구 사항으로 해시 알고리즘을 정하는 매개변수를 지원하고, MUST 요구 사항으로 SHA-256과 SHA-384 [FIPS-180-4]를 지원해야 합니다. 다른 해시 알고리즘을 지정하는 기능도 지원하는 것이 SHOULD (권고)입니다. 다른 알고리즘은 일반적으로 기본 알고리즘과 다른 출력을 만듭니다.

참고

정규 N-Quads 결과의 해시 다이제스트를 만드는 애플리케이션도 기본 해시 알고리즘을 쓸 것으로 기대하지는 않습니다.

식별자 발급기
식별자 발급기는 새로운 빈 노드 식별자를 발급하며 빈 노드 식별자 발급기 상태를 유지합니다.
입력 빈 노드 식별자 맵
입력 데이터셋에 이미 할당된 빈 노드 식별자를 기록합니다. 입력 데이터셋 이 N-Quads 문서이면 이 맵 은 추상 입력 데이터셋 의 빈 노드를 문서의 식별자와 연결합니다. 그렇지 않으면 아직 식별되지 않은 각 빈 노드에 임의의 식별자를 할당합니다.
참고
구현이나 환경은 파싱된 또는 추상 데이터셋에 식별자를 보존하는 등 이를 더 직접적으로 다룰 수 있습니다. 알고리즘 밖에서도 입력과 출력 식별자 간의 유용한 매핑을 얻도록 구현은 이를 재사용할 것으로 기대됩니다.
입력 데이터셋
알고리즘의 입력으로 제공되는 추상 RDF 데이터셋 .
언급
노드가 쿼드 의 구성 요소, 즉 주어, 술어, 목적어또는 그래프 이름이면 그 쿼드가 노드를 언급한다고 합니다.
언급 집합
쿼드 중 데이터셋 안에서 언급 하는 대상이 노드 n 인 모든 쿼드의 집합을 언급 집합 ( n의 것)이라 하며 Qn으로 표기합니다.
쿼드
주어, 술어, 목적어와 그래프 이름으로 구성된 튜플입니다. RDF 트리플 에 그래프 이름을 더한 일반화입니다.

4. 정규화

정규화는 입력 데이터셋 을 직렬화된 정규 형식으로 변환하는 과정입니다. 같은 정보를 포함한 두 입력 데이터셋 은 배열 방식과 무관하게 같은 직렬화된 정규 형식으로 바뀝니다. 방향 그래프를 노드와 간선의 집합으로 결정적으로 정렬해야 합니다. 모든 노드에 전역적으로 고유한 식별자가 있으면 쉽지만 그렇지 않으면 어려울 수 있습니다. 고유 식별자가 없는 노드에는 결정적 식별자를 발급해야 합니다.

참고

이 명세의 정규화된 데이터셋 은 빈 노드의 안정적인 식별자를 포함하며, 실제 사용 시 항상 그 정규 직렬화를 생성합니다.

향후 여러 정규화 알고리즘이 존재할 수 있으므로 식별을 위해 “RDF 정규화 알고리즘 버전 1.0”(RDFC-1.0)이라고 합니다.

그림 1 은 RDFC-1.0의 개요를 보여 주며, 1~7단계는 4.4.3 알고리즘의 각 단계에 대응합니다.

4.1 개요

이 절은 비규범적입니다.

정규 라벨을 결정하기 위해 RDFC-1.0 은 각 빈 노드에 연결된 정보를 살핍니다. 1차 정보가 고유하면 식별자 발급 알고리즘으로 즉시 정규 식별자를 발급할 수 있습니다. 고유하지 않으면 데이터셋 전체에서 전이적으로 연결된 모든 정보를 구해야 합니다. 4.6 1차 쿼드 해시 는 1차 해시를 통해 노드의 1차 정보를 정의합니다.

각 빈 노드의 정보에서 해시를 계산하여 연관 언급 을 인코딩합니다. 해시 (문자열 s의 것)는 s 를 암호학적 해시 함수에 넣은 결과의 소문자 16진수 표현입니다. RDFC-1.0 은 기본적으로 SHA-256 [FIPS-180-4]를 사용합니다.

참고

이 명세에서 “차수”는 데이터셋의 두 노드에 대한 이심도 이나 반지름 을 일상적으로 설명하는 용어입니다. “여섯 단계 분리”처럼 분리 단계와도 관련됩니다. 1차 정보가 고유한 노드는 반지름이 1인 노드로 볼 수 있습니다.

4.2 정규화 상태

정규화 알고리즘을 실행할 때 정규화 상태라는 자료 구조로 상태를 추적하면 편리합니다. 정규화 상태 에 포함되는 정보는 다음과 같습니다.

빈 노드-쿼드 맵
맵 으로, 빈 노드 식별자 를 그 식별자가 나타나는 쿼드 ( 입력 데이터셋안의 것)와 연결합니다.
해시-빈 노드 맵
맵 으로, 해시 를 리스트 ( 빈 노드 식별자의 목록)와 연결합니다.
정규 발급기
식별자 발급기를 접두사 c14n (canonicalization의 약자)으로 초기화하여 정규 빈 노드 식별자를 발급합니다.
참고
모든 빈 노드 에 이 규칙을 적용하면, RDF 데이터셋 이 서로 다른 두 RDF 그래프 로 구성될 때 각 그래프를 독립적으로 처리한 경우와 다른 식별자가 나옵니다. 자기동형이나 겹치는 진술로도 이런 일이 생길 수 있지만, 결과 해시 와 그 해시 에 고유한 발급 순번으로 식별자를 만들면 작은 변경에도 유지될 가능성이 높아져 RDF 차이 비교에 유용합니다.

4.3 빈 노드 식별자 발급기 상태

정규화 알고리즘은 빈 노드에 식별자를 발급합니다. 식별자 발급 알고리즘 은 식별자 발급기 를 사용합니다. 식별자 발급기 가 추적할 정보는 다음과 같습니다.

식별자 접두사
식별자 접두사는 빈 노드 식별자앞에 쓰는 문자열이며 정규화 알고리즘이 지정한 문자열로 초기화해야 합니다. 새 빈 노드 식별자를 만들 때 접두사와 식별자 카운터를 이어 붙입니다. 예를 들어 c14n 은 적절한 식별자 접두사 초깃값이며 빈 노드 식별자 로 c14n1등을 만듭니다.
식별자 카운터
식별자 접두사 뒤에 붙여 빈 노드 식별자를 만드는 카운터이며 0으로 초기화합니다.
발급된 식별자 맵
순서 있는 맵 으로, 빈 노드 식별자 를 발급된 식별자와 연결하여 같은 기존 식별자에 여러 새 식별자가 발급되는 것을 막습니다. 발급 이후에 빈 노드 에 식별자를 할당할 수도 있게 합니다.

4.4 정규화 알고리즘

정규화 알고리즘은 입력 데이터셋 을 정규화된 데이터셋 으로 변환하며, 너무 복잡하다고 판단하면 오류를 발생시킵니다. 모든 빈 노드 ( 입력 데이터셋안의 것)에 결정적 식별자를 할당합니다.

4.4.1 개요

이 절은 비규범적입니다.

RDFC-1.0 은 RDF 데이터셋 의 각 빈 노드 에 정규 식별자를 할당하여 정규 라벨을 붙입니다. RDFC-1.0에서 데이터셋 D 는 쿼드 < s, p, o, g > 의 집합입니다. 그래프 성분 g 가 비는 것은 트리플 < s, p, o > 가 기본 그래프에 있을 때뿐입니다. 두 데이터셋에 대해 RDFC-1.0 은 두 집합이 동형(빈 노드 식별자를 제외하면 같음)일 때, 그리고 그때만 같은 정규 라벨 쿼드 목록을 반환할 것으로 기대됩니다.

RDFC-1.0 은 여러 하위 알고리즘으로 이루어지며 다음 절에서 설명합니다. 먼저 RDFC-1.0의 전체 개요를 제시합니다.

  1. 초기화. 4.2 정규화 상태에 따라 필요한 상태를 초기화합니다. 정규화된 데이터셋 도 입력 데이터셋 (불 변)과 입력 빈 노드 식별자 맵 (가능하면 입력 식별자를 유지하고 아니면 임의로 할당)으로 초기화합니다. 발급된 식별자 맵 은 알고리즘이 끝날 때 정규 발급기 에서 추가합니다.
  2. 1차 해시 계산. 4.6 1차 쿼드 해시로 각 빈 노드의 1차 해시를 계산합니다.
  3. 고유 노드에 정규 라벨 부여. 4.5 식별자 발급 알고리즘으 로 유니코드 코드 포인트 순서에 따라 1차 해시가 고유한 각 빈 노드에 정규 식별자를 할당합니다.
  4. 고유하지 않은 노드의 N차 해시 계산. 중복 1차 해시를 유니코드 코드 포인트 순서로 처리하며 4.8 N차 쿼드 해시 로 대응하는 미표시 빈 노드 각각의 N차 해시를 계산합니다.
  5. 나머지 노드에 정규 라벨 부여. N차 해시의 유니코드 코드 포인트 순서 로 4.5 식별자 발급 알고리즘을 사용해 대응 노드에 정규 식별자를 발급합니다. 같은 N차 해시를 만드는 노드가 여러 개면 발급 순서는 중요하지 않습니다.
  6. 완료. 직렬화된 정규 형식 ( 정규화된 데이터셋의 것)을 반환합니다. 또는 정규화된 데이터셋 을 입력 빈 노드 식별자 맵 과 발급된 식별자 맵을 포함해 반환합니다.

일반 적인 입력 데이터셋에서는 각 단계의 반복 횟수가 최소한입니다. 극단적인 경우, 특히 5단계에서 성능이 나빠질 수 있습니다. 구현은 MUST 요구 사항으로 적절한 예외를 발생시키고 조기에 종료하여 서비스 거부 공격을 방어해야 합니다. 7.1 데이터셋 오염 을 참조하세요.

참고

구현 은 4.8 N차 쿼드 해시 의 호출 횟수를 해시-빈 노드 맵의 노드 수에 따라 제한할 수 있습니다. 일반적인 데이터셋에서는 노드마다 4.8 N차 쿼드 해시 를 몇 회 이상 반복하는 일이 드뭅니다.

  1. 정규화 상태를 만듭니다. 입력 데이터셋 이 N-Quads 문서이면 이를 파싱하여 정규화된 데이터셋안의 데이터셋으로 만들고, 문서에서 사용한 빈 노드 식별자를 입력 빈 노드 식별자 맵에 보존합니다. 아니면 각 빈 노드에 임의의 식별자를 할당합니다.
    설명

    빈 노드-쿼드 맵과 해시-빈 노드 맵을 초기화하고 새 정규 발급기를 만듭니다.

    완료 후 입력 빈 노드 식별자 맵 과 정규 발급기 로 입력 데이터셋 의 노드를 원래 식별자와 정규 식별자 모두에 연결할 수 있습니다.

  2. 각 쿼드 Q ( 입력 데이터셋안의 것)에 대해:
    1. 각 빈 노드 가 Q의 성분이면, Q 로의 참조를 맵 항목 ( 빈 노드 식별자 identifier 에 대응하는 빈 노드-쿼드 맵의 항목)에서 추가합니다. 필요하면 새 항목을 만들고, 노드의 식별자는 입력 빈 노드 식별자 맵에서 찾은 것을 사용합니다.
      설명

      빈 노드-쿼드 맵을 만들며, 입력 노드와 할당 식별자의 매핑을 통해 각 빈 노드 를 그 노드를 포함하는 쿼드 집합에 연결합니다.

      참고

      리터럴 성분은 쿼드 안에서 정규화하지 않습니다. 3.3절 ([RDF11-CONCEPTS])에 따르면 리터럴 항의 동등성 은 어휘 형식에 기반하며 리터럴 값에 기반하지 않습니다. 따라서 "01"^^xsd:integer 와 "1"^^xsd:integer 는 다른 자원입니다.

    설명

    3. 맵 항목 ( hash 에 대응)을 해시-빈 노드 맵에서 제거합니다.

    1. hash path list 를 만듭니다. 각 항목은 N차 쿼드 해시 알고리즘의 실행 결과가 됩니다.
      설명

      1. n에 정규 식별자를 이미 발급했다면 다음 빈 노드 식별자로 넘어갑니다.
      2. temporary issuer를 식별자 발급기 로 만들고 접두사 b로 초기화합니다.
      3. 식별자 발급 알고리즘에 temporary issuer 와 n을 전달하여 새 임시 빈 노드 식별자 bn 을 n에 발급합니다.

        로그 기록

      설명

      앞 단계에서 같은 1차 해시를 공유하는 노드에 만든 임시 식별자를 사용해 정규 식별자를 생성합니다.

      1. 각 빈 노드 식별자 existing identifier에 대해 identifier issuer ( result안의 것)가 임시 식별자를 발급한 순서대로 정규 식별자를 발급합니다. 식별자 발급 알고리즘에 정규 발급기 와 existing identifier를 전달합니다.
        설명

      로그 기록

4.5 식별자 발급 알고리즘

이 알고리즘은 새 빈 노드 식별자 를 기존 빈 노드 식별자에 대해 발급하고, 새 빈 노드 식별자 의 발급 순서를 추적하는 상태도 갱신합니다. 다른 노드와 동형인 빈 노드에 정규 라벨을 붙일 때 발급 순서가 중요합니다.

4.5.1 개요

발급된 식별자 맵 으로 기존 빈 노드 식별자 ( 입력 데이터셋 의 것)를 새 빈 노드 식별자 에 연결합니다. 주어진 식별자 접두사 (c14n)에 증가하는 번호를 붙여 발급합니다. 예를 들어 e3에 대해 c14n1을 발급할 수 있습니다.

4.5.2 알고리즘

입력은 식별자 발급기 I 와 existing identifier 이며 출력은 새 issued identifier입니다. 단계는 다음과 같습니다:

  1. 맵 항목 이 existing identifier 에 대응하여 발급된 식별자 맵 ( I의 것)에 있으면 반환합니다.
  2. issued identifier 를 식별자 접두사 와 식별자 카운터의 문자열 값을 이어 붙여 생성합니다.
  3. 항목 을 existing identifier 에서 issued identifier 로의 매핑으로 발급된 식별자 맵 ( I의 것)에 추가합니다.
  4. 식별자 카운터를 증가시킵니다.
  5. issued identifier를 반환합니다.

4.6 1차 쿼드 해시

해시 를 주어진 빈 노드 에 대해 그 노드를 포함하는 쿼드 ( 데이터셋 안의 것)로부터 계산합니다. 고유하게 식별되면 추가 검사가 필요 없습니다. 아니면 4.8 N차 쿼드 해시 를 4.4 정규화 알고리즘에서 호출하여 계산합니다.

4.6.1 개요

이 절은 비규범적입니다.

노드 n 의 1차 정보가 고유한지 판단하려고 해시 를 언급 집합 Qn에 할당합니다. 빈 노드 n의 1차 해시 hf(n)는 4.6 1차 쿼드 해시 에 n을 전달한 결과입니다. 고유한 1차 해시는 고유한 1차 정보를 뜻합니다.

일관성을 위해 빈 노드 식별자 ( Qn 안의 것)는 쿼드의 정규 N-Quads 직렬화에서 자리표시자로 대체합니다. 각 성분은 a 또는 z로 바꾸며, 해당 성분이 n 인지에 따라 결정합니다.

직렬화한 쿼드를 코드 포인트 순서로 정렬하고 이어 붙여 해시합니다. 이것이 n의 1차 해시 hf(n)입니다.

4.6.2 예제

이 절은 비규범적입니다.

예제 4: 고유 해시

이 예제는 빈 노드를 포함한 쿼드의 해시를 보여 줍니다. 해당 노드에 대한 언급 을 포함한 진술을 해시하면 고유한 결과가 나옵니다.

:p :q _:e0 .
:p :r _:e1 .
_:e0 :s :u .
_:e1 :t :u .

각 빈 노드(e0 와 e1)마다 한 번씩, 총 두 번 호출합니다. 참조 노드 e0 으로 실행하면 빈 노드를 대체한 뒤 다음 쿼드가 나옵니다:

:p :q _:a .
_:a :s :u .

그다음 이를 직렬화한 정규 N-Quads 형식: '<http://example.com/#p> <http://example.com/#q> _:a .\n_:a <http://example.com/#s> <http://example.com/#u> .\n', 을 이어 붙이고 해시 알고리즘 (SHA-256)으로 해시하면 결과는 21d1dd5ba21f3dee9d76c0c00c260fa6f5d5d65315099e553026f4828d0dc77a입니다.

참조 노드 e1 으로 두 번째 실행하여 다음 쿼드를 얻습니다:

:p :r _:a .
_:a :t :u .

그다음 이를 직렬화한 정규 N-Quads 형식: '<http://example.com/#p> <http://example.com/#r> _:a .\n_:a <http://example.com/#t> <http://example.com/#u> .\n', 을 앞과 같이 이어 붙여 해시하면 결과는 6fa0b9bdb376852b5743ff39ca4cbf7ea14d34966b2828478fbf222e7c764473입니다.

각 해시는 하나의 빈 노드만 가리키므로 정규화 알고리즘은 1차 쿼드 해시 알고리즘만 사용하면 됩니다.

예제 5: 공유 해시

이 예제는 빈 노드를 포함한 쿼드의 해시를 보여 줍니다. 해당 노드에 대한 언급 을 포함한 진술을 해시하면 결과가 겹치는 경우입니다.

:p :q _:e0 .
:p :q _:e1 .
_:e0 :p _:e2 .
_:e1 :p _:e3 .
_:e2 :r _:e3 .

각 빈 노드(e0, e1, e2, e3)마다 한 번씩, 총 네 번 호출합니다. 참조 노드 e0 으로 실행하면 대체 후 다음 쿼드가 나옵니다:

:p :q _:a .
_:a :p _:z .

해시는 3b26142829b8887d011d779079a243bd61ab53c3990d550320a17b59ade6ba36입니다.

참조 노드 e1 도 같은 쿼드를 만들므로 해시도 같습니다.

참조 노드 e2 로 다음 쿼드를 얻습니다:

_:z :p _:a .
_:a :r _:z .

해시는 15973d39de079913dac841ac4fa8c4781c0febfba5e83e5c6e250869587f8659입니다.

마지막으로 참조 노드 e3 로 다음 쿼드를 얻습니다:

_:z :p _:a .
_:z :r _:a .

해시는 7e790a99273eed1dc57e43205d37ce232252c85b26ca4a6ff74ff3b5aea7bccd입니다.

e2 와 e3 의 해시는 고유하지만 e0와 e1 은 해시를 공유합니다. 고유한 해시를 구하려면 N차 쿼드 해시 알고리즘으로 직접적인 언급 보다 더 멀리 있는 쿼드를 살펴야 합니다.

4.6.3 알고리즘

입력은 정규화 상태 와 reference blank node identifier 입니다.

  1. nquads 를 빈 리스트로 초기화하여 정규 N-Quads 형식의 쿼드를 저장합니다.
  2. 리스트 ( 쿼드 의 목록)quads 를 맵 항목 ( reference blank node identifier 에 대응하는 빈 노드-쿼드 맵의 항목)에서 가져옵니다.
  3. 각 쿼드 quad ( quads안의 것)에 대해:
    1. quad 를 정규 N-Quads 형식 으로 직렬화하되 다음 특별 규칙을 적용합니다:
      1. quad 의 어느 성분이든 빈 노드이면 다음과 같이 특수 식별자를 사용하여 직렬화합니다:
        1. 빈 노드의 기존 빈 노드 식별자 가 reference blank node identifier 와 일치하면 빈 노드 식별자 a를 쓰고, 아니면 빈 노드 식별자 z를 씁니다.
  4. nquads 를 유니코드 코드 포인트 순서로 정렬합니다.
  5. 해시 를 반환합니다. 이는 정렬하고 이어 붙인 nquads 를 해시 알고리즘에 전달한 결과입니다.
    로그 기록

    이 알고리즘의 입력과 실행 결과를 기록합니다.

    # Inputs and hash result for the Hash First Degree Hash algorithm for unique hashes example
h1dq:
  log point: Hash First Degree Quads function (4.6.3).
  nquads:
    - <http://example.com/#p> <http://example.com/#q> _:a .
    - _:a <http://example.com/#s> <http://example.com/#u> .
  hash: 21d1dd5ba21f3dee9d76c0c00c260fa6f5d5d65315099e553026f4828d0dc77a

4.7 관련 빈 노드 해시

이 알고리즘은 해시 를 빈 노드 성분에 대해 쿼드안의 위치를 고려하여 생성합니다. N차 쿼드 해시 알고리즘 의 일부로서 언급 집합안에서 특정 빈 노드와 관련된 노드의 특징을 나타냅니다.

4.7.1 개요

이 절은 비규범적입니다.

identifier 는 빈 노드 related를 식별하며 이 노드는 쿼드의 성분입니다. 식별자와 위치 정보로 쿼드 안의 노드 표현을 만든 뒤 해시합니다. 먼저 다음에서 식별자를 찾습니다:

  1. 정규 발급기 ( 정규화 상태안의 것)의 발급된 식별자,
  2. issuer의 발급된 식별자, 또는
  3. N차 쿼드 해시 알고리즘 을 related에 적용한 결과.

4.7.2 예제

이 절은 비규범적입니다.

예제 6: 정규 식별자 할당됨

이 예제는 쿼드의 빈 노드 성분에 관련 해시를 생성합니다. 성분은 목적어 위치에 있고 정규 발급기가 이미 정규 식별자를 할당했습니다.

술어 :p와 related 가 가리키는빈 노드 e2 (정규 빈 노드 식별자 c14n0을 이미 할당)를 바탕으로 input 을 o<http://example.com/#p>_:c14n0로 만들며, 해시는 29cf7e22790bc2ed395b81b3933e5329fc7b25390486085cac31ce7252ca60fa입니다.

아직 식별자가 없으면 1차 쿼드 해시 알고리즘의 결과를 앞의 _:없이 사용합니다.

4.7.3 알고리즘

이 알고리즘은 해시 를 만들어 한 빈 노드 가 다른 노드와 어떻게 관련되는지 식별합니다. 입력은 정규화 상태, related 라는빈 노드 식별자, quad, 식별자 발급기 issuer및 문자열 position 입니다.

  1. 문자열 input 을 position값으로 초기화합니다.
  2. position 이 g가 아니면 <, 술어 의 값( quad안의 것), > 를 차례로 input에 추가합니다.
  3. related에 정규 식별자 또는 issuer가 발급한 식별자가 있으면, 문자열 _:뒤에 해당 식별자를 붙여(정규 식별자가 있으면 그것을, 없으면 issuer가 발급한 것을 사용하여) input에 추가합니다.
    설명

    related에 정규 식별자가 이미 발급되었다면 정규 발급기 ( 정규화 상태안의 것)에 있습니다. 아니면 임시 issuer 가 related의 매핑을 가지고 있을 수 있습니다.

  4. 그렇지 않으면 1차 쿼드 해시 알고리즘에 related 를 전달한 결과를 input에 추가합니다.
    설명

    정규 식별자도 임시 식별자도 아직 발급되지 않았다면 1차 쿼드 해시 알고리즘으로 새 식별자를 만듭니다.

    1차 쿼드 해시 알고리즘 은 단계 3 ( 정규화 알고리즘안의 것)에서 이미 모든 노드에 호출되었습니다. 구현은 1차 쿼드 해시 알고리즘 을 다시 실행하기보다 기존 결과의 재사용을 고려해야 합니다.

  5. 해시 를 반환합니다. 이는 input 을 해시 알고리즘에 전달한 결과입니다.
    설명

    결과 문자열은 해시 생성에 사용합니다. 이는 1차 쿼드 해시 알고리즘 이 쿼드 의 직렬화를 nquads 에서 해시하는 것과 비슷합니다. 일관성을 위해 nquad 표현의 identifier 를 사용하므로 _: 문자열이 나타납니다.

    로그 기록

4.8 N차 쿼드 해시

이 알고리즘은 해시 를 주어진 빈 노드 에 대해, 그 노드를 포함하는 쿼드 ( 데이터셋 안의 것)의 해시로 고유하게 식별할 수 없는 경우 계산합니다. 직접 참조하는 쿼드( 언급 집합)에서 그 집합의 쿼드와 성분 노드를 공유하는 다른 쿼드로 탐색을 넓힙니다. 이를 전파 경로라고 합니다. 고유한 해시를 얻을 때까지 간접 차수를 높여 갑니다.

4.8.1 개요

이 절은 비규범적입니다.

보통 그래프의 두 노드가 동등한지는 식별자를 비교하면 됩니다. 식별자가 없다면 그래프 전체에서 동등한 노드에 동등한 방식으로 연결되어 있는지 판단해야 합니다. 이것이 그래프 동형 문제입니다. 이 알고리즘은 종이에 그래프를 그리는 방식을 생각하여 접근합니다. 첫 노드를 종이 중앙에 놓고 그린 다음, 두 번째 노드를 중앙에 놓아도 똑같은 그림을 그릴 수 있다면 두 노드는 동등합니다. 즉 특정 노드에서 시작하면 언제나 같은 방식으로 그리는 결정적 방법을 정의합니다. 서로 다른 두 노드에서 같은 그래프 그림이 나오면 노드는 동등합니다. 해시 는 특정 그리기 방식을 나타내며 노드를 비교하는 데 사용할 수 있습니다.

두 빈 노드의 1차 해시가 같으면 전체적인, 즉 N차 차이를 탐지하는 추가 단계가 필요합니다. 다른 빈 노드를 통해 전이적으로 연결되는 경우를 포함하여 빈 노드 n 에 어떤 방식으로든 연결된 모든 정보를 고려해야 합니다.

모든 전이적 정보를 고려하려고 알고리즘은 연관 언급 의 가능한 모든 경로를 탐색하고 인코딩합니다. n에서 시작하는 이 전파 경로는 n에 연결된 모든 미표시 빈 노드에 도달합니다. 각 노드에는 탐색 중인 경로에서 도달한 순서대로 임시 식별자를 할당합니다. 연결된 노드에 도달하려고 거친 언급은 관련 해시를 통해 경로에 인코딩합니다. 따라서 입력 식별자에 의존하지 않고 n 에서 모든 연결 노드에 도달하는 경로를 결정적으로 정렬할 수 있습니다.

이 알고리즘은 주 정규화 알고리즘과 협력하여 특정 빈 노드에 고유하고 결정적인 식별자를 만듭니다. 이 해시 는 연결된 모든 정보와 연결 방식을 포함합니다. 이를 위해 해당 노드에서 다른 인접 빈 노드를 지나는 결정적 경로를 만듭니다.

마지막으로 문자열 인코딩에 따른 최단 전파 경로 를 선택하고 미표시 노드에 경로의 등장 순서대로 정규 식별자를 할당합니다. 이 최단 인코딩 경로의 해시는 n의 N차 해시라고 하며 n 을 다른 빈 노드와 구별합니다.

명확히 하자면 전파 경로 를 문자열 s 로 인코딩한 것이 다음 조건을 만족할 때 최단으로 봅니다:

  1. s 의 길이가 다른 모든 전파 경로 문자열 s′의 길이보다 작거나 같다.
  2. s 와 s′ 의 문자열 길이가 같으면, s 는 코드 포인트 순서 에서 s′보다 작거나 같습니다.

예를 들어 abc 는 bbc보다 짧고, abcd 는 bcd보다 깁니다.

다음은 n 의 N차 해시를 가장 짧은 전파 경로를 따라 계산하는 방법의 개요입니다. 전체 알고리즘은 모든 전파 경로를 고려하고 최종적으로 인코딩된 최단 경로의 해시 를 반환합니다.

  1. 관련 해시 계산. 관련 해시 집합 Hn 을 n에 대해 계산합니다. 즉 모든 1차 언급 ( n 과 다른 빈 노드 사이의 것)입니다. 라벨이 없는 노드와 이미 정규 식별자가 발급된 라벨 있는 노드를 모두 포함합니다.
  2. 언급 탐색. 관련 해시 x ( Hn안의 것)가 주어지면 x 를 해시할 데이터 Dn에 기록합니다. 각 빈 노드에 대해 언급 (관련 해시가 x 인 것)을 통해 도달할 수 있다면 이미 식별자를 받았는지 확인합니다.
    1. 라벨 있는 노드의 식별자 기록. 빈 노드에 식별자가 있으면 Dn 에 기록합니다. 각 언급 의 관련 해시가 x일 때마다 한 번 기록합니다. Hn 의 다음 관련 해시로 넘어가 2단계를 반복합니다.
    2. 라벨 없는 노드에 임시 식별자를 할당하고 기록. 전파 경로에서 도달한 순서대로 각 노드에 임시 식별자를 할당하고 Dn 에 중복을 포함하여 기록합니다. 같은 순서로 각 노드를 재귀 목록 Rn(x) 에 추가하되 중복은 생략합니다.
    3. 새로 라벨을 붙인 노드에 대해 재귀. 각 ni ( Rn(x) 안의 것)에 대해
      1. 식별자를 Dn에 기록합니다
      2. < r(i) > 를 Dn 에 추가합니다. r(i) 는 1단계로 돌아가 n 을 ni로 대체해 얻은 해시 대상 데이터입니다.
  3. n의 N차 해시 계산. Dn 을 해시하여 N차 해시( n의 것), 즉 hN(n)을 반환합니다. 갱신된 발급기 In 도 반환하며, 이는 n에 연결된 모든 미표시 빈 노드에 임시 식별자를 할당한 상태입니다.

앞의 2.3단계처럼 HN 은 탐색 중인 전파 경로 에서 처음 도달한 각 미표시 빈 노드에 재귀합니다. 이는 경로를 따라 n 에서 임시 식별자를 받는 노드 ni 로 이동하는 것으로 볼 수 있습니다. ni에 재귀하는 동안 다른 미표시 노드 nj 를 발견하면 다시 재귀합니다. 이 재귀는 전파 경로 , 즉 n 에서 nj 로 가며 ni를 지나는 경로를 따릅니다.

재귀 해시 r(i) 는 반환된 해시 로, 노드 ni 의 재귀를 hN(n)계산 중 완료한 결과입니다. hN(n) 이 Dn의 해시이듯, ni 에 대한 재귀의 해시 대상 데이터를 Di로 표기합니다. 따라서 r(i) = h(Di)입니다. 각 관련 해시 x ∈ Hn에 대해 Rn(x) 를 알고리즘이 재귀하는 재귀 목록 이라고 합니다.

5. 직렬화

이 절에서는 직렬화된 [N-Quads] 표현을 정규화된 데이터셋에서 생성하는 과정을 설명합니다.

직렬화된 정규 형식 ( 정규화된 데이터셋 의 것)은 N-Quads 문서 [N-QUADS] 입니다. 각 쿼드 를 정규화된 데이터셋 에서 가져와 정규 N-Quads 형식으로 표현하고 코드 포인트 순서로 정렬한 다음 연결하여 만듭니다. (각 정규 N-Quads 문장은 줄바꿈으로 끝나므로 연결할 때 추가 구분자가 필요하지 않습니다.) 결과 문서의 미디어 유형은 application/n-quads이며 , C. N-Quads 인터넷 미디어 유형, 파일 확장자 및 Macintosh 파일 유형 ([N-QUADS])에 설명되어 있습니다.

정규 N-Quads 형식으로 쿼드를 직렬화할 때 빈 노드 인 구성 요소는MUST 요구 사항에 따라 반드시 대응하는 정규 라벨을 사용하여 직렬화해야 합니다. 각 빈 노드 의 라벨은 발급된 식별자 맵 ( 정규화된 데이터셋의 구성 요소)에서 얻습니다.

6. 개인정보 보호 고려 사항

이 절은 비규범적입니다.

정규화 알고리즘의 특성상 출력인 정규 라벨과 쿼드 정렬 순서는 입력 데이터셋과 본질적으로 연관됩니다. 특히 개인정보가 포함된 데이터셋에서는 문제가 될 수 있습니다. 예를 들어 개인정보 보호를 위해 정규화된 데이터셋 에서 일부 정보를 제거해도 제삼자가 이를 분석하여 생략된 데이터를 추론할 가능성이 있습니다. 입력과 출력의 연관성을 제거해야 한다면 정규화 출력에 적절한 후처리를 수행해야 합니다. 이 명세는 추가 처리를 쉽게 하도록 설계되었지만 구체적인 세부사항은 이 명세를 기반으로 하는 다른 명세에서 제공할 책임이 있습니다. 이러한 후처리는 선택적 공개 ( 검증 가능한 자격 증명 데이터 무결성 1.0 [VC-DATA-INTEGRITY])를 참고하십시오.

7. 보안 고려 사항

이 절은 비규범적입니다.

7.1 데이터셋 오염

이 절은 비규범적입니다.

정규화 알고리즘은 각 빈 노드가 고유 정규 식별자를 올바르게 받도록 연결된 정보의 모든 차이를 검사합니다. 공격자는 이를 악용하여 정규화에 많은 계산 시간이 들지만 유용한 정보를 표현하지 않거나 불필요하게 복잡하게 표현하는 데이터셋을 만들 수 있습니다. 알고리즘 구현자는 문제가 있는 입력의 정규화를 기본적으로 중단하는 완화책을 추가할 것으로 기대됩니다.

권장 완화책은 다음을 포함하되 이에 한정되지 않습니다.

  • 설정 가능한 시간 제한을 제공하고 구현의 일반적인 용도에 맞는 기본값을 두는 것
  • 알고리즘 단계, 특히 재귀 단계와 긴 목록의 순열에 대한 반복 횟수 상한을 설정할 수 있게 하는 것

또한 알고리즘 구현을 사용하는 소프트웨어는 스키마 검증 모범 사례를 적용하여 애플리케이션 요구 사항에 맞지 않는 데이터를 거부하고 쓸모없는 오염 데이터셋의 처리를 막을 수 있습니다. 그러나 이러한 완화책은 애플리케이션별로 다르므로 정규화 알고리즘 자체의 구현자에게 직접 적용되지는 않습니다.

7.2 안전하지 않은 해시 알고리즘

이 절은 비규범적입니다.

기본 해시 알고리즘 ( RDFC-1.0 에서 사용)이 미래의 어느 시점에 안전하지 않게 될 수 있습니다. 이를 완화하기 위해 알고리즘과 구현은 매개변수로 다른 해시 함수를 사용할 수 있으며 정규화 알고리즘 자체를 변경할 필요는 없습니다. 그러나 다른 해시 알고리즘을 사용하면 일반적으로 결과도 달라집니다. 이 명세를 사용하는 애플리케이션은 대체 해시 함수의 장단점을 신중하게 따져야 합니다.

참고

내부 해시값을 공개하지 않고 정규화 알고리즘이 1차 해시 충돌에 대응하도록 설계되어 있으므로 기본 해시 알고리즘이 안전하지 않게 될 때의 잠재적 영향이 완화됩니다.

A. N-Quads의 정규 형식

이 절은 배치 형식을 완전히 지정한 N-Quads 정규 형식을 정의합니다. 언어 문법은 바뀌지 않습니다.

정규 N-Quads는 정규 N-Triples ([N-TRIPLES])를 갱신하고 확장하여 graphLabel을 포함합니다.

N-Quads 구문 [N-QUADS]은 RDF 데이터의 표현과 배치를 선택할 수 있게 하지만, 정규 형식은 각 쿼드에 고유한 구문 표현을 제공합니다. 해당 생성 규칙이 표현 선택을 허용하는 경우 각 코드 포인트는 UCHAR, ECHAR또는 인코딩하지 않은 문자 중 하나로만 표현합니다. 각 쿼드는 지정된 공백과 함께 한 줄에 완전히 표현합니다.

정규 N-Quads는 배치에 다음 추가 제약을 둡니다:

  • 공백은 MUST NOT 요구 사항에 따라 subject, predicate, object및 graphLabel뒤를 제외하고는 사용하면 안 됩니다. 각 위치의 공백은 MUST 요구 사항으로 하나의 공백 문자(코드 포인트 U+0020)여야 합니다.
  • 리터럴 의 데이터 유형이 http://www.w3.org/2001/XMLSchema#string 이면MUST NOT 요구 사항에 따라 데이터 유형 IRI 부분을 리터럴에 사용하지 않고 STRING_LITERAL_QUOTE만으로 표현합니다.
  • HEX 는MUST 요구 사항으로 숫자([0-9])와 대문자([A-F])만 사용해야 합니다.
  • STRING_LITERAL_QUOTE안에서:
    • 문자 BS (백스페이스, 코드 포인트 U+0008), HT (수평 탭, U+0009), LF (줄 바꿈, U+000A), FF (쪽 바꿈, U+000C), CR (캐리지 리턴, U+000D), " (따옴표, U+0022), \ (역슬래시, U+005C)는 MUST 요구 사항으로 ECHAR로 인코딩해야 합니다.
    • U+0000 ~ U+0007범위의 문자, VT (수직 탭, 코드 포인트 U+000B) , U+000E ~ U+001F범위의 문자, DEL (삭제, U+007F), 그리고 Char 생성 규칙([XML11])에 맞지 않는 문자는 MUST 요구 사항으로 UCHAR 로 표현하되 소문자 \u 와 4개의 HEX를 사용해야 합니다.
    • ECHAR 또는 UCHAR 로 표현할 필요가 없는 모든 문자는MUST 요구 사항으로 원래의 [UNICODE] 표현을 사용해야 합니다.
  • 토큰 EOL 은MUST 요구 사항으로 하나의 LF (줄 바꿈, 코드 포인트 U+000A)여야 합니다.
  • 마지막 EOL 은MUST 요구 사항으로 제공해야 합니다.

B. URDNA2015

이 절은 비규범적입니다.

RDF 데이터셋 정규화 [CCG-RDC-FINAL]은 “범용 RDF 데이터셋 정규화 알고리즘 2015”(URDNA2015)를 설명합니다. 이는 RDFC-1.0과 본질적으로 같은 알고리즘이며 URDNA2015 구현은 대체로 이 명세와 호환될 것으로 예상됩니다. 작은 차이는 N-Quads 정규 형식 에서 이전에 일부 제어 문자를 이스케이프 없이 표현했다는 것입니다. A. N-Quads의 정규 형식 에 정의된 알고리즘 버전은 단순 리터럴 의 표현과 STRING_LITERAL_QUOTE 안에서 ECHAR로 인코딩하는 문자를 명확히 합니다.

C. URGNA2012

이 절은 비규범적입니다.

이 알고리즘의 이전 버전은 소규모로 배포되어 있습니다. 식별을 위해 이 알고리즘을 “범용 RDF 그래프 정규화 알고리즘 2012”(URGNA2012)라고 하며, 앞서 설명한 알고리즘과 다음과 같이 다릅니다:

  • 4.6 1차 쿼드 해시에서 그래프 이름 위치의 값으로 쿼드에서 빈 노드를 사용했다면, 특별한 빈 노드 식별자 g를 z대신 사용하여 값을 직렬화했습니다.
  • 4.7 관련 빈 노드 해시에서는 술어 값을 < 와 >로 구분하지 않았습니다. 구분자가 없었습니다.
  • 4.8 N차 쿼드 해시에서 position 매개 변수를 관련 빈 노드 해시 알고리즘 에 전달하는 대신 direction 매개변수로 모델링했습니다. 값 p는 property를 뜻하며 관련 빈 노드가 주어 일 때 사용하고, 값 r은 reverse 또는 reference를 뜻하며 관련 빈 노드가 목적어일 때 사용했습니다. URGNA2012 는 데이터셋이 아닌 그래프만 정규화하므로 그래프 이름 위치는 사용하지 않았습니다.
  • 4.8 N차 쿼드 해시에서는 Hn 을 다음과 같이 구성했습니다:
    1. 각 quad ( quads안의 것)에 대해:
      1. 만약 quad의 subject 가 빈 노드 이 고 identifier와 일치하지 않으면, hash 를 관련 빈 노드 해시 알고리즘의 결과로 설정합니다. 전달할 빈 노드 식별자 는 subject 의 것으로 related로 전달하고, quad, issuer및 p 를 position으로 전달합니다.
      2. 그렇지 않고 quad의 object 가 빈 노드 이 고 identifier와 일치하지 않으면, hash 를 관련 빈 노드 해시 알고리즘의 결과로 설정합니다. 전달할 빈 노드 식별자 는 object 의 것으로 related로 전달하고, quad, issuer및 r 를 position으로 전달합니다.
      3. 그렇지 않으면 다음 쿼드로 진행합니다.
      4. hash 에서 일치한 구성 요소의 빈 노드 식별자 ( subject 또는 object)로의 매핑을 Hn에 추가하고 필요에 따라 항목을 만듭니다.

E. 2022년 11월 24일 최초 공개 작업 초안 이후의 변경 사항

이 절은 비규범적입니다.

  • 알고리즘과 예제를 변경하여 빈 노드 식별자에 xyz 형식을 일관되게 사용하고 _:xyz는 사용하지 않도록 했습니다. 논의는 Issue 46 을 참조하세요.
  • 4.6 1차 쿼드 해시 를 단순화하여 기존 구현에서 사용하지 않던 simple 플래그를 제거했습니다. 원래 알고리즘은 할당된 정규 빈 노드 식별자가 있으면 _:a 또는 _:z대신 사용하도록 설계되었습니다. 이는 관련 해시 알고리즘의 방식과 비슷하지만 구현이 진행되기 전에 이 내용은 명세에 포함되지 않았습니다. 따라서 해시는 변하지 않으므로 simple 플래그를 기준으로 이 알고리즘을 호출하는 반복문은 불필요합니다. 논의는 Issue 23 을 참조하세요.
  • N-Quads 정규 형식의 정의를 추가했습니다. 궁극적으로 [N-Quads]가 갱신되면 해당 명세의 인용으로 대체해야 합니다. N-Quads 정규 형식 은 4.6 1차 쿼드 해시에서 사용합니다.
  • Issue 15 의 이슈 표시를 4.4 정규화 알고리즘에서 제거하고, 리터럴 인 쿼드 구성 요소는 정규화되지 않으며 구문 표현이 다른 두 리터럴은 서로 다른 자원으로 남는다는 참고를 추가했습니다.
  • 빈 노드 식별자의 설명 방식을 변경하여( Issue 46참조), 직렬화에 따른 접두부인 _: 를 일반적으로 생략했습니다. 알고리즘에서는 여전히 필요하지만 식별자 자체와 직렬화 형식의 차이를 명확히 했습니다.
  • 알고리즘 이름을 URDNA2015 에서 RDFC-1.0으로 변경했습니다.
  • 용어 normalized dataset 을 정규화된 데이터셋으로 변경했습니다. 이는 입력 데이터셋, 입력 빈 노드 식별자 맵및 발급된 식별자 맵으로 구성됩니다.

G. 감사의 말

이 절은 비규범적입니다.

편집자는 그래프 정규화 문제를 연구한 Jeremy Carroll, 이 명세의 알고리즘에 귀중한 피드백과 테스트 입력을 제공한 Andy Seaborne과 Gavin Carothers, 오랜 세월 그래프 정규화를 고찰한 Tim Berners-Lee 경, 유사한 알고리즘을 연구한 Jesús Arias Fisteus, 그리고 Aiden Hogan에게 감사드립니다. Hogan의 출판물 [Hogan-Canonical-RDF]은 정규화 문제에 대한 중요한 동시대 분석을 제공하고 RDFC-1.0개발의 독립적인 근거가 되었습니다.
